# Модуль `correspondence` (#55, ADR-0027)

Письма компании на движке «Процессы»: очередь «Новые», регистрация с
нумерацией, журналы «Входящие»/«Исходящие», карточка с реквизитами, файлами,
историей и чатом. Заменяет СЭД «Е-дело» и папки Bitrix24.

## Что здесь

| Папка       | Содержимое                                                                                                                                                                                        |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `letters/`  | Контроллер `/api/v1/letters`, чтения (списки, карточка, адресаты), мутации (ручное создание multipart, правка, спам, присоединение), проверка регистрационных полей, маппер DTO, разбор multipart |
| `workflow/` | Адаптер категории `letter` для движка «Процессов», применение окна «Регистрация», смена стадии с событиями, сервис переходов                                                                      |
| `history/`  | История карточки из event log по агрегату `letter`                                                                                                                                                |
| `ports/`    | `LETTER_CHAT_READER` — порт для моста чата (состав беседы, ссылки, видимость)                                                                                                                     |
| `access/`   | Одна функция видимости и прав карточки (Р7)                                                                                                                                                       |

## Как устроено

- **Письмо — сущность движка** (ADR-0024): тип, маршрут и стадия — plain UUID
  без FK; категория типа `letter`. Адаптер регистрируется DiscoveryService по
  `static readonly workflowCategory = 'letter'`.
- **Регистрация — переход** `register` маршрута входящего: окно
  `{kind:'registration'}` + пост-действие `assign_number`. Номер выдаёт движок
  в той же транзакции (`NumberSeriesService`), откат перехода не сдвигает
  счётчик — номеров без пропусков. Формат «Вх-2026/118», год — по
  `COMPANY_TIMEZONE` (Минск).
- **Видимость** (`access/letter-access.ts`): зарегистрированное — всем,
  незарегистрированное — держателям `correspondence.register`; невидимое —
  404 без оракула. Той же функцией пользуются мост чата и (в #461) файлы.
- **Права карточки**: `canEdit` — регистрация + зарегистрировано,
  `canDeleteSpam` — «Новое» и не закрыто, `canJoin` — зарегистрировано и не
  участник. Сервер — истина (I8), веб прячет недоступное.
- **Файлы** — plain UUID модуля files (I3): метаданные через
  `FILE_OBJECT_READER`, запись через `FILE_STORAGE`, отдача — подписанные
  ссылки `SignedUrlService` после проверки видимости. Роли: `main` (документ
  вкладки «Письмо»), `body` (HTML/текст почты), `attachment`, `source` (.eml,
  #56). Файлы писем неизменяемы (`canEdit:false` в реестре доступа файлов).
- **Чат письма** — модуль chat по событиям `correspondence.*`: состав
  (адресат + участники, регистратор не входит — В2) читается портом
  `LETTER_CHAT_READER`, блок `letter_transition` пишется по
  `letter_stage_changed`.
- **Спам** удаляется физически только из «Новое» (Р12): письмо, вложения,
  объекты хранилища (после коммита, best-effort); в аудит — только id.

## Запреты

- Не импортировать модули `workflows`, `chat`, `files`, `crm`, `dictionaries`
  напрямую — только порты-модули (`WorkflowsPortsModule`,
  `CorrespondencePortsModule`, …) и события.
- Не менять контракты `@nodus/contracts` ради удобства сервера: они
  заморожены UI-пакетом.
- Не писать в чужие таблицы: `letters`, `letter_attachments`,
  `letter_participants` — только через `LettersRepository`.
- Тяжёлую работу (PDF-производные) — не в HTTP-запросе: очередь модуля files.
