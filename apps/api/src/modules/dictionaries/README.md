# Модуль dictionaries (ядро)

Справочники и классификаторы — бизнес-списки как **данные, а не код** (I15): «Вид документа», будущие «Типы зданий», «Виды работ» и списки кастомных полей enum/multienum (M10). Модуль ядра — без feature flag (modules.md).

- **Справочник** адресуется стабильным `code` (kebab-case, `SystemDictionary` в контрактах для системных); **элемент** — по UUID: модули-потребители хранят UUID элемента plain-колонкой без FK (I3), переименование элемента ничего не трогает у ссылающихся.
- **Удаления нет** — архивация (`isActive: false`): архивный элемент остаётся читаемым у старых записей, но не предлагается в новых (по умолчанию скрыт в списке). FK внутри модуля — Restrict.
- **Иерархия** — `parentId` у элементов справочника с `hierarchical: true`; у плоского — всегда null. Список выдаётся плоским в порядке (sortOrder, name, id), дерево строит клиент.
- **Системные справочники** (`isSystem`) и их стартовые элементы — данными **миграции** `INSERT … ON CONFLICT DO NOTHING`: есть на любой установке (prisma/seed на проде не запускается — gotcha #311), правки администратора повторным применением не перетираются. Элементы сида несут `code` (`letter`, `contract`, …) — стабильный ключ для дефолтов потребителей.

## Контракты (`@nodus/contracts`)

`dictionarySchema`, `dictionaryItemSchema`, `dictionaryCodeSchema`, `listDictionariesQuerySchema`, `listDictionaryItemsQuerySchema`, `SystemDictionary`.

## Эндпоинты (`/api/v1/dictionaries`)

| Маршрут                                            | Права | Назначение                                                           |
| -------------------------------------------------- | ----- | -------------------------------------------------------------------- |
| `GET /dictionaries?cursor=&limit=`                 | auth  | Справочники в порядке `code`                                         |
| `GET /:code/items?cursor=&limit=&includeArchived=` | auth  | Элементы справочника; неизвестный код — 404, кривой код/курсор — 400 |

Чтение — любому аутентифицированному: элементы нужны всем формам портала, бизнес-списки не секретны.

## Системные справочники

| Код             | Название      | Стартовые элементы (code — название)                                                                          | Потребитель                       |
| --------------- | ------------- | ------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| `document-kind` | Вид документа | letter — Письмо (дефолт регистрации, первым), contract — Договор, order — Приказ, request — Запрос, act — Акт | Регистрация корреспонденции (#55) |

## События (outbox, I9)

Пока не эмитятся: модуль только читает. `dictionary.created/updated`, `dictionary.item_created/updated/archived` (каталог api-conventions.md) появятся с управлением справочниками.

## Не реализовано (следующий шаг — админ-контур M12)

Управление справочниками и элементами (создание, правка, порядок, архивация) правом `dictionary.manage` с событиями `dictionary.*`; права редактирования на уровне справочника; поиск по элементам.

## Лимиты

- Списки — курсорная keyset-пагинация ≤ 100 (по умолчанию 50); курсор — opaque (sortOrder, name, id).
- Индекс `(dictionary_id, sort_order, name, id)` — выдача элементов без сортировки в памяти.
