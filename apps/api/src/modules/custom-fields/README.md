# Модуль custom-fields (ядро)

Реестр **атрибутов** — настраиваемых пользователем полей сущностей (M10, ADR-0029, #431). В интерфейсе термин «Атрибуты»; в коде и API — `custom field` / `customFields`: ключи таблиц и контрактов не переименовываются.

Модуль ядра без feature flag (modules.md): атрибуты нужны карточкам, фильтрам и окнам переходов задач, а те уже под флагом `tasks`.

## Что здесь, а что — нет

- **Здесь:** определения (область, тип, настройки, умолчание, скрытие, порядок), их CRUD, проверка использования перед удалением, порт `CUSTOM_FIELD_REGISTRY` для модулей-владельцев сущностей.
- **Не здесь:** значения. Они живут в JSONB-колонке сущности-владельца (`tasks.custom_fields`, письма/проекты/контрагенты — #55/#52/Н2) по id определения. Чужой таблицы модуль не читает и не пишет (I3): «сколько карточек заполнено» и уборку значений после удаления выполняет владелец — через порт `CUSTOM_FIELD_VALUES_READER` и обработчик события `custom_field.definition_changed` (`change='deleted'`).

## Типы (16 в 13 семействах интерфейса)

`text` · `long_text` · `number` (точность 0–6) · `money` (сумма + валюта системного справочника `currency`) · `date` · `datetime` · `duration` (минуты, показ «ч:мм») · `bool` · `enum` · `multienum` (справочник `dictionaries`) · `user` · `users` · `department` · `project` (недоступен до #52 — 422 `CUSTOM_FIELD_TYPE_UNAVAILABLE`) · `counterparty` (порт CRM) · `link` (URL `http(s)://` или путь `\\сервер\…`).

Смена типа — только расширяющая: `text → long_text`, `enum → multienum`, `user → users` (409 `CUSTOM_FIELD_TYPE_CHANGE_INCOMPATIBLE`). Скаляр читается как массив (`readCustomFieldValue`), данные не переписываются.

## Порт реестра (ADR-0012)

```ts
CUSTOM_FIELD_REGISTRY: CustomFieldRegistry {
  definitions(scope, tx?)                       // определения области, включая скрытые
  prepareCreate(scope, { input, authorId }, tx?) // умолчания + ввод (ввод важнее) + проверка
  prepareUpdate(scope, { current, patch }, tx?)  // null удаляет ключ; проверяются ТОЛЬКО изменённые
  refs(scope, values, tx?)                       // имена/аватары/архивность для DTO детали
}
```

Владелец сущности не собирает zod-схемы и не ходит в справочники сам: единственная точка динамической валидации — порт (I7). Отказ — `422 CUSTOM_FIELD_VALUE_INVALID` с `details.issues[] = {fieldId, reason: unknown|invalid|not_found|inactive, message}`.

Ссылки проверяются пачками через порты владельцев данных: `USER_PROFILE_READER`, `ORG_STRUCTURE_READER`, `DICTIONARY_READER`, `COUNTERPARTY_READER`. Умолчание со ссылкой, ставшей неактивной, тихо пропускается с warn в лог — создание сущности не ломается.

## Эндпоинты (`/api/v1/custom-fields`)

| Маршрут                      | Права                 | Назначение                                               |
| ---------------------------- | --------------------- | -------------------------------------------------------- |
| `GET /definitions?scope=`    | auth                  | Реестр (массив, без курсора — О9: ≤ 100 на область)      |
| `POST /definitions`          | `custom_field.manage` | 201; 409 имя/лимит; 422 недоступный тип                  |
| `PUT /definitions/order`     | `custom_field.manage` | `ids` = ровно все атрибуты области, иначе 409 `CONFLICT` |
| `PATCH /definitions/:id`     | `custom_field.manage` | 200; 409 тип/имя; 422 форма настроек                     |
| `DELETE /definitions/:id`    | `custom_field.manage` | 204; 409 `CUSTOM_FIELD_IN_USE` со списком процессов      |
| `GET /definitions/:id/usage` | auth                  | `{ valueCount, workflows: [{id, name}] }`                |

Правила: имя уникально в области без учёта регистра (`lower(btrim(name))`, выраженный уникальный индекс + проверка под `pg_advisory_xact_lock(431, hashtext(scope))`); лимит 100 на область считается по всем атрибутам, включая скрытые; `sortOrder = max+1` при создании; `reorder` — по всем атрибутам области.

**Удаление** физическое и стирает значения (вердикт владельца 25.10.2026 — архива у атрибутов нет). Запрещено, пока атрибут стоит в окне перехода или в условии «Заполнены поля» **опубликованного** маршрута области: порт `WORKFLOW_FIELD_USAGE_READER` ищет ключ `cf.<id>` в `form.sections[kind=fields].fields` и `rules.validators[kind=fields_required].fields` (оператор jsonb `?`, без LIKE по тексту документа). Черновик удаление не блокирует: публикация с неизвестным полем даёт ошибку `custom_field_unknown`.

## События (outbox, I9)

`custom_field.definition_changed {definitionId, scope, change: created|updated|deleted|reordered, fields?}` — каталожное (gateway рассылает в presence-комнату): клиенты инвалидируют реестр, блок «Атрибуты» карточек и подписи вариантов.

Значение атрибута в отдельном событии не ездит: изменение — в событии сущности (`task.updated` c `customFieldChanges[{fieldId, from, to}]`, ≤ 50, `long_text` обрезан до 500, ключи `cf.<id>` в `fields`).

## Умолчания (Р5)

`{kind:'static', value}` или `{kind:'author_department'}` (только тип `department`). Подставляются при создании сущности на всех путях создания; явное значение важнее. «Подразделение автора» — снимок на момент создания, при переводе сотрудника не пересчитывается.

## Что `hidden` НЕ делает

Скрытие — **видимость, а не контроль доступа** (вердикт владельца 25.10.2026: «не показывать всем, использовать для будущих вычислений»). Скрытый атрибут не отдаётся карточкам, фильтрам и окнам переходов, но:

- остаётся в `GET /custom-fields/definitions` (реестр — инструмент администратора, право на мутации отдельное);
- его значение по-прежнему можно записать через API задачи (`PATCH`/окно) — так пишет автоматика и процессы;
- `customFieldRefs` детали гидрирует его значения.

Секретных данных в атрибутах быть не должно: для «не видит никто, кроме владельца» нужен отдельный механизм прав на значение (не входит в #431).

## Известные ограничения

- `reportIndexed` только запоминается: материализация — по триггеру (Н4). DDL из рантайма не делаем (дрейф схемы, права на DDL).
- Тип `project` появится с модулем проектов (#52); `counterparty` пишется с Н2.
- Фильтры по значениям — клиентские (Р8): серверный `filter[cf.<id>]` с `Prisma.sql` и GIN `@>` — #435.
- Сортировка и сводки по атрибутам — #435; «обязательность при создании» — форма типа #432.
- **Путь-ссылка (`link`) проверяется только грамматикой**: значение не передаётся ни в shell, ни в `explorer.exe` — в вебе путь копируется строкой. Когда появится «Открыть в проводнике» (Н3), мост обязан экранировать путь и запрещать запуск `.exe`/`.lnk`: регэксп значения допускает в хвосте пути любые непробельные символы (кавычки, `&`, `%`, `..`) — это нормальный UNC, но не аргумент командной строки.
