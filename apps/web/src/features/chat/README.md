# features/chat

Мессенджер в теме «Инструмент»: **единый список бесед по активности БЕЗ
секций-заголовков** (вердикт владельца 2026-09-10, раунд 2 — чаты
перемешиваются по свежести; тип строки читается маркером на аватаре: канал —
мегафон, группа — участники, задача — список) + активная беседа справа
(механика Телеграма). **Поиск по беседам** — строка над списком (модель
Битрикс24 «Найти сотрудника или чат»: подстрока по названию и подписи/
последнему сообщению). Подразделы **«Чаты» / «Чаты задач» — в топбаре** по
канону каркаса (search `?tab=tasks`); чаты задач (`type=task`, привязка
`conversation.task`) — обсуждения задач с кнопкой «Открыть задачу» (карточкой
поверх, стек ADR-0009).

**Аватарки и участники (#186):** аватар беседы (группы/каналы) кликабелен в
топбаре при праве changeInfo (дефолт — владелец и модераторы): клик — выбор
файла (превалидация ≤10 МБ PNG/JPEG/WebP в `shared/chat/avatar-upload.ts`),
ПКМ — меню «Сменить/Убрать фото»; сервер квадратизирует в WebP (порт
AVATAR_PROCESSOR), URL приходит подписанной ссылкой. Название в топбаре —
inline-редактирование кликом (Enter — сохранить, Esc — отмена, те же права);
обновление у всех участников — событием `chat.conversation_updated`
(инвалидация списка). Подзаголовок групп/каналов — КНОПКА «N участников»
(`membersCount` контракта, считая себя): открывает панель участников В ТОЙ ЖЕ
колонке, что тоггл-панель «О чате» (view-переключение `chat-side-panel`,
геометрия 1:1; сверху слева стрелка «назад», если панель под ней открыта,
иначе крестик). Панель: поиск (debounce, серверный), чипы ролей
(Владелец/Модератор), меню строки «⋯» по правам (`memberRowActions` — чистая
функция: назначить/снять модератора — manageSettings=владелец, удалить —
removeMembers + иерархия «строго старше»), кнопка «Добавить» — окно
`add-members` (серверный поиск справочника, мультивыбор чипами; тот же
`AddMembersDialog` открывает кнопка UserPlus СЛЕВА от тоггла панели в
топбаре — единственный способ добавления). Окно создания чата/канала:
аватарка выбирается сразу (превью в кнопке, «×» сброс), загрузка — ПОСЛЕ
создания беседы (id узнаём в момент ответа create — `useSetConversationAvatar`
берёт conversationId переменной мутации, не пропом хука: stale-closure).
Мой профиль: большое фото карточки сотрудника кликабельно только у себя
(`canEditAvatar = card.id === me`), аватар — `POST/DELETE /directory/users/me/avatar`.
API разрешает эти мутации только группам и каналам — состав direct/task/letter
фиксирован сущностью (гвард restrictTypes: название/аватар #186, участники
#195, `VALIDATION_FAILED`); моки MSW зеркалят гвард
(`api/mocks/conversation-mutation-handlers.ts`).
WS-инвалидации новых событий — `socket-invalidation.ts` (conversation_updated →
список; member_added/removed/role_changed → список + members(id)); gateway
маршрутизация — fanout.ts (updated → user-комнаты всех участников,
removed/role_changed → user-комната целевого).

**Мессенджер — карточка стека** (`messenger:<conversationId>`, ADR-0009 п.7,
план `docs/mvp/archive/messenger-fullscreen-plan.md`, вердикт владельца 15.09.2026,
модель Битрикс24): клик по беседе служебной полосы открывает ПОЛНОЭКРАННУЮ
карточку мессенджера — то же тело, что страница `/chat`:
`components/messenger-body.tsx` (ЕДИНЫЙ код страницы и карточки — ноль
дублей: список бесед с поиском + рабочая область + панель беседы; вкладка
«Настройка» — без списка). Вкладки Чаты/Чаты задач/Настройка в карточке —
`components/messenger-tabs.tsx` в хроме слайдера (`SliderPanel cardTopbar` +
`headerContent`, порты `data-tab-port` для контура в режиме карточки); на
странице — в топбаре шелла (search `?tab=`). Карточка — inset-2 периметра
(мягкая область на весь экран, `SliderPanel fullscreen` → stripW=0),
служебная полоса НАКРЫТА самой карточкой (шелл её НЕ скрывает — карточки
стека под верхней иначе ехали бы на 40px во время раскрытия, баг-вердикт
владельца 15.09.2026; скрытие полосы — только на модуле мессенджер,
`useRailHidden`); закрытие (X/Esc) возвращает к карточке предыдущей сущности с её
состоянием; клик по другой беседе полосы ПОДМЕНЯЕТ беседу верхней карточки
без ремаунта. Тред и вкладка карточки — локальное состояние (чужой `?thread=`
в маршрут не пишется). Рабочая область беседы — `chat-workspace.tsx` (общая
для всех хозяев; режим compact упразднён вместе с видом `chat`).

**Тоны мессенджера (вердикт 14.09.2026: «зоопарк оттенков»):** список бесед и
весь хром (шапки, композеры, панели) — тон панели `card`; лента каналов,
личных чатов и тредов — ОДИН токен углубления `chat-zone` в обеих темах;
пузыри — выделенные токены `bubble-in`/`bubble-out` поверх углубления (канон
Telegram, #127; вложения внутри пузыря — чипы `card`); разделение зон —
hairline-линии, не ступени цвета. **Сообщение — ЕДИНАЯ сущность во всех хостах
рендера** (пузырь чата, корень треда, карточка поста канала, обсуждение
задачи): заливку и акценты решает ОДНА точка — `shared/chat/message-surface.ts`
(fill/accentText/accentBg/ring/onFilled на токенах bubble-*); карточка поста —
та же поверхность + hairline-бордюр и радиус карточки ленты. Новый хост рендера
сообщения не изобретает свою заливку (урок #127: посты жили на node-panel и
оказались «пузырями другого цвета»).

видна слева в ленте постов»; попытки р.8–9 (авто-маргин, растяжка)
отменены).
**Морф островка композера (р.9–10) — КРОССФЕЙД, не подмена**: сужение в
батч-тулбар — тулбар ПРОЯВЛЯЕТСЯ (`composer-reveal`: @starting-style +
transition, паттерн MDN/CSS-Tricks для маунт-фейда без JS-флага);
расширение — тулбар РАСТВОРЯЕТСЯ на старте (`composer-hide` 120мс),
фаза меняется на СЕРЕДИНЕ роста ширины (140 из 200мс), новый контент
(ввод/заглушка прав) проявляется до конца расширения — счётчик не висит
слева у широкой области, один плавный переход.

**@упоминания-чипы (#176 + ревизия #224, модель Slack)**: упоминание —
inline-токен `@[текст](user:uuid)` в тексте сообщения (источник истины —
текст, привязка по id, отображаемый текст редактируется свободно; парсер —
`@nodus/contracts` mention-tokens) либо токен «Все» `@[Все](user:all)`
(#224: пинг всем активным участникам беседы кроме автора). Рендер:
лента/тред/пост/медиа-пузырь — `shared/chat/mention-chip.tsx` через
MessageText (клик — карточка сотрудника; «Все» — не человек, нейтральный
тон, без карточки); КОНТРАСТ ПО ПОВЕРХНОСТИ (#224): на СВОЁМ цветном
пузыре (variant=default) чип = цвет текста пузыря + полупрозрачная
заливка этого цвета (канон Telegram), персональный тон — на светлых
поверхностях; поля пилюли px-1.5. Сниппеты (цитата-ответ,
поиск/«Избранное»/заметки через FavoriteHitRow, закреп, ЦЕНТР
УВЕДОМЛЕНИЙ #224) — пассивный чип `MentionSnippet`; однострочные
превью (список бесед) и копирование — `stripMentionTokens`. Композер:
автокомплит `composer-mention-autocomplete.tsx` («@» на границе слова →
панель над полем: «Все» закреплено первой строкой (#224, иконка вместо
аватара), участники + серверный поиск справочника с пометкой «не в
беседе», ↑↓/Enter/Tab/Esc). **Модель поля #228 (ревизия #224,
dev-фидбек 06.10): в черновике лежит ВИДИМЫЙ текст — просто ИМЯ
сотрудника** (без «@», без разметки токена; чип в поле — персональный
тон + точечное подчёркивание, заливка-пилюля ТОЛЬКО в пузыре после
отправки, «как делают все»); привязка id — реестром диапазонов
`composer-mention-registry.ts` (дифф-сдвиги/инвалидации при правках,
wire-токены `@[имя](user:id)` пересобираются на отправке, разбор wire —
в правке сообщения и миграции персиста v3; draft-sync хранит на сервере
wire — чипы переживают перезагрузку). Текст textarea прозрачный,
зеркальный оверлей `composer-mention-overlay.tsx` рендерит видимый текст
метрически 1:1 — каретка/клики/выделение/IME НАТИВНЫЕ (канон
react-mentions/css-tricks; кастомный кареточный слой #224 удалён).
Backspace/Delete у чипа АТОМАРНЫ (композит по реестру, клавиатура —
`composer-keydown.ts`); клик по подчёркнутому имени — компактный поповер
правки (✓/✕/🗑, без заголовка), привязка не меняется. Уведомление
получают только упомянутые-участники (решает api, моки — паритет).

«Сегодня/Вчера/дата» (`day-chip.tsx`).
**Серия — grid «колонка аватара + пузыри» с ЛИПКИМ аватаром** (#164, вердикт
30.09, референсы Telegram/Битрикс24; `shared/chat/message-run.tsx` — общая
компонента серий всех хостов: лента беседы, окно треда, обсуждение задачи):
аватар — отдельный элемент серии `grid-row: 1/N+1, align-self: end,
position: sticky; bottom: 8px` — при прокрутке высокой серии прижат к нижней
кромке ленты над композером, у конца серии — обычное место у последнего
пузыря; один высокий пузырь работает тем же механизмом. Чистый CSS без
JS-замеров (антипример coder/coder#27673 — 902 forced layout). «По обе
стороны» — своя серия зеркалится (аватар справа). Виртуализация ленты
(задел после пилота) совместима только с оконной виртуализацией на распорках
(react-virtuoso-стиль): абсолютное позиционирование строк (react-window)
вынимает их из grid-потока и ломает sticky; серия в окно передаётся срезкой,
first/last — от полной серии. Пузыри
чата БЕЗ рамки — вариант `card` Bubble-примитива на токенах
`bubble-in`/`bubble-out` (канон Telegram, #127; контур ступенью тона поверх
chat-zone); хвостик у последнего пузыря серии — ОДНА заливка SVG
(`bubble-tail.tsx`): силуэт сам несёт вогнутую кромку и закруглённый носик к
низу аватарки (линий нет — стык CSS-бордюра и SVG-обводки давал артефакты).
Мета сообщения — ОБЩИЙ компонент `shared/chat/message-meta.tsx` для пузыря чата
И карточки поста канала (#96): пин → «изменено» → время → галочки, микро-кегль
10px (`text-badge`), плотные зазоры; в пузыре это нижняя строка (реакции слева,
мета справа; поля пузыря — единые 10px, #181), в
посте — строка под текстом с тем же зазором. Тон меты — по поверхности (#127):
на залитом своём пузыре `bubble-out-accent` (в тон заливке, канон Telegram),
на чужом пузыре и карточке поста — `muted-foreground`. Время — ВНУТРИ пузыря справа
внизу + галочки отправлено/просмотрено у своих: «просмотрено» — сообщение
просмотрел ХОТЯ БЫ ОДИН участник (`readBy.length > 0`, модель
Битрикс24/Telegram, #102 раунд 2; левая галочка поверх, правая прячется за
ней; терминология «Просмотрено» — семантика ВИДИМОСТИ, не «прочитано»).
Строки прочитавших ПОД сообщениями НЕТ (раунд 2 убрал: «точно Битрикс»):
вместо неё ОДНА строка просмотров НАД областью ввода — см. секцию Realtime.
Реакции и
вложения — ВНУТРЬ пузыря: расширяют его по высоте (иначе аватар и хвостик
отлипают к строке реакций). Композер забирает фокус при входе в чат
(autoFocus; ремоунт по conversationId). Каналы-посты (`thread-feed`,
`post-card.tsx`) — грамматика новостей: БЕЗ хвостов, карточка мягкая; посты —
СЕРИЯМИ одного автора/дня, как в чатах (вердикт 30.09, #164: аватар — один
на серию, колонкой слева тем же run-grid, липкий; имя — у ПЕРВОГО ЧУЖОГО
поста серии, СВОИ посты БЕЗ имени — канон чатов (репорт владельца 01.10,
#180), у остальных — sr-only; в карточке аватар не дублируется; зазор постов
одного автора — 6px, #175). Полоса
обсуждения («N ответов · Обсудить») — у КАЖДОГО поста: пост самостоятельный
тред. Надгробие удалённого поста
с живым тредом (#163 «по ответам») — двухуровневая карточка: строка
«Сообщение удалено» (имя — всегда, не по серии) + ТА ЖЕ полоса обсуждения
(кнопка) — доступ к обсуждениям сохраняется; без живых ответов пост
исчезает бесследно (obliterated).

**Вложения (план `docs/mvp/archive/chat-attachments-plan.md`, вердикты 14.09
и 29.09.2026):** схема `messageAttachment`: `kind` (image/file — явно, не из
mime), `url`, `thumbnailUrl` (серверное WebP-превью, ADR-0015), `width/height`
(габариты). Режимы (#150, `attachments.tsx` — `attachmentsLayout`): галерея —
ТОЛЬКО когда вложения исключительно изображения (1 — крупная плитка, 2+ —
сетка рядами по 3); любой файл в наборе «разбивает» галерею — весь набор
рендерится КАРТОЧНЫМ списком (картинка в списке — карточка с квадратной
миниатюрой, как в Telegram). **Медиа-стиль Telegram (#187): изображение =
ЧАСТЬ пузыря** — BubbleContent медиа-сообщения БЕЗ полей (p-0, full-bleed),
ширина изображения = ширина пузыря; шапка (имя/#180, «Переслано от»,
цитата) — блок с полями 10px НАД картинкой, подпись — блок ПОД картинкой
(перенос по ширине фото, Telegram captionw), низ — реакции слева + мета
справа; свои — без шапки, скруглённые верхние углы картинки режет контейнер.
Ширина пузыря/поста с вложениями задаётся блоком вложений
(`mediaBubbleWidth`: single — бокс из габаритов с полом меты (чистое
изображение) или полом колонки текста (подпись/шапка), `bare` — строго бокс;
gallery — MEDIA_MAX_W;
карточный список — CARD_LIST_W с полом текста), текст переносится внутри;
`maxWidth: 100%` + aspect-ratio плитки — медиа-пузырь сужается вместе с
панелью ПРОПОРЦИОНАЛЬНО, без обрезки (баг #187: карточное вложение не
сжималось). Геометрия плиток — детерминированные px из габаритов
(`fitSingleBox`, крупное не апскейлится до капа 480dp — модель FB Messenger;
растяжка до пола пузыря допустима), лента не прыгает при загрузке. Карточка вложения
(`attachment-card.tsx`) — примитив `Attachment` flat на тоне пузыря: иконка
типа/миниатюра, имя, размер, кнопка скачивания у правого края пузыря. Клик:
файл → просмотрщик (#138), изображение → лайтбокс (`image-lightbox.tsx`:
портал, Esc/стрелки, счётчик; прогрессивно — превью мгновенно, кросс-фейд на
оригинал; БЕЗ скруглений, #151). Карточка поста канала (`thread-feed.tsx`):
автор сверху, медиа — full-bleed в карточке (тот же #187-вид, клип углов —

## Realtime (#104 + раунд 3 пилота): WS-доставка вместо опроса

- **Клиент** — `shared/socket/` (вынос в shared — два потребителя чата):
  соединение живёт с сессией (`useChatSocket` в шелле), токен — function-auth
  из auth-store (свежий на каждую попытку reconnect); обработчики вешаются
  ДО коннекта; статус сокета тихий. Активная беседа подписывается комнатой
  (`useConvRoom` → `conv:join/leave`).
- **События применяются как инвалидации КОАЛЕСЦИНГОМ + локальное применение
  message_sent по seq (раунд 3, «буря рефечей»)**: `message_sent` несёт
  ПОЛНЫЙ DTO нового сообщения в payload (сервер собирает его в транзакции
  отправки) — клиент дописывает его в кэш ленты/треда по непрерывности seq
  (`ws-apply.ts`, канон Telegram: 30–40 сообщ/с отображаются поступательно,
  БЕЗ рефеча; +1 к счётчику корня у ответов треда); дыра в seq / нет DTO /
  темповая оптимистичная запись → рефеч. Прочие события (`edited/deleted/
закрепы/создание`) роутятся в `socket-invalidation.ts` через
  **батчер окон** (`invalidation-batcher.ts`): каждый ключ инвалидируется
  ОДИН раз за окно — ленты ~150 мс, список бесед ~600 мс (гистерезис
  пересортировки: порядок меняется раз за пачку, не на каждое событие).
  Реакции и чужие read патчатся ТОЖЕ локально (`ws-apply`:
  `applyReactionEvent`/`applyReadEvent` — readBy/readAt автора и чипы без
  рефеча; «шторм квитанций» аудита #123). Свой read с ДРУГОГО устройства
  тих — бейдж там догонит следующим событием (мультидевайс-трейд-офф
  пилота). Сервер — единственная истина; локальное применение — только
  добавление строк, всё остальное — рефечем. Reconnect → flush батчера +
  инвалидация всего чат-дерева + повторный join.
- **Поллинг — fallback** (`shared/chat/api.ts` livePoll): сокет жив → 60 с,
  разрыв → прежние 5/10 с; в мок-режиме chat сокет не поднимается.
- **Скролл догона (раунд 3 + #132)**: одиночная своя отправка — плавный smooth,
  быстрая серия — мгновенный auto (`scroll-end-store.ts` несёт поведение в
  нонсе; smooth на каждую пачку = «дёргание»); **чужие сообщения у низа
  докручивает app-layer догон #132** (`use-incoming-follow.ts`: слушатель
  скролла держит «у низа» (32px) в ref, layout-effect после прибытия чужого
  сообщения просит `scroll-end-store.request('auto')` — тот же канал, что
  своя отправка; гейт `!anchoring`; режимы примитива не наблюдаемы из
  приложения — у пилотов догона не было). **Раунд 5 (баг «первая после F5
  реакция дёргает ленту»): pre-paint компенсация роста** — layout-effect
  после КАЖДОГО рендера ленты, пока «у низа»: scrollHeight вырос на delta →
  `scrollTop += delta` синхронно ДО отрисовки кадра (чип реакции/правка
  растят высоту, скролл-догон примитива приходит лишь следующим кадром —
  кадр рисовался «недокрученным» рывком; компенсация закрывает любые
  роста низа единым механизмом, значения совпадают с последующим
  scrollToEnd — конфликта нет; вне enabled высота лишь запоминается —
  фаза якоря). В истории (выше низа) сообщения
  копятся: на стрелке «вниз» чип-счётчик НЕпрочитанных (mono 11px, #132),
  клик — прежний прыжок к первому непрочитанному/в конец. **Весь этот стек
  (примитив + догон + компенсация + стрелка) — ЕДИНЫЙ для ленты беседы и
  ленты постов канала (#175): канал всегда открывается вниз (без якорной
  фазы, `autoScroll` с маунта), самописный stick-эффект постов удалён.**
- **«Печатает…» (#104 раунд 2, модель Telegram: и в шапке, и в списке)**:
  композер эмитит `chat.typing` (троттл 2 с, typing-emitter; threadRootId —
  печать В ТРЕДЕ, раунд 3), gateway троттлит 3 с и рассылает в conv-комнату
  ПЛЮС user-комнаты участников без автора (thread-печать — ТОЛЬКО conv-
  комнату: в список бесед и шапки каналов не попадает); индикатор —
  подзаголовок шапки беседы (`conversation-bar.tsx`) И превью строки списка
  бесед; в ОКНЕ ТРЕДА — свой индикатор в шапке (`thread-pane.tsx`,

- **Просмотры = видимость вьюпортом ВСЕЙ строки (#102 р.2 + раунд 3)**:
  квитанции `POST /chat/conversations/:id/read { upToSeq, threadRootId? }` —
  `use-viewport-read.ts`: ЕДИНЫЙ IntersectionObserver (root=скроллер) по
  строкам `[data-message-id]` держит пересекающиеся, а решение «строка
  просмотрена ⇔ её НИЖНИЙ КРАЙ виден» принимает по живой геометрии
  (`maxSeenSeq`, допуск 4 px; пересчёт в колбэке IO и на скролле контейнера —
  IO не перефирашивает частично видимые при прокрутке внутри порога);
  верхушка пузыря ≠ просмотр. `viewport-read-scheduler.ts` — тротthrottle
  ~500 мс, только вперёд, flush на уходе из беседы/таба, скрытый таб не
  отправляет. Квитанция из треда (threadRootId) двигает watermark БЕСЕДЫ
  («увидел где угодно = просмотрено») И трэда (гасит точку «есть новые»);
  GET ленты курсор не двигает.
- **Pill просмотров (#102 р.2 → раунд 4 → #132, модель Битрикс24 по вердиктам
  владельца)**: flow-элемент ПОСЛЕДНИМ в ленте (`views-line.tsx`, все три
  ленты: беседа, тред, лента канала) — прикреплён к низу последнего
  сообщения/поста (≈5px под ним), скроллится с лентой (вверх — уезжает),
  в короткой ленте стоит под пузырём, а не у низа экрана; появление —
  fade-only (`views-pill` @starting-style; translate в flow читался как
  «лента оседает»). **#132: кегль 13px (`text-label`, фидбек «мелкий»);
  высота под метку РЕЗЕРВИРУЕТСЯ всегда при наличии своего последнего
  сообщения** (невидимый слот той же геометрии, `views-reserved`):
  появление/исчезновение «Просмотрено» не меняет высоту ленты — стена
  чата неподвижна (раньше первый просмотр приподнимал ленту). Нет своих
  сообщений — резерва нет. Текст — квитанция СВОЕГО последнего сообщения окна:
  группы/каналы — «✓✓ Просмотрено: {Имя Фамилия} и ещё N» (имена БЕЗ
  отчества, `shortPersonName`; подчёркнут только кликабельный «и ещё N» →

- **Открытие на первом непрочитанном (раунд 3 → раунд 4, паттерн Telegram)**:

  попыток»), иначе unreadCount>0 → якорь. Якорь и jump открытия идут ОДНИМ

  цели в последнем экране). Разделитель «Непрочитанные сообщения» — ЖИВОЙ
  по watermark: строго над первым непрочитанным (даже внутри серии одного
  автора), спускается по мере чтения и ИСЧЕЗАЕТ сразу после прочтения
  всего (вердикт раунда 4). Авто-догон — только фактом «пользователь у
  низа». Стрелка «вниз» (`feed-scroller-button.tsx`): первое непрочитанное
  ниже сгиба — ПЛАВНЫЙ скролл к нему (вердикт: без телепорта), уже видно —
  штатный плавный скролл в конец; «навигации по одному сообщению» нет.

  (`useForwardMessages.onSuccess` → scroll-end-store): одиночная шла через
  композер, батч оставался без догона (вердикт раунда 4).
- **Треды: наблюдатели (раунд 3)** — уведомление и счётчик трэда видит
