# features/chat

Мессенджер в теме «Инструмент»: **единый список бесед по активности БЕЗ
секций-заголовков** (вердикт владельца 2026-09-10, раунд 2 — чаты
перемешиваются по свежести; тип строки читается маркером на аватаре: канал —
мегафон, группа — участники, задача — список) + активная беседа справа
(механика Телеграма). **Поиск по беседам** — строка над списком (модель
Битрикс24 «Найти сотрудника или чат»: подстрока по названию и подписи/
последнему сообщению). Подразделы **«Чаты» / «Чаты задач» — в топбаре** по
канону каркаса (search `?tab=tasks`); чаты задач (`type=task`, привязка
`conversation.task`) — обсуждения задач с кнопкой «Открыть задачу» (карточкой
поверх, стек ADR-0009).

**Мессенджер — карточка стека** (`messenger:<conversationId>`, ADR-0009 п.7,
план `docs/mvp/archive/messenger-fullscreen-plan.md`, вердикт владельца 15.09.2026,
модель Битрикс24): клик по беседе служебной полосы открывает ПОЛНОЭКРАННУЮ
карточку мессенджера — то же тело, что страница `/chat`:
`components/messenger-body.tsx` (ЕДИНЫЙ код страницы и карточки — ноль
дублей: список бесед с поиском + рабочая область + панель беседы; вкладка
«Настройка» — без списка). Вкладки Чаты/Чаты задач/Настройка в карточке —
`components/messenger-tabs.tsx` в хроме слайдера (`SliderPanel cardTopbar` +
`headerContent`, порты `data-tab-port` для контура в режиме карточки); на
странице — в топбаре шелла (search `?tab=`). Карточка — inset-2 периметра
(мягкая область на весь экран, `SliderPanel fullscreen` → stripW=0),
служебная полоса НАКРЫТА самой карточкой (шелл её НЕ скрывает — карточки
стека под верхней иначе ехали бы на 40px во время раскрытия, баг-вердикт
владельца 15.09.2026; скрытие полосы — только на модуле мессенджер,
`useRailHidden`); закрытие (X/Esc) возвращает к карточке предыдущей сущности с её
состоянием; клик по другой беседе полосы ПОДМЕНЯЕТ беседу верхней карточки
без ремаунта. Тред и вкладка карточки — локальное состояние (чужой `?thread=`
в маршрут не пишется). Рабочая область беседы — `chat-workspace.tsx` (общая
для всех хозяев; режим compact упразднён вместе с видом `chat`).

**Тоны мессенджера (вердикт 14.09.2026: «зоопарк оттенков»):** список бесед и
весь хром (шапки, композеры, панели) — тон панели `card`; лента каналов,
личных чатов и тредов — ОДИН токен углубления `chat-zone` в обеих темах;
пузыри и вложения — `node-panel` поверх углубления; разделение зон —
hairline-линии, не ступени цвета.

**Ленты сообщений — серии по канону Битрикс24/Телеграм** (вердикты 14.09.2026,
план `docs/mvp/archive/chat-messages-plan.md`; имя в пузыре — вердикт
24.09.2026, #96): `shared/chat/message-groups.ts` группирует подряд идущие
сообщения одного автора в серии (разрыв — только смена автора или календарного
дня; чистые функции + unit-тесты). В серии: имя — чужое и только у первого
сообщения серии, при этом имя живёт ВНУТРИ пузыря верхней строкой (полужирное
`text-info`, реф Битрикс24 — имя цветное и отличается от текста; у сообщений
серии без видимого имени — sr-only автор), аватар
один — у ПОСЛЕДНЕГО (self-end; колонка аватара зарезервирована у всех
сообщений серии, пузыри на одной вертикали), ритм 2px внутри серии / 12px
между, при смене дня — дата-чип «Сегодня/Вчера/дата» (`day-chip.tsx`). Пузыри
чата БЕЗ рамки — вариант `card` Bubble-примитива (контур ступенью тона, рефы
Битрикс24); хвостик у последнего пузыря серии — ОДНА заливка SVG
(`bubble-tail.tsx`): силуэт сам несёт вогнутую кромку и закруглённый носик к
низу аватарки (линий нет — стык CSS-бордюра и SVG-обводки давал артефакты).
Мета сообщения — ОБЩИЙ компонент `shared/chat/message-meta.tsx` для пузыря чата
И карточки поста канала (#96): пин → «изменено» → время → галочки, микро-кегль
10px (`text-badge`), плотные зазоры; в пузыре это нижняя строка (реакции слева,
мета справа, вертикальные паддинги облака 6/5px — метка прижата к низу), в
посте — строка под текстом с тем же зазором. Время — ВНУТРИ пузыря справа
внизу + галочки отправлено/прочитано у своих: «прочитано» — сообщение прочитал
ХОТЯ БЫ ОДИН участник (`readBy.length > 0`, модель Битрикс24/Telegram, #102;
левая галочка поверх, правая прячется за ней; мок «прочитывает» через ~2 с с
первым участником в readBy, отложенная инвалидация без polling). ПОД своим
сообщением/постом — строка прочитавших `shared/chat/message-readers.tsx` (#102):
стек аватарок с тултипами ФИО + «Прочитано», при >5 — «Прочитано N из M» и
первые аватарки (M = участники без автора, из кэша списка бесед); в direct
строки нет (только галочки), у чужих сообщений readBy пуст (приватность
автора). Реакции и
вложения — ВНУТРЬ пузыря: расширяют его по высоте (иначе аватар и хвостик
отлипают к строке реакций). Композер забирает фокус при входе в чат
(autoFocus; ремоунт по conversationId). Каналы-посты (`thread-feed`) — без
серий, хвостов и этой анатомии: грамматика новостей.

**Вложения (план `docs/mvp/archive/chat-attachments-plan.md`, вердикт 14.09.2026):** схема
`messageAttachment` расширена ЗАРАНЕЕ под будущую загрузку и лайтбокс: `kind`
(image/file — явно, не из mime), `url`, `thumbnailUrl`, `width/height` (резерв
бокса до загрузки — лента без сдвига). Грамматика Битрикс24 внутри пузыря и
карточки поста СВЕРХУ ВНИЗ: галерея изображений → чипы файлов → текст →
нижняя строка (реакции + время). Галерея (`attachment-gallery.tsx`): одно фото —
крупное превью, 2–3 — ряд равновысотных плиток, 4+ — ряды по 3; `onOpen(index)` —
точка подключения будущего лайтбокса (портал, Esc/стрелки, счётчик). Чип файла
(`attachment-file.tsx`) — примитив `Attachment`: иконка по mime, имя (truncate),
размер, скачивание справа. Карточка поста канала (`thread-feed.tsx`): автор
сверху, вложения выше текста, реакции+время строкой, ответы — тонированной
полосой с аватарами и счётчиком («N ответов») и входом «Обсудить».

**Тёмная тема — без теней; композер — «вечный курсор» (вердикты 14.09.2026):**
тени рамы и слайдера (`frame-shadow`/`slider-shadow`) — ТОЛЬКО светлая тема;
в тёмной `none`: чёрная тень на почти чёрном читается разлитым пятном
(«неровные границы, будто разлитая жидкость»), элевацию держат ступени тона и
hairline-бордюры (Exa-research: Material M3, Atlassian — в тёмной теме
элевация тоном поверхности, тень там артефакт). Композер (вердикт 15.09.2026,
модель Битрикс24 «tools in the reply field»): ЕДИНЫЙ `shared/chat/chat-composer.tsx`
для чатов, каналов, тредов и обсуждения задач; бар в покое `min-h-16` (канон
нижних баров карточек), растёт ВВЕРХ; поле ввода — ОДИН окаймлённый контейнер
(`rounded-xl border-input`): скрепка внутри слева, textarea
середина (rows=1 + field-sizing, авторост до `max-h-[45vh]`, дальше скролл
внутри поля), смайл и микрофон внутри справа; выравнивание иконок —
grown-тоггл (ResizeObserver по высоте textarea против базовой строки): в
покое (одна строка) все иконки ПО ЦЕНТРУ высоты строки (баг-вердикт
15.09.2026: скрепка сидела выше центра), при росте поля — скрепка вверху,
иконки внизу (модель Битрикс24), отправка SendHex — СНАРУЖИ справа;
иконки — ЗАГЛУШКИ до issues загрузки/эмодзи/голосовых (схема вложений готова
их принять); контур поля при активном курсоре НЕ подсвечивается (фокус виден
самим курсором). «Вечный курсор»
(`shared/chat/composer-focus.ts`, канон Телеграм): пока открыт чат/канал/тред —
каретка живёт в его композере; обычные клики по UI (карточки, кнопки, пустое
место) возвращают её; фокус передаётся ВНУТРЕННЕ только вручную другому
композеру (закрыли тред — курсор снова в ленте канала); клавиатурная навигация,
выделение текста и открытый оверлей-слой (диалог/поповер/меню владеют фокусом
в момент открытия — гард stealFocus, #71) фокус не отбирают; постоянные
вместилища композера (карточка-слайдер — тоже role="dialog") слоем НЕ
считаются — иначе «Ответить»/«Редактировать» и обычные клики в слайдере не
возвращали курсор (вердикт 25.09). Команды меню
сообщения (копировать, закрепить, заглушки с тостом) и закрытие глобальных
диалогов (пересылка/удаление/откреп) ВОЗВРАЩАЮТ курсор в композер, дождавшись
освобождения оверлей-слоёв (#91: `focusComposerWhenFree` в обработчиках
реестра, `dialog-hosts` — на закрытии диалога; гард #71 не крадёт фокус у
открытого слоя — следующий поверх диалог переживает переход).
Подзаголовок беседы НЕ дублирует название проекта/номер задачи — они уже в
заголовке (`conversationSubtitle`, вердикт 15.09.2026).

**Контекстное меню беседы и лайтбокс (вердикт 14.09.2026 «всё отлично»):** ПКМ по
строке списка бесед — меню модели Битрикс24 (`conversation-menu.tsx`):
«Посмотреть позже» / «Закрепить»⇄«Открепить» / «Выключить звук»⇄«Включить
звук» / «Скрыть»; состояния читаются на строке глифами (булавка, перечёркнутый
колокол, часы), закреплённые — ВСЕГДА сверху списка (`sortByActivity`),
«посмотреть позже» прячет счётчик непрочитанных до нового сообщения, «скрыть»
убирает из списка (история сохраняется). Контракт: `pinned/muted/snoozed` в
`conversationListItem` + `conversationUpdateBody` (PATCH). **Рамка закрепов и
сепараторы списка (#96, вердикт владельца 24.09.2026, реф Битрикс24):**
ведущая группа закреплённых строк обрамлена hairline-рамкой со скруглением
(БЕЗ заливки; смещение рамки от краёв списка одинаковое, 5px со всех сторон);
ховер закреплённой строки занимает РОВНО внутреннюю область рамки (скругление =
внутренний радиус), у остальных строк ховер с тем же боковым зазором 5px — все
подсветки на одной вертикали; ритм текста единый (`mx + border + px = px-4`
обычной строки — список не «сдвигается»; кнопка строки — inline-level элемент:
ширина только явная `w-full`/`w-[calc(100%-…)]`, `w-auto` сжимается по
контенту, а `w-full` поверх полей даёт горизонтальное переполнение). Между
строками — hairline-сепараторы НЕ на всю ширину колонки (mx по началу текста),
внутри рамки тоже; при ховере строки СОСЕДНИЕ сепараторы исчезают
(`data-row`/`data-sep` + правило в globals.css — подсветка «поглощает»
разделитель, visibility, не display). Лайтбокс галереи
(`image-lightbox.tsx`): портал поверх интерфейса, Esc/задник — закрыть,
стрелки — листание, счётчик «N / M», фокус возвращается плитке; клик по плитке
галереи больше не заглушка. Вспышка контура шелла ЗАПРЕЩЕНА на сворачивание/
разворачивание панелей (флаг width-transition в `circuit-frame.tsx`: на
переходной геометрии пульс улетал поверх рейки — вердикт владельца).

**Каналы — лента новостей-тредов** (вердикт владельца 2026-09-10): каждое
сообщение канала — корневой пост (новость), ответы ссылаются на корень
(`threadRootId`, ровно один уровень). Тред открывается **ПОЛНОВЫСОТНЫМ окном
рядом с лентой** (`shared/chat/channel-view.tsx`, #42 + вердикт 15.09.2026;
Slack-паттерн по research slack.design: тред — отдельная панель, не оверлей
и не замена ленты): лента, тред и панель беседы — три полновысотные колонки,
их бары стоят НА ОДНОЙ ЛИНИИ и ОДНИМ ТОНОМ (в карточках — `bg-card`: зона
чата темнее только НИЖЕ бара — баг-вердикт 15.09.2026 «бар другого
цвета»; бар треда — `threadBarClass`: мессенджер h-14,
проект h-10 bg-card — в высоту и тон баров хоста; «Обсуждение N» слева,
крестик у ПРАВОГО КРАЯ колонки — закон колонки, как у панели); бар беседы живёт В КОЛОНКЕ
ЛЕНТЫ (`header` канала) и сжимается вместе с ней — тоггл панели стоит на
правом краю ЛЕНТЫ. У окна треда свой композер; перегородка тянется мышью с
памятью (`nodus-thread-w-v1`, `shared/ui/use-pane-width.ts` — императивный
drag по канону use-chat-width); открытие/закрытие — вталкивание шириной
(transition-[width], приём панели «О задаче»). Узкая зона канала (< 640px:
лента 320 + тред 320) — фолбэк drill-down: тред заменяет ленту с кнопкой
«К ленте» (бар беседы остаётся). Посты ленты сжимаются с лентой
(w-full max-w-2xl), перегородка ходит влево до минимума ленты 320
(вердикт владельца). **СВЯЗИ «пост → тред» НЕТ** (вердикт владельца
15.09.2026): грамматика контура — для ПОСТОЯННОЙ структуры (рейка, вкладки,
рамка), а пост — движущийся контент (скролл/подгрузка ломали живой замер);
**бары — запретная зона для связей**. Семантику «к какому посту тред» несёт
корневой пост внутри окна (показан сверху, отделён штриховой линией) —
как в Slack. Тред — search-параметр
`?thread=<rootId>` (deep-link). Посты ленты — ограниченной ширины
(`max-w-2xl`, референс — каналы Битрикс24: действия поста под ним, не на
другом краю экрана); счётчик ответов скрыт при нуле. Уведомления канала —
ТОЛЬКО участники треда и наблюдатели проекта (анти-спам; бэкенд-механика —
M13, в концепте не реализуется). Канал проекта создаётся автоматически при
создании проекта (`project.channelId`, см. features/projects — колонка
обсуждения карточки проекта рендерит тот же механизм из `shared/chat`).

Групповые/личные/задачи — обычная лента сообщений (MessageScroller +
Bubble-примитивы как в обсуждении задачи).

## Realtime (#104): WS-доставка вместо опроса
