# features/automation

Раздел «Автоматизация» — единый дом настройки процессов (эпик #377, north-star §5):
вкладка раздела «Типы задач» (#378) живёт в топбаре шелла; позже «Права
доступа» (#379), «Схемы проектов» (#38, V2). Новая автоматизация — новая
вкладка, не новый модуль меню.

**Веб-раздел — композиция API модуля tasks** (отдельный backend-модуль не
заводим, I13): типы задач, их маршруты и публикация — эндпоинты `/tasks/types*`,
`/tasks/workflows*` (README `apps/api/src/modules/tasks/README.md`).

## Состав (#378)

- `pages/automation-page.tsx` — рама окна в грамматике мессенджера: слева
  колонка типов (`bg-card`, `border-r`, шапка h-14 с поиском и «+»), справа
  редактор маршрута выбранного типа. Названия НЕ дублируются (вкладка — в
  топбаре, имя типа — в строке списка). Глубокая ссылка `/automation?type=<id>`.
- `components/types/*` — список типов (строка: плитка-значок + имя + мета
  «7 статусов · 128 задач», меню «⋯» по ховеру — настройки/копировать/архив,
  архив свёрнут группой; поиск локальный), диалог создания
  (название/значок/цвет/основа «копия или простой»), настройки типа —
  внутриоконная панель (свойства сохраняются сразу, оптимистично).
- `components/editor/*` — редактор маршрута: строка инструментов h-14 с
  разделителем (создание статуса с выбором этапа, «+ Кнопка», undo/redo,
  «Упорядочить», чип версии, проблемы, отмена/публикация, зум — атрибуция
  React Flow в углу не пересекается), холст `shared/flow` (свободная
  слоевая раскладка, узлы-статусы, рёбра-кнопки с подписями в коридорах),
  инспекторы статуса и кнопки (внутриоконные панели справа), диалог
  публикации (сводка, обязательные переносы, конфликт версий 409).
- `model/route-doc-store.ts` — zustand-стор рабочей копии (ADR-0021):
  документ, история (снимки ≤100), черновик в localStorage
  `nodus-workflow-draft-v1:<workflowId>` (zod на границе, версия-гейт);
  ручные позиции узлов — часть черновика (в публикацию не попадают,
  историю undo не засоряют).
- `lib/plural-ru.ts` — формы множественного числа (сводка публикации).
- `api/automation-api.ts` — CRUD типов и публикация (кэш — `automationKeys`,
  в `shared/api/automation-keys.ts`: его читает WS-инвалидация каталожных
  событий); кросс-фичевые хуки типов (создание/смена типа) —
  `shared/api/task-types-api.ts`. Моки — `api/mocks/automation-handlers.ts`
  (проверки `checkWorkflowDocument`, конфликт версий, переносы — как сервер).

## Границы

- Фича **не импортирует** `features/tasks` (eslint-boundaries): общее живёт
  в `shared/flow` (движок холста, ADR-0022), `shared/workflow`
  («Схема маршрута», группировка панели процесса, значки типов) и
  `shared/api/*-keys.ts`.
- Без права `task.workflow_manage` (до матрицы #379 — только администратор):
  холст и инспекторы только для чтения, бейдж «Только просмотр».
- Маршрут правится на клиенте и публикуется целиком (`display`/порядок кнопок
  задаёт сервер); удаления нет — архив (ADR-0021).
