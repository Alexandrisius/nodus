# features/automation

Раздел «Автоматизация» — единый дом настройки (эпик #377, north-star §5):
вкладки в топбаре шелла — **«Процессы»** (#428, ADR-0024), **«Атрибуты»**
(#431, ADR-0029) и **«Права доступа»** (#379, ADR-0034); позже «Схемы
проектов» (#38, V2). Новая автоматизация — новая вкладка, не новый модуль меню.

**Веб-раздел — композиция API двух модулей.** «Процессы» (`apps/api/src/modules/workflows`,
ADR-0024): типы процессов, их маршруты и публикация — эндпоинты `/workflows/types*`,
`/workflows/*` (README `apps/api/src/modules/workflows/README.md`). Типы категории
`task` дополнительно читают задачные хуки — `shared/api/process-types-api.ts`.
«Права доступа» — API модуля `directory` (`/directory/roles*`, README
`apps/api/src/modules/directory/README.md`): общая матрица «роль × право»
живёт в `shared/access` и `shared/api/roles.ts` (её же переиспользуют другие
модули и #432).

## Состав (#378, #431, #379)

- `pages/automation-page.tsx` — переключатель вкладок по `?tab=`
  (`fields` → реестр атрибутов, `access` → матрица прав, иначе «Процессы»);
  «Процессы» и «Атрибуты» — окна-сплиты, матрица — таблица во всю ширину.
- `components/processes/processes-tab.tsx` — окно-сплит в грамматике мессенджера: слева
  колонка типов (`bg-card`, `border-r`, шапка h-14 с поиском и «+»), справа
  редактор маршрута выбранного типа. Названия НЕ дублируются (вкладка — в
  топбаре, имя типа — в строке списка). Глубокая ссылка `/automation?type=<id>`.
- `components/types/*` — список типов (строка: плитка-значок + имя + мета
  «7 статусов · 128 задач», меню «⋯» по ховеру — настройки/копировать/архив,
  архив свёрнут группой; поиск локальный), диалог создания
  (название/значок/цвет/основа «копия или простой»; категория — задача),
  настройки типа — та же правая панель-колонка (свойства сохраняются сразу,
  оптимистично). **Категория — группировкой:** заголовки групп «Задачи»/
  «Письма» показываются, только когда категорий в списке две и больше
  (`lib/group-by-category.ts`, решение владельца 25.10); меток на строках нет.
- `components/editor/*` — редактор маршрута (#378 ред. 2, рефы Jira / Трекер):
  - `route-toolbar.tsx` — верхний бар окна h-14 с линией: тип и состояние,
    проблемы, «+ Статус», «+ Переход», «Упорядочить»; справа «Сбросить» и
    «Опубликовать» (не уезжает никогда — контейнерные брейкпоинты);
  - `route-canvas.tsx` — холст `shared/flow` (ADR-0022): общая раскладка,
    12 точек подключения, подписи на стрелках, метка «Любой статус», старт
    «Создание задачи»; масштаб и отмена — слева внизу; клик по любому узлу
    открывает панель (статус — свою, метка — своей кнопки, старт —
    начального статуса);
  - `panel/*` — правая панель: полновысотная колонка как панель беседы
    мессенджера (`side-panel.tsx`, выезжает и сужает холст), одна анатомия у
    статуса и кнопки (`panel-kit.tsx`: поля → строки «›» → удаление),
    разделы «Кнопки из статуса» (порядок, добавление, «Как увидят в карточке»
    со «Смотреть как»), «Кто видит», «Условия перехода», «Особые правила»;
    «Настройки типа» из меню «⋯» строки открываются ДЛЯ ЭТОЙ строки
    (`settingsTypeId`, а не boolean + selected) — выделение редактора не
    меняется (#409);
  - `publish-dialog.tsx` — сводка, обязательные переносы; отказы сервера
    понятны: 409 — «Загрузить свежую версию», 422 «нужен перенос» — выбор
    цели, 422 «схема с проблемами» — список, прочее — текст ошибки.
- `model/route-doc-store.ts` — zustand-стор рабочей копии (ADR-0021):
  документ со статусами, кнопками и ОБЩЕЙ раскладкой холста, история
  (снимки ≤100), черновик в localStorage `nodus-workflow-draft-v1:<workflowId>`
  (zod на границе, версия-гейт). `dirty` — только правки структуры
  (`structureChanged`): расстановка — оформление. При загрузке baseline и
  документ проходят ОДНУ канонизацию (`canonicalDocument`: sortOrder
  статусов — индекс в группе, кнопок — индекс в группе fromStageId), потому
  что сервер отдаёт глобальную нумерацию, а клиент после правок — групповую;
  без этого вход показывал ложное «есть изменения» (#409). После публикации
  правки закрыты (`pendingReload`), пока не придёт свежий документ сервера:
  `sync()` перечитывает его по смене версии — `baseVersion` берётся только
  из документа сервера, черновые `new:*` повторно не уходят.
- `model/route-doc-layout.ts` — сопровождение раскладки на каждом шаге:
  `freezeLayout` («что видишь — то и стоит»: первая правка фиксирует
  картинку целиком), `settleLoops` (сдвинутые обходы не слипаются),
  `settleLabels` (подписи не наезжают на узлы и друг на друга),
  `persistedLayout` + `layoutFingerprint` (что и когда автосохранять).
- `model/use-layout-autosave.ts` — расстановка уходит на сервер сама
  (`PUT /workflows/:id/layout`, 600 мс тишины, без новой версии);
  смена типа, уход со страницы и «Опубликовать» отправляют несохранённое
  сразу (`flushLayoutAutosave`: места стоящих элементов сервер при
  публикации берёт из сохранённой раскладки). Чужая сохранённая
  расстановка той же версии приходит в открытый редактор (`sync` →
  `adoptSavedLayout`), свои неотправленные места остаются.
- `lib/plural-ru.ts` — формы множественного числа (сводка публикации).
- `api/automation-api.ts` — CRUD типов, публикация и сохранение расстановки (кэш — `automationKeys`,
  в `shared/api/automation-keys.ts`: его читает WS-инвалидация каталожных
  событий `workflow.*`); кросс-фичевые хуки типов категории задачи —
  `shared/api/process-types-api.ts` (там же `defaultProcessType` — тип по
  умолчанию экспресс-формы и доски проекта). Моки —
  `api/mocks/automation-handlers.ts` (проверки `checkWorkflowDocument`,
  конфликт версий, переносы, постоянные id вместо `new:*` при публикации —
  `publish-resolve.ts` — как сервер).

## Окно перехода (#380)

Инспектор кнопки: раздел «Окно перехода» (`window-section.tsx`) — тумблер,
заголовок (пусто — название кнопки), шесть разделов в фиксированном порядке:
поля, трудозатраты (режим «если ещё не списаны» / «всегда»), итог, файлы
(подпись + минимум 0–5 = валидатор `result_files`), сообщения из чата как итог,
причина/комментарий. «Обязательно» у времени/итога/файлов правит **гейты**
(Р3), у причины и сообщений — собственный флаг раздела. «Посмотреть окно» —
настоящий `TransitionWindow` в режиме превью (без данных, отправка неактивна).
Правки формы — `model/transition-form.ts`; документ публикуется вместе с
кнопкой, черновики без формы читаются через default.

## Вкладка «Атрибуты» (#431, ADR-0029; ревизия UI 25.10.2026)

Реестр атрибутов — кастомных полей сущностей (в коде — `custom field`):
определения по сущностям (задачи/письма/проекты/контрагенты), значения — в
JSONB сущности по id определения. Термин «Атрибуты» и модель «список по
центру, как в Битриксе» — вердикт владельца; архива нет: «Удалить» и флаг
«Скрытый атрибут».

- `components/fields/fields-tab.tsx` — шапка журнала (заголовок + счётчик,
  пилюля сущности, «Создать», поиск, шестерёнка) + каноническая таблица
  `shared/views` (`custom-fields.list`, колонки — `field-columns.tsx`) +
  меню строки (`field-row-menu.tsx`: изменить, поднять/опустить — порядок
  карточки, скрыть/показать, удалить) + островок пачки
  (`field-bulk-island.tsx`). Маршрут
  `/automation?tab=fields[&scope=<сущность>][&field=<id>]` (field — окно
  атрибута). Права — `custom_field.manage`; без права — просмотр.
- `field-dialog.tsx` (+ `field-type-picker`, `field-dialog-form`,
  `field-settings`, `field-options-editor`, `field-default-value`) — ОДНО
  окно создания и правки фиксированной высоты: слева колонка типов, справа
  форма; всё правится в черновике (`lib/field-draft.ts` + тест) и уходит
  на сервер по «Создать»/«Сохранить» (варианты справочника → атрибут).
  Тип после создания закреплён, модификаторы («Многострочный», «Несколько
  значений») — односторонние; умолчание списка — флажок на варианте (модель
  Битрикс24), остальных — редактор карточки.
- `field-delete-dialog.tsx` — удаление одного/пачки: число заполненных
  карточек (сотрутся) и маршруты процессов, где атрибут стоит в окне или
  условии, — тогда удаление заблокировано со списком (`GET …/usage`).
- `api/custom-fields-api.ts`, `api/dictionaries-api.ts` — правка
  определений (оптимистично с откатом), удаление, «где используется»,
  применение черновика вариантов (`commitOptionDrafts`: удалить →
  переименовать → добавить → порядок).
- `lib/field-type-families.ts` — 16 типов → 13 семейств и модификаторы.

## Вкладка «Права доступа» (#379, ADR-0034)

Срез общей матрицы «роль × право» по правам раздела: строки — каталог
`PERMISSION_CATALOG` контрактов (`module: 'automation'` — «Настраивать
процессы и маршруты», «Управлять атрибутами», «Управлять справочниками»),
столбцы — роли портала. Вкладка появляется по каталогу: `accessTab('automation')`
в `nav-registry` возвращает пусто у раздела без прав.

- `shared/access/module-access-matrix.tsx` — тело вкладки: шапка h-14,
  пилюля «Только просмотр» без `role.manage`, матрица, подпись «Изменения
  применяются у сотрудников после перезагрузки страницы или повторного входа».
- `shared/access/access-matrix.tsx` — презентационная матрица (прокрутка
  подводом к краю, закреплённые шапка и колонка прав, замок у «Администратора»).
- `shared/api/roles.ts` — роли и точечное переключение права
  (`PUT/DELETE /directory/roles/:id/permissions/:permission`), оптимистично и
  только по своей ячейке. Моки — `shared/access/mocks/roles-handlers.ts`
  (домен `roles`).
- Создание ролей и состав «кто в роли» — не здесь (инкубатор, Н8).

## Окно создания и настройки типа (#432, ADR-0024 п.5)

- **Форма создания** — раздел документа маршрута (`document.creation`):
  узел «Создание» на холсте (`START_NODE_ID`) открывает панель
  `creation-panel.tsx` — та же анатомия, что у статуса и кнопки: список
  полей строками «подпись / сводка ›» (`creation-slot-row.tsx`, dnd +
  клавиатура; сводка — `model/creation-slot-summary.ts`: «Дата ·
  обязательно», «Скрыто: Высокий» — именами, не id), тихое «+ Поле»
  (`creation-field-picker.tsx`: системные / атрибуты типа / добавить в тип /
  создать атрибут), тумблеры чипов «Чек-лист»/«Планируемое время» и
  «Посмотреть окно» — настоящее окно создания по центру экрана с черновой
  формой (`TaskCreateWindow preview`). Настройка поля — переход внутрь
  (`creation-slot-section.tsx`, `field` выделения; туда же ведёт клик по
  проблеме публикации): своё название, «Обязательно при создании», скрытое
  значение тем же контролом, что у сотрудника (`SlotControl`), «Убрать из
  формы». Правки — шаг истории и черновик (ввод скрытого значения
  сливается в один шаг отмены); вступают в силу после «Опубликовать»;
  публикация одной формы задач в работе не трогает. Правила слотов — общая
  грамматика `contracts/creation-form.ts` (`requiredAllowed`,
  `presetAllowed`, `checkCreationForm`): те же коды проблем, что в чипе
  публикации.
- **Настройки типа** (`⋯` в строке типа, `types/type-settings.tsx`) — в
  корне поля типа (название, значок, цвет, описание), дальше строки «›» со
  сводками (`lib/type-settings-summary.ts`): «Доступ», «Блоки карточки»,
  «Названия ролей» — каждая открывает свой раздел со стрелкой «назад».
  Сохраняются СРАЗУ (`PATCH …/config`, оптимистично, мутации одного типа по
  очереди; текст — по уходу фокуса, `commit-field.tsx`). «Создают: никто,
  кроме администратора» — это `creatable=false` (прежний `PATCH` типа);
  «Стандартный» заблокирован (по нему создают быстрые входы). Состав
  карточки — представление, не права. Флага «в пульсе проекта» у типа нет
  (вердикт владельца 26.10.2026): что видно в пульсе, решает проект (#469).
- Примитивы панели — `panel-kit.tsx` (`PanelField`, `PanelNote`,
  `SwitchRow`, `SectionLink`, `ModeChoices`, `PanelAction`, `PanelDanger`):
  тихие ghost-действия вместо outline-кнопок, тумблер одного размера.

## Границы

- Фича **не импортирует** `features/tasks` (eslint-boundaries): общее живёт
  в `shared/flow` (движок холста, ADR-0022), `shared/workflow`
  («Схема маршрута», группировка панели процесса, значки типов),
  `shared/access` (матрица прав) и `shared/api/*-keys.ts`.
- Без права `workflow.manage` (по умолчанию — администратор; выдаётся во
  вкладке «Права доступа»): холст и панели только для чтения, бейдж
  «Только просмотр»; расстановка не сохраняется.
- Маршрут правится на клиенте и публикуется целиком (`display`/порядок кнопок
  задаёт сервер); удаления нет — архив (ADR-0021).
