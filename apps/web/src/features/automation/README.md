# features/automation

Раздел «Автоматизация» — единый дом настройки процессов (эпик #377, north-star §5):
один пункт левой рейки, внутри — вкладки сверху; сейчас «Типы задач» (#378),
позже «Права доступа» (#379), «Схемы проектов» (#38, V2). Новая автоматизация —
новая вкладка, не новый модуль меню.

**Веб-раздел — композиция API модуля tasks** (отдельный backend-модуль не
заводим, I13): типы задач, их маршруты и публикация — эндпоинты `/tasks/types*`,
`/tasks/workflows*` (README `apps/api/src/modules/tasks/README.md`).

## Состав (#378)

- `pages/automation-page.tsx` — рама: вкладка + список типов слева (колонка
  `bg-muted`, архив свёрнут группой) + шапка типа и холст справа; глубокая
  ссылка `/automation?tab=types&type=<id>` выбирает тип.
- `components/types/*` — список и строка типа (значок в цветном квадрате,
  мета «7 статусов · 128 задач», бейджи «Системный»/«Скрыт»), диалог создания
  (название/значок/цвет/основа «копия или простой»), шапка (чип версии,
  переключатель «Доступен при создании», меню «⋯» — копировать/архив),
  инспектор настроек типа (свойства сохраняются сразу, оптимистично).
- `components/editor/*` — редактор маршрута: холст `shared/flow` (колонки
  этапов, узлы-статусы, рёбра-кнопки по показу `display`, пилюли «из любого»),
  строка инструментов (undo/redo, чип проблем, публикация), инспекторы
  статуса (этап, цвет, итог, начальный, список кнопок, превью панели
  процесса по ролям) и кнопки (откуда/куда, показ, роли, условия DoR/DoD,
  особый случай `route_if`), диалог публикации (сводка, обязательные
  переносы задач архивируемых статусов, конфликт версий 409).
- `model/route-doc-store.ts` — zustand-стор рабочей копии (ADR-0021):
  документ, история (снимки ≤100), черновик в localStorage
  `nodus-workflow-draft-v1:<workflowId>` (zod на границе, версия-гейт).
- `api/automation-api.ts` — CRUD типов и публикация (кэш — `automationKeys`,
  в `shared/api/automation-keys.ts`: его читает WS-инвалидация каталожных
  событий); кросс-фичевые хуки типов (создание/смена типа) —
  `shared/api/task-types-api.ts`. Моки — `api/mocks/automation-handlers.ts`
  (проверки `checkWorkflowDocument`, конфликт версий, переносы — как сервер).

## Границы

- Фича **не импортирует** `features/tasks` (eslint-boundaries): общее живёт
  в `shared/flow` (движок холста, ADR-0022), `shared/workflow`
  («Схема маршрута», группировка панели процесса, значки типов) и
  `shared/api/*-keys.ts`.
- Без права `task.workflow_manage` (до матрицы #379 — только администратор):
  холст и инспекторы только для чтения, бейдж «Только просмотр».
- Маршрут правится на клиенте и публикуется целиком (`display`/порядок кнопок
  задаёт сервер); удаления нет — архив (ADR-0021).
