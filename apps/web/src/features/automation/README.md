# features/automation

Раздел «Автоматизация» — единый дом настройки (эпик #377, north-star §5):
вкладки в топбаре шелла — **«Процессы»** (#428, ADR-0024) и **«Поля»**
(#431, ADR-0029); позже «Права доступа» (#379), «Схемы проектов» (#38, V2).
Новая автоматизация — новая вкладка, не новый модуль меню.

**Веб-раздел — композиция API модуля «Процессы»** (`apps/api/src/modules/workflows`,
ADR-0024): типы процессов, их маршруты и публикация — эндпоинты `/workflows/types*`,
`/workflows/*` (README `apps/api/src/modules/workflows/README.md`). Типы категории
`task` дополнительно читают задачные хуки — `shared/api/process-types-api.ts`.

## Состав (#378, #431)

- `pages/automation-page.tsx` — переключатель вкладок по `?tab=`
  (`fields` → реестр полей, иначе «Процессы»); обе вкладки — окна-сплиты.
- `components/processes/processes-tab.tsx` — окно-сплит в грамматике мессенджера: слева
  колонка типов (`bg-card`, `border-r`, шапка h-14 с поиском и «+»), справа
  редактор маршрута выбранного типа. Названия НЕ дублируются (вкладка — в
  топбаре, имя типа — в строке списка). Глубокая ссылка `/automation?type=<id>`.
- `components/types/*` — список типов (строка: плитка-значок + имя + мета
  «7 статусов · 128 задач», меню «⋯» по ховеру — настройки/копировать/архив,
  архив свёрнут группой; поиск локальный), диалог создания
  (название/значок/цвет/основа «копия или простой»; категория — задача),
  настройки типа — та же правая панель-колонка (свойства сохраняются сразу,
  оптимистично). **Категория — группировкой:** заголовки групп «Задачи»/
  «Письма» показываются, только когда категорий в списке две и больше
  (`lib/group-by-category.ts`, решение владельца 25.10); меток на строках нет.
- `components/editor/*` — редактор маршрута (#378 ред. 2, рефы Jira / Трекер):
  - `route-toolbar.tsx` — верхний бар окна h-14 с линией: тип и состояние,
    проблемы, «+ Статус», «+ Переход», «Упорядочить»; справа «Сбросить» и
    «Опубликовать» (не уезжает никогда — контейнерные брейкпоинты);
  - `route-canvas.tsx` — холст `shared/flow` (ADR-0022): общая раскладка,
    12 точек подключения, подписи на стрелках, метка «Любой статус», старт
    «Создание задачи»; масштаб и отмена — слева внизу; клик по любому узлу
    открывает панель (статус — свою, метка — своей кнопки, старт —
    начального статуса);
  - `panel/*` — правая панель: полновысотная колонка как панель беседы
    мессенджера (`side-panel.tsx`, выезжает и сужает холст), одна анатомия у
    статуса и кнопки (`panel-kit.tsx`: поля → строки «›» → удаление),
    разделы «Кнопки из статуса» (порядок, добавление, «Как увидят в карточке»
    со «Смотреть как»), «Кто видит», «Условия перехода», «Особые правила»;
    «Настройки типа» из меню «⋯» строки открываются ДЛЯ ЭТОЙ строки
    (`settingsTypeId`, а не boolean + selected) — выделение редактора не
    меняется (#409);
  - `publish-dialog.tsx` — сводка, обязательные переносы; отказы сервера
    понятны: 409 — «Загрузить свежую версию», 422 «нужен перенос» — выбор
    цели, 422 «схема с проблемами» — список, прочее — текст ошибки.
- `model/route-doc-store.ts` — zustand-стор рабочей копии (ADR-0021):
  документ со статусами, кнопками и ОБЩЕЙ раскладкой холста, история
  (снимки ≤100), черновик в localStorage `nodus-workflow-draft-v1:<workflowId>`
  (zod на границе, версия-гейт). `dirty` — только правки структуры
  (`structureChanged`): расстановка — оформление. При загрузке baseline и
  документ проходят ОДНУ канонизацию (`canonicalDocument`: sortOrder
  статусов — индекс в группе, кнопок — индекс в группе fromStageId), потому
  что сервер отдаёт глобальную нумерацию, а клиент после правок — групповую;
  без этого вход показывал ложное «есть изменения» (#409). После публикации
  правки закрыты (`pendingReload`), пока не придёт свежий документ сервера:
  `sync()` перечитывает его по смене версии — `baseVersion` берётся только
  из документа сервера, черновые `new:*` повторно не уходят.
- `model/route-doc-layout.ts` — сопровождение раскладки на каждом шаге:
  `freezeLayout` («что видишь — то и стоит»: первая правка фиксирует
  картинку целиком), `settleLoops` (сдвинутые обходы не слипаются),
  `settleLabels` (подписи не наезжают на узлы и друг на друга),
  `persistedLayout` + `layoutFingerprint` (что и когда автосохранять).
- `model/use-layout-autosave.ts` — расстановка уходит на сервер сама
  (`PUT /workflows/:id/layout`, 600 мс тишины, без новой версии);
  смена типа, уход со страницы и «Опубликовать» отправляют несохранённое
  сразу (`flushLayoutAutosave`: места стоящих элементов сервер при
  публикации берёт из сохранённой раскладки). Чужая сохранённая
  расстановка той же версии приходит в открытый редактор (`sync` →
  `adoptSavedLayout`), свои неотправленные места остаются.
- `lib/plural-ru.ts` — формы множественного числа (сводка публикации).
- `api/automation-api.ts` — CRUD типов, публикация и сохранение расстановки (кэш — `automationKeys`,
  в `shared/api/automation-keys.ts`: его читает WS-инвалидация каталожных
  событий `workflow.*`); кросс-фичевые хуки типов категории задачи —
  `shared/api/process-types-api.ts` (там же `defaultProcessType` — тип по
  умолчанию экспресс-формы и доски проекта). Моки —
  `api/mocks/automation-handlers.ts` (проверки `checkWorkflowDocument`,
  конфликт версий, переносы, постоянные id вместо `new:*` при публикации —
  `publish-resolve.ts` — как сервер).

## Окно перехода (#380)

Инспектор кнопки: раздел «Окно перехода» (`window-section.tsx`) — тумблер,
заголовок (пусто — название кнопки), шесть разделов в фиксированном порядке:
поля, трудозатраты (режим «если ещё не списаны» / «всегда»), итог, файлы
(подпись + минимум 0–5 = валидатор `result_files`), сообщения из чата как итог,
причина/комментарий. «Обязательно» у времени/итога/файлов правит **гейты**
(Р3), у причины и сообщений — собственный флаг раздела. «Посмотреть окно» —
настоящий `TransitionWindow` в режиме превью (без данных, отправка неактивна).
Правки формы — `model/transition-form.ts`; документ публикуется вместе с
кнопкой, черновики без формы читаются через default.

## Вкладка «Поля» (#431, ADR-0029)

Реестр кастомных полей: определения по областям (задачи/письма/проекты/
контрагенты), значения — в JSONB сущности по id определения.

- `components/fields/fields-tab.tsx` — сплит `FieldList | FieldEditor`;
  маршрут `/automation?tab=fields[&scope=<область>][&field=<id>]` (глубокая
  ссылка из карточки «Настроить»). Права на правку — `custom_field.manage`
  (`shared/custom-fields/use-can-manage-fields.ts`).
- `field-list.tsx` + `field-list-row.tsx` — левая колонка в грамматике списка
  типов: группы областей с моно-заголовком и счётчиком, строка «плитка типа +
  имя + мета (тип, умолчание)», меню «⋯» по ховеру/фокусу, архив свёрнут
  внизу; порядок внутри группы — dnd-kit с `KeyboardSensor` (ADR-0007).
- `field-editor.tsx` (+ `field-editor-header/main`, `field-settings`,
  `field-options-editor`, `field-default-value`, `field-preview`) — секции без
  линий: «Основное» (сохранение по blur), «Тип» (односторонние модификаторы
  «Многострочный»/«Несколько значений» с подтверждением, Р3), настройки типа
  (точность, валюта), «Варианты» (справочник: добавить/переименовать/порядок/
  архив), «Значение по умолчанию» (нет / значение / подразделение автора),
  «Отчёты» (флаг `reportIndexed`, честная подсказка), превью строки карточки.
- `field-create-dialog.tsx` + `field-type-picker.tsx` — 13 плиток семейств
  (16 типов), область, название, для списка — новые варианты строками или
  существующий справочник; создание ПЕССИМИСТИЧНОЕ (справочник → поле, id нужен
  редактору); «Проект» без модуля проектов — недоступная плитка с подсказкой.
- `api/custom-fields-api.ts`, `api/dictionaries-api.ts` — правки определений
  (оптимистично с откатом) и минимальная запись справочников (варианты).
  Чтение — `shared/custom-fields/queries.ts`, `shared/dictionaries/queries.ts`.
- `lib/field-type-families.ts` — 16 типов → 13 семейств и модификаторы;
  `lib/use-can-manage-fields.ts` переехал в shared (потребитель — карточка).

## Границы

- Фича **не импортирует** `features/tasks` (eslint-boundaries): общее живёт
  в `shared/flow` (движок холста, ADR-0022), `shared/workflow`
  («Схема маршрута», группировка панели процесса, значки типов) и
  `shared/api/*-keys.ts`.
- Без права `workflow.manage` (до матрицы #379 — только администратор):
  холст и панели только для чтения, бейдж «Только просмотр»; расстановка не сохраняется.
- Маршрут правится на клиенте и публикуется целиком (`display`/порядок кнопок
  задаёт сервер); удаления нет — архив (ADR-0021).
