# features/directory

Сотрудники в теме «Инструмент»: три вида (#84, вердикты владельца 23–24.09.2026) —
**Подразделения** (дефолт: дерево карточек подразделений + правая панель),
**Подчинённость** (фокус-граф по managerId) и **Список** (каноническая таблица),
вкладки в топбаре (search-параметр `view`, nav-registry). Графа карточек ЛЮДЕЙ
на всю компанию больше нет: сотни карточек непросматриваемы (вердикт владельца).
Шапка — ОДНА строка h-14 без border-b: заголовок со счётчиком голым числом,
переключатель структур и поиск (в «Подразделениях»), строка инструментов
(в «Списке»), кнопка **«Пригласить»** всегда (диалог-заготовка
`components/invite-dialog.tsx` → `POST /directory/invitations`, полный поток —
с бэкендом директории).

- **Подразделения** (`components/divisions-view.tsx`) — дерево карточек
  подразделений в грамматике контура Nodus: node-панели (название, руководитель,
  моно-счётчики сотрудников с подподразделами и подотделов), ортогональные рёбра
  1px на токене `--edge` с портами r=3 (хук `lib/use-tree-edges.ts`, snapPx,
  каждый сегмент — ровно один штрих, gotchas SVG-графа; обмер живого DOM
  ResizeObserver по РАСКРЫТЫМ узлам). Сворачивание подотделов шевроном (дефолт:
  свёрнуто от 3-го уровня), поиск фильтрует ветки. Переключатель
  **управленческая/юридическая** (kind) — два дерева из одной модели
  (departments.kind, эпик #18): структуры расходятся, как в жизни.
- **Правая панель подразделения** (`components/department-panel.tsx`) — клик по
  карточке подразделения (НЕ стек): руководитель и зам (клик — карточка
  сотрудника в стеке, ADR-0009), сотрудники подразделения ТЕКУЩЕЙ структуры с
  поиском, «Подчинённые руководителя» по managerId — возможны из ДРУГИХ
  подразделений и это нормально (кейс «группы ГИПов», требование 1 #18).
  Мягкая область с бордером по периметру (вердикт 24.09): absolute поверх
  канваса — ПЕРЕКРЫВАЕТ структуру, не двигая её (модель Битрикса); обёртка
  монтирована постоянно (w-0), раскрытие — transition-[width] 200ms (закон
  выдвижных поверхностей); верхняя граница — на горизонтали оси контура
  (measureCircuit.axisY), правый край чуть левее границы мягкой рамы, крестик
  закрытия у края шапки. Действия подразделения (меню): пригласить, добавить подподразделение,
  править — `components/department-dialog.tsx` (название + руководитель + зам
  автокомплитом `components/employee-combobox.tsx`), мутации оптимистичны (I4:
  узел дерева появляется/меняется до ответа, откат при ошибке).
- **Подчинённость** (`components/subordination-view.tsx`) — граф людей по
  managerId ВОКРУГ сотрудника: цепочка руководителей вверх + прямые подчинённые
  вниз, раскрытие пошаговое кнопкой «+N» (нераскрытые дети), «прицел» на карточке
  переставляет фокус; дефолт фокуса — текущий пользователь. Рёбра — тот же
  `use-tree-edges.ts` (вынут из бывшего org-chart.tsx, удалён).
- **Список** — `DataTable` (shared/views, ключ вида `directory.employees`, реестр
  `lib/employee-fields.tsx`: сотрудник, должность, подразделение, почта,
  руководитель — резолвится из того же списка, HR-статус скрыт по умолчанию).
- **Карточка сотрудника** (`components/employee-card.tsx`, стек карточек
  ADR-0009) — анатомия карточки проекта (вердикт владельца 15.09.2026):
  **ЕДИНЫЙ бар h-10 на всю карточку** — вкладки слева + тоггл панели беседы
  крайний справа; общего бара h-16 с аватаром НЕТ (его инфа дублировала
  поля, имя — в хроме слайдера; полезная высота — данным). **Левая зона** —
  контент вкладок на всю высоту: **Профиль**
  (`components/employee-profile-tab.tsx`): БОЛЬШАЯ фотография Ø176 с
  presence-чипом под ней (модель профиля Битрикс24 — не аватарка в баре) +
  полный `UserCard` полями-реестром `EntityFields` (ключ
  `nodus-employee-fields-v1`: должность, подразделение, почта, телефон,
  город, кабинет, удалёнка, ставка, пол, день рождения, дата приёма, начало
  дня, руководитель — переход стеком, HR-статус; на узкой зоне поля уходят
  под фото) + секция «Подчинённые», **Задачи** (`GET /tasks?assigneeId=`) и
  **Проекты** (`GET /projects?memberId=`) со счётчиками — ПОЛНОЦЕННЫЕ журналы
  на shared-реестрах (`makeTaskTableFields()` / `projectListFields`, ключи
  видов `directory.tasks` / `directory.projects`): СТРОКА ИНСТРУМЕНТОВ
  (`components/employee-journal-tabs.tsx`) — поисковая строка с панелью
  фильтра (модель Битрикс24: пресеты слева, поля справа; у задач скрыт
  «Ответственный» — список и так по сотруднику), все поля + шестерёнка
  отображаемых полей в строке + ресайз колонок, как в модулях («модули не
  отличаются», вердикт); связи открываются карточками поверх (стек). **Правая колонка — личный диалог с сотрудником
  ВСЕГДА** (find-or-create, `GET /chat/conversations/direct/:userId`, хук
  `useDirectConversation` в shared/chat; диалог с собой — «заметки для
  себя»); **шапки у чата НЕТ** (собеседник и так в хроме карточки —
  вердикт); тоггл панели беседы — в ЕДИНОМ баре карточки справа (канон
  кнопки «О задаче»); панель — полновысотный сиблинг, её шапка h-10 на
  линии бара, ширина — ЗА СЧЁТ ЧАТА (одна анимируемая ширина — левая зона
  не дёргается; лента ≥ 360 при открытой панели);
  перегородка тянется с памятью (общая на все карточки); контекстное меню
  сообщений — из shared/chat. Кнопки «Написать сообщение» больше нет — чат
  уже здесь.
- Чистая логика дерева и фокуса — `lib/department-tree.ts` (суммы сотрудников,
  путь к подразделению, фильтр поиска, фокус-множество подчинённости,
  оптимистичные вставка/патч узла кэша) с unit-тестами.
- Связи сотрудника — `shared/api/user-relations.ts` (`useAssigneeTasks`,
  `useMemberProjects`): I6 запрещает фичам импортировать друг друга, поэтому
  хуки на публичные list-ресурсы — в shared-слое.
- Контракты: `UserListItem` (+`departmentId`/`legalDepartmentId` — принадлежность
  обеим структурам), `UserCard` (полный профиль), `PresenceEntry`,
  `DepartmentNode`/`departmentTreeQuerySchema`/create-update DTO подразделений;
  query `/tasks` (+`assigneeId`), `/projects` (+`memberId`). Семантика фильтра
  `GET /directory/users?departmentId=`: принадлежность в ТОЙ структуре, к которой
  относится само подразделение (kind сервер берёт из подразделения).
- Эндпоинты (моки): `GET /directory/users?limit=50` (+`departmentId`),
  `GET /directory/users/:id` (UserCard), `GET /directory/presence`,
  `GET /directory/departments?kind=` (лес корней DepartmentNode),
  `POST /directory/departments`, `PATCH /directory/departments/:id`.
  Бэкенд: users-эндпоинты живые (`apps/api/src/modules/directory`, kind-осознанный
  фильтр подразделения реализован), endpoints подразделений — контракт-ТЗ для
  бэкенд-агента: UI сверстан по контрактам и мокам (ADR-0001).
- Открытие карточки — shared-element из rect узла графа/строки списка/строки
  панели; закрытие сохраняет вид (`view`).
