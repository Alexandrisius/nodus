# features/correspondence

Корреспонденция v2 (вердикты владельца 22.09.2026, issue #69): почтовый
клиент общего ящика + документы канцелярии. **Письмо и документ — разные
вещи**: почта — базовый слой, регистрация — действие поверх; не вся почта
становится документом. У письма статуса нет; у документа — «в работе →
исполнено → в дело» (+ «просрочено» — производное: срок < сегодня, не
значение статуса). Раздел называется «Корреспонденция» (почтой станет с
личными ящиками — фаза 2 продукта).

## Список (`pages/letters-page.tsx`)

Папки-табы топбара (nav-registry): **Входящие / Отправленные / Журнал**.
«Незарегистрированные» — НЕ папка: это входящие с пустым рег.№, очередь
секретаря — пресет-фильтр «К регистрации» (`lib/letter-filter-fields.ts`).
Журнал — вид-реестр ТОЛЬКО документов (Вх/Исх, `lib/registry-fields.tsx`,
ключ вида `letters.registry`): фильтры «в работе / просрочено / в деле».
Шапка — одна строка h-14: заголовок со счётчиком, переключатель ящиков
«Общий / Личная» (задел: личный неактивен), строка инструментов (поиск +
панель фильтра), «Написать письмо», шестерёнка представления. Таблицы —
канон shared/views (ключ почтового списка `letters.mail`), колонки:
рег.№ (моно) с иконкой направления, канал (Почта/СМДО/Бумага — чип),
контрагент, тема, статус документа, ответственный, дата. Экспресс-действие
«Зарегистрировать» — в ячейке действий и меню строки входящих без регистрации.

## Карточка письма — единый шаблон сущности (образец: task-card)

Полоса цепочки h-14: само-узел «ПИСЬМО/ДОКУМЕНТ · рег.№», связь «ответ на»
(inReplyToId — кликабельный узел исходника), чипы канала и направления,
«Ответить» (входящие). Левая зона: почтовая шапка (`letter-header.tsx` —
корреспондент, кому/копии — только внутренние, дата, чип регистрации) → тело
читательской колонкой max-w-3xl → вложения (Attachment-примитивы) →
реквизиты (`letter-requisites.tsx`, EntityFields, ключ
`nodus-letter-fields-v2`) → [у документа] резолюции
(`letter-resolutions.tsx`: поручение = задача, строки-ссылки openCard с
живым снапшотом стадии). Нижний бар h-16 (`letter-bottom-bar.tsx`):
«Зарегистрировать» | «Резолюция» + «В дело» (только из «исполнено»).
Справа — **чат письма**: колонка `useChatWidth` (канон «чат — буфер
сужений», #63) с общим механизмом обсуждений `ConversationPane` — беседа
type 'letter' (контракт chat), участники ТОЛЬКО внутренние сотрудники,
обсуждение наружу не уходит. Пересылка запрещена концептуально: вместо неё
ссылка (deep-link стека или `portal://letter/<id>`) — в чате разворачивается
карточкой-превью (`letter-link-preview.tsx`, реестр shared/chat/link-previews).

## Диалоги

- `registration-dialog.tsx` — карточка регистрации: тип Вх/Исх чипом (из
  папки, сменяем), контрагент — автокомплит справочника с созданием «на
  лету» (shared/counterparties/counterparty-combobox), проект, адресат
  (дефолт — ГИП/руководитель проекта), срок, № и дата документа
  корреспондента, вид документа (словарь, дефолт «Письмо» — значение, не
  контрол). Рег.№ присваивает сервер-мок (счётчик серии: Вх-…/118, Исх-…/42).
- `resolution-composer.tsx` — резолюция + 0..N строк поручений (что
  сделать / исполнитель / срок); каждое поручение становится задачей
  source 'letter' с цепочкой Письмо → Резолюция → Поручение → Задача.
  Резолюция без поручения допустима («для сведения»).
- `letter-compose-dialog.tsx` — исходящее: «От кого» (ящик), контрагент из
  справочника, проект, переключатель «Письмо / Документ с Исх-№» (документ
  регистрируется при отправке), канал Почта/Бумага, ФАЙЛЫ ВПЕРЁД текста
  (сценарий «скан → отправка»), сопроводительный текст опционален;
  «Ответить» — префил контрагента/темы + связь «ответ на».

## Контракты и эндпоинты (моки MSW)

Контракты: `packages/contracts/src/correspondence/letter.schemas.ts`
(LetterListItem/LetterDetail v2: receiveChannel, mailbox, counterparty-ref,
recipients/cc, registration — nullable-объект РКК, documentStatus,
резолюции с массивом поручений и снапшотом стадии задачи, conversationId,
inReplyToId), `src/counterparties/` (справочник контрагентов).
Эндпоинты: `GET /letters?folder=incoming|outgoing|registry[&counterpartyId=]`
(без folder — все письма), `GET /letters/:id`, `POST /letters`
(createLetterBodySchema v2), `POST /letters/:id/register` (повторно — 409),
`POST /letters/:id/resolutions` (не-документ — 409),
`POST /letters/:id/archive` (не «исполнено» — 409), `GET /mailboxes`,
`GET /dictionaries/document-kinds`.

## Мутации

**Пессимистичные обоснованно** (юридически значимые, сервер авторитетен):
регистрация (рег.№ без щелей и дублей), резолюция (создание задач),
«в дело», исходящий ДОКУМЕНТ (Исх-№ присваивает сервер). Тост об успехе,
ошибка — `shared/api/error-toast` (строка по коду, I15). **Оптимистичные**
(I4): «просто письмо» в композере (детерминированный тест
`letters-api.test.tsx`), сообщения чата (общий механизм бесед).
Закрытие задачи-поручения синхронизирует документ (мок: `syncLetterWithTasks`
в `shared/mocks/data/letters.ts`; кэш писем инвалидируется из tasks-api
через shared-ключи `lettersKeys` — без cross-feature импорта, I6).

## Границы

Контрагенты — своя фича `features/counterparties/` (раздел, карточка);
общие хуки API и комбобокс — `shared/counterparties/` (потребители:
регистрация и композер писем). Беседы писем — в общем списке чатов:
вкладка «Чаты задач и писем» мессенджера; служебная полоса (right-rail)
чаты писем НЕ показывает (как и чаты задач). Видимость: документы и журнал
— всем сотрудникам; личная почта (фаза 2) — только владельцу.

НЕ входит (концепт на моках): бэкенд, IMAP/SMTP, личные ящики, СМДО-коннектор
(канал в модели есть), CRM, «внутренние письма» (внутренняя переписка —
мессенджер), сканирование.
