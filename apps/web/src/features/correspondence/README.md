# features/correspondence

Письма в теме «Инструмент»: журнал — каноническая таблица (shared/views
`DataTable`, ключ вида `letters.journal`: колонки-реестр
`lib/letter-fields.tsx`, видимость шестерёнкой, ширина ручкой, память
`nodus-views-v1`), папки — секции в топбаре (Входящие / Незарегистрированные /
Исходящие). Шапка — ОДНА строка h-14 без border-b: заголовок со счётчиком
голым числом, **строка инструментов** (поиск по рег.№/теме/корреспонденту +
панель фильтра: пресеты «В работе»/«Просрочено», поля статус/адресат/
корреспондент/срок — реестр `lib/letter-filter-fields.ts`),
**«Написать письмо»** (композер исходящего,
`components/letter-compose-dialog.tsx`: кому/тема/текст/файлы, отправка —
`POST /letters`, созданное открывается карточкой стека и видно в
«Исходящих») и шестерёнка представления.

Карточка письма — **почтовый клиент** (вердикт владельца 2026-09-10, раунд 2):
длинные тела и пачки приложений читаются удобно. Полоса цепочки: само-узел
«ПИСЬМО · рег.№» + чип направления + «Ответить» (входящие — композер с
предзаполнением Re:). Почтовая шапка (корреспондент-организация квадратом с
иконкой; «Кому» у входящих / «От» у исходящих + дата; чип статуса) → тело
читательской колонкой max-w-3xl → вложения (Attachment-примитивы, размер
КБ/МБ) → реквизиты регистрации полями-реестром (`EntityFields`, ключ
`nodus-letter-fields-v1`; корреспондент/адресат/дата — в шапке, не
дублируются) → резолюции (node-панели со ссылкой на поручение стеком);
замоноличенный нижний бар h-16 — «Зарегистрировать» (очередь) + композер
резолюции «В поручение» (поток А). Открытие — стек карточек (ADR-0009),
shared-element из rect строки журнала.

- Контракты: `LetterListItem` (+`addressee` — кому адресовано/ответственный),
  `LetterDetail`, `Resolution`, `createLetterBodySchema` (`@nodus/contracts`).
- Эндпоинты (моки): `GET /letters?folder=`, `POST /letters` (создание
  исходящего — рег. Исх-2026/NN сразу), `GET /letters/:id`,
  `POST /letters/:id/resolutions`, `POST /letters/:id/register`.
- Мутации `useIssueResolution`/`useRegisterLetter` — **пессимистичные
  обоснованно** (вердикт владельца): юридически значимые действия (регномер,
  поручение) — сервер авторитетен; тост об успехе, списки инвалидируются в
  onSettled. `useCreateLetter` — созданное письмо кэшируется в detail-ключ,
  списки инвалидируются.
- Инлайн-регистрация из очереди «Незарегистрированные» — ячейка действий
  `DataTable` (≤ 30 с на регистрацию, без открытия карточки).
