# features/correspondence

Корреспонденция v3 (#55, ADR-0027): **письмо — сущность модуля на движке
«Процессы»** (категория `letter`), а не отдельная почтовая модель. Тип
письма задаёт маршрут (стадии, кнопки, окна), регистрация — обычный переход
с окном «Регистрация» и пост-действием «Присвоить номер» (сервер выдаёт
`Вх-ГГГГ/N` без пропусков). Раздел называется «Корреспонденция».

## Вкладки (`/letters?tab=…`, `pages/letters-page.tsx`)

- **Новые** — очередь канцелярии (право `correspondence.register`): письма из
  почты и бумага, созданная вручную; конвейер регистрации (U4).
- **Входящие / Исходящие** — журналы зарегистрированных писем (U6):
  каноническая таблица `shared/views`, серверный поиск, курсорная подгрузка.
- **Права доступа** — общая матрица раздела `ModuleAccessMatrix`.

Вкладку решает `lib/letters-tab.ts#resolveLettersTab(search, permissions)` —
она же подсвечивает вкладку в топбаре (`NavTabDef.permission`). Явная валидная
вкладка уважается; «Новые» без права → «Входящие» (без 403-экрана).

## Почтовые письма (#56)

Строки очереди «Новые» показывают отправителя конверта («Имя <адрес>», у
ручных — «внесено вручную») и бейдж «Ответ на Исх-…» (авто-связь по почтовой
цепочке). Форма регистрации: чип-галочка «Похоже, ответ на …» (подсказка по
теме, только пока связи нет), подстановка контрагента/подписанта по адресу
отправителя (`useSuggestedCounterparty`, один раз, выбор Вики не перетирается).
Карточка: поле «Отправитель», предупреждения «не разобрано»/«часть вложений
не сохранена», метки «Электронная подпись» (.p7s/.sig) и «Файл Outlook»
(winmail.dat); inline-картинки скрыты из блока «Файлы». HTML-тело: cid:
картинки резолвятся в подписанные ссылки на показе (санитайзер `cidMap`,
CSP `'self'`).

## Конвейер «Новые» (`components/pipeline/`)

Рабочее место канцелярии: очередь (ресайз `use-split-width`) → документ
(`LetterBodyView`: PDF/офис по ширине панели, HTML — песочница) → форма
регистрации (~420 px). После регистрации — тост с номером и следующее письмо,
фокус в «Корреспондент». Клавиатура вне полей ввода: `Alt+↑/↓` — соседнее
письмо, `Ctrl+Enter` — «Зарегистрировать», `Shift+Delete` — «Удалить как
спам» (подтверждение). `Ctrl+Enter` работает и внутри формы (главная кнопка
окна — тот же закон у задач).

Сценарий владельца «≤ 30 секунд»: «Галур» → Enter (корреспондент) → их № →
Enter → их дата → Enter → адресат «Шай» → Enter → `Ctrl+Enter`. Enter всегда
ведёт к следующему **пустому обязательному** полю (`nextEmptyField`).

## Списки (`components/letters-table.tsx`)

Колонки и фильтры — общие реестры `shared/views/letter-table-fields.tsx`
(`makeLetterTableFields`) и `shared/views/letter-filter-fields.ts`
(`useLetterFilterDefs`): их же использует вкладка «Письма» карточки
контрагента (I6 — фичи друг друга не импортируют). Сортировка № идёт по
моменту регистрации (строковое «Вх-2026/99» > «…/108» врало бы), «Проект» —
только когда проекты и письма в одном мире (`projectsAvailable('letters')`).
Пресеты: «Мне адресованы», «Срок ответа истёк» (просрочка — календарный день
в прошлом у письма в работе).

## Карточка письма (`components/card/`)

Анатомия карточки задачи (вердикт владельца 25.10.2026):

- **полоса цепочки** h-14 — «ПИСЬМО · Вх-…», источник, чип статуса; резолюции
  и поручения (#463) встанут сюда же следующими узлами;
- **левая зона** — доска регистрационных данных на `EntityFields` (правка по
  месту у `access.canEdit`, оптимистично; смена корреспондента сбрасывает
  подписанта тем же PATCH; даты проверяются до запроса — та же грамматика,
  что у сервера), атрибуты типа (`CustomFieldsBlock`, область `letter`),
  «Файлы» (клик — вкладка, тело письма — вкладка «Письмо»), «История»
  (свёрнута, курсорная подгрузка, «поле: было → стало»);
- **бар h-16** — кнопки маршрута (`useLetterTransitionRunner` → общее
  `TransitionWindow`; у нового письма «Зарегистрировать» с разделом
  регистрации), «Ещё» → пункты меню + «Удалить как спам», справа
  «Присоединиться к обсуждению»;
- **правая панель** — вкладки «Письмо» / «Чат» (неснимаемые) + вложения
  (закрываемые, ≤ 6; седьмое вытесняет самую давнюю неактивную —
  `lib/letter-tabs.ts`). Вкладки монтируются при первом показе и дальше живут
  скрытыми (`invisible` + `inert`, не `display: none`): прокрутка и масштаб
  документа не теряются. Геометрия — канон «чат — буфер сужений»: рельса
  сужает панель до пола, дальше — левую зону; ширина перегородки — общая
  память портала (`useChatWidth`).

Тема письма — в хроме слайдера (`LetterTitle`), в теле не дублируется.

## Мутации (`api/letters-mutations.ts`)

**Пессимистичные обоснованно:** переход окна/конвейера (номер юридически
значим, ввод не теряется; идемпотентность — на попытку «письмо+кнопка»),
ручное создание (файлы и письмо — атомарно на сервере), присоединение к
обсуждению (состав беседы решает сервер). **Оптимистичные (I4):** правка
регистрационных данных и удаление спама — с точечным снимком своей строки
(`letters-cache.ts#snapshotLetterInList`) и откатом по ней
(`restoreLetterInLists`): снимок всех списков затирал чужие изменения при
параллельных мутациях (#522, patterns.md:108). После settled списки
помечаются устаревшими без перезапроса (`listsStale`, `refetchType: 'none'`) —
рефетч не должен затирать летящие оптимистичные правки соседей. Восстановленная
строка возвращается в начало первой страницы: до следующего перезапроса журнал
может показывать её не по дате. Ответ сервера (`letter` + `transitions`)
кладётся в кэш одним ходом
(`letters-cache.ts#applyLetter`), строка обновляется во всех списках, а где
вкладка больше не совпадает (зарегистрировали) — уходит из списка.

## Безопасность тела письма (Р9)

HTML письма показывается в `SandboxedHtml` (iframe `sandbox`, CSP в `srcdoc`),
текст — `sanitizeEmailHtml` (DOMPurify: скрипты, обработчики, `javascript:`,
`meta/form` снимаются; внешние картинки блокируются до «Показать
изображения»). Тело больше 2 МБ не читается в память вкладки — карточка
скачивания. Белый «лист» внутри iframe — намеренное исключение: письмо
выглядит как почтовый документ и в тёмной теме.

## Чат письма (Р10)

Обычная беседа мессенджера `type='letter'` (`useLetterConversation`):
участники — внутренние сотрудники (адресат и присоединившиеся), наружу не
уходит. Не участнику — пустое состояние с «Присоединиться к обсуждению»
(если письмо в работе). Переходы письма — сообщения `letter_transition`
(общий `TransitionBlock`).

## Границы

Контрагенты и комбобокс — `shared/counterparties/`; файлы — `shared/files/`
(общий просмотрщик); чат — `shared/chat/`; права и матрица —
`shared/access/`; типы писем и нумерация — `features/automation` (только
просмотр, каталог системный). Контракты — `packages/contracts/src/
correspondence/` (`letter.schemas.ts`, `letter-registration.schemas.ts`,
`letter-transitions.schemas.ts`). Моки — `api/mocks/` (тела мутаций парсятся
схемами contracts).

НЕ входит в UI-пакет #55: бэкенд, IMAP/SMTP-приём (#56), исходящие с
отправкой (#464), резолюции/поручения и конфиденциальность (#461/#463),
редактор типов писем (#504).
