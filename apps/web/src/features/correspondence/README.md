# features/correspondence

Корреспонденция v3 (#55, ADR-0027): **письмо — сущность модуля на движке
«Процессы»** (категория `letter`), а не отдельная почтовая модель. Тип
письма задаёт маршрут (стадии, кнопки, окна), регистрация — обычный переход
с окном «Регистрация» и пост-действием «Присвоить номер» (сервер выдаёт
`Вх-ГГГГ/N` без пропусков). Раздел называется «Корреспонденция».
Редизайн #56 (28.10): конвейер регистрации упразднён — «Новые» список,
карточка незарегистрированного письма = форма.

## Вкладки (`/letters?tab=…`, `pages/letters-page.tsx`)

- **Новые** — очередь канцелярии (право `correspondence.register`): письма
  из почты и бумага, созданная вручную; список тем же каноном, что журналы,
  клик по строке открывает карточку-форму. Кнопка «Создать» — в шапке.
- **Входящие / Исходящие** — журналы зарегистрированных писем (U6).
- **Права доступа** — общая матрица раздела `ModuleAccessMatrix`.

Вкладку решает `lib/letters-tab.ts#resolveLettersTab(search, permissions)` —
она же подсвечивает её в топбаре (`NavTabDef.permission`). Явная валидная
вкладка уважается; «Новые» без права → «Входящие» (без 403-экрана).

## Почтовые письма (#56)

Колонка «Отправитель» в «Новых» показывает конверт («Имя», title — «Имя
<адрес>»; у ручных — «внесено вручную»); в карточке — строка-отправитель
`LetterSenderLine` (аватар, имя, полный адрес, время). Личная точка «я ещё
не открывал» у темы (`viewed === false`) гаснет при открытии карточки:
`api/mark-letter-viewed.ts` — один POST `/letters/:id/view`, затем патч
строки во всех списках (журналы точку не показывают). Форма регистрации:
чип-галочка «Похоже, ответ на …» (подсказка по теме, только пока связи
нет), подстановка контрагента/подписанта по адресу отправителя
(`useSuggestedCounterparty`, один раз, выбор Вики не перетирается).
Карточка: предупреждения «не разобрано»/«часть вложений не сохранена»,
метки «Электронная подпись» (.p7s/.sig) и «Файл Outlook» (winmail.dat);
inline-картинки скрыты из блока «Файлы». HTML-тело: cid: картинки
резолвятся в подписанные ссылки на показе (санитайзер `cidMap`,
CSP `'self'`); лист письма красится токенами портала (`emailSheetColorsFor`)
— в тёмной теме нет белого «прожектора» (вердикт владельца 28.10).
Скрепка в списке — только настоящие вложения (`role='attachment'`).
Новое письмо из почты появляется в «Новые» без F5: будильник
`notification.dispatch_requested` с `kind='letter.arrived'` инвалидирует
`lettersKeys.lists()` (WS-роутер, `shared/socket/socket-invalidation`).

## Списки (`components/letters-table.tsx`)

Все вкладки — одна каноническая таблица `shared/views` (свой viewKey на
вкладку — своя память колонок и фильтров), серверный поиск, курсорная
подгрузка. Колонки и фильтры — общие реестры
`shared/views/letter-table-fields.tsx` (`makeLetterTableFields`,
`box: 'new'` меняет набор по умолчанию: отправитель/поступило/вложения,
без номеров) и `shared/views/letter-filter-fields.ts`
(`useLetterFilterDefs`); их же использует вкладка «Письма» карточки
контрагента (I6 — фичи друг друга не импортируют). Сортировка № идёт по
моменту регистрации (строковая «Вх-2026/99» > «…/108» врала бы), «Проект»
— только когда проекты и письма в одном мире (`projectsAvailable('letters')`).
Пресеты журналов: «Мне адресованы», «Срок ответа истёк» (у «Новых» пресетов
нет). Ручное создание (бумага) — `ManualLetterDialog` из шапки «Новых».

## Карточка письма (`components/card/`)

Анатомия карточки задачи (вердикт владельца 25.10.2026; редизайн 28.10 —
карточка-форма):

- **полоса цепочки** h-14 — «ПИСЬМО · Вх-…», источник, чип статуса;
- **левая зона** — доска реквизитов на `EntityFields`. Незарегистриро-
  ванное письмо — ФОРМА: тема и адресат редактируются по месту (адресат —
  PATCH `addresseeId`, после регистрации — только чтение, Р11),
  обязательные поля (корреспондент, их № и дата, тема, способ, адресат)
  помечены звёздочкой, пустой пропуск — предупреждающим тоном; правка
  оптимистична, смена корреспондента сбрасывает подписанта тем же PATCH;
  атрибуты типа (`CustomFieldsBlock`), «Файлы», «История»;
- **бар h-16** — кнопки маршрута. «Зарегистрировать»: все обязательные
  заполнены — переход идёт НАПРЯМУЮ (`letterRegistrationInput` собирает
  ввод из самого письма), номер присваивается сразу, тост с номером; списки
  рефечатся сами (строка уходит из «Новые» и приходит во «Входящие» без
  F5), затем карточка закрывается — возврат к списку «Новых» (вердикт
  владельца 28.10); что-то
  пусто или сервер
  ответил 422 — окно `TransitionWindow` (контроль пропусков, раздел
  регистрации). В «Ещё» — пункты меню, «Пригласить в обсуждение»
  (канцелярия) и «Удалить как спам»; справа «Присоединиться» /
  «Начать обсуждение» (незарегистрированное, канцелярия);
- **правая панель** — вкладки «Письмо» / «Текст письма» (когда у письма
  есть и документ, и текстовая часть — `letterTextPart`; неснимаемая,
  пропала часть — карточка нормализует активную) / «Чат» / вложения
  (закрываемые, ≤ 6; седьмое вытесняет самую давнюю неактивную —
  `lib/letter-tabs.ts`). Переключателя «Документ / Текст» больше нет.
  Вкладки монтируются при первом показе и дальше живут скрытыми
  (`invisible` + `inert`): прокрутка и масштаб не теряются. Геометрия —
  канон «чат — буфер сужений».

Тема письма — в хроме слайдера (`LetterTitle`), в теле не дублируется.

## Мутации (`api/letters-mutations.ts`)

**Пессимистичные обоснованно:** переход окна/прямой регистрации (номер
юридически значим, ввод не теряется; идемпотентность — на попытку
«письмо+кнопка»), ручное создание (файлы и письмо — атомарно на сервере),
присоединение и приглашение в обсуждение (состав беседы решает сервер).
**Оптимистичные (I4):** правка реквизитов (в т.ч. полей незарегистриро-
ванного) и удаление спама — с точечным снимком своей строки
(`letters-cache.ts#snapshotLetterInList`) и откатом по ней
(`restoreLetterInLists`, #522, patterns.md:108). После settled списки
помечаются устаревшими без перезапроса (`listsStale`). Ответ сервера
кладётся в кэш одним ходом (`applyLetter`), строка обновляется во всех
списках, а где вкладка больше не совпадает (зарегистрировали) — уходит.

## Безопасность тела письма (Р9)

HTML письма показывается в `SandboxedHtml` (iframe `sandbox`, CSP в
`srcdoc`), текст — `sanitizeEmailHtml` (DOMPurify: скрипты, обработчики,
`javascript:`, `meta/form` снимаются; внешние картинки блокируются до
«Показать изображения»). Тело больше 2 МБ не читается в память вкладки —
карточка скачивания. Белый «лист» внутри iframe — намеренное исключение:
письмо выглядит как почтовый документ и в тёмной теме.

## Чат письма (Р10; редизайн #56 — до регистрации)

Обычная беседа мессенджера `type='letter'` (`useLetterConversation`):
участники — внутренние сотрудники, наружу не уходит. Канцелярия может
«Начать обсуждение» у НЕзарегистрированного письма (`/join`) и приглашать
коллег в любом состоянии (`/participants`, диалог выбора сотрудника —
тот же селектор, что у адресата); обсуждение переживает регистрацию. Не
участнику — пустое состояние с кнопкой присоединения. Переходы письма —
сообщения `letter_transition` (общий `TransitionBlock`).

## Границы

Контрагенты и комбобокс — `shared/counterparties/`; файлы — `shared/files/`
(общий просмотрщик); чат — `shared/chat/`; права и матрица —
`shared/access/`; типы писем и нумерация — `features/automation` (только
просмотр, каталог системный). Контракты — `packages/contracts/src/
correspondence/` (`letter.schemas.ts`, `letter-registration.schemas.ts`,
`letter-transitions.schemas.ts`). Моки — `api/mocks/` (тела мутаций
парсятся схемами contracts; личный признак «я открывал» — множество
`viewedLetterIds` в памяти страницы).

НЕ входит в UI-пакет #55: бэкенд, IMAP/SMTP-приём (#56), исходящие с
отправкой (#464), резолюции/поручения и конфиденциальность (#461/#463),
редактор типов писем (#504).
