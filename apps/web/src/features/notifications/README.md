# Фича notifications — web (#100, ADR-0016; приоритеты/вкладки — #189, ADR-0017)

Живые обновления и уведомления на клиенте: экран «Главная» = витрина
компании (метрики, труд, дни рождения) с лентой журнала в центре (на месте
прежней новостной), колокольчик-поповер, индикация «число + точка», тосты
двух видов, карточка просмотра поверх ленты для важных и записей без
источника. Данные — журнал на бэке (истина); WS только будит. Приоритеты
urgent/high/medium/low — ось важности, независимая от kind (ADR-0017).

## Состав

- `api/notifications-api.ts` — query-хуки (лента/сводка/settings/acks),
  оптимистичные мутации read-one и ack (детерминированный тест: строка уходит
  из живых фильтров и сводки до ответа, история 'all' держит запись для
  карточки, откат при ошибке). Массового «прочитать всё» НЕТ — осознанное
  гашение только (фидбек владельца 01.10). Ключи — shared
  `notifications-keys.ts` (второй потребитель — сокет).
- `api/mocks/` — MSW-хендлеры домена `notifications` + демо-журнал (полный
  срез приоритетов: важное requireAck с длинным текстом под гейт «долистал», высокий/
  средний, низкий с горкой 999+ и правкой сообщения). Демо-набор
  ПЕРЕПРИВЯЗЫВАЕТСЯ к реальным беседам аккаунта (догрузка /chat/conversations
  из хендлера): клик по мок-уведомлению на :5173 открывает настоящий чат.
  Фильтр 'all' — история целиком (включая прочитанные).
- `pages/home-feed-page.tsx` — маршрут Главной: витрина слотами `top`
  (метрики) и `rail` (труд/переработки/дни рождения) из app-слоя, центр —
  лента на ЕДИНОЙ базе `filter=unread` (лента, вкладки и колокольчик читают
  один журнал; секции делятся на клиенте по приоритету); при недоступности
  домена в колонке заглушка (витрина жива, I10/G4).
- `components/notifications-feed.tsx` — вкладки-фильтры (#189, Slack-паттерн):
  системные (Все — защищённая: без ПКМ, не скрывается; Важные; Упоминания)
  - кастомные вкладки пользователя; кнопка «+» — окно настройки; ПКМ на
    вкладке — «Переименовать»/«Удалить» (кастомная) или «Скрыть» (системная);
    счётчики по каждой вкладке; группы по источнику (важное → высокий →
    средний), свёрнутый журнал низкого («Показать все низкие (N)»), пустое
    состояние, onboarding. Строки поиска НЕТ (фидбек 02.10; поиск уведомлений
    — будущий глобальный поиск топбара, #172).
- `components/tabs-settings-dialog.tsx` — окно «+»: название + фильтры по
  типам событий (kind) и приоритетам (оси независимы, пустой выбор = «любой»)
  - видимость системных вкладок. Окно с пополняемыми данными: без крестика,
    не закрывается кликом снаружи (правило 30.09); список типов — фиксированной
    высоты (канон пикер-листов).
- `model/feed-tabs.ts` — модель вкладок: матчинг фильтров, резолв видимых,
  защита «Все», валидация имени — чистые функции (unit).
- `model/tabs-prefs-store.ts` — persist кастомных вкладок и скрытых
  системных (`nodus-notification-tabs-v1`, zod-валидация rehydrate; «Все»
  не проходит схему скрытых — двойная защита с резолвером).
- `components/notification-row.tsx` — строка: аватар · выжимка · источник
  (только название беседы/обсуждения — у личных источник = автор, дубля
  имени нет) · время · метка приоритета. Клик — сразу карточка источника
  (Битрикс24-паттерн, `model/open-notification.ts`); важное и
  безисточниковое — ридер.
- `components/notification-reader.tsx` — карточка просмотра: открывается
  ПОВЕРХ колонки ленты на Главной (не полноэкранная панель — метрики и
  дни рождения остаются видимыми; фидбек владельца 01.10), живёт в колонке
  ленты (home-feed-page). Важное С ПОДТВЕРЖДЕНИЕМ (#177) — лист ознакомления с гейтом «долистал»
  - «Перейти к источнику»; прочее — «Прочитать» + «Перейти к источнику».
    Открытое уведомление — `model/detail-store.ts`; открытие из другого
    раздела ведёт на Главную (`openNotificationReader`).
- `components/bell-popover.tsx` — колокольчик топбара: последние 7 из ВСЕХ
  непрочитанных, старший приоритет сверху (#189: точка низкого всегда
  раскрываема — колокольчик и лента показывают одно и то же); клик — тот же
  сценарий, что в ленте (поповер закрывается); число важного / точка низкого.
- `components/notification-toasts.tsx` — тост-контур: стак личного (≤4,
  «+1» при повторе автора ≤60 с, автоскрытие ~8 с, hover-пауза), сводная
  карточка среднего приоритета (персистентная), aria-live=polite, z-[70].
- `model/toast-store.ts` — подавления: низкий никогда; DND кроме важного;
  muted/snoozed; открытый активный чат (B3–B8, F2/F4/F6).
- `model/use-pause-escalation.ts` — эскалация по паузам (Ф4): idle ≥30 с /
  смена раздела → одна мягкая волна «Требуют внимания: N», не чаще 1/5 мин.
- `model/group-notifications.ts` — группировка по источнику (Telegram-канон),
  сортировка приоритетов (PRIORITY_ORDER), cap «999+» — чистые функции (unit).
- `model/use-notification-sink.ts` — приём WS-будил через shared-мост
  `shared/socket/notification-bridge.ts` (паттерн card-bridge).

## Интеграционные точки (вне фичи)

- `shared/notifications-keys.ts`, `shared/notifications-acks.ts` (мета чата
  «Ознакомились N/M» (только requireAck у автора; метку пузыря несёт чип), live по WS), `shared/socket/*` (приём
  notification.*, точечная догрузка после reconnect), `app/shell/*`
  (колокольчик, бейдж рейки, document.title, ридер в AppShell),
  `shared/lib/persist-zod.ts` (envelope вкладок).

## Мок-режим

Домен `notifications` в `VITE_API_MOCK` (csv) или `true`. На :5173 владельца
чат живой, уведомления можно держать на моках — фронт одинаков.
