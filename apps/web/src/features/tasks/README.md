# features/tasks

Задачи в теме «Инструмент»: канбан «Мой план» (колонки = **личные стадии**
пользователя из его личной workflow-схемы — ADR-0008: цветные чипы, меню
управления, создание инлайн; привязка колонки к системному состоянию даёт
встроенное автоперемещение доски без роботов), список с **графом вложенности**
слева (уровни подзадач — сквозные вертикали, локти, порты; ветки сворачиваются
«−»/«+», как папки в проводнике), карточка-слайдер с доменной цепочкой
(Письмо → Резолюция → Поручение → Задача) и обсуждением, стек-слайдер до
проекта.

**Бэкенд (#37) и веб на живом API (#311):** API модуля — `apps/api/src/modules/tasks/README.md` (маршруты с гейтами ADR-0020, видимость, «Мой план», время, участники). Экраны ходят в эндпоинты #37 (подробности — секция «Живой API (#311)» ниже): бар переходов из `GET /tasks/:id/transitions`, выбор типа и `access`-права карточки; моки MSW (`VITE_API_MOCK` с доменом `tasks`) — только демо и тесты; обсуждение задачи — обычная беседа мессенджера `type='task'` (#252): `task-discussion.tsx` = `ConversationPane` по `useTaskConversation` (`GET /chat/conversations/by-task/:taskId`, find-or-create; не участник — 404 и подсказка «для участников»); параллельного конвейера `/tasks/:id/messages` больше нет. Моки держат форму контракта (`type`, `access`, `result`, создание без колонки — начальная стадия).

**Две оси стадий (ADR-0008):** глобальная (стадия workflow-схемы — официальный
статус; в карточке: панель процесса — замоноличенный нижний бар
`TaskActionBar` по показу кнопок маршрута (`display`: слева главная
залитая, далее видимые, «Ещё …» — меню; порядок задаёт сервер, #378);
справа — таймер учёта времени; «Схема маршрута…» — пунктом в дропдауне
поля-чипа «Стадия» со списком стадий в инспекторе под проектом — модель
Битрикса, `task-stage-controls.tsx`) и личная
(personalStageId — колонки «Моего плана»; **в карточке не показывается и не
меняется из неё — только DnD на доске**, визуальная организация канбана).
Перенос задачи в личную колонку ДРУГОГО системного состояния = смена
systemState (моки эмулируют автоперемещение при смене глобальной стадии).
Поля карточки — реестр дескрипторов с настройкой видимости («+ Поле»; каркас
общий — `shared/ui/entity-fields.tsx`, потребители: задача, письмо, проект,
сотрудник). **Атрибуты — кастомные поля (#431)** — отдельный блок `TaskCustomFields`
(`task-custom-fields.tsx` → `shared/custom-fields/custom-fields-block.tsx`)
сразу после системных: та же грамматика строки, правка по месту
оптимистично (`useUpdateTaskCustomField`: значение и ссылка выбора в кэше до
ответа, `null` удаляет ключ, откат по снапшотам); скрытые атрибуты не
показываются, многострочный текст — на всю ширину. Настройка атрибутов —
только во вкладке «Атрибуты» «Автоматизации» (кнопки в карточке нет).
Старый API без `customFields` терпится (`customFieldValuesOf`) — блок живёт
пустым, карточка не падает.

  (порог 4px; с карточек и контролов — нет). Только мышь — тач листает
  нативно. При переносе карточки доску листает autoScroll dnd-kit, ограниченный
  скроллером доски и колонками (`[data-board-scroller]`, порог 8%/12%) —
  страница не едет.
- **Пагинация объёма (industry-паттерн, research Exa):** колонки канбана —
  курсорные фиды (`GET /tasks?personalStageId=&cursor=&limit=30`), первая
  страница при входе, дальше бесконечная подгрузка sentinel-ом
  (IntersectionObserver, root — скролл-контейнер колонки), как в Битриксе;
  целиком колонки не грузятся
  («Завершена» держит тысячи); упавшая догрузка — тост `loadError`, флаг
  загрузки снимается, колонка не повторяет сама до пересборки борда из
  свежих фидов (иначе sentinel дёргал бы шквал запросов при обрыве сети). Список-дерево — страницы по 100 с подгрузкой у
  дна таблицы (дереву нужен связный набор; родитель вне окна страницы
  отображается корнем до серверного lazy-дерева). Счётчики колонок и сводка —
  из каталога стадий (`GET /tasks/stages` c count/overdueCount; totals в
  list-ответах запрещены каноном api-conventions). Поиск (палитра Ctrl+K) —
  серверным фильтром `search`, клиент не держит весь список.
  **Фаза 2 (до пилота, отдельным issue):** виртуализация колонок/таблицы

  вместо сдвига индексов), серверные фильтры/сортировки, debounce onDragOver
  16 мс на 10k+ карточек.
