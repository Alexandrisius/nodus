# features/tasks

Задачи в теме «Инструмент»: канбан «Мой план» (колонки = **личные стадии**
пользователя из его личной workflow-схемы — ADR-0008: цветные чипы, меню
управления, создание инлайн; привязка колонки к системному состоянию даёт
встроенное автоперемещение доски без роботов), список с **графом вложенности**
слева (уровни подзадач — сквозные вертикали, локти, порты; ветки сворачиваются
«−»/«+», как папки в проводнике), карточка-слайдер с доменной цепочкой
(Письмо → Резолюция → Поручение → Задача) и обсуждением, стек-слайдер до
проекта.

**Две оси стадий (ADR-0008):** глобальная (стадия workflow-схемы — официальный
статус; в карточке: замоноличенный нижний бар действий `TaskActionBar` —
«вернуть»/«вперёд»/«Завершить» + поле-чип «Стадия» со списком в инспекторе
под проектом — модель Битрикса, `task-stage-controls.tsx`) и личная
(personalStageId — колонки «Моего плана»; **в карточке не показывается и не
меняется из неё — только DnD на доске**, визуальная организация канбана).
Перенос задачи в личную колонку ДРУГОГО системного состояния = смена
systemState (моки эмулируют автоперемещение при смене глобальной стадии).
Поля карточки — реестр дескрипторов с настройкой видимости («+ Поле»; каркас
общий — `shared/ui/entity-fields.tsx`, потребители: задача, письмо, проект,
сотрудник): любое количество полей, кастомные после MVP — те же дескрипторы.

- Контракты: `TaskListItem` (+`parentId`, +`personalStageId`), `TaskDetail`
  (+`chain`), `TaskStage` (+`color: StageColor`), `TaskChainNode`,
  `TaskBranch` (дерево ветки навигатора), `PersonalStageCreate/UpdateBody`,
  `CreateTaskBody` (+поля экспресс-формы: description/assigneeId/deadline/
  checklist), `ChecklistItemCreate/UpdateBody`,
  `ChatMessage` (`@nodus/contracts`); код ошибки `TASK_LAST_STAGE` (409).
- Эндпоинты (моки): `GET /tasks` (фильтры `stageId`/`personalStageId`/
  `search`), `POST /tasks` (быстрое создание из колонки: название +
  personalStageId, глобальная стадия — первая стадия схемы того же
  состояния; экспресс-форма шлёт те же + описание/ответственного/срок/
  пункты чек-листа — деталь наполняется сразу), `GET /tasks/stages` (глобальный каталог), `GET|POST|PATCH|DELETE
/tasks/personal-stages(/:id)` (личная схема: CRUD колонок, последняя
  запрещена, задачи удаляемой — в первую колонку того же состояния),
  `GET /tasks/:id`, `GET /tasks/:id/branch` (дерево от корня ветки),
  `GET|POST /tasks/:id/messages`, `PATCH /tasks/:id` (stageId|personalStageId
  - index), `POST /tasks/:id/subtasks`, `POST /tasks/:id/checklist` (пункт),
    `PATCH /tasks/:id/checklist/:itemId` (выполнение/текст; счётчики
    списочного элемента пересчитываются — бейдж канбана).
- **Кастомизация представлений** (инфраструктура `shared/views`, все модули):
  реестр списка-дерева — `lib/task-fields.tsx` (`taskListFields`, с контекстом
  ветки); реестры плоских таблиц задач/проектов и блоков карточки канбана —
  ЕДИНЫЕ в shared (`shared/views/task-table-fields.tsx` `makeTaskTableFields`,
  `task-card-fields.ts` `makeTaskCardFields`, `project-table-fields.tsx`
  `projectListFields`; потребители: задачи проекта, карточка сотрудника —
  «модули не отличаются», вердикт раунда 3); видимость полей — шестерёнка в
  строке инструментов; ширина колонок — ручкой на грани хедера (`ColumnResizer`);
  пресеты персистятся в localStorage (`nodus-views-v1`, схема — contracts
  `viewPresetSchema`, на проде — API персонализации).
- **Строка инструментов списка** (раунды 4–5, единый стандарт `shared/views`):
  `ListToolbar` — ОДНА поисковая строка (placeholder «Поиск…», в фокусе
  расширяется), из которой выезжает панель фильтра (отдельной кнопки нет —
  модель Битрикс24): слева пресеты (встроенные `taskBuiltinPresets`: «В работе»,
  «Я — ответственный/постановщик», «Просрочены», «Завершённые» + сохранённые
  со «скрепкой по умолчанию», память `nodus-list-filters-v1:<viewKey>`), справа
  поля реестра `shared/views/task-filter-fields.ts` (стадия, состояние, роль,
  ответственный, постановщик, проект, приоритет, крайний срок — КОМБОБОКСАМИ
  с вводом и подсказками, person — с аватарами; `overdue` — скрытое
  служебное); чипы активных; фильтрация — чистые функции `list-filters.ts`
  (unit-тесты); у списка и канбана — свои viewKey (key по виду на странице);
  в канбане при фильтре счётчики «n из m», DnD выключен. **Шапка страницы —
  ОДНА строка h-14 БЕЗ border-b** (заголовок + тулбар + **«Создать задачу»**
  (экспресс-форма `shared/tasks/task-quick-create.tsx` — в shared, потому
  потребители за пределами фичи: карточка сотрудника создаёт задачу ему,
  I6; вердикт владельца 15.09.2026 —
  модель Битрикс24, но в грамматике Nodus без чиповой философии Битрикса:
  название, описание сворачиваемое, ответственный/проект — FilterCombobox,
  крайний срок, чек-лист листом поверх формы во ВСЮ её ширину со смещением
  вниз `task-checklist-sheet.tsx`; создание — в первую личную колонку;
  экспресс-форма СОЗДАЁТ и ЗАКРЫВАЕТСЯ (тост «Задача создана») — карточку
  НЕ открывает, «Полная форма» появится своей кнопкой позже, вердикт
  15.09.2026) + счётчик «Просрочено»-фильтр + шестерёнка;
  сводок-лейблов нет — вердикт раундов 5–6).
  Глобальный «Умный поиск» — лупа в топбаре (не конкурирует с локальным).
- **Ведущая колонка журналов** (вердикт владельца 15.09.2026, модель
  Битрикс24; общая у `DataTable` и `TaskList`, 48px `LEADING_COL_W`):
  чекбокс множественного выбора (`useRowSelection`: хедер — «выбрать все»
  с indeterminate, выбранная строка — тон accent) + «шашка» контекстного
  меню строки (`RowMenu` — только реальные действия: «Открыть»,
  «Копировать ссылку» deep-link `?cards=kind:id` через `copyCardLink`).
- **Порядок колонок и сортировка журналов** (концепт #4, общая машина
  `DataTableHeader` у `DataTable` и `TaskList`): порядок — drag за
  заголовок моделью Битрикс24 (заголовок и данные едут вместе 1:1 строго
  по X, ручной pointer-drag с императивными трансформами без перерисовок,
  коммит на отпускании — gotchas), сортировка — клик по заголовку с
  `sortValue` (↑/↓, `sort-rows.ts`; журнал задач — сортировка СИБЛИНГОВ:
  плоский список сортируется до `buildTaskRows`, структура дерева не
  ломается); порядок и сорт — в пресете вида (`nodus-views-v1`).
- Граф списка: `lib/task-tree.ts` (дерево → строки с геометрией связей),
  `components/task-list-graph.tsx` (единый SVG-оверлей поверх строк:
  непрерывные рёбра без зазоров, каскадное построение от родителя к подзадачам
  при раскрытии, ширина колонки растёт с глубиной вложенности).
- Раскрытие слайдера: rect клика пробрасывается через `useShellStore.lastSource`
  (клик по строке/карточке → `getBoundingClientRect` → `SliderPanel sourceRect`),
  панель раскрывается из источника (CSS @keyframes `slider-expand` строго на
  transform — композитор, контент монтируется после первого кадра); без
  источника — scale-fade. Затемняющего задника нет: тень `slider-shadow` +
  прозрачный click-catcher (фон страницы цвета не меняет). Роут слайдера —
  НЕ lazy (центральный экран): первое открытие равно повторным. Зональные
  фоны карточки (тёмный чат) — структура вне content-fade (`fadeContent=false`
  в SliderPanel): видны с первого кадра роста, fade — только текст/контролы.
- Карточка: поля — `components/task-fields.tsx` (строки иконка+метка/значение
  без рамок, container-query сетка 1→2 колонки с центрированием — модель
  ClickUp; на предельно узкой зоне значение переносится под метку, не
  исчезает); чек-лист — `components/task-checklist.tsx`, сразу после полей,
  ДО подзадач (вердикт владельца 15.09.2026: «чек-листам — важное место»):
  прогресс линией, живые отметки (оптимистично, `api/checklist-api.ts`),
  добавление пунктов, секция видна всегда; навигатор ветки — `components/task-branch-drawer.tsx` (левая
  ВТАЛКИВАЮЩАЯ колонка сетки 0↔300px с transition — контент и разделитель
  чата сдвигаются плавно, не оверлей): вкладка «Подзадачи» — дерево от корня
  СТАРТОВОЙ задачи сессии (карта стабильна), вкладка «Связи» — связи
  просматриваемой (поле «Отношения», заготовка `GET /tasks/:id/relations`
  под зависимости Ганта #39); переходы — РЕЖИМ «НАВИГАЦИЯ» (вердикт раунда
  4, ADR-0009 доп.): клики по строкам панели и полям «Подзадачи»/«Связи»
  ЗАМЕНЯЮТ содержимое карточки (`useReplaceTopCard` — стек не растёт, панель
  не закрывается и не ремонтируется, один Escape закрывает сессию, «←» в
  шапке — шаг назад по переходам, автооткрытие панели из полей); внешние
  переходы (чат, палитра) — ПОВЕРХ стеком; быстрое создание «+» на строке /
  инпутом внизу к текущей; тоггл — `Waypoints` в полосе цепочки; чат —
  постоянная колонка с ресайзом (`shared/ui/use-chat-width.ts`), обсуждение —
  на ОБЩЕЙ анатомии чата (`task-discussion.tsx`: серии сообщений, дата-чипы и
  единый `ChatComposer` из `shared/chat` — «всё должно изменяться
  одновременно», вердикт владельца 15.09.2026); «О задаче» — ПОЛНОВЫСОТНАЯ
  вталкивающая колонка, занимающая верхний бар карточки тоже (геометрия
  Битрикс24, вердикт 15.09.2026 — канон панели беседы: верхняя строка h-14 =
  «О задаче» слева + звезда и крестик у края справа, полоса цепочки той же
  высоты h-14, тоггл уезжает влево): чат сужается на ширину панели по
  канону «чат — буфер сужений» (#63): общий пол чата = drag-пол
  `MIN_CHAT_W` (глубже — только исключение открытой «О задаче»
  `MIN_CHAT_WITH_PANEL`), левая зона и разделитель стоят, пока чат выше
  пола; после упора сужение двигает левую зону без пола.
- Доменная цепочка: `shared/ui/domain-chain.tsx` (узлы из `taskDetail.chain`;

- Оптимистичность: `useSendTaskMessage`, `useUpdateTaskStage`,
  `useUpdateTaskPersonalStage` — канон patterns.md; детерминированные тесты —
  `api/tasks-api.test.tsx`, `shared/mocks/data/personal-stages.test.ts`

- **Пессимистичные мутации (обоснование по patterns.md):** `useAddSubtaskTo`
  (создание подзадачи произвольному родителю из навигатора ветки — родитель
  может быть не открыт, темпу в кэше детали взяться неоткуда; инвалидация
  дерева/детали по завершении) и CRUD личных колонок
  (`useCreatePersonalStage`/`useUpdatePersonalStage`/`useDeletePersonalStage` —
  структурные операции над схемой: удаление переезжает задачи на сервере,
  локальная проекция результата была бы фальшью; ждём инвалидации).
- **DnD канбана (ADR-0007, @dnd-kit/core+sortable):** живая сортировка —
  карточки уступают место и переезжают между колонками ВО ВРЕМЯ переноса
  (`onDragOver`, sortable-трансформы), финализация — персист колонки+индекса
  (`PATCH /tasks/:id` с `personalStageId`, оптимистично I4 с откатом и
  тостом); Esc — откат к снапшоту dragStart; призрак DragOverlay садится на
  живой слот (обратного перелёта нет). **Каркас доски — ЕДИНЫЙ движок
  `shared/ui/board/use-kanban-board.ts` (аудит #45, второй потребитель —
  проектная доска):** борд, фиды колонок через React Query
  (`tasksKeys.kanban(scope)` — перенос степпером виден на доске),
  sentinel-подгрузка, скелетон `kanban-skeleton.tsx`; фича — конфиг оси
  (`personalAxis`)/фида/мутаций + CRUD колонок и countDelta. Колонка
  `shared/ui/board/board-column.tsx` (чип-шапка + счётчик + слоты меню
  и quick-add + скролл с sentinel), карточка `board-task-card.tsx`
  (презентационная, onOpen/onHover подключает фича), sortable-обёртка
  `board-sortable-card.tsx`, тона стадий `stage-tone.ts`; доменная обёртка
  колонки с CRUD личной схемы — `components/task-kanban-column.tsx`. Борд — локальное состояние, синхронизированное
  с query вне переноса; структурная смена набора колонок (создание/удаление
  стадии) перезагружает борд из фидов. PointerSensor distance 6 (клик без
  движения открывает слайдер), Keyboard/Touch-сенсоры.
- **Пагинация объёма (industry-паттерн, research Exa):** колонки канбана —
  курсорные фиды (`GET /tasks?personalStageId=&cursor=&limit=30`), первая
  страница при входе, дальше бесконечная подгрузка sentinel-ом
  (IntersectionObserver, root — скролл-контейнер колонки), как в Битриксе;
  целиком колонки не грузятся
  («Завершена» держит тысячи). Список-дерево — страницы по 100 с подгрузкой у
  дна таблицы (дереву нужен связный набор; родитель вне окна страницы
  отображается корнем до серверного lazy-дерева). Счётчики колонок и сводка —
  из каталога стадий (`GET /tasks/stages` c count/overdueCount; totals в
  list-ответах запрещены каноном api-conventions). Поиск (палитра Ctrl+K) —
  серверным фильтром `search`, клиент не держит весь список.
  **Фаза 2 (до пилота, отдельным issue):** виртуализация колонок/таблицы
  (@tanstack/react-virtual + dnd-kit clone-feedback — официальный пример),
  порядок колонок через LexoRank/fractional indexing (O(1)-запись переноса
  вместо сдвига индексов), серверные фильтры/сортировки, debounce onDragOver
  16 мс на 10k+ карточек.
- Виды переключаются search-параметром `view` (секции в топбаре).
