# Definition of Done (чеклист готовности задачи)

Задача считается готовой к PR, только когда пройден **каждый** применимый пункт. Исполнитель отмечает пункты в комментарии issue; субагент-валидатор перепроверяет.

Читать: перед пометкой фазы/задачи как «готово».

## Код

- [ ] Реализован скоуп issue — ни больше, ни меньше (смежное — вынесено в комментарии/новые issues).
- [ ] Инварианты I1–I15 не нарушены; отклонения оформлены ADR и согласованы владельцем.
- [ ] Линтер чист: границы модулей (boundaries), размер файлов (> 300 — обоснование в комментарии, > 500 — недопустимо), форматирование.
- [ ] Typecheck чист (`strict`, без новых `any` без обоснования).
- [ ] Build проходит.
- [ ] Нет хард-списков/хард-строк (I15): бизнес-списки — `dictionaries`, UI-строки — i18n.
- [ ] Мутации идемпотентны; изменения сущностей — события через outbox; действия — в аудит (I7, I9).
- [ ] Изменение API = обновлены zod-схемы в `@nodus/contracts` и OpenAPI-аннотации в том же коммите.

## Тесты

- [ ] Новая бизнес-логика покрыта unit-тестами (Vitest) **в том же коммите**.
- [ ] Изменённые критичные пути — e2e (Playwright) зелёные.
- [ ] Оптимистичные мутации проверены детерминированным тестом (применение к кэшу до ответа сервера).
- [ ] Все тесты зелёные локально и в CI; флаки-тесты не добавлялись.

## Документация (I12)

- [ ] `README.md` затронутых модулей обновлены в том же коммите.
- [ ] Изменены команды/структура/правила → обновлены `AGENTS.md` и документы `docs/`.
- [ ] Архитектурные решения оформлены ADR.
- [ ] Найденные ловушки — строкой в «Gotchas» AGENTS.md.

## Процесс

- [ ] Комментарии в issue: отчёты по фазам («что сделано, как проверить»).
- [ ] **Валидация субагентом пройдена**: независимый агент со свежим контекстом проверил diff на соответствие issue, инвариантам и этому чеклисту; вердикт — в комментарии issue; замечания исправлены.
- [ ] PR по шаблону: что/зачем/как проверить + `Closes #N`; CI зелёный.
- [ ] Мерж — **только после явного подтверждения владельца**.

## Чеклист субагента-валидатора (промпт-основа)

Валидатор получает: номер issue, diff ветки, этот чеклист. Он **не видел** переписку исполнителя и проверяет результат с нуля:

1. Прочитай issue: скоуп и критерии приёмки. Сверь с diff: всё ли из скоупа сделано? Нет ли лишнего?
2. Прогони проверки: lint, typecheck, build, тесты — сам, не верь отчёту исполнителя.
3. Проверь инварианты, релевантные diff (границы модулей, идемпотентность, события, i18n, оптимистичность).
4. Проверь наличие и адекватность тестов новой логики (не «тест ради теста»).
5. Проверь, обновлена ли документация затронутых модулей.
6. Вердикт в комментарий issue: «Принято» или нумерованный список замечаний вида [файл:строка] → [проблема] → [почему] → [минимальное исправление]. Замечания без привязки к месту отклоняются исполнителем.
