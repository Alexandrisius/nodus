# Фронтенд (React, Tailwind)
- **Условный вызов хука (`cond && useHook(...)`) проходит typecheck/lint/build и падает ТОЛЬКО в рантайме React 19 на смене состояния** («Internal React error: Expected static flag was missing») — хук вне фиксированного порядка ломает компилятор статических флагов, а не линтер типов (воспроизведение PR #167/#164; правило rules-of-hooks — react.dev/learn/rules-of-hooks «call Hooks at the top level»). До подключения `eslint-plugin-react-hooks` (#168) такой код ловился только ручным аудитом валидатора — теперь `pnpm lint` режет его как error.
- **Клики по контенту React-ПОРТАЛА (Radix-меню/поповеры) всплывают через REACT-дерево, а не DOM** (react.dev/portals «events bubble up through the React tree»): capture-обработчик DOM-предка (глушитель селекта в `message-row.tsx`) ловит клики по пунктам контекстного меню, хотя в DOM портал живёт в body — команда молча не выполнялась, «клик» снимал выделение строки (репро юнит-тестом `message-menu-selection.test.tsx`, фидбек владельца 10.10). Канон: перехватчики кликов предков обязаны фильтровать `rowRef.contains(event.target)` — клик по оверлей-слою предку не принадлежит. Тот же механизм в кликабельной карточке поста (#409): клик по заднику лайтбокса закрывал его И открывал панель тредов (гвард видел target вне DOM карточки, но `closest('button')` не находил интерактива) — лечение: `if (!e.currentTarget.contains(e.target)) return` в обработчике карточки + `stopPropagation` на заднике.
- Замер просмотрщика изображений: «картинка загрузилась» ≠ «картинка показана» — naturalWidth/complete/opacity могут быть идеальны при rendered-боксе, сжатом под потоковую миниатюру (контейнер `inline-flex` сжимается по содержимому, `max-w/max-h` НЕ растягивают; #221: natural=2400 при client=800×533). Вердикт приёмки — по `getBoundingClientRect()` изображения, не по natural-полям (подтверждено воспроизведением пробы #221, 06.10).
- **`max-w`/`w-*`/`self-end` молча не действуют на ИНЛАЙН-элементе** (non-replaced inline — ширина не применяется, MDN width «Applies to: all elements but non-replaced inline»): обёртка цитаты `<span className="max-w-52">` не ограничивала ширину — сниппет растягивал родителя w-fit (репро #288, 14.10). Канон: любые width-ограничения — на `flex`/`block` обёртке.
- **`border-radius` на ФИКСИРОВАННОМ боксе с `object-contain` не скругляет вписанный арт** (репро #288, 14.10: квадратный стикер скруглился, прямоугольный нет): радиус клипит бокс, картинка letterbox'ится внутри с полями — её собственные углы внутри, радиус их не достаёт. Канон: бокс обнимает картинку — `max-h/max-w` вместо фикс-размера (пропорции сохраняются, миниатюры меньше капа рендерятся в натуральную величину).
- Плитки ленты НЕ грузят оригинал изображения при отсутствии миниатюры (#221): `thumbnailUrl ?? url` в `<img>` ленты — мегабайты в пузыре и «висящая» картинка после отправки; оригинал грузит только лайтбокс по клику, лента живёт на серверном WebP-превью, фоновая готовность — событием `chat.attachment_preview_ready` (канон Zulip thumbnailing: спиннер до готовности воркера, docs/subsystems/thumbnailing.md; подтверждено исследованием #221).
- **Список поверхностей ПКМ-меню (`message-menu.tsx` onContextMenuCapture) — точка расширения:** новая вариация сообщения без слота из списка (`bubble-content`, `post-surface`, `message-tombstone`, `sticker-surface`, `media-message`) = контекстное меню ТИХО не открывается на ней (stopPropagation для «пустого места строки»); до #171 bare-медиа (своё фото без пузыря, #187) не имело слота в списке — меню было недоступно на нём вовсе. Добавляя новый data-slot поверхности сообщения — проверять список. (воспроизведением, #171)

- **Ховер-пилюля с отрицательным полем внутри truncate-контейнера режется клипом на КОРОТКОЙ стороне (#269):** кнопка-название с `-mx` + `rounded` + `hover:bg` внутри `overflow-hidden`-обёртки (усечение для многоточия) вылезает полем за клип-границу; когда соседний текст (подпись) длиннее названия, контейнер шире пилюли и её левое скругление срезается в прямую вертикаль, правое остаётся мягким — асимметрия зависит от ДЛИНЫ СОСЕДНЕГО текста, не кнопки. Канон: `-mx` раздвигающего клип живёт на ОБЁРТКЕ, усечение (`truncate w-fit max-w-full`) — на самой кнопке (conversation-bar.tsx; воспроизведено живой приёмкой владельца, механика — CSS overflow: клип по padding-краю контейнера).

- **Зеркальный оверлей прозрачного поля ввода — метрики суть классы САМОГО поля, не «похожие»** (#303, репро владельца 16.10: многострочное выделение в композере уезжало полоской от текста построчно, каретка мерцала при наборе): `leading-normal` на зеркале давал line-height 21px против 20px пары `text-sm` у textarea — 1px расхождения на КАЖДУЮ строку; зеркало красит над полем, поэтому сдвиг уводил и полоску `::selection` (стал заметен после появления авторской непрозрачной полоски, #300/#301), и глифы по каретке. Канон: зеркало несёт ту же пару font-size/line-height и те же паддинги, что поле (`text-base md:text-sm` + композерные `px-1.5 py-1.5`), без собственных line-height; правка классов поля = синхронная правка зеркала (парный комментарий в `composer-mention-overlay.tsx`). Механизм Tailwind: утилита `text-*` задаёт СВЯЗКУ размера и line-height, любой `leading-*` поверх неё разрывает пару. **Вторая ось той же пары (#409): ширина** — классический скроллбар забирает место из content-box (MDN scrollbar-gutter: «classic scrollbars consume space from the content box»), поэтому появление вертикального скроллбара на капе 45vh сужало textarea, а зеркало с `overflow-hidden` оставалось полной ширины → переносы расходились, каретка уезжала на строку; плюс `font-medium` на чипах менял ширину глифов. Канон: скроллбар поля скрыт (`[scrollbar-width:none]` + webkit), начертание чипов = начертанию поля.
- **Без явного правила `::selection` выделение текста живёт на браузерных дефолтах, которые НЕОДИНАКОВЫ по элементам** (#300, репро владельца 15.10: в остальном документе чёрный текст становился белым на системной тёмно-синей полоске, а в поле набора сообщения оставался чёрным — нечитаемо): поля ввода красят выделение отдельным путём движка (селект разрешается через shadow-host поля, фон кладётся на внутренний `#inner-editor`, текст держит свой цвет — codereview.chromium.org/220343006), а авторские цвета `::selection` браузер больше не «спасает» инверсией (blink-dev PSA 03.2024 по резолюции CSSWG #6150 — контраст целиком на авторе, MDN ::selection: текст↔полоска ≥ 4.5:1, полоска↔фон ≥ 3:1). Канон: пара токенов `--selection-bg`/`--selection-fg` на обе темы + `::selection` в `@layer base` (globals.css). **Следствие для дизайна пар (#300, репро владельца 16.10 «светло-голубая заливка + белый текст — нечитаемо»): раз в полях ввода fg выделения = цвет элемента всегда, тёмная тема НЕ имеет права инвертировать (светлая полоска + тёмный текст — в инпуте остаётся светлый текст); полоску подбирают под САМЫЙ светлый текст темы (foreground), а не под идеальную видимость полоски.**

- **Пиксельная идентичность двух линий возможна только в ОДНОМ механизме отрисовки (#155, 8 раундов):** CSS (box-shadow/border) и SVG-штрих каждый по-своему округляют координаты к физическим пикселям — на целых зумах совпадают (вводит в заблуждение), на дробных расходятся принципиально, это не баг, а свойство. Идеальный стык «пузырь+хвост» получился только когда ВСП (заливка И граница) стал одним SVG-путём на весь силуэт. Правило: требуется пиксель-в-пиксель — рисуй одним растеризатором; стык двух механизмов «подгонкой констант» не лечится. Полезные числа из блужданий, вошедшие в итог: глубина кольца [1,2]css (inset-тень рисуется под прозрачной рамкой 1px), вертикальная касательная на входе кромки, продление полосы по низу (заливка хвоста перекрывает полосу пузыря), device-снаппинг рёбер (round(rect×dpr)/dpr), полу-штрих SVG центрируется на контуре (внутрь = ширина/2). **Реинкарнация в #187 (раунд 14):** плавник медиа-части, нарисованный ОТДЕЛЬНЫМ svg рядом с CSS-фоном части, на 125/175/200% «разъезжался вертикальной линией» — нижняя часть переведена на Bubble+BubbleOutline (один путь); отдельный BubbleFin удалён.

- **absolute right-0/bottom-0 на блоке с собственным padding даёт 0px от КРАЯ (#187, раунды 6–8):** abs-pos отсчитывается от PADDING-бокса якоря (внутренний край рамки), а не от контентного — если несущая padding (px-2.5) сама является якорем, метка прилипает к внешнему краю; если якорь — вложенный контентный блок, метка уезжает ВНУТРЬ на двойное поле. Канон: якорь = элемент, растянутый на ширину ПОВЕРХНОСТИ (пузырь/часть/блок-карточки), инсеты от края задавать явно. Подтверждено CSS-спекой (CSS 2.1 §10.1: containing block = padding edge).

- **overflow-hidden НЕ клипает абсолютного потомка с внешним containing block (#187, валидатор):** клип-спан (overflow-hidden + border-radius) обязан быть `relative` — иначе absolute-щит селекта (inset-0) якорится к внешнему фрейму и красится КВАДРАТОМ поверх скруглённых углов картинки. Механизм: CSS-overflow не применяется к abs-pos, чей containing block вне клип-контейнера (CSS 2.1 §11.1.1). Общий вывод: абсолют-оверлей внутри клипа = явный `relative` на клипе.

- **Метка времени «уголком» без обрезки узких карточек — пара «призрак+булавка» (#187, раунды 7–11):** чистый absolute не участвует в shrink-to-fit (карточка из 1 символа ОБРЕЗАЕТ метку), флоат топится к верху line-box, а на своей строке (только флоат) линия нулевой высоты — метка проваливается без зазора; чистый inline садится сразу за текстом и слева на своей строке. Решение: невидимая КОПИЯ меты в потоке (резервирует точную ширину, без замеров — состав меты меняется сам) + видимая absolute от края с явными инсетами. Зазор текст→мета живёт на призраке (ml-14px): перенос «метки на свою строку» происходит автоматически, когда текст+зазор+призрак не влезают.

- **fit-content пузырь + процентные размеры детей = схлоп до загрузки** (#150, подтверждено research Telegram tdesktop/FB Messenger): `w-full`/`aspect-ratio` внутри `w-fit`-контейнера не дают вклада в intrinsic-ширину, незагруженный `<img>` = 0×0 → контент прыгает при доскролле (lazy). Лечится ЯВНЫМИ px из сохранённых габаритов (fit-в-бокс, «не апскейлим мелкое» — модель FB Messenger); ширина пузыря с вложениями задаётся блоком вложений, текст переносится (captionw = _maxw − padding, Telegram).

- Эндпоинт конфигурации, нужный реестру на буте (office-config #138), должен быть `@Public`: запрос до логина с Bearer-получением 401 кэширует «движок выключен» на staleTime, и все офисные вложения тихо едут в фолбэк до рефеча.
- **`dark:`-утилиты Tailwind в проекте НЕ применяются** (мертвый код): вариант объявлен на класс `.dark` (`@custom-variant dark (&:is(.dark *))` в globals.css), а тема переключается АТРИБУТОМ `data-theme='dark'` на `<html>` (index.html/app-shell) — селектор `.dark *` никогда не матчится. Проверка замером: под `[data-theme='dark']` computed-стиль элемента с `bg-muted dark:bg-accent/60` остаётся `--muted` (#96). Следствие: тона обеих тем — ТОЛЬКО токенами (`--chat-zone`, семантика в globals.css); попутно многие `dark:`-классы в shadcn-примитивах (switch, button, bubble) фактически не работают — чинить точечно при касании, не разом.

- **Ширина кастомного DialogContent: голый `max-w-*` НЕ перебивает дефолт с вариантом (`sm:max-w-sm` у dialog.tsx)** — tailwind-merge считает классы с разными вариантами разными группами конфликта; на десктопе панель остаётся 384px и широкий контент вылезает за её фон («фон не покрывает»); канон: `className="w-full sm:max-w-2xl"` (тот же вариант + w-full). Воспроизведено скриншотом (#69), фикс в четырёх диалогах корреспонденции/контрагентов.

- **`animationend` всплывает**: обработчик `onAnimationEnd` на контейнере ловит завершение CSS-анимаций всех потомков — фильтруй по `event.animationName`, иначе дочерняя короткая анимация (напр. draw-on 450мс) преждевременно «завершит» логику родителя (подтверждено воспроизведением: док-ребро слайдера исчезало до кадра, issue #4).
- **SMIL `<animateMotion>` не стреляет DOM `animationend`** — для «один пробег и убрать» таймаут/JS, не событие; перемонтирование через `key` перезапускает SMIL-анимацию надёжнее, чем смены атрибутов.
- **SMIL `<animateMotion>` с `begin > 0` и без `fill="freeze"` показывает элемент в (0,0)**: до старта движения и после окончания пробега анимируемый кружок возвращается в начало координат SVG — виден как «светящийся пиксель» в левом верхнем углу экрана. Лечение: `fill="freeze"` на animateMotion (остаётся в конце пути) + стартовый `opacity={0}` с `<animate attributeName="opacity">` на момент begin (подтверждено воспроизведением: пиксель в углу при каждой вспышке контура, issue #4; механика — модель времени SMIL: до begin и после активной длительности значение не применяется).
- **`transitionend` приходит на КАЖДОЕ свойство и всплывает**: цикл покадрового слежения за transition панели глохнет от `transitionend` посторонних коротких анимаций (затухание текста 200мс против движения панели 300мс) — запуск и остановку фильтруй по `event.propertyName` (у нас — только `'width'`; подтверждено воспроизведением: контур «отставал» от правой панели на последние ~100мс, issue #4).
- **transition на треке сетки с drag-ресайзом = фризы**; и даже БЕЗ transition `setState` на каждый pointermove/rAF-кадр гоняет ре-рендер всего дерева (сообщения, поля, панели) — на реальных машинах это видимые лаги. Канон ресайза (подтверждено react-resizable-panels issue #310, bvaughn + замерами issue #4): во время drag ширина выставляется ИМПЕРАТИВНО (`el.style.width` через ref в rAF-лупе), React-state и persist — один раз на pointerup; transitions — только для программных toggle, на время drag сняты флагом (`!dragging && 'transition-[width]'`); «панель выталкивает соседа» = две синхронные transition-[width] (растёт одна — на ту же величину суется соседняя, сумма постоянна); тяжёлые дети (обсуждение, поля, панели) — memo + стабильные колбэки. Итог замера: 0 лонгтасков, ~60 fps, ширина следует за мышью 1:1.
- **vite: добавление `export *` в barrel на живой dev-сессии залипает модульный граф** — свежая страница падает с `SyntaxError: does not provide an export named …` при корректных исходниках; лечится перезапуском dev-сервера (не правь код вслепую; подтверждено воспроизведением в issue #4, mocks/data/tasks.ts).
- **fr-колонка слева от ресайзимых ломает drag-ресайз таблицы**: в grid `… 1fr …` при изменении фиксированной колонки резиновая компенсирует дельту — ручка отрывается от курсора, колонка визуально «растёт не в ту сторону» (компенсация меняет её ЛЕВУЮ грань). Ресайзимая таблица — только с фиксированными px-треками (включая колонку названия), контейнер `w-max min-w-full` + `overflow-x-auto` (модель Битрикса: пустое место справа, переполнение — скролл; подтверждено воспроизведением: ручка «Стадии» инвертировала drag, issue #4).
- **Эталон ресайза колонок (AG Grid / Excel):** drag меняет только свою колонку, соседние сдвигаются не меняя ширины (переполнение — скролл); защиты — `minWidth` под осмысленный контент (контент не «спрятать») и `maxWidth` (не «растянуть навсегда»), сужение — с ellipsis; **dblclick на ручке = автоподбор по контенту**. Измерение контента для автоподбора — по ДЕТЯМ ячейки: `scrollWidth` самой ячейки не бывает меньше её `clientWidth` и возвращает текущую ширину трека (подтверждено: доки AG Grid column-sizing, воспроизведение в issue #4).
- **dnd-kit multi-container: «Maximum update depth» при ховере у границы колонок** — осцилляция onDragOver (переложил в B → раскладка сдвинулась → под указателем снова A → переложил обратно) плюс setState с НОВОЙ ссылкой массива при идентичном порядке топливают цикл измерение→setState (measureRect в layout-эффектах). Предохранители, не меняющие поведение: анти-осциллятор (кадр после межколоночного переноса игнорируем, сброс rAF-ом) и гейт `isSamePlacement` (идентичное размещение не создаёт состояния); трансформ sortable у активного элемента обязателен (иначе слот не едет за пересортировкой), но именно он же даёт обратную связь rect→проекция — держим оба предохранителя. - **transition на ширине панели, перевязываемой при ВНЕШНЕМ resize контейнера = «гармошка» (issue #65)**: если ширина панели следует из ширины контейнера (кламп-формулой) и контейнер сужается ИЗВНЕ покадрово (drag колонки-родителя императивным width, рефлоу рельсы, окно), ре-рендер перевязывает ЦЕЛЬ панели каждый кадр — а transition-[width] на панели отрабатывает эти перевязки eased-шагами с отставанием: гибкий сосед (лента flex-1 min-w-0) забирает дефицит ниже своего минимума («пружина»), а контент панели клипится переходящим краем рывками. - **Порядок уступок места весами `flex-shrink` ломается, если веса меньше 1**: дефицит делится пропорционально `вес × базис`, упёршийся в min-width элемент замораживается — веса на порядки (1e6/1e3/1) дают строгую очередь «навигатор → чат → центр» без замеров (#365, `SHRINK_ORDER`). - **Правило в `@layer base` ПРОИГРЫВАЕТ любому utilities-классу независимо от специфичности** (порядок слоёв сильнее): переопределения поверх утилит — вне @layer (раунд 4 чата).
- **Переименовывая/удаляя элемент с `data-slot`, участвующим в глобальных CSS-правилах, — grep правил по старому селектору в том же изменении**: селектор молча перестаёт матчиться (ни линт, ни тесты не падают) (#155).
- **UI-канон SVG: CSS `clip-path: path()` на SVG-элементе отсчитывается от bbox элемента, не viewBox** — клип смещается/срезает контент; только SVG `<clipPath clipPathUnits="userSpaceOnUse">` + `url(#id)`; id из `useId()` чистить от не-ASCII (#155).
- **UI-канон согласования SVG-штриха с CSS-полосой**: `vector-effect: non-scaling-stroke` на геометрии, масштабируемой ui-scale, даёт штрих ЧУЖОЙ толщины; пересчёт units = cssPx × vie
- **UI-канон: 1px «цветные дуги» на углах скруглённых картинок на дробном DPR — неустранимый анти-алиасинг** (цвет = mix кромки фото с фоном, зависит от субпиксельной фазы позиции): translateZ/clip-path/снап размеров бесполезны (A/B на живой сборке); смягчение — радиус соло-фото меньше пузырёвого (12px); не тратить часы на «фикс» физики растеризатора (#187, пиксельные пробы).

- **Снятие выбора строки после удаления — только `deselect(key)`, не `toggle(key)`** (#460, 25.10.2026): `toggle` на невыделенном ключе его ДОБАВЛЯЕТ — удалённая через меню строка попадала в счётчик островка и висела там, хотя строки уже нет. В общем `useRowSelection` (`shared/views/use-row-selection.ts`) есть явный `deselect`; островок дополнительно считает ТОЛЬКО пересечение выбора с реально видимыми строками (страховка от ключей удалённых/отфильтрованных записей).
- **Окно-диалог правки держать смонтированным нельзя — на анимации закрытия оно перерисовывается в ДРУГОМ режиме** (#460, 25.10.2026): форма правки оставалась в дереве, `target` становился `null`, и за закрывающимся окном мелькало окно «Создать» — другой заголовок, панель «Похожие», выше по высоте (баг владельца «мелькает такое же окно, но чуть больше»). Канон: диалог монтируется ТОЛЬКО при наличии цели (`{target ? <Dialog open … /> : null}`), а не флагом `open` на постоянно смонтированном компоненте.
- **Меню «шашки» строки — ПОЛНЫЙ набор команд сущности, а не только «Открыть/Копировать ссылку»** (#460, вердикт владельца 25.10.2026): базовая пара живёт в `shared/views/card-row-menu.tsx`, модуль обязан добавить свои действия следом (`separatorBefore: true`) — правку, архив/возврат, удаление; состав команд реестра = состав команд карточки, недоступное по правам не показываем.
