# Процесс и документация

- ADR нумеруются плотно, без дыр: перед созданием нового — проверь max существующего номера (`ls docs/adr/`), не присваивай «следующий с конца + запас».
- `gh api .../branches/main/protection`: поле `restrictions` обязательно (передавать `-F restrictions=null`), булевы значения — только через `-F` (через `-f` уходит строка и API отвечает 422 «not a boolean»).

- **Незакоммиченное рабочее дерево «ездит» за git switch/checkout**: неподконфликтные между ветками локальные правки сохраняются при переключении (git-scm git-checkout: «Uncommitted changes will otherwise be kept») — параллельная сессия, сменившая ветку, утаскивает чужую незакоммиченную фичу с собой; ветка сменяется и МЕЖДУ проверкой и коммитом (между проверкой и коммитом могут пройти минуты валидации субагентом) — проверка обязана стоять в ОДНОЙ команде с коммитом (`git branch --show-current | grep -qx main && git commit -m …`), «проверил в начале задачи» не считается. Правило: коммить на свою ветку НЕМЕДЛЕННО после правок (канон — локальный коммит до вердикта, push после; грязное дерево между правкой и коммитом — процессная ошибка), параллельная сессия живая — только отдельный worktree (`git worktree add`). Коммит, севший на чужую ветку, переносится без checkout: `git push origin HEAD:main` + `git branch -f main HEAD` + на чужой ветке `git reset --hard HEAD~1` (дерево чистое). Воспроизведено 24.09.2026: дерево линии A (#87) уехало с feat/87 на fix-ветку хотфикса #88 и далее на main; повторено 03.10.2026 (#204): 20 минут правок без коммита — коммит лёг на чужую ветку и уехал в main чужим squash-PR #205; повторено 29.10.2026: проверка ветки в начале задачи → 5 минут валидации субагентом → коммит сел на свежесозданную ветку параллельной сессии.
- **Revert-ветка для чистки main плодить ТОЛЬКО от текущего main**: дифф PR GitHub считает от merge-base — ветка, ответвлённая ДО случайного сквоша, показывает в PR только свои коммиты (hotfix), а чужой WIP в main не убирает; squash применяет ровно то, что в диффе. Репро 30.09: #159 (ветка от fa935fe) не убрал WIP-стикеры из сквоша #158, потребовался честный `git revert <sha-WIP>` от origin/main (#160; механизм — docs.github.com «comparing branches», трёхточечный дифф).

- **`gh … --body "…"` с бэктиками/`$` из Git Bash публикует изуродованный текст** (command substitution отрабатывает до отправки; `personTone: command not found` остаётся в stderr) — тело только через `--body-file`; **`gh issue edit --body-file` ЗАМЕНЯЕТ тело целиком** («дописать» = `gh issue view --json body` → дописать в файл → edit целиком, либо комментарий; инцидент #239: затёрли спецификацию issue).
- **«Ок» владельца на UI-чекпоинте ≠ сигнал начинать бэкенд: сначала комментарий «UI freeze»** (#379, 26.10.2026): заморозка — не формальность, а точка, от которой проверяется инвариант «после freeze контракты и визуал не менялись» (`git diff --stat <freeze>..HEAD -- apps/web/src packages/contracts/src` должен быть пуст). Если комментарий не опубликован, а бэкенд-пакет начат, точку заморозки приходится восстанавливать задним числом по коммиту, который владелец смотрел, — аудит-трейл врёт, а ревьюер не может проверить контроль. Правило: «ок» → комментарий freeze → первая строка бэкенда; в #379 комментарий опубликован после B0 (диффом подтверждено, что контракты и визуал не менялись).
