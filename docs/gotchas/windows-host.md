# Хост разработки (Windows)

- **Git Bash (MSYS) конвертирует слэш-флаги Windows-инсталляторов в пути**: `setup.exe /S` доходит до процесса аргументом `S:/` (видно в CommandLine процесса) — тихая установка «зависает», потому что инсталлятор молча ждёт в интерактивном окне. Тишина MSI/NSIS из Git Bash — только `MSYS_NO_PATHCONV=1` перед командой (или `//S`); подтверждено воспроизведением 09.10.2026 (#263: NSIS-установщик висел с искажённым `S:/` в командной строке до убийства процесса).

- **`grep -rl` в Git Bash отдаёт пути с ОБРАТНЫМИ слэшами — циклы `for f in $(grep -rl …); grep -q паттерн "$f"` врут**: обратные слэши в переменной доезжают до grep как escape-последовательности, файл не находится → «нет вхождения» на файле, где оно есть (поймано дважды за одну сессию 10.10.2026: файлы с `tabular-nums` ложно «не покрыты»; воспроизведено подстановкой одного пути с `\` и с `/`). Канон: массовые проверки — только прямыми рекурсивными вызовами `grep -rl/-rL -e …` по каталогам (сами справляются с Windows-путями), без промежуточных циклов по списку файлов; единичный файл — `grep … "apps/web/src/…"` с прямым слэш-литералом в команде.

- **Инструмент `edit` — только после инструмента `read`**: вывод `Get-Content` в консоли Windows показывает UTF-8 файлы мозиброй cp866 (кириллица и эмодзи искажены); скопированный оттуда `oldString` не матчится с точными байтами файла — edit падает «not found». Механизм: консоль Windows рендерит вывод в OEM-кодовой странице локали (для русской — 866; подтверждено: Microsoft Learn, about_Character_Encoding — кодовые страницы консоли/ANSI, плюс воспроизведение в сессии issue #2). Тяжёлые правки кириллических файлов — `write` всего файла.

- EOL нормализованы `.gitattributes` (всё LF, кроме `*.bat`/`*.cmd`); sh-скрипты и хуки Husky — всегда LF, иначе ломаются в Linux-контейнерах с неочевидной ошибкой.
- **Vite dev-сервер на Windows может застрять на старой трансформации модуля после перезаписи файла** (watcher пропускает событие изменения): страница рендерит старый JSX без ошибок, полный reload не помогает. Дешёвое лечение БЕЗ перезапуска: тронуть mtime файла (`(Get-Item <путь>).LastWriteTime = Get-Date`) — watcher шлёт событие и трансформация протухает (подтверждено воспроизведением 14.09.2026: новый компонент был в графе модулей, но отсутствовал в трансформации импортера; после touch появился). Полное лечение — перезапуск dev-сервера. Симптом для диагностики: код в файле новый, а в DOM его нет (проверять `locator(...).textContent()` или computed-стили; отдачу модулей — curl'ом `/src/<путь>.tsx`). Долгоживущие серверы деградируют массово: 04.09 обе инстанции (5173/5174) отдавали код недельной давности — владелец не видел ни одной правки; прежде чем спорить с фидбеком, сверь DOM с репо и перезапусти сервер. Воспроизведено многократно в issue #4 (подтверждено воспроизведением).
- **Dev-сервер web — ОДИН общий инстанс на :5173** (канон #91): vite без `strictPort` при занятом порте ТИХО уходит на следующий порт (официальная документация vite: «if the port is already being used, Vite will automatically try the next available port») — владелец и агент оказываются на разных инстансах, каждый со своими stale-трансформами (инциденты 04.09 и 24.09: параллельные инстанции 5173/5174). В `apps/web/vite.config.ts` — `strictPort: true`: второй `pnpm dev` падает громко вместо тихого ответвления. Перед запуском сервера проверяй занятость порта (`netstat -ano | grep 5173`) и НЕ плоди второй инстанс: верификация, скриншоты и показ владельцу — на единственном живом :5173 (подтверждено документацией vite + воспроизведением 24.09.2026).
- **Inline-JSON в `curl.exe -d` из PowerShell ломается об экранирование** (`\"` остаётся литеральным → 400 от сервера): тело — из файла (`-d @file.json`) или `Invoke-RestMethod -Body ($obj | ConvertTo-Json)`; ложный «сервер вернул 400» стоил итерации в issue #3 (подтверждено воспроизведением).
- **`@swc/core` 1.16.x не грузится на этом хосте — интеграционные тесты api/gateway локально не стартуют** (`Failed to load native binding`, глубже в стеке — `ERR_SWC_NATIVE_CACHE: DACL grants replacement rights`): нативный аддон проверяет права каталога кэша И ВСЕХ его предков и отказывается, если хоть один даёт другим пользователям права замены; профиль пользователя хоста даёт их второй локальной учётке, корень `D:` — Authenticated Users, поэтому `SWC_NATIVE_BINDING_CACHE` на любой каталог хоста не помогает (воспроизведено 17.10 в #54). Лечение (#324): `@swc/core` запинен ТОЧНО на `1.15.47` (последняя 1.15.x, грузится на хосте) в `apps/api/package.json` — без `^` (иначе `pnpm update` поднимет 1.16) И правилом `ignore` в `.github/dependabot.yml` (иначе еженедельный PR поднимет пин, а зелёный Linux-CI его пропустит); снимать оба после стабильного 1.16.19+ (фикс Windows — swc-project/swc#12534) с проверкой `node -e "require('@swc/core')"` на этом хосте. **Это не только «не грузится»**: проверка 1.16 — защита от подмены `.node` другой учёткой, и она сработала по делу — каталоги проекта и worktree закрыты по runbook (`repo-bootstrap.md` §9, #337, 19.10), но пин остаётся: 1.16 проверяет кэш в профиле (`%LOCALAPPDATA%\swc`) и его предков, а профиль `C:\Users\klim9` открыт второй учётке на полный доступ — #360 (решение владельца). (подтверждено: swc-project/swc#12442 и сторонний разбор «framework starters on Windows» 10.10.2026 — 1.16.13/1.16.18 падают, 1.15.47 грузится — подтверждено и на этом хосте 17.10)
- `corepack enable` падает без прав на `Program Files` — pnpm ставится через `npm i -g pnpm@11`.
- winget определяет установленные версии по ARP-записям реестра (`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall`), а не по файлам: установка MSI поверх пакета другого семейства даёт косметический mis-id в `winget list`. Проверяй сами Uninstall-ключи; «призрачную» запись чисти удалением ключа (с export-бэкапом), НЕ `winget uninstall` — тот снесёт файлы актуальной версии по тому же пути.
- **Docker Desktop рвёт idle TCP к Redis на published-порту примерно через 40 с — ioredis получает ECONNRESET и переподключается** (#507, воспроизведено пробой 28.10.2026): голый клиент без трафика рвётся на 40.1/80.4/120.7 с простоя; `keepAlive: 10_000` в ioredis не спасает (хуже — разрывы каждые 20 с), а прикладной `PING` каждые 20 с держит соединение (130 с без единого события). В коде — `createRedisClient`/`watchRedisClient` (`apps/api/src/core/redis/redis-connection.ts`): heartbeat, имя в `CLIENT LIST`, ошибки — одной строкой на код не чаще 30 с (auth-ошибка не тонет в шторме переподключений); для соединений с блокирующими командами (`XREADGROUP`/`BZPOPMIN`) heartbeat выключается — PING встал бы за блокировкой.

- **Статус пайпа `A | B` — статус B**: `pnpm typecheck | tail -2 && pnpm test` продолжит цепочку после фейла (тесты гонялись зря); статус гейта — `cmd > log 2>&1; echo $?` или `set -o pipefail` (#269).
- **`powershell -Command "... $_ ..."` из Git Bash**: bash разворачивает `$_`/`$var` в СВОИ значения (PowerShell получает мусор) — экранировать `\$` во всех PS-переменных внутри двойных кавычек или выносить однострочник в temp .ps1.
- **`/tmp` Git Bash и нативного Windows-python/gh — РАЗНЫЕ пути** (MSYS-темп против `C:\tmp`): временный файл, который читают/пишут разные инструменты одной цепочки, — только абсолютный Windows-путь, никогда `/tmp` (репро #91: PATCH применил тело без исправления).
- **Дефолт `core.quotepath=true` показывает кириллические пути октальными эскейпами в кавычках** — данные целы, только отображение: `git config core.quotepath false`; диагностику «битой кириллицы» начинать с байтов (`git log | cat -A`), не с перекодировок.
- **push/pull «git: 'remote-https' is not a git command»** — в PATH первым стоит ucrt64-git без libexec/git-core-хелперов (на хосте два git): префикс `PATH="/c/Program Files/Git/mingw64/libexec/git-core:$PATH"` или переустановка Git поверх (`winget install --force Git.Git`).
- **`git mv` каталога под живым dev-сервером — Permission denied** (vite/chokidar держит handle на каталоге; удаление отдельных файлов при этом работает): обход — `cp -r` в новый каталог → правки импортов → `rm -rf` старого → `git add -A`.
- **Софт на хост владельца — только winget (`--force` при перезаписи) или штатные мастера**: самописные PS-скрипты «скачай+тихо поставь» AV карантинит по паттерну дроппера.
