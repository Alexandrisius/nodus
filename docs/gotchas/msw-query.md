# Моки MSW и TanStack Query (линия A, #87)

- **Мок-стор MSW (demoMessages/demoPins из `shared/mocks/data`) — состояние модуля В БРАУЗЕРЕ: полный reload страницы (page.goto) его сбрасывает**, созданные мутациями сущности (отправленные/пересланные сообщения) живут только внутри SPA-сессии. В Playwright-проверках переход к результату мутации — кликами внутри SPA, НЕ goto (воспроизведено 24.09.2026: «исчезнувшие» копии пересылки после goto).
- **TanStack Query v5 читает mutationFn из опций ПОСЛЕДНЕГО рендера в момент исполнения**: если инициатор мутации опустошает замыкание сразу после mutate() (диалог закрылся → request=null → ре-рендер), запрос уходит с пустыми параметрами (`DELETE /conversations//messages/…` → 404). Id мутаций, запускаемых из закрывающихся диалогов, передавать В ПЕРЕМЕННЫХ мутации, не замыканием хука (воспроизведено 24.09.2026).
- **zustand persist с partialize: не-perсистятся поля отсутствуют после rehydrate** — нормализовать в merge (иначе компоненты падают на undefined: chat-drafts.attachments после F5, белый экран; найдено скриншот-прогоном 24.09.2026).

- **MSW матчит хендлеры ПО ПОРЯДКУ массива, специфичность пути не учитывается**: старый дубль маршрута в другом файле затеняет новый хендлер (typecheck не ловит), а после чистки дубля параметрический `:id` ест буквальный путь (NOT_FOUND) — буквальные пути регистрировать ПЕРЕД агрегатами с `:id`; при переезде маршрута grep всех хендлеров того же пути (#378). Пример переезда #428: `/tasks/types` → `/workflows/types` рядом с `/workflows/:id` — буквальный `types` объявлен выше параметрического `:id` в том же файле (`automation-handlers.ts`).

- **`setQueriesData<ListPage>` по списку на `useInfiniteQuery` падает в `onMutate` ДО запроса** (#460, 25.10.2026): кэш страниц — `InfiniteData` (`{pages, pageParams}`), обращение к `data.items` бросает TypeError, мутация умирает в оптимистичном апдейте и наружу уходит общий тост «Не удалось отправить», а сетевого запроса нет вовсе (диагноз по отсутствию запроса в Network). Канон: патч списков — через `pages[].items` и ключи фабрики (`keys.all + 'pages'` / `'options'`), а не типом одиночной страницы; регресс-тест обязан проверять и форму кэша, и факт отправки (`expect(fetchMock).toHaveBeenCalledTimes(1)`).
- **Моки домена + живой справочник: связь по id не совпадает** (#460): демо-письма/проекты ссылаются на мок-id контрагента, а карточка открыта по живому id — фильтр `?counterpartyId=`/`?clientId=` возвращал пусто. Сопоставление вынесено в `shared/mocks/live-counterparty.ts` (совпадение по id ИЛИ названию, живая карточка — через `bypass()` с авторизацией исходного запроса). Правило: мок-связь через живую сущность сопоставляется по стабильному человекочитаемому ключу, и только в моках — в продукте связь строго по id.
