# Изоляция песочницы и инструменты ночного прогона (#100, 01.10.2026)

- **Песочница подписывала токены ПРОД-секретом** (security-ревью #247, подтверждено 17.10 сравнением sha256 `JWT_SECRET` `.env` и прод-api): live-stack передавал api/gateway весь корневой `.env`, а access-JWT stateless — права из payload, в БД гвард не ходит. Итог: токен песочницы (night-a/b, пароль в публичном репо, роль employee) принимался продом. Теперь у песочницы свои секреты (`.live-stack/secrets.json`), известные пароли сеются только в `nodus_night`. Урок: изоляция контура = БД + Redis + бакет + **секреты подписи**; при любом новом контуре сверять все четыре.
- **Сиды сред обязаны совпадать — иначе CI-баг невоспроизводим локально** (#247, репро 07.10 на PR #246): CI-e2e входил под `admin@nodus.by`/`a.klimovich@…` (пароли из env CI), песочница жила со своими night-a/night-b — штатный спек против песочницы не логинился, понадобилась одноразовая проба. Теперь единый источник `tests/e2e/e2e-users.json` читают спеки (`tests/e2e/e2e-users.ts`), CI-сид и сид песочницы (`live-stack` бутстрап, только на `nodus_night`); новый тестовый пользователь/пароль — только там.
- **Интеграционные тесты с корневым `.env` = прод-Redis** (до #332, воспроизведено 17.10: `XINFO STREAM nodus:domain:events` в db0 рос от прогона gateway-набора): `vitest.integration.config.ts` грузит корневой `.env`, PG тесты сами уводят в `nodus_test`, а `REDIS_URL` шёл как есть — XADD в боевой стрим (его читает прод-gateway) и общие очереди BullMQ с прод-api. Теперь конфиг переписывает db на 15 (`@nodus/config/test-env`), хелперы БД падают при чужом db; проверка изоляции — `last-generated-id` стрима в db0 до/после прогона не меняется.
- **Флейки CI — три класса, все с одним корнем «тест обогнал фон»** (#358, 19.10; канон: CI красный только от настоящей ошибки). (1) **Поллер с флагом-замком отвечает no-op** — `RedisStreamPublisher.publishPending` возвращался сразу, пока фоновый тик держал `publishing`, и ручной прогон теста «проскакивал» свежие события (`expected null not to be null`); теперь как у диспетчера (#212): ручной вызов ЖДЁТ чужой проход и делает свой, а фоновый тик при живом проходе — ПРОПУСК (`if (!this.pass)`), не очередь: иначе при зависшем Redis копятся тысячи ожидающих тиков. Любой новый поллер с ручным входом — «фоновый тик skip, ручной вход wait», не `if (busy) return` для обоих. (2) **Фиксированное число раундов конвейера** — «два раунда диспетчер+издатель» ломались, когда хвост чужих событий в батче отодвигал событие второго порядка; гонять ДО ТИШИНЫ outbox (`publishedAt`/`fanoutAt` IS NULL = 0) с потолком раундов. (3) **Fire-and-forget `import()` в продуктовом коде** — ленивый импорт, запущенный тестом, доезжал после teardown окружения vitest (`EnvironmentTeardownError` валил весь прогон web, main 17.10); развязывать модули без ленивого импорта (реестр-модуль без зависимостей, как `shared/desktop/shell-hidden.ts`).
- **Фейк `FileStorage`, не читающий поток, оставляет `ReadStream` с асинхронным `open` после теста** (#537, воспроизведено в CI 29.10; подтверждено Node fs docs + nodejs/node#18274): `fs.createReadStream` открывает путь не синхронно (`'open'` эмитится позже, `autoClose` закрывает fd по error/end), а `rm` временного `mkdtemp`-каталога в `finally` может обогнать открытие — поздний `ENOENT` на `.eml` приходит unhandled и валит уже зелёный прогон (Vitest: unhandled errors влияют на результат, `onUnhandledError`). Канон: фейк порта обязан дренировать `content` (`for await`), как реальный `putObject` (`office-callback.service.test.ts`); непрочитанный стрим временного файла — не «безвредный мусор».
- **Динамический `import()` в теле jsdom-теста платит Vite-transform внутри бюджета `testTimeout`** (#533, замер 30.10; подтверждено Vitest docs: `testTimeout` default `5_000`, `vi.mock` хоистится): изолированный `notification-reader` — 2,95 с из 5 с (transform 1,49 с + import 0,37 с — внутри `it`), под параллельным `turbo test` (api+web+contracts одновременно) — `Test timed out in 5000ms`; после перевода на статические импорты тело теста — 0,18 с. Канон: модули в тесте импортируются статически (`vi.mock` всё равно хоистится), в `apps/web/vite.config.ts` — `testTimeout: 15_000` как потолок холодного старта компонентных тестов.
- **Два EventDispatcher'а на одной БД воруют события друг у друга** (прод-контейнер api + live-stack api на общем DATABASE_URL): pending-хвост `events` разбирает кто первый — событие помечается published у процесса, у которого НЕТ хендлера (event_deliveries пуст, уведомления не создаются). Песочница ветки обязана жить на изолированной БД и Redis-db (`docker exec nodus_postgres psql -c CREATE DATABASE nodus_night`, `migrate deploy` туда, `REDIS_URL …/1`) — воспроизведено 01.10.2026 (deliveries=0 при зелёных integration-тестах).
- **live-stack.mjs: env-файл ПЕРЕКРЫВАЛ process.env** (`{...process.env, ...loadDotEnv()}`) — экспортированные переменные окружения (изолированные DATABASE_URL/REDIS_URL, NOTIFY_URGENT_* для e2e) молча терялись. Порядок обращён: env процесса главнее файла (01.10.2026, #100).
- **Прямое общение с живым API — python/файлами, не curl в git-bash: кириллица в `-d` уезжает в cp1251** (упоминание `@Борис` не матчилось). Скрипты проб — `python` c `json.dumps(...).encode('utf-8')` (01.10.2026).
- **`vite build` без `VITE_API_MOCK=false` — мок-сборка** (MSW включён по умолчанию): сокет не поднимается, «живая» проба тихо мокается. Ручная пересборка под live-проверку — всегда с явным env (канон turbo-кэша, повторено 01.10.2026). **Класс закрыт 04.10: `vite.config.ts` вшивает `VITE_API_MOCK='false'` в ЛЮБОЙ build (моки — только dev-сервер `command==='serve'`)** — гейт-сборка больше не может заразить превью.
- **`pnpm build` (турбо-гейт) ПОСЛЕ `live-stack up` перетирал non-mock dist превью** — до фикса vite-конфига (см. строку выше) на :4173 стартовал MSW, его service worker на origin перехватывал запросы — GET проходили насквозь, а мутации (DELETE/PATCH) съедались ДО сети: в api.log только GET/POST, у клиента тост «Не удалось сохранить изменение», после F5 всё возвращается (инцидент #171 04.10; подтверждено api.log владельца + обёрткой window.fetch). Канон остаётся: `live-stack up` — ПОСЛЕДНИЙ билд ветки (после гейтов — переподнять); non-mock сборка сама снимает рег SW (main.tsx unregister), вкладку — Ctrl+Shift+R. (воспроизведением, 04.10.2026, #171)

- **Префикс queryKey в getQueriesData накрывает СОСЕДНИЕ запросы другой формы** (#171, 04.10, «страшный баг» владельца): `favoriteKeys.all` — префикс и списка (страницы `{pages}`), и labels (`{items}`); `patchCard/removeCard` делали `data.pages.map` → у labels `.pages` нет → TypeError В onMutate → мутация умирала ДО сети (тост «не удалось сохранить изменение», сервер не тронут, после F5 всё на месте — воспринималось как плавающий баг: срабатывало только при закэшированном labels-запросе). Канон: патчи кэша по префиксу фильтруют по форме данных (`Array.isArray(data.pages)`), регрессионный тест обязателен. (воспроизведением живой пробой + юнит-тест, 04.10.2026)

- **Рестарт documentserver запускает `allthemesgen` = 100% CPU на ~2–4 мин**: свежий DS не собирает сохранения (sfc-колбэки молча не идут); симптом маскируется под «memory runtime detected — embedded converter» (это штатный режим DS 9.4, исходник `FileConverter/sources/convertermaster.js`). - **DS-редактор теряет незакрытый ввод ячейки при destroyEditor**: печать в cell открывает inline-редактор; без Enter (commit) закрытие модалки выбрасывает правку — DS считает документ неизменённым (status 4, версии нет). - **`docker exec` БЕЗ `-i` молча не читает stdin** — heredoc-скрипт «выполняется» без единого эффекта и без ошибок; только `docker exec -i`. - **Локальные интеграционные тесты api не стартуют без тестовой S3-учётки** (#520, воспроизведено 28.10): в корневом `.env` `STORAGE_TEST_*` пусты, а сервисная учётка `nodus-api` имеет доступ только к `nodus-files` — `MinioStorageDriver.onModuleInit` падает на `bucketExists('nodus-test-files')` с `S3Error: Valid and authorized credentials required` до первого теста.
