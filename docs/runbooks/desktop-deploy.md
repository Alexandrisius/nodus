# Runbook: выпуск и развёртывание десктоп-оболочки Nodus

Аудитория: системный администратор компании (и агент, выпускающий сборки).
Оболочка — тонкий клиент портала (ADR-0019, issue #254): обновление контента
происходит деплоем сервера; этот runbook — про установщики и обновления САМОЙ
оболочки (редко) и про первое развёртывание на машинах сотрудников.

## Модель обновлений (что обновляется как)

| Что | Как обновляется | Участие сисадмина |
|---|---|---|
| Функциональность портала (~99% изменений) | Деплой сервера (`docker compose up`) — все клиенты получают при следующем запуске | деплой сервера |
| Сама оболочка (окно/трей/попапы) | Автообновление с сервера портала: тихо качает подписанный установщик из `/desktop/` и ставит | выложить артефакты в `NODUS_DESKTOP_DIR` |
| Принудительная замена устаревших оболочек | `NODUS_MIN_SHELL_VERSION` на сервере: оболочка ниже минимума показывает экран «обновите приложение» и не пускает к порталу | поднять env при ломающем релизе |

## Первый выпуск: ключи подписи (однократно)

1. Пара minisign-ключей уже создана агентом: приватный —
   `C:\Users\<агент>\.nodus\desktop-updater.key` на машине сборки (вне репо!),
   публичный зашит в `apps/desktop/src-tauri/tauri.conf.json`
   (`plugins.updater.pubkey`).
2. **Владельцу:** добавить GitHub-секрет `TAURI_SIGNING_PRIVATE_KEY` —
   содержимое файла приватного ключа (и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`
   пустым, ключ без пароля). Настройки репозитория → Secrets and variables →
   Actions. Без секрета CI собирает установщики без updater-артефактов.
3. Потеря приватного ключа = автообновления мертвы (выпуск новой сборки с новым
   ключом и ручная переустановка на машинах). Хранить в менеджере секретов.

## Выпуск сборки

1. Версия оболочки: `apps/desktop/src-tauri/tauri.conf.json` → `version`
   (semver; мажор — ломающие изменения моста, минор — функции, патч — фиксы).
2. Коммит в `main` с изменениями `apps/desktop/**` → CI (`workflow desktop`)
   собирает на windows-runner NSIS `-setup.exe` + MSI. Ручной запуск —
   Actions → desktop → Run workflow.
3. Релиз с артефактами: тег `desktop-v<версия>` (например `desktop-v1.1.0`) →
   job `release` публикует установщики + `.sig` + `latest.json` в GitHub
   Release. Артефакты забирать оттуда.
4. Выложить на сервер портала (в `NODUS_DESKTOP_DIR`, см. ниже) файлы:
   `Nodus_<версия>_x64-setup.exe`, `Nodus_<версия>_x64-setup.exe.sig` (та же
   базовая часть имени!) и `latest.json`. Установщик кладите под ИМЕНЕМ,
   указанным в `latest.json` (поле `platforms.windows-x86_64.signature`
   ссылается на `.sig`; URL манифеста — относительные пути от `/desktop/`).
5. Проверка: `curl https://<портал>/desktop/latest.json` — отдаёт манифест;
   запущенная оболочка в трее → «Проверить обновления» — обновляется тихо.

## Настройка сервера портала

`.env` (или переменные окружения compose):

```env
# Имя сервера на экране подключения оболочки
NODUS_SERVER_NAME=Название компании
# Минимальная версия оболочки (semver); 0.0.0 — без ограничения
NODUS_MIN_SHELL_VERSION=0.0.0
# Каталог артефактов оболочки (absolute путь на хосте)
NODUS_DESKTOP_DIR=/srv/nodus/desktop
```

nginx web-контейнера отдаёт каталог как `/desktop/` (без кэша). Изменение env
требует `docker compose up -d web api` (api отдаёт `/api/v1/desktop/config`).

## Установка сотрудникам

- **Самостоятельно:** передать `Nodus_<версия>_x64-setup.exe` — обычный
  установщик (per-user, без прав администратора). Первый запуск: экран
  «Адрес портала» → ввести адрес → вход. Далее — автозапуск опционально
  (трей → «Запускать при входе в Windows»).
- **Корпоративная раскатка (адрес не вводят):** MSI из релиза — в GPO-папку
  (perMachine, тихая установка `msiexec /i Nodus.msi /quiet`), адрес портала
  зашивается build-аргументом при сборке: env `NODUS_PORTAL_URL` на шаге
  `tauri build` (например `https://portal.company.local`). Для зашитой сборки
  закажите её у агента с этим аргументом.
- Windows 10 без WebView2: установщик докачивает bootstrapper сам; для
  изолированной сети положите offline-распространяемый пакет WebView2 рядом
  (докатка вручную).

## Поддержка

- Логи оболочки: `%APPDATA%\by.nodus.desktop\logs\nodus-desktop.log`
  (ротация 8 МБ). Адрес портала: `%APPDATA%\by.nodus.desktop\portal.json`.
- «Нет связи с сервером» на экране подключения — проверьте адрес/сеть;
  кнопка «Повторить» ходит в `GET /api/v1/desktop/config`.
- Смена сервера: трей → «Сменить сервер…» (перезапуск оболочки на экран
  подключения; для зашитых сборок адрес фиксирован политикой сборки).
- Антивирус на рабочих станциях может эвристически ругаться на неподписанный
  установщик: добавьте исключение/дождитесь подписи внутренним CA (ТЗ §13).
