# Runbook: обновление прода (docker-контур nodus.by)

**Цель:** выкатить выпуск `vX.Y.Z` с `main` на прод-контур этого хоста
(контейнеры `nodus_*`, `:3000/:3001/:3002`, туннель `nodus.by`) так, чтобы
пользователи получили новую версию и окно «Что нового».

Полный цикл выпуска (сбор изменений, тексты, релизный PR, тег, GitHub
Release) — навык `nodus-release`; этот runbook — шаги выкатки, смок и откат.
Будущий прод в компании обновляется так же: по тегу из чистого дерева.

**Предусловия:**

- выпуск смержен в `main`, тег `vX.Y.Z` создан и запушен;
- рабочее дерево чистое (`git status` пуст): прод собирается ИЗ рабочего
  дерева этого каталога — незакоммиченное уедет на прод;
- `.env` заполнен, `NODUS_WEB_MOCK=false` (боевой режим web — build-arg,
  gotchas «VITE_* — build-time»).

## Шаги

1. Встать на выпуск:
   ```bash
   git switch main && git pull --ff-only
   git describe --tags --exact-match   # → vX.Y.Z, иначе стоп
   ```
2. Пересобрать и перезапустить (только изменённые сервисы пересоздаются;
   данные в томах `nodus_*data` не трогаются):
   ```bash
   docker compose --profile tunnel up -d --build
   ```
   Миграции БД применяет api при старте (`prisma migrate deploy` в CMD
   образа) — отдельной команды нет. Сборка web+api+gateway — несколько минут.
3. Дождаться здоровья: `docker ps --filter name=nodus_` — web/api/gateway
   `healthy` (api после миграций — до ~1 мин).

## Смок (только чтение — создавать данные и гонять пробы на проде запрещено)

```bash
curl -fsS http://localhost:3001/api/v1/health          # api жив, JSON 200
curl -fsS -o /dev/null -w "%{http_code}\n" https://nodus.by/   # 200 через туннель
docker exec nodus_web sh -c "grep -l '\"X.Y.Z\"' /usr/share/nginx/html/assets/*.js" \
  | head -1                                             # бандл несёт новый выпуск
docker logs --since 5m nodus_api 2>&1 | grep -iE "error|migrat" | tail -20
```

Последняя команда — только у выпусков с текстами «Что нового» (технический
выпуск JSON не добавляет). Логи api: применённые миграции и отсутствие
ошибок старта.

## Откат

Выпуск сломал прод (контейнер не healthy, смок красный):

1. `git switch --detach v<предыдущий>` → `docker compose --profile tunnel up -d --build`.
2. **Миграции назад не откатываются** (только вперёд, навык
   `prisma-migrations`): expand-миграции (новые таблицы/колонки) старому коду
   не мешают; если выпуск содержал contract-изменение (drop/rename) — откат
   кода невозможен без восстановления БД, STOP & ASK владельца.
3. Вернуть дерево: `git switch main`. Доклад владельцу + issue `type:bug` с
   механизмом; тег сломанного выпуска не удаляется (история), исправление
   выходит следующим патчем.
