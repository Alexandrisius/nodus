# docs/mvp — рабочая зона треков: карта

Единый живой план — `process-model-plan-2026-10-25.md`. Стратегия и бизнес-кейсы — `docs/product/roadmap.md`. Этот файл — карта зоны и её правила, ещё один план он не создаёт.

## Что где

| Что | Роль |
|---|---|
| `process-model-plan-2026-10-25.md` | **Единый план декабря**: решения и целевая модель (§1–§5), нарезка issues с зависимостями и оценками (§6), календарь и порядок потоков (§7), журнал исполнения — что сделано и что в хвосте (§9, дополняется каждым закрытым треком) |
| `process-map.md` | Карта ядра управления проектированием (процесс А: письмо → поручение) |
| `plans/` | Локальные черновики планов задач; в git не попадают (`.git/info/exclude`), исполнитель чистит при закрытии issue |
| `archive/` | Отработанные планы и промпты сессий — история «как решили», не канон; индекс — `archive/README.md` |

## Агенту: как понять «что делать дальше»

1. `docs/product/roadmap.md` — какой бизнес-кейс и фаза, что вне сроков.
2. План §7 — порядок и календарь; §6.2 — зависимости и оценка задачи (коды треков: К — корреспонденция, П — процессы, З — задачи, Пр — проекты, О — оргструктура, Р — ресурсы, Э — эксплуатация).
3. §9 «Журнал исполнения» — что уже сделано.
4. Текущее состояние — issues (`gh issue list`); детальный план задачи — комментарием в issue при взятии, не отдельным файлом.

## Правила зоны

- Новых «планов трека» и «промптов сессий» в корне не создаём: план один. Выводы сессий и находки — в план (§2, §9), ADR, инкубатор или комментарий issue.
- Документ отработал (решения в каноне, трек закрыт) → тем же PR в `archive/` + строка в `archive/README.md`.
- Зона временная: после MVP (20.12.2026) сворачивается целиком — канон живёт в `docs/` и ADR.
