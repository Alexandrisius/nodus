# Карта ядра: единая модель управления проектированием (v1.2)

Источники: интервью (Вашуров, Кураленя, Левчук) · обсуждение с владельцем (`project-model-discussion-report-2026-10.md`) · независимые анализы (инкубатор, раунды 1–7) · ISO 19650 (UK BIM) · практики СНГ: КОРУС (провал внедрения), ГОСТ 21.1002/21.101, СП 246.1325800 (авторский надзор), BIM-стандарт ds.do, Положение №1476 РБ, Положение о параллельном проектировании и стройке РБ · шесть волн критики субагентов (ГИП, главспец, документооборот, стройка/надзор, BIM-координатор, директор-параллельщик).

**Проектный принцип (владелец):** интервью — жалобы на текущее, не требования. Ядро делает так, чтобы болей не возникало: статусы собираются сами, след дешевле обхода, видимость = готовность, поиск по структуре. Отбор правок: **обобщаем механизм, а не добавляем сущность под кейс**; базовая формула неизменна с v1 — меняются только обобщения.

**Формула (не менялась с v1): работа производит документы. Документы ходят по конвейеру выдачи. Выдача порождает следующую работу. Всё живёт в дереве проекта. Снаружи — письма.**

Роли: Руководство · ГИП · Главспец · Инженер · Нормоконтроль · Сметчики/смежники · Канцелярия/помощник · Стройка/надзор (внешние) · Заказчик (внешний).

## 0. Ядро

### Понятия (8)

| Понятие | Что это |
|---|---|
| **Проект** | объект + договор + ранг портфеля |
| **Узел** | дерево: стадия/очередь/раздел/комплект; структурная задача (чат, срок, ответственный, время детей вверх). Узел может нести **строительный контекст**: снапшот «построено/утверждено к производству по ревизиям {…}» + свои события (экспертиза, начало работ) — якорь для «изм. бьёт по построенному». Дерево создаётся когда угодно |
| **Работа** | задача с типом (Обычная/Разработка/Задание/Изменение/**Проверка**/…): маршрут, DoR/DoD, подзадачи, время. Нарезка: кусок = работа, если у него свой файл/выдача/получатели. Работа «Проверка» — контейнер визита надзора |
| **Документ** | единица информации; три рода: **простой** (шифр СПДС — сущность ревизий), **сборка** (манифест «документ×ревизия» + файлы: сводная координационная модель, IFC наружу; ревизия сборки = снапшот состава), **плоский** (акты, протоколы — без конвейера; **журнал** — append-строки без смены ревизии: лист согласования замен). Ревизия принадлежит документу; узел — агрегатор (датированная связь, дробление историю не рвёт); узел-владелец + узлы-потребители |
| **Передача** | заголовок (задание/письмо/накладная) + строки «документ × ревизия × кол-во экз. × взамен №». Подтверждение строки = **распорядок получателя**: принято / **изъято по взамен** (для бумажных) / оспорено / отложено — с основанием; оспорено = событие для ГИПа (спор). Событие внешней судьбы = фиксация **доказательства** (скан накладной/акта) или явный разрыв |
| **Обращение** | единая лёгкая сущность вместо «замечания»: **вопрос** (стройка→проектировщик, срок ответа) / **замечание** (смежник/заказчик на ревизию) / **нарушение** (надзор→стройка, срок устранения). Цели — одна или несколько «ревизия × внешний якорь (элемент модели, opaque id)». Закрывающее основание типизировано классом: **документное** (новая ревизия закрывает) или **надзорное** (фактическая проверка/визит — письмом не закрывается). Группировки: ревизией (свод ответа экспертизе) или визитом (журнал надзора — рендер) |
| **Порядок** | правила-строки «когда X → создать черновик работы Y»; без дат. «Пора» = вычисляется |
| **Веха** | точечное обещание/ожидание: дата + предмет (документ/позиция/этап) + получатель; статус автоматический из событий (выполнено/сломано/ждём). Здесь живут «обещал заказчику ОВ до пятницы» и «стройка ждёт документацию к разбивке» — единственное осмысленное место дат |

Письмо — внешний контур (вход изменений, выход передач), описан в процессе А.

### Конвейер документа (не менялся идейно; дополнен)

```
В РАБОТЕ (WIP)  — у инженера (у модели — коллективный, worksharing); правки свободны
   ▼  главспец проверил
ВЫДАНО ВНУТРИ (Shared) — рабочие ревизии (номер автоматом) + назначение
   │   («Предварительно», «Для координации»…); циклы: обращения → работа → новая ревизия;
   │   часть документов — вечно здесь (обрубки, модели координации)
   ▼  основание-ссылка (письмо/обращение/предписание/ТУ) → работа «Изменение» →
      DoD: чек-лист ВЛИЯНИЯ (конструкции/объёмы/стоимость/безопасность — справочник) →
      повторный нормоконтроль → регистрация изм.N → печать
ВЫПУЩЕНО ОФИЦИАЛЬНО (Published) — причина = ссылка; promotion из рабочей той же
   │   редакции без контент-дельты уведомлений не шлёт; чек-лист влияния «да» →
   │   черновики «повторная экспертиза» / «уведомить стройку» (+ блок выпуска до решения)
   ▼  события судьбы на передачах (доказательство!): доставлено → принято →
      согласовано → утверждено к производству; заключение экспертизы = событие
      со снимком покрытых ревизий (новое изм. на покрытом → «заключение под пересмотром»)
ЗАМЕНЕНО / АННУЛИРОВАНО — история вечна
```

**Инвалидация зависимых (обобщение уведомлений):** у каждой ревизии — связи «основано на» (по каким ревизиям смежников сделана; автоподстановка из последнего принятого распорядка). Новая ревизия X → всё, основанное на старой X (работы, задания, обращения, сборки), помечается **«требует перепроверки»** + черновик перепроверки адресно. Не спам «данные изменились», а адресная инвалидация. Diff-строка обязательна; для моделей — описание автора + приложенный артефакт сравнения (Copy/Monitor, отчёт клэшей).

**Ввод следа дешевле обхода:** файл в чате получателям комплекта = видимый «неоформленный» + 1 клик «Выдать» (значения из правила). Текст-ответ стройке на вопрос = обращение-вопрос (1 действие из чата); накопленные ответы — рендер «лист вопросов-ответов».

### Порядок = правила (4 семейства + инвалидация; действие всегда — черновик)

```
1. ДОКУМЕНТ ВЫДАН:      «ОВ1.1 "Предварительно" → черновик задания сметчикам»
2. РАБОТА/УЗЕЛ ЗАКРЫТ:  «разработка закрыта → черновик нормоконтроля»;
                        «работы комплекта закрыты → черновик выдачи заданий»
3. ОЖИДАНИЕ (ритм/срок): «каждую пятницу АР выдаёт ревизию "Для координации"»
                        (не выдал в цикл = разрыв данных в пульсе);
                        «веха <30 дней → нет утверждённых комплектов → строка пульса»;
                        «предписание/извещение стройки → черновик визита»
4. ИНВАЛИДАЦИЯ:         «новая ревизия X → основанное на старой X требует перепроверки»;
                        «изм.N на документе из снимка построенного → черновик
                         "Влияние на построенное" (ответственный — ГИП этапа)»
```

### Инварианты (10, обновлены)

1. Содержимое ревизии иммутабельно; **иммутабельна запись** (метаданные/связи/события — навсегда), носители старше N месяцев уходят в холодный слой, лёгкое представление остаётся.
2. изм.N — нормоконтроль, по основанию-ссылке, после чек-листа влияния и повторного НК; рабочие — автоматом.
3. Каждый переход/передача пишут кто/когда/кому автоматически; событие внешней судьбы = доказательство или явный разрыв.
4. Подтверждение = распорядок получателя (принято/изъято/оспорено/отложено); оспорено — видимый спор.
5. Работа не закрывается с открытыми подзадачами; дети живут в сроке работы.
6. Черновик невидим исполнителям до DoR; «пора» — из порядка, сортировка по рангу.
7. Деньги — по позициям штампа; состояние позиции (продано → выдано (авто из официальных ревизий) → акт → счёт → оплачено) — событиями; смета несёт снимок «считали по ревизии X».
8. Порядок без дат; даты живут только в вехах и точечных дедлайнах обращений.
9. Обычные задачи — вне дерева и конвейера.
10. Закрытие работы ≤3 обязательных полей; часы — таймер/дневной раскид; результат автособирается; обращение надзорного класса письмом не закрывается.

## 1. Процесс А: письмо → затреканная работа — без изменений против v1.1 (регистрация ≤30с; матрёшки — карточки без рег.№ + связи + сквозной поиск; резолюция → 1..N работ; стучалки открытых дат; Revision итогов; «исполнено» = все поручения закрыты; исходящее с документацией = передача). Дополнение: предписание госоргана закрывается не выдачей ревизии, а событием судьбы «подтверждено устранение» (доказательство/повторная проверка).

## 2. Процесс Б: спайн — как в v1.1 (портфель-ранги → штамп → дерево когда угодно → работы → конвейер → правила → пульс над событиями; разрывы явные). Дополнение: портфельный пульс содержит колонки вех/обещаний («сломанные обещания недели»), влияний на построенное и финансовую колонку «выдано/выставлено».

## 3. Проверка на живых кейсах (дополнена; все старые — без изменений)

| Кейс | Проход через ядро |
|---|---|
| Стройка с изм.3, вышло изм.5 | передача изм.5 со строками «взамен изм.3»; распорядок получателя «принято + изъято»; неизъятое — видимый разрыв |
| Залили колонны не по проекту | обращение-нарушение (надзорный класс) → работа «Изменение»/согласование отклонения → изм.N → передача на стройку → закрытие фактической проверкой (визит) |
| Замена утеплителя | лист согласования замен = журнал-документ (append) + при затрагивании — работа «Изменение» |
| Ось передвинули, смежники против | уведомление + связи «основано на» → у каждого «требует перепроверки»; распорядок «оспорено» → спор у ГИПа (веха решения — опция) |
| Сводная модель по пятницам | сборка-документ; правило-ритм; невыдача = разрыв; IFC заказчику = передача ревизии сборки |
| Короб сквозь балку | обращение с двумя целями (ОВ r5 × КР r3, якоря-элементы), владелец, закрытие перепроверкой |
| Задания на отверстия | работы «Задание» с DoD-чекпойнтами согласований АР/КР/ИНЖ раздельно; инвалидация при изменении носителя |
| Этап 1 строится, этап 2 проектируется | строительный контекст узла (снимок построенного); изм. этапа 2 из снимка этапа 1 → черновик «Влияние на построенное» |
| «Обещал ОВ до пятницы» | веха-обязательство; статус авто из событий; «сломанные обещания» — колонка портфельного пульса |
| Предписание Госстройнадзора | письмо → работы; закрытие предписания = событие судьбы «подтверждено устранение» с доказательством |
| Порог повторной экспертизы | чек-лист влияния на DoD «Изменения» ДО регистрации; «да» → черновики + блок; заключение экспертизы = событие со снимком покрытия |

## 5. Вопросы

**Продуктовые (владельцу):** терминология конвейера и назначений; шифр/учёт у сводных моделей и IFC (сборка без шифра или позиция штампа?); глубина финансов (до «выдано» или до оплаты); плоские документы и журналы — подтверждить классификацию; подтверждение внутренних выдач — от кого обязательно; правила руками или авто в первой поставке.

**Для интервью с руководством (через владельца):**
1. Кто и с какой гранулярностью фиксирует «этап начат / утверждено к производству» — прораб заказчика, наш ГИП, бумага? (источник правды для «изм. бьёт по построенному»)
2. Чек-лист влияния перед каждым изм.N (+30 секунд) — приемлемо? Если нет — пороги повторной экспертизы остаются в голове.
3. Арбитраж споров смежников (ось сдвинута, ОВ против): кто решает и есть ли окно «молчание = согласие»?
4. Деньги: акты по договорным этапам или по позициям штампа? Где сегодня живёт «выставлено/оплачено»?
5. Изъятие бумаг на объекте: наша процедура (двусторонняя строка) или только напоминание? Кто отвечает за действующую бумагу на стройке?
6. Обещания заказчику: кто их фиксирует сегодня и должен ли Nodus показывать «сломанные обещания недели» руководству?
7. Задания на отверстия: как оформлены сейчас, кто ведёт согласования АР/КР/ИНЖ, есть ли ведомость отверстий как документ?
