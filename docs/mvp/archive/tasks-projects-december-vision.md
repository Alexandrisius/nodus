# Модуль задач и проектов Nodus — декабрьское видение (канон цели M4)

- **Статус:** канон ЦЕЛИ эпика M4 (#49). Принят владельцем 16.10.2026 вместе с планом из трёх ступеней (§«Ступени»). Источник — обсуждение 09–10.10 (`project-model-discussion-report-2026-10.md`), замороженное ядро `core-project-flow/core.md`.
- **Читать:** любому агенту перед работой над задачами, проектами, «Моим планом», поручениями из писем. Детальные спеки — в issues ступеней (#37, #252, #52); этот документ — куда идём и почему, не «как кодить».

## Суть одной фразой

Замена битриксовой свалки задач на **проект с деревом комплектов, работы с типами и одной личной очередью каждого сотрудника**, где система сама знает, чему «пора», кто от кого зависит и что изменилось — а документами остаётся файловый сервер (мы даём ссылку, версии не ведём).

**Задача без проекта — обычный случай** («Принести справку», «Сделать отчёт о загрузке»): модуль задач самостоятелен, проект в нём — необязательная привязка. Проект живёт и без дерева; работы перекрепляются в дерево потом.

## Четыре этажа

```
РУКОВОДСТВО: рейтинг проектов («что горит сильнее») — один список на всех
    ↓
ПРОЕКТ: дерево → Раздел ОВ → Комплект ОВ1.1 (структурная задача:
    ответственный-главспец, чат, срок; часы детей суммируются в неё;
    в личные планы исполнителей НЕ попадает)
    ↓
РАБОТЫ с типами: Разработка / Задание / Изменение / Проверка / Обычная
    (исполнитель, маршрут статусов, чат, подзадачи в сроке, часы,
    ссылка на файл-результат на сервере)
    ↓
ПОРЯДОК: правила «когда X → создать задание Y» (в декабре — кнопкой)
```

## Экраны (шесть)

1. **«Мой план»** — утро любого сотрудника: одна очередь из «пора» (правила сработали) и задач с дедлайнами, отсортирована рейтингом проекта, «огонёк» руководителя поднимает строчку. Директор и инженер видят одну и ту же очередь инженера. Фильтр «все мои по участию» — в один клик, но не в лицо.
2. **Проект** — дерево разделов и комплектов; создаётся когда угодно.
3. **Карточка комплекта** — чат, срок, ответственный, сумма часов снизу, статус собирается сам, список работ.
4. **Карточка работы** — статус маршрута, чат, подзадачи, таймер, ссылка на файл-результат, происхождение (кликабельно до письма или работы-источника), строка «далее по порядку».
5. **Канбан** узла/проекта — колонки-статусы, чипы-фильтры («что у Вероники по заводу Х» — 3 клика), сохранённые виды.
6. **Пульс** — таблица «комплект × что происходит»: статусы работ, открытые изменения, просрочки. Собирается сам, никакой ручной правды.

Плюс стык с письмами (M5): входящее → резолюция → 1..N поручений, каждое — задача (`source=letter`, проект необязателен); письмо «исполнено», когда закрыты все.

## Типы работ и маршруты (ступень 2)

| Тип | Маршрут | Зачем |
|---|---|---|
| **Разработка** | Новая → В работе → **Ядро выдано** → На проверке → Готово | главная работа; «Ядро выдано» — триггер для сметчиков |
| **Задание** | Черновик → Дозаполняется → Выдано → Принято | сметчикам/смежникам; черновик невидим исполнителю, пока не заполнены «что сделать, файл, срок» (DoR) |
| **Изменение** | Основание → В работе → Готово (строка «что изменилось») | письмо/замечание/звонок → правка комплекта |
| **Проверка** | Назначена → Проведена | визиты надзора, приёмка |
| **Обычная** | Получена → Выполнена | «трудовая книжка», вне дерева, без обязательных часов |

Типы — **данные** на одном движке маршрутов (ADR-0020), не код: ступень 2 добавляет их сидом без миграций. «Обязательство» типом задачи не является (отдельная семантика, отложена до боли после запуска).

## Пять механик

1. **Костяк не ждёт идеала.** Разработка достигла «Ядро выдано» → система предлагает (кнопкой): «Создать задание сметчикам?» → черновик со ссылкой на файл → дозаполнил → у сметчиков «пора».
2. **«Данные изменились».** Работа «Изменение» на комплекте при закрытии уведомляет всех, чьи задания произошли от этого комплекта: «проверьте: [что изменилось]». Потребители известны по происхождению задач — адресно, не спамом.
3. **Никаких мёртвых грузов.** Задание, которому рано, не висит у исполнителя (черновик у ответственного). Задача с открытыми подзадачами не закрывается; подвинул срок родителя — детям предложено подвинуться.
4. **Закрытие — три поля, часы сами.** Таймер или вечерний «раскид дня»; результат собирается системой, отчёт вручную — опционально.
5. **Пульс вместо Google-таблиц.** Статус комплекта — проекция его работ. Не хватает данных — виден разрыв, а не выдуманный статус.

## Чего сознательно НЕ делаем до декабря

Конвейер документов (ревизии, изм.N, накладные) — отдельный будущий эпик; модуль задач пристегнётся к нему без переделок (результат работы — сущность). «Обещания/ожидания» руководителей. Каскад дат и расписаний (сортировка очереди — рейтингом, дедлайны точечные). Гант. Редактор маршрутов (#38). Повторяющиеся задачи.
