# План: мессенджер без дублей — скрытие правой полосы на модуле + полноэкранная карточка мессенджера

**Статус:** план составлен 15.09.2026 по вердикту владельца; РЕАЛИЗОВАН в
рабочем дереве ветки `feat/4-node-ui` 15.09.2026 по прямой команде владельца
(коммит пакета — до реализации, по его же указанию); ждёт живого «ок»
владельца до коммита. Открытые вопросы закрыты дефолтами плана: периметр
фулскрин-карточки 8px + радиус мягкой рамы сохранён; кнопок «чат» в карточках
сотрудника/проекта нет (их чаты — колонки внутри карточек), упразднён вид
`chat` стека. Баг-вердикты владельца 15.09.2026 (учтены): под фулскрин-
карточкой полоса НЕ скрывается шеллом — карточка (inset-2) накрывает её сама,
иначе карточки стека под верхней ехали на 40px во время раскрытия, и лишняя
ширина уходила в левую зону задачи («непрофессионально»); скрытие полосы —
только на модуле мессенджер (`/chat*`, `useRailHidden`), фулскрин-карточка
получает stripW=0 пропом `fullscreen` у SliderPanel.
**База:** ветка `feat/4-node-ui`, HEAD = коммит пакета чатов/вложений/панелей.
**Референсы владельца:** скриншоты Битрикс24 (мессенджер без правой панели; клик по правой
панели открывает карточку мессенджера со списком чатов); скрин нашего мессенджера с красной
рамкой «должно быть на весь экран»; скрин свёрнутой левой рейки как реф оформления шины.

## Проблема

1. На модуле «Мессенджер» правая узкая полоса-экспресс-мессенджер дублирует список бесед
   самого модуля (тот же список чатов второй раз). Битрикс24 решил это так: на модуле
   мессенджер правая панель НЕ отображается, рабочая область доходит до края экрана.
2. Клик по коллеге/чату в правой полосе открывает компактную карточку чата
   (`kind: 'chat'`, ADR-0009) — «слишком широкая и неудобная», без списка чатов и вкладок.
   В Битрикс по клику в правой панели открывается КАРТОЧКА МЕССЕНДЖЕРА: полноценный
   мессенджер (вкладки Чаты / Чаты задач / Настройка, список бесед, весь функционал),
   отдельная карточка стека: закрыл — вернулся на карточку предыдущей сущности (задачи).
3. Карточка мессенджера — НА ВЕСЬ ЭКРАН (перекрывает левую рейку и правую полосу — дубли
   исчезают сами). Возникает вопрос шины-контура: собственные вкладки карточки
   (Чаты / Чаты задач / Настройка) нуждаются в портах и засечках; решение — как при
   свёрнутой левой рейке: урезанная шина начинается точкой на границе мягкой области
   карточки и идёт осью до правого края с засечками к точкам вкладок.

## Решения

### 1. Модуль «Мессенджер» — без правой полосы

- Правило шелла: активный модуль = мессенджер (маршрут `/chat*`) → RightRail НЕ рендерится;
  мягкая рама расширяется до правого края периметра (рама получает правый отступ
  периметра сама, mr-2, как ml-2 слева). На остальных модулях полоса возвращается в
  своём состоянии (`edgeOpen` из nodus-shell-v1 не сбрасывается).
- Анимация: колонка полосы ужимается w-10 → w-0 (transition-[width] 200ms, easing как у
  остальных рефлоу), рама расширяется синхронно (transition-[margin]); без скачка.
- Контур: правок не требует — геометрия измеряет живой DOM (рама стала шире, точка
  левого узла/ось пересчитываются существующими слушателями resize/transition).
- Карточки-слайдеры: их правый край = правый край рамы (EDGE_* константы полосы больше
  не участвуют на /chat: slider-panel берёт ширину полосы = 0, когда полоса скрыта).

### 2. Полноэкранная карточка мессенджера (`kind: 'messenger'`)

- Тело мессенджера выносится в общий компонент `MessengerBody` (табы Чаты / Чаты задач /
  Настройка + список бесед + рабочая область беседы + правая панель беседы): его используют
  И страница `/chat`, И карточка — единый код, без дублей (урок «чаты в задачах»).
- Новый вид карточки стека (ADR-0009): `{ kind: 'messenger', conversationId? }`:
  - рендер — ФУЛСКРИН: портал в body, `fixed inset-2` (периметр 8px и радиус 18px мягкой
    рамы сохраняются — карточка выглядит как мягкая область на весь экран, реф красной
    рамки владельца), z выше рейки/полосы/рамы, ниже оверлеев (меню, поповеры, лайтбокс);
  - пока фулскрин-карточка вершина стека — правая полоса и левая рейка перекрыты ею
    («карточка закрывает правую узкую панель», дубля нет); дополнительно полоса может
    не рендериться вовсе (см. п.1 правило: расширяем на модуль ИЛИ на фулскрин-карточку);
  - содержимое: `MessengerBody` с начальным выбором беседы из payload (клик по коллеге в
    полосе → карточка сразу с этим чатом; клик без беседы → список без выбора);
  - закрытие (X / Esc) — обычный pop стека: возвращаемся на карточку предыдущей сущности
    (задача/проект/сотрудник), состояние той карточки не терялось и не теряется;
  - shared-element раскрытие: из rect источника (аватарка в полосе / кнопка чата) —
    существующий механизм `slider-expand`, целевой rect = inset-2.
- Отказ от `kind: 'chat'` (компактная карточка чата): все вызовы
  `openCard({ kind: 'chat' })` (правая полоса, «Заметки», кнопки чатов в карточках
  сотрудника/проекта, поток «уточнить в чате») переводятся на
  `openCard({ kind: 'messenger', conversationId })`. Компонент ChatWorkspace compact
  уходит из кода вместе с видом (не мёртвый код — architecture-no-dead-code).
- Данные: те же query-ключи чата (TanStack) — страница и карточка читают один кэш,
 _second_ источника правды не появляется; «вечный курсор» композера работает внутри
  карточки без правок (реестр composer-focus глобален).

### 3. Шина-контур в фулскрин-карточке (режим «карточка»)

- Хедер карточки мессенджера помечается `data-card-topbar`, его вкладки-табы —
  `data-tab-port` (те же атрибуты, что табы шелла).
- circuit-geometry: когда открыта фулскрин-карточка (флаг из card-stack store), контур
  переключается в РЕЖИМ КАРТОЧКИ: измеряет `data-card-topbar` вместо `data-topbar`;
  левый узел-точка ставится на левой границе мягкой области карточки на оси табов
  (ровно как сейчас при свёрнутой левой рейке — реф владельца); ось идёт до правого края
  карточки, засечки вверх к точкам её вкладок; шина шелла под карточкой не рисуется
  (карточка перекрывает, но флаг глушит и расчёт — без лишней работы в rAF).
- Переключение режима — событие стека (открытие/закрытие фулскрин-карточки): контур
  перемеряется существующим remeasure; вспышка на смену фокуса внутри карточки работает
  по общей логике (фокус = moduleTo|tabLabel, tabLabel берётся из табов карточки).
- Свёрнутая/развёрнутая левая рейка под фулскрин-карточкой не важна (перекрыта); после
  закрытия карточки контур возвращается в режим шелла тем же флагом.

## Точки правки

1. `app/shell/app-shell.tsx` + `right-rail.tsx`: условие скрытия полосы (модуль мессенджер
   ИЛИ фулскрин-карточка вершина стека), анимация w-10→w-0, правый отступ рамы.
2. `features/chat/pages/chat-page.tsx` → вынести `MessengerBody`
   (`features/chat/components/messenger-body.tsx`); страница = обёртка маршрута над телом.
3. `app/shell/use-card-stack.ts` + `slider-panel.tsx`: вид `messenger`, фулскрин-рендер
   (портал, fixed inset-2, z-лестница), payload conversationId, retired `kind: 'chat'`.
4. Вызовы `openCard({kind:'chat'})` → `messenger` (right-rail, employee-card,
   project-card, message-menu «уточнить»? — ревизия всех мест grep-ом).
5. `app/shell/circuit-geometry.ts` + `circuit-frame.tsx`: режим карточки
   (data-card-topbar, левый узел на границе карточки, глушение шины шелла).
6. Удаление мёртвого: ChatWorkspace compact-ветка, ChatCard-разметка вида 'chat'.

## Приёмка

- /chat: правой полосы нет, мягкая рама до правого края периметра; переход без скачка;
  на других модулях полоса на месте в прежнем состоянии.
- Клик по коллеге в полосе (на карточке задачи): открывается фулскрин-карточка мессенджера
  с этим чатом; вкладки/список/панель беседы работают; Esc/X — вернулись на карточку задачи
  с её состоянием (ресайз чата, открытая «О задаче» — всё живо).
- В фулскрин-карточке: шина = точка на левой границе карточки + ось + засечки к точкам
  вкладок Чаты/Чаты задач/Настройка; вспышка при переключении вкладок карточки.
- Дублей списка бесед нигде нет: модуль мессенджер без полосы; карточка мессенджера
  перекрывает полосу; компактной чат-карточки больше не существует.
- Обе темы; гейты зелёные; e2e-проба: полоса→карточка→Esc→карточка задачи.
