# Ядро управления проектированием — правила (core.md, v2 после раунда атак 1)

Ядро: обобщённая модель того, как в продуктовой компании живут работы, документы и их передачи. Развёртка — `docs/mvp/process-map.md` v1.3; правила — здесь, с трассировкой. v2 = v1 + усиления по 20 FAIL раунда 1 (см. attack-log); ни одной новой сущности — только обобщения существующих механизмов.

| # | Правило | Трассировка |
|---|---|---|
| R1 | Единица передачи — **ревизия документа** (шифр); у **официальной** ревизии — структурированный **листовой манифест** («лист → замена/введение/аннулирование»): состояние бумажного экземпляра после выборочной замены = смесь, «экземпляр принял изм.N» без перечня листов — юридическая ложь; из манифеста собираются таблица регистрации изменений и фронт повторного НК. Ревизия принадлежит документу; узлы — агрегаторы с датированными связями | досье №2,13; ГОСТ 21.101 (операции по листам), ГОСТ 21.1002 (повторный НК изменённого); атака A2-С1/С4 |
| R2 | Рабочие ревизии (автономер + назначение) vs **официальные изм.N** (нормоконтроль; основание-ссылка; повторный НК **перечисленных в манифесте листов**; печать по перечню) | досье №11; ГОСТ 21.1002; атака A2-С4 |
| R3 | Содержимое ревизии и **итог закрытия работы** иммутабельны: итог = ревизия итога, не перезаписываемое поле; правка = новая ревизия; старая «Заменено» | досье №14; Левчук «мусор поверх»; атака A2-С3 |
| R4 | Передача = строки «документ × ревизия × экз. × взамен №» + распорядок получателя (принято / изъято по перечню / отклонено с основанием). **События судьбы бывают негативными**: отклонено/отозвано/«не действует с D» — и триггерят инвалидацию наравне с новой ревизией. Для плоских документов (акты, протоколы) события судьбы тоже живут: «получено» ≠ «согласовано» ≠ «отказано с мотивировкой» | ds.do; СП 246; атака A2-С2/С5 |
| R5 | Событие внешней судьбы = доказательство (скан) или видимый разрыв. **Работа, чей предмет — внешнее событие** (согласование, ответ, устранение), закрывается только событием с доказательством или явным разрывом; сообщение чата = «кандидат в доказательство» (1 клик) | КОРУС C1; атака A3-С7, A1-С3 |
| R6 | След дешевле обхода: чат-файл получателям комплекта = видимая «неоформленная выдача», 1 клик оформить (с автопоиском родителя по шифру; неопознанный файл оформляется с обязательным выбором документа). **Неоформленная выдача стареет**: сверх окна — разрыв на пульсе обеим сторонам | КОРУС; атака A3-С6 |
| R7 | Изменение выданного = новая ревизия с diff + **адресная инвалидация всей цепочки «основано на» до корня** (не один хоп: АР→КЖ→ВК); **основание обязательно на DoR** в одной из двух форм: «по ревизии X» или «вне системы (opaque + дата)» — вторая = видимый разрыв, и если источник выпустил свежей — «требует перепроверки» | PMSoft C2; Revit C5; атака A1-С5, A3-С4 |
| R8 | Обращение (вопрос/замечание/нарушение) — сущность с якорем хотя бы одного из трёх видов: «ревизия × элемент | версия плоского документа | объект/узел» (нарушение может не иметь ревизии — «нет исполнительной документации»). Закрытие = основание-ссылка (ревизия / версия плоского / визит с доказательством; письмом не закрывается) | СП 246; атака A2-С5/С6 |
| R9 | «Пора» вычисляется из порядка (правила: документ выдан / работа-узел закрыт / внешнее письмо-событие), не из дат. **Персональная очередь одна для всех ролей** (директор, ГИП, исполнитель видят одну и ту же очередь человека): «пора» + обязательства, ранжированные рангом портфеля и ручными «огоньками» (= обязательство с рангом; смена ранга — событие в ленте) | досье №8,16; LPS; атака A1-С2 |
| R10 | Черновик до DoR невидим исполнителям; виден ответственному и руководителю узла (роль). Наличие чужих черновиков руководителю выше — вопрос заказчику (границы) | досье №6; атака A1-С1a |
| R11 | Закрытие ≤3 полей; **часы обязательны** (0 часов или несобравшийся результат = не «выполнено», а видимый разрыв; правила порядка от пустого закрытия не запускаются); «вне графика» (сверхурочные) **выводится из факта записи** (задним числом / сверх порога дня) — не выбирается человеком; результат автособирается | досье №17; КОРУС; атака A3-С3/С5 |
| R12 | Работа не закрывается с открытыми подзадачами **и с открытыми обращениями на свои результирующие ревизии** (групповая передача «сводный ответ» — гейт: открытые обращения группы = блок или явное переопределение с автором); дети в сроке работы; кусок = работа, если свой файл/выдача/получатели | Jira C7; атака A1-С7, A2-С8 |
| R13 | Порядок = правила-строки, действие всегда «создать черновик»; ритмы = повторяющиеся задачи; правило «молчание = согласие» допустимо только с доказательством договорного основания | Jira/ADePT; атака A2-С2 |
| R14 | Пульс — витрина над событиями; разрывы явные; **покрытие учёта первоклассно** для всего счётного: обязательства («внесено X из Y»), триаж импорта («13 из 30, старший 34 дня»), неоформленные выдачи | досье №13,15; атака A3-С2 |
| R15 | Порождение работы: **из письма (резолюция) и из чата** (сообщение с файлом/сроком одному адресату → «сделать поручением», 1 клик) — происхождение кликабельно до источника. Входящее письмо проходит **явный триаж судьбы** из словаря: обращение / работа / обязательство / информационное; «информационное» — тоже явный выбор, не тишина; ответ-письмо с решением об изменении без ревизии/обращения = видимый разрыв | досье №20; атака A1-С3, A2-С7 |
| R16 | Обычные задачи вне дерева и конвейера | досье №21 |
| R17 | Дерево создаётся когда угодно; проект живёт без дерева | КОРУС |
| R18 | Корреспондент — единый живой справочник: **слияние записей = событие с перепрошивкой всех ссылок**; создание новой записи — поверх подсказки «похожие»; хвост регистрации письма «вложения осмотрены: слоёв N / это сканы» — иначе видимый разрыв. Связи «ответ на»/«вложено в»/«объединено с» первоклассны; реквизиты корреспондента индексируемы | досье №19; атака A3-С1 |
| R19 | «Мир до ядра» — тоже данные, и **ретро-факт = полноценное событие** (передача в формате R4 с доказательством; событие порядка с временем факта и ретро-рангом): импортный бэклог живёт (старение триажа, «пора» вычислима по ретро-событиям), а не заморожен. Импорт не порождает будущие правила; арминг-дата у правил; время факта ≠ время записи | КОРУС-провал; атака A1-С1б/С4, A3-С2 |
| R20 | Расписания нет; **дата точки — либо абсолютная, либо якорь-обязательство** («до начала монтажа»): сдвиг якоря — событие, зависимые сроки переезжают и видны в ленте. Предел числа якорей — вопрос заказчику (иначе это календарь, отвергнутый 3/3) | досье №16; атака A1-С6 |

Класс-вывод раунда 1 (одна строка на все фиксы): **след факта обязателен; выводимое — выводится системой, а не выбирается человеком; невыводимое — видимый разрыв.** Ни один фикс не добавил сущность: листовой манифест = «состав» (уже был), негативные события = расширение перечня судьбы, якоря обращений = расширение словаря, очередь = обязательства+«пора».

Статус: **НЕ ЗАМОРОЖЕНО** — раунд 1 дал новые FAIL, по навыку требуется раунд 2 (регрессионный: прошлые FAIL → PASS, выборочные старые PASS не сломать) до сатурации; запуск — по слову заказчика.
