# Ядро управления проектированием — правила (core.md, v2.1)

Ядро: обобщённая модель того, как в продуктовой компании живут работы, документы и их передачи. Развёртка — `docs/mvp/process-map.md` v1.3; правила — здесь, с трассировкой. v2.1 = v2 + уточнения раунда 2 (стыки правил + доказательность): **ни одной новой сущности, структура понятий неизменна** — правки только формулировки. Класс-вывод раундов 1–2: *след факта обязателен; выводимое — выводится системой; невыводимое — видимый разрыв; записанное событие — append-only, прошлое не переписывается, а шьётся видимым швом.*

| # | Правило | Трассировка |
|---|---|---|
| R1 | Единица передачи — ревизия документа (шифр); у официальной ревизии — листовой манифест «лист → замена/введение/аннулирование» (исключение: ретро-официальная ревизия без манифеста допустима только как ретро-факт с вечной меткой «состав листов не восстановлен»). Ревизия принадлежит документу; узлы — агрегаторы с датированными связями | досье №2,13; ГОСТ 21.101/21.1002; атака A2-С1/С4 (р.1), A5-К2 (р.2) |
| R2 | Рабочие ревизии (автономер + назначение) vs изм.N (нормоконтроль, основание-ссылка, повторный НК перечисленных листов, печать по перечню) | ГОСТ 21.1002; атака A2 |
| R3 | **Всё записанное — append-only**: ревизии, итоги закрытия (итог = ревизия итога), события, строки передач и их ссылки. Правка = новая ревизия; старая «Заменено». Слияния и переименования — события резолвинга поверх, записи хранят значение-на-момент-события, «вид на дату» вычисляется по цепочке (UPDATE запрещён) | досье №14; атака A4-10, A5-К7 |
| R4 | Передача = строки «документ × ревизия × экз. × взамен» + распорядок получателя, **построчный по листам манифеста**: принято / изъято по перечню / отклонено с основанием; частичное отклонение = «листы L не действуют с D» + одно обращение с листовыми якорями. Распорядок по бумаге двуступенчат: «заявлено» (клик) ≠ «подтверждено» (скан акта); заявленное сверх окна = разрыв. События судьбы негативны тоже (отклонено/отозвано) и триггерят инвалидацию; плоские документы имеют «получено ≠ согласовано ≠ отказано с мотивировкой» | ds.do; СП 246; атака A2, A4-5, A5-К4 |
| R5 | Событие внешней судьбы = доказательство (скан) или видимый разрыв. Работа с внешним предметом (согласование/ответ/устранение) закрывается событием-доказательством или явным разрывом; **ожидание — легальное состояние** («ждёт доказательства», в очереди с огоньком; авто-разрыв отключён; сверх окна — обязательство «выбить доказательство или порвать», решение человека). Чат-сообщение = кандидат в доказательство (1 клик) | КОРУС; атака A3-С7, A4-6 |
| R6 | Чат-файл получателям комплекта = видимая «неоформленная выдача», 1 клик оформить (автопоиск родителя по шифру; неопознанный файл — с обязательным выбором документа). Неоформленное стареет: сверх окна — разрыв обеим сторонам. **Режим чат-файла один** (триаж): «неоформленная выдача» (стареет) или «вложение поручения» (не стареет; определитель — направление); оформление выдачи = ретро-пакет: ревизия с временем записи + строка передачи с временем факта, шов D..D+9 вечен и виден. **Окна и пороги — константы ядра, не настройки** заинтересованной стороны | КОРУС; атака A3-С6, A4-7, A5-К1/К5 |
| R7 | Изменение выданного = новая ревизия + diff + **инвалидация цепочки «основано на» до корня; инвалидация никогда не создаёт сущности** — только флаг на связь (видимость флага не зависит от видимости черновиков). Правила порядка идемпотентны по паре (ревизия источника × целевой узел): новый выпуск поглощает открытый производный черновик старой ревизии. Основание на DoR обязательно: «по ревизии X» или «вне системы (opaque + дата)» = видимый разрыв; opaque старее свежей ревизии источника → «требует перепроверки» | PMSoft; Revit; атака A1-С5, A3-С4, A4-1 |
| R8 | Обращение (вопрос/замечание/нарушение), якорь хотя бы один: ревизия×элемент | версия плоского | объект/узел; закрытие основанием-ссылкой (ревизия / версия плоского / визит с доказательством; **+ «аннулировано вместе с якорем»**). Аннулирование ревизии требует судьбы её открытых обращений: переякорение на преемника или закрытие — мёртвых якорей в живых обращениях не бывает | СП 246; атака A2-С5/С6, A4-11 |
| R9 | «Пора» вычисляется из порядка; **персональная очередь одна для всех ролей** = «пора» + обязательства (якорь-срок — обязательство, не «пора»; виды элементов очереди не смешиваются), ранжированные рангом портфеля и «огоньками» (смена ранга — событие в ленте). **Обязательства адресата — полноправный источник «пора»**: получил документ → «распорядись», открыто обращение к тебе → «ответь», заявлен распорядок → «подтверди»; старение сверх окна = разрыв обеим сторонам | досье №8,16; LPS; атака A1-С2, A4-3/8, A5-К6 |
| R10 | Черновик до DoR невидим исполнителям; виден ответственному и руководителю узла (роль). Наличие чужих черновиков выше руководителю — вопрос заказчику | досье №6 |
| R11 | Закрытие ≤3 обязательных полей — **для работ** (критерий R12: свой файл/выдача/получатели): часы обязательны (0 часов или несобравшийся результат = видимый разрыв «не выполнено», правила порядка молчат); «вне графика» выводится из **факт-времени** закрытия против срока (время записи — только аудит; факт ≤ записи, иначе событие «правка задним числом»); окна/пороги — константы; выгрузка для спора печатает само правило. **Обычные задачи (R16) закрываются отметкой факта — без часов, автосбора и разрывов**; эскалация (файл/получатель/подзадача) переводит в режим работы с этого момента | досье №17; КОРУС; атака A3-С3/С5, A6-11, A4-4а/12, A5-К5 |
| R12 | Работа не закрывается с открытыми подзадачами и **с открытыми обращениями, чей якорь указывает на работу/узел/её результирующие ревизии (любой вид якоря)**; групповая передача «сводный ответ» гейтится открытыми обращениями группы (блок или явное переопределение с автором); дети в сроке работы | Jira; атака A1-С7, A2-С8, A4-4б |
| R13 | Порядок = правила-строки, действие «создать черновик»; **правило срабатывает ⇔ факт-время события ≥ арминг-даты**: ретро-события живут в порядке и пульсе (показ), действий не исполняют; ручной ввод с факт-временем в прошлом = импорт (один контур триажа). Ритмы = повторяющиеся задачи; «молчание = согласие» только с договорным доказательством | Jira/ADePT; атака A2-С2, A4-2/8 |
| R14 | Пульс — витрина над событиями; разрывы явные; покрытие учёта первоклассно (обязательства, триаж импорта, неоформленные выдачи, заявленные-но-неподтверждённые распорядки) | досье №13,15; атака A3-С2, A5-К6 |
| R15 | Работа рождается из письма (резолюция) и из чата (сообщение с файлом/сроком → «сделать поручением», 1 клик). Входящее письмо — явный триаж судьбы (обращение/работа/обязательство/информационное); ответ-письмо с решением об изменении без ревизии/обращения = разрыв. **Обязательство «вне системы» (звонок/устно) = opaque + дата факта + метка «основание вне системы» + автор записи** (видимый разрыв происхождения) | досье №20; атака A1-С3, A2-С7, A5-К3 |
| R16 | Обычные задачи вне дерева и конвейера; закрываются отметкой факта (см. R11) | досье №21 |
| R17 | Дерево создаётся когда угодно; проект живёт без дерева | КОРУС |
| R18 | Корреспондент — единый живой справочник: слияние = событие резолвинга поверх (алиасы, обратимо), без UPDATE записей; исторические документы показывают имя-как-написано + бейдж «ныне X»; создание записи — поверх подсказки «похожие»; хвост регистрации «вложения осмотрены: слоёв N / это сканы» = иначе разрыв. Связи «ответ на»/«вложено в»/«объединено с» первоклассны | досье №19; атака A3-С1, A4-10, A5-К7 |
| R19 | «Мир до ядра» = данные: ретро-факт = полноценное событие (передача R4-формата с доказательством; событие порядка с временем факта); **ретро-события показываются, но не исполняют правила** (арминг по факт-времени, см. R13); импорт не порождает будущих правил; время факта ≠ время записи — в каждой выгрузке | КОРУС; атака A1-С1б/С4, A3-С2, A4-2 |
| R20 | Расписания нет; дата = абсолютная или якорь-обязательство («до начала монтажа»; якорь требует фиксируемого факта-события, иначе вечносдвигаем); сдвиг якоря — событие, зависимые сроки переезжают и видны в ленте; предел числа якорей — вопрос заказчику | досье №16; атака A1-С6, A4-3 |

Статус: **НЕ ЗАМОРОЖЕНО**. Раунд 3 (сатурационный: регрессия v2.1 + стыки фиксов раунда 2) — по слову заказчика; критерий заморозки — раунд без новых FAIL/OUT.
