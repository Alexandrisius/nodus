## 4. #191 — Клиентское сжатие фото АВАТАРОК (~2–3 ч + живая проба)

**Суть (и что НЕ трогаем):** аватар грузится любым декодируемым фото, по сети уходит сжатая копия (8 МБ → 100–300 КБ). **Вложения сообщений и просмотрщик оригиналов НЕ трогаются вообще** (это отдельный конвейер #221, работает и остаётся). Аватар никогда не крупнее 176px, сервер и так делает 640px WebP-дериват (#186) — результат на экране тот же, меняется только тело запроса. Механизм ОДИН в `apps/web/src/shared/chat/avatar-upload.ts` (сейчас 53 строки: validate ≤10 МБ + multipart) — три точки выбора (окно создания `chat-create-dialog.tsx:30`, топбар беседы `conversation-bar.tsx:15`, профиль `employee-profile-tab.tsx:16`) получают автоматически.

**Механика (тело issue, Canvas API, БЕЗ зависимостей):** `createImageBitmap(file)` (+EXIF-ориентация `from-image`; метаданные/GPS срезаются), даунскейл maxEdge **1024** без апскейла, WebP q≈0.85 с честным fallback JPEG q≈0.9 (проверять фактический mime `canvas.toBlob`), ≤512 КБ без запаса габаритов не пережимать (порог — параметр), HEIC/недекодируемое — отказ ДО сжатия существующим тостом, превью окна создания — из сжатой копии. Квадратизация остаётся серверной (sharp; потолок 4096²/10 МБ уже влит — #231).

**Тесты:** unit механики (формат/fallback/порог/ориентация, моки canvas) + живая проба на песочнице: фото 8 МБ → аватар в беседе и профиле, тело запроса <1 МБ, EXIF не доезжает (канон проб — `nodus-dev-testing/references/probes.md`; данные с маркером «Проба 191», зачистка за собой). Не входит: кроп-UI, GIF, сжатие вложений, настройка качества.
