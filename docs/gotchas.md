# Ловушки (Gotchas)

Каждая ловушка, найденная в работе, добавляется сюда одной строкой в соответствующий раздел **в том же коммите, что и фикс**. Пишем механизм (почему ломается и как обойти), не симптом. Универсальные ловушки хоста (могут сломать любую задачу) дублируются в AGENTS.md — остальное живёт только здесь.

Читать: перед работой в соответствующей области; при непонятной ошибке — свериться сначала здесь.

## Docker и инфраструктура

- На dev-хосте крутятся чужие Docker-проекты: контейнеры/сети/тома Nodus — только с префиксом `nodus_`, порты — через `.env`, перед `docker compose up` проверяй занятые порты (`docker ps`).
- В alpine-контейнерах `localhost` резолвится в ::1 (musl предпочитает AAAA), а наши сервисы слушают IPv4 (`0.0.0.0`) — healthcheck'и docker-compose ходят на `127.0.0.1`, не `localhost`.
- Образ `postgres:18+` ждёт данные в `/var/lib/postgresql`, а не `/var/lib/postgresql/data` — со старым путём контейнер не стартует («unused mount/volume»); новый путь заодно даёт мажорные апгрейды через `pg_upgrade --link`.
- **В runner-стадии Dockerfile глобальных CLI нет** (pnpm ставится только в builder): CMD и seed-скрипты вызывают бинарники из `node_modules/.bin/` пакета (`./node_modules/.bin/prisma migrate deploy`), иначе контейнер рестартит с «pnpm: not found» (подтверждено воспроизведением в issue #3).
- **`prisma db seed` в контейнере не находит tsx на PATH** (pnpm-бины не экспортированы): seed-команда — `node --import tsx prisma/seed.ts`, кроссплатформенно (Windows-хост и alpine-контейнер; подтверждено воспроизведением в issue #3).
- **ONLYOFFICE DS (#138, все — официальные доки API DS + репро 28.09):**
  - `window.DocsAPI` — ОБЪЕКТ с конструктором `DocsAPI.DocEditor`, не сам конструктор (`new DocsAPI(...)` → TypeError; api.onlyoffice.com/docs/docs-api/usage-api/doceditor).
  - Алфавит `document.key` — `0-9-.a-zA-Z_=`: двоеточие в `${id}:v1` молча валит канал ко-эдитинга (`io.on connection unexpected key use key pattern` в логах docservice, в UI — ошибка -23).
  - DS строит абсолютные ссылки (Editor.bin в /cache, колбэки) от УВИДЕННОГО Host: прокси обязан слать браузерный `Host`/`X-Forwarded-Host` С ПОРТОМ (nginx `$http_host`, не `$host`; vite-прокси — БЕЗ changeOrigin) — подменённый хост = кросс-origin ERR_FAILED.
  - **cloudflared НЕ ставит `X-Forwarded-Proto`**: nginx за туннелем видит `$scheme` = всегда http — DS строит `http://`-ссылки на свой кэш, а HTTPS-браузер режет их как Mixed Content («Редактор недоступен», errorCode -1; репро nodus.by 29.09). Схему оригинала берём из `CF-Visitor` (edge всегда шлёт): map `$http_cf_visitor → $nodus_proto` → `X-Forwarded-Proto` (web.conf); Edge Cloudflare инжектит и beacon cloudflareinsights.com в HTML iframe — CORS-шум в консоли, продукт не трогает, выключается в панели CF.
  - DS 302-редиректит статику на версионный префикс `/<версия>-<хэш>/web-apps/...` — прокси должен покрывать и его (regexp `^/(web-apps|...|[0-9]+\.[0-9]+\.[0-9]+-[0-9a-f]+)`).
  - SSRF-фильтр DS (`request-filtering-agent`) по умолчанию режет приватные адреса — скачивание `document.url` из compose-сети требует env `ALLOW_PRIVATE_IP_ADDRESS=true`.
  - Callback-токен приходит Bearer-заголовком с payload-обёрткой `{payload:{...тело}}` (`JWT_IN_BODY=false` по умолчанию; api.onlyoffice.com signature/request).
  - **DS считает ошибкой ЛЮБОЙ не-200 ответ колбэка** (включая семантически успешный Nest-дефолт 201 для `@Post`): в логах docservice `postData error: statusCode:201`, в UI «Не удается сохранить документ», повторные доставки → `storeForgotten` — на колбэке обязателен `@HttpCode(200)` (репро 29.09, вердикт владельца #138; доки DS callback handler: response 200 + `{"error":0}`).
  - **Встраивание DS корневыми путями = коллизия со своими публичными ассетами**: `/fonts/*` приложения перехватывается DS-прокси ДО статики (vite proxy и nginx) → 404 из documentserver; свои публичные файлы держать вне DS-путей (`/app-fonts/` вместо `/fonts/`, репро 29.09 #138).
  - **DS не автоопределяет кодировку txt/csv/tsv**: показывает диалог «Выбрать параметры TXT/CSV» (конфигом НЕ отключается — официальный ответ ONLYOFFICE, community 9910; feature request открыт годами). UTF-8 **с BOM** открывается без диалога (проверено живьём 29.09) — API отдаёт текст DS через `office=1`-нормализацию (UTF-8/1251→BOM). CSV всё равно спрашивает РАЗДЕЛИТЕЛЬ (предзаполняется автодетектом). **Кэш конвертаций привязан к document key**: сменив отдаваемые байты без смены ключа (наш office=1), чисти `/var/lib/onlyoffice/documentserver/App_Data/cache+forgotten` — иначе DS вечно отвечает старым «спросить кодировку» (репро 29.09).
- **NestJS `@Global()`-модуль глобализирует ТОЛЬКО `exports`**: провайдер без попадания в exports невидим другим модулям, а `@Optional()` на инжекте маскирует провал пустым дефолтом — баг молчит до живой проверки (репро 29.09 #138: multi-порт FILE_ACCESS_CONTRIBUTORS без exports → доступ «только владелец», участник беседы получал 404; docs.nestjs.com/modules «global scope + exports»; замок — probe-потребитель без @Optional, компиляция падает при регрессе).
- Cloudflare Tunnel после пересоздания web-контейнера теряет origin («connection refused» до переподключения): `docker restart nodus_cloudflared`; проверяй демо curl'ом, а не Invoke-WebRequest (тот капризничает с таймаутами на этой машине).
- **`VITE_*`-переменные — build-time**: `.env` хоста не попадает в docker-сборку, режим демо задаётся `ARG`/build-args в compose (`NODUS_WEB_MOCK` → `VITE_API_MOCK`); сменил режим — пересобирай образ (`docker compose up -d --build web`), рестарта контейнера мало.
- **turbo-кэш build не видит env — и не только «не пересобирает», но и ЗАТИРАЕТ чужую сборку**: ручная non-mock сборка web (`VITE_API_MOCK=false vite build`) была перезаписана кэшированной задачей последующего `pnpm build` (в кэше лежал бандл с .env-значением флага) — на вердикт-стек уехал полумок-бандл с активным MSW (репро #57: владелец получил «Не удалось загрузить файл»). Лечение: `turbo.json` → `tasks.build.env: ["VITE_API_MOCK"]` — env входит в хэш задачи, смена значения = гарантированный промах кэша.
- **Порты сервисов опубликованы на `127.0.0.1`** (postgres/redis/minio/api/gateway; у gotenberg опубликованного порта нет вовсе): k6 и dev с хоста ходят через localhost, из LAN сервисы не видны — это осознанно (аудит #123), «чинить» обратно на `0.0.0.0` не нужно. После ребута хоста `docker compose up -d` БЕЗ `--profile tunnel` не поднимает cloudflared — nodus.by лежит до `--profile tunnel up -d` (runbook `host-reboot.md`).
- **SILO (клиент mcli И СЕРВЕР) отвергает `_` в hostname**: `alias set http://nodus_minio:9000` — «invalid hostname» на клиенте; Host с подчёркиванием — 400 InvalidRequest на КАЖДЫЙ запрос к серверу (репро пересборки прода 28.09: api падал на ensureBucket). Всё, что ходит в SILO — по алиасу через дефис (`aliases: [nodus-minio]`, `STORAGE_ENDPOINT: nodus-minio`) (подтверждено воспроизведением, #57).
- **Дефолт nginx `client_max_body_size` — 1 МБ**: любой аплоад через прокси-локацию /api молча срезается 413 до api; при добавлении загрузок поднимай лимит в локации (`infra/nginx/web.conf`, #57 — 200m + таймауты 300s на медленные каналы; поведение дефолта — документация nginx).
- **Cloudflare режет тело проксированного запроса по тарифу** (Free/Pro 100 МБ, Business 200, Enterprise 500; не отключается): любой upload через туннель nodus.by >100 МБ падает на edge независимо от нашего кода — «серые облака»/VPS или прямой presigned в фазу 2 (подтверждено: developer docs Cloudflare «Limits», #57/ADR-0013).

## Монорепо и toolchain (pnpm, turbo, TS, ESLint)
- **pnpm 10 НЕ читает поле `pnpm` в package.json** («The pnpm field is no longer read»): настройки (auditConfig.ignoreGhsas, overrides, onlyBuiltDependencies…) живут в **pnpm-workspace.yaml** (подтверждено docs.pnpm.io/settings, 03.10.2026 #187: ignoreGhsas в package.json молча игнорировался и аудит продолжал падать).

- pnpm 11 блокирует install-скрипты зависимостей: пакеты с бинарниками (esbuild, unrs-resolver) — в `allowBuilds` в `pnpm-workspace.yaml`, иначе падают в рантайме с невнятной ошибкой (в pnpm 10 механизм был `onlyBuiltDependencies`).
- **`turbo test` включает ВСЕ пакеты workspace с test-скриптом**: новый пакет с особыми рантайм-требованиями (браузеры Playwright в tests/e2e) падает в CI без этих требований — исключать фильтром в корневом скрипте (`turbo test --filter=!@nodus/e2e`), прогон — отдельной командой (`pnpm test:e2e`) и отдельной CI-джобой (подтверждено воспроизведением в issue #3).
- **YAML GitHub Actions: двоеточие+пробел в незакавыченной строке** (`name: E2E (путь: логин)`) — ошибка «workflow file issue» без job-логов, вся джоба молча не стартует; перед пушем workflow-файлов — локальный YAML-парсинг (подтверждено воспроизведением в issue #3).
- **Фоновые процессы в GitHub Actions умирают в конце шага** без `nohup ... > /tmp/x.log 2>&1 &`: «запустил сервер одним шагом, жду другим» падает с connection refused (подтверждено воспроизведением в issue #3).
- **`vite preview`/`vite dev` биндят `localhost`, который может уйти в ::1** (как и alpine-gotcha с musl, но на любой ОС): в CI и скриптах — явный `--host 127.0.0.1`, health-curl на тот же адрес (подтверждено воспроизведением в issue #3).
- pnpm 11 отклоняет зависимости, опубликованные < 24 ч назад (политика `minimumReleaseAge`, анти-supply-chain): свежая версия «не резолвится» — либо ждём окно, либо осознанное исключение в `minimumReleaseAgeExclude` там же.
- **pnpm 11 НЕ читает `pnpm.overrides` из package.json** («The "pnpm" field is no longer read», миграция на pnpm.io/settings): overrides живут ТОЛЬКО в `pnpm-workspace.yaml`, селективные селекторы версий там же без кавычек (`undici@>=8.0.0: 8.10.2` — кавычки в ключе ломают парсер селектора; подтверждено предупреждением самого pnpm и docs.pnpm.io/settings, #161).
- **Свежий security-advisory роняет CI-гейт `pnpm audit` на ВСЕХ открытых PR разом** (транзитивные цепочки не зависят от кода ветки): лечится селективными overrides в `pnpm-workspace.yaml` и ребейзом зависимых PR — иначе каждый PR «красный» без вины авторов (репро 30.09: undici GHSA-rfgv-xxqx-mfg5, #160/#161).
- **lint-staged гоняет eslint по ВСЕМ staged-файлам, включая временные**: probe-скрипт в `tests/e2e/tmp-*.mjs`, попавший в индекс через `git add -A`, роняет коммит (no-undef на импортах playwright) с неочевидным выводом в логе husky. Канон: временные пробы удалять ДО `git add` (подтверждено воспроизведением дважды, issue #4).
- Каждый пакет, наследующий пресеты `@nodus/config` (tsconfig/eslint), обязан декларировать его в своих dependencies/devDependencies — pnpm не даёт «соседских» пакетов, `extends` упадёт с «file not found».
- ESLint при явном пути к файлу берёт ближайший к нему `eslint.config.*` (а не корневой): вложенный конфиг `tests/lint/fixtures` не содержит ignores и файлы фикстур линтуются — исключения фильтруются вручную в `lint-staged.config.mjs`.
- **ESLint `max-lines` с `skipBlankLines+skipComments` (наш конфиг, max 500) считает МЕНЬШЕ `wc -l`** — пустые и коммент-строки выкидываются из счёта (подтверждено eslint.org/docs/latest/rules/max-lines): файл с wc=587 проходил гейт «на глаз» годами и упал только когда lint-staged впервые коснулся его коммитом (#243: conversations.repository.ts). Канон: размер файла проверять `npx eslint <файл>`, не wc; pre-commit (lint-staged) линтует только ИЗМЕНЁННЫЕ файлы — переразмерный файл молчит, пока ты его не тронешь.

## Бэкенд (NestJS, Prisma)
- **`prisma migrate dev` на dev-хосте бьёт в ПРОД-инстанс PostgreSQL**: корневой `.env` держит `DATABASE_URL` на `127.0.0.1:5432/nodus` — опубликованный порт контейнера `nodus_postgres` (прод); live-stack подменяет URL только своим процессам (репро #211 05.10: migrate dev применил schema-миграцию к прод-БД до деплоя — expand-only таблицы безвредны, но тело уже применённой миграции править нельзя, данные поехали отдельной миграцией `vault_backfill`, применяемой `migrate deploy` при старте api-контейнера; Prisma docs: migrate dev — интерактивная команда разработки, пишущая в целевую БД). Канон: миграции с backfill-данными — `--create-only` + SQL руками; перед любой prisma-командой сверять, куда смотрит DATABASE_URL.
- **Prisma-фильтр JSON-массива объектов по полю элемента НЕ выражается `array_contains`/`path`** (`path:['$','*','name'], array_contains:[x]` молча возвращает 0 строк: path с array_contains матчит МАССИВ по пути, а не скалярные поля элементов; подтверждено докам Prisma JSON filters через Context7 + воспроизведением #171): для «jsonb-массив [{emoji,name}] содержит элемент с name=X» — raw `jsonb_path_exists(col, '$[*] ? (@.name == $label)', '{"label":X}'::jsonb)` (vars — ТОЛЬКО объект, массив PostgreSQL отвергает «vars argument is not an object»). (Context7 Prisma docs + воспроизведением, #171)
- **zod 4 `z.string().uuid()` строже RFC 9562, чем zod 3**: требует версию `[1-8]` в третьей группе и вариант `[89ab]` в четвёртой (все-нулевые/произвольные hex-UUID падают `invalid_format`) — тестовые константы-UUID давайте валидной формы v4 (`00000000-0000-4000-8000-…`, воспроизведено #195: курсор-схема участников отвергла тестовые id).
- **Перевыпуск подписи на каждом DTO-сборе убивает браузерный кэш** (#150): HMAC от `now` давал новые `exp/sig` на каждый рефеч ленты → `<img src>` менялся → полная перезагрузка всех картинок. Лечится округлением `exp` до часового бакета (signed-url.service.ts) — URL детерминирован в пределах часа, ETag/max-age попадают.
- **sharp `.metadata()` бросает на недекодируемом буфере** (failOn не применяется к парсу метаданных, подтверждено reproduс-тестом #150): пайплайн превью оборачивается в try/catch — тихий отказ без ретраев job.
- **BullMQ запрещает ':' и в имени очереди (api падает на старте), и в custom jobId** («Custom Id cannot contain :» — молчаливый catch в enqueue прятал это, превью тихо не становились в очередь, репро прод-деплоя #150): локальные unit-тесты этого не ловят (приложение не бутится в unit-контуре), ловит только boot — CI-интеграция/e2e (урок PR #157: прогонять test:integration локально перед пушем при новых провайдерах). Конвенция ключей `nodus:<module>:*` живёт в опции `prefix`, имя — без двоеточий.
- **pnpm 11 блокирует install-скрипты новых пакетов**: msgpackr-extract (bullmq) «игнорируется» и `pnpm install` внутри prisma CLI падает — пакет надо явно разрешить в `pnpm-workspace.yaml` allowBuilds (pnpm вписывает заглушку-подсказку прямо в файл).


- Prisma 7 не загружает `.env` сам: `apps/api/prisma.config.ts` грузит корневой `.env` через dotenv; для CLI-миграций на хосте нужен `DATABASE_URL` в `.env` (в compose api получает свой из environment).
- Генерируемый Prisma client лежит в `apps/api/src/generated/prisma` (не коммитится, eslint-игнор): typecheck/test/build падают на свежем checkout без `pnpm --filter @nodus/api db:generate` — в CI это отдельный шаг после install, в `build` клиент генерируется автоматически.
- Json-полям Prisma `Record<string, unknown>` не назначается напрямую — нужен каст `as Prisma.InputJsonValue` (типы generated client строже входных DTO).
- Vitest (vite 8, rolldown/oxc) не эмитит decorator metadata, нужную Nest DI: тесты, поднимающие Nest-приложение (integration), идут через `unplugin-swc` (`vitest.integration.config.ts`); unit-тесты без декораторов SWC не требуют.
- **Чек-сумма Prisma в `_prisma_migrations` — SHA-256 файла migration.sql**: миграция, применённая из рабочего дерева до финальной формулировки коммита, даёт «modified after applied» и требование RESET в `migrate dev`; если живыми пробами подтверждено, что DDL применившейся версии идентичен текущему файлу — расхождение книжное: `UPDATE _prisma_migrations SET checksum='<sha256 файла>'` (алгоритм опознан 27.09.2026 сверкой с немодифицированными миграциями: md5/sha1 не совпали). Reset живой БД запрещён всегда.
- **Nest DI пытается резолвить КАЖДЫЙ параметр конструктора**, включая «опциональный со значением по умолчанию» (`constructor(env: ProcessEnv = process.env)`): модуль не поднимается «can't resolve dependencies» — такие параметры помечай `@Optional()` (подтверждено воспроизведением, SignedUrlService, #57).
- **Интеграционные фикстуры, поднимающие приложение вручную, повторяют бут main.ts**: fastify-плагины (cookie, multipart) обязаны регистрироваться в обеих точках, иначе маршрут отвечает 415 в тестах при живом коде — вынесено в `core/http/register-fastify-plugins.ts` единой точкой (подтверждено воспроизведением, #57).
- **`putObject` minio-js из стрима требует явный size** (SDK не знает длину Readable): размер передаёт клиент полем формы, драйвер считает фактически прожитые байты обёрткой — расхождение = мусор не храним, объект удаляется (SDK при несовпадении и сам падает — переводим в доменную ошибку по счётчику; #57/ADR-0013).
- **`@fastify/multipart`: `request.file()`/`parts()` видят текстовые поля ТОЛЬКО ДО файловой части** — на маленьких телах busboy успевает спарсить тело целиком и поля «после файла» чудом доходят, на больших (реальные фото, ~МБ) теряются (репро #57: size=NaN → 400 при рабочем коде; e2e с PNG 107 байт этого НЕ ловил). Контракт: текстовые поля ДО файла в FormData, сервер читает `parts()`-итератором (подтверждено воспроизведением 28.09).
- `@swc/core`, `prisma`, `@prisma/engines` — в `allowBuilds` (pnpm 11): после их обновления проверяй, что pnpm снова не подставил заглушку «set this to true or false».
- **pnpm 11 молча игнорирует поле `pnpm` в package.json** (overrides, allowBuilds, ...): настройки читаются только из `pnpm-workspace.yaml` — overrides в package.json просто не применяются, без предупреждений (подтверждено: pnpm.io/package_json, pnpm.io/migration, PR pnpm/pnpm#10086).
- Интеграционные тесты используют отдельную БД `nodus_test` (создаётся автоматически, миграции — `migrate deploy`): никогда не направляй их на рабочую `nodus` — очистка таблиц деструктивна.

- `DiscoveryService` (скан провайдеров по метаданным) не глобален: модуль, инжектящий его, обязан импортировать `DiscoveryModule` из `@nestjs/core` — моки в unit-тестах это не ловят, падает только bootstrap контейнера (проверяй `docker compose up` после добавления таких провайдеров).
- **Ошибки Fastify-плагинов (например @fastify/rate-limit) — не Nest-исключения**: приходят в глобальный фильтр как объект со `statusCode`, без него ветки фильтра уходят в 500 INTERNAL_ERROR вместо 429. Фильтр обязан иметь ветку для `{ statusCode: number }` (подтверждено воспроизведением в issue #3: e2e получал 500 на rate-limit).
- **`keyGenerator` @fastify/rate-limit выполняется ДО парсинга тела** (`request.body` undefined): per-account лимиты по email через keyGenerator не работают — брутфорс-защита login живёт в AuthService (Redis-счётчик `nodus:auth:login_fail:<email>`), а не в плагине; IP-ключ за NAT офиса блокировал бы всех сотрудников разом (подтверждено воспроизведением: лимит срабатывал с ключом `ip:` при 2 логинах).
- **JWT детерминирован в пределах секунды** (NumericDate = секунды, RFC 7519): два signAsync одного payload в ту же секунду дают идентичный токен — в тестах не сравнивай access-токены на неравенство, проверяй ротацию по refresh-cookie (флаки в integration issue #3).
- **Расширение payload доменного события ломает ТОЧНЫЕ ассерты (toEqual) в любом тестовом дереве**: grep по имени payload-схемы/события обязан пройти по ВСЕМ тестам (unit + test/integration + моки), не только по модулю-владельцу — карта изменений, собранная по одному ключу (напр. `tier`), не видит ортогональных осей: payload правки расширяли для #189, ассерт в chat-messages.integration ждал ровно 3 поля, поймал только CI. (воспроизведением: красный CI PR #203, фикс 641ee1b)
- Чтение строк, записанных в открытой транзакции, ДОЛЖНО идти через тот же tx-клиент: репозиторный метод `findById` без tx-параметра читает пулом и не видит uncommitted-записей — карточка возвращается со старым состоянием (поймано при реализации directory: `findCardById(id, tx)`).
- **`SwaggerModule.setup` регистрирует маршруты напрямую в HTTP-адаптере** (`httpAdapter.get`), в обход конвейера Nest: глобальные гуарды (наш `JwtAuthGuard`) на `/api/docs` НЕ действуют — документация защищается отдельным middie-посредником (подтверждено: исходники @nestjs/swagger 12, `serveSwaggerUi`/`serveDefinitions`; issue #19).
- **Nest-Fastify передаёт в `app.use`-посредники СЫРЫЕ объекты Node** (`req.raw`, `reply.raw` — см. `fastify-middie.js`: `run(req.raw, reply.raw, next)`), не `FastifyRequest`/`FastifyReply`: `reply.status()` — «not a function»; ответ пишется в `ServerResponse` (`statusCode`/`setHeader`/`end`), `request.id` fastify кладёт на `req.raw` сам (подтверждено исходниками @nestjs/platform-fastify и воспроизведением, issue #19).
- **`@nestjs/swagger` на Fastify требует peer `@fastify/static`**: без него `SwaggerModule.setup` падает «The @fastify/static package is missing» + `process.exit(1)` прямо в bootstrap; версия должна удовлетворять пиру `@nestjs/platform-fastify` (подтверждено воспроизведением, issue #19).
- **`@nestjs/swagger` тянет `@scarf/scarf`** (install-аналитика): в `allowBuilds` — `false` (self-hosted, чужая телеметрия не нужна, I11), build-скрипт не одобрять.
- **Проверка префикса пути по сырому `req.url` обходится одним percent-символом**: роутер Fastify (find-my-way) декодирует путь при матчинге (`safeDecodeURI`), поэтому `/api/%64ocs` минует проверку `startsWith('/api/docs')` и попадает в защищаемый маршрут; путь перед сравнением декодируется один раз (при `URIError` — остаётся сырым: роутер его тоже не матчит). Любой префикс-гуард в посредниках — только после той же нормализации (подтверждено воспроизведением: валидация issue #19 нашла обход `/api/docs*` без токена).

- **Хендлер события, пишущий в дочернюю таблицу (FK) по id из payload, превращает удаление родительской строки в ЯДОВИТОЕ событие**: `notification.dispatch_requested` после чистки строки (удалённое сообщение #267) падал FK-нарушением в `notification_deliveries`, а EventDispatcher без потолка ретраев крутит неудачное событие КАЖДУЮ секунду вечно (лог «Event dispatch failed, will retry»; поймано интеграционным прогоном). Правило: событие второго порядка обязано переживать исчезновение своего источника — pre-check существования строки перед записью по FK + тест на отсутствующую строку. (воспроизведением, #267)
- **Идемпотентность-реплей ответов с токенами отдаёт истёкшие access-токены**: TTL кэша 24 ч (ADR-0005) >> TTL токена 15 мин; фиксированный `Idempotency-Key` на логине (например, в k6-скриптах) после первой реплики шлёт шторм 401. `/api/v1/auth/*` исключён из кэширования интерсептором (правка #58); в тестах/нагрузке ключи логина всегда уникальны за прогон. Воспроизведено k6-прогоном 24.09.2026 (#58: 100% реплеев — истёкшие JWT при валидной подписи, проверено декодированием).
- **`nest start --watch` не загружает .env** — dotenv живёт только в prisma.config.ts (для CLI Prisma); локальный запуск api требует экспорта: `set -a; source <(grep -E '^(DATABASE_URL|REDIS_URL|JWT_SECRET)=' .env); set +a; API_PORT=<порт> pnpm --filter @nodus/api dev` (воспроизведено 24.09.2026, #58). Порт 3001 занят контейнером демо — брать соседний.
- **Prisma `@updatedAt` не создаёт DEFAULT в БД** — значение проставляет клиент Prisma; сырой `INSERT ... ` мимо клиента обязан подставлять `updated_at = now()` сам, иначе NOT NULL-нарушение (P2010/23502). Подтверждено docs.prisma.net (updatedAt «managed by Prisma Client», DDL без default) + воспроизведено 24.09.2026 на raw-вставках чата (#58).
- **`prisma migrate dev` в неинтерактивном окружении виснет/абортит** (detected drift → interactive confirm), а убитый процесс оставляет за собой advisory-lock `pg_advisory_lock(72707369)` и висячие коннекты — следующий migrate падает по таймауту лока. Лечение: детерминированный путь `prisma migrate diff --from-config-datasource --to-schema ... --script` → ручная папка миграции (дополнения вроде partial index — руками, Prisma их не декларирует) → `prisma migrate deploy`; застрявшие локи — `pg_terminate_backend` по `pg_stat_activity`. Подтверждено pris.ly/d/migrate-advisory-locking + воспроизведено 24.09.2026 (#58).
- **Кириллический пароль в DATABASE_URL**: реальный пароль демо-стека — «замените-на-случайный-пароль» из .env.example (владелец не заменил плейсхолдер); Git-Bash sed/extraction на хосте искажает многострочные подстановки (cp866), а Prisma не энкодит не-ASCII в userinfo сам. Байт-точная синхронизация .env — нодой из `docker inspect`; .env.example стоит заменить на ASCII-плейсхолдер (воспроизведено 24.09.2026, #58).
- **Дрейф schema.prisma ↔ миграции**: `Session.userAgent` без `@map("user_agent")` при колонке `user_agent` в миграции — сгенерированный клиент пишет в несуществующую колонку `userAgent` (P2022), live-логин падал бы с 500 (e2e на моках этого не видел). Правка `@map` + `pnpm --filter @nodus/api db:generate` обязательна после ЛЮБОЙ правки map-атрибутов. Найдено 24.09.2026 (#58), подтверждено миграцией 20260902134836.

## Realtime (WS-gateway, Socket.IO, Redis Streams)

- **Новое доменное событие = ТРИ точки подписки, молчаливая третья (#171, воспроизведением 04.10):** событие публикуется в outbox/стрим, gateway маршрутизирует его в комнату — но SPA-клиент слушает только перечисленные в `DOMAIN_EVENTS` (socket-client.ts: `client.on(event)` в цикле по списку); события вне списка приходят в сокет и ТИХО исчезают (ни ошибки, ни warn; поймано прямым socket.io-клиентом: событие в сокете есть, страница молчит). Новое событие: каталог contracts → ветка gateway fanout → СТРОКА в клиентском `DOMAIN_EVENTS` (+ кейс в socket-invalidation). (воспроизведением, #171)

- **Команды одного ioredis-соединения СТОЯТ за заблокировавшим его XREADGROUP BLOCK**: Redis, заблокировав клиента блокирующей командой, перестаёт читать его сокет — последующие команды этого же соединения (XADD из теста) исполняются только после истечения BLOCK (виделось как «доставка фанута ровно 5 с»); издатель и консьюмер обязаны жить на РАЗНЫХ соединениях/в разных процессах (воспроизведено #104, gateway-интеграционный тест: отдельное publisher-соединение).
- **Обработчики socket.io-client регистрируются ДО коннекта**: при тёплых кэшах сервер эмитит presence-snapshot в том же сетевом батче, что и CONNECT, — клиент диспатчит пакет синхронно, и слушатель, навешанный после `await connect`, опаздывает навсегда; в тестах — pre-registered listener, в реальном клиенте — обработчики при создании сокета (воспроизведено #104, gateway-интеграционный тест).
- **Auth сырого WS-клиента против Socket.IO едет payload-ом CONNECT-пакета, не query-параметром**: для websocket-транспорта (без polling-хендшейка) токен передаётся фреймом `40{"token":…}` (socket.io protocol v5: auth = данные CONNECT-пакета namespace'а) — так k6/ws говорит с сервером напрямую; заодно обязательны engine.io ping/pong фреймы «2»→«3» для долгоживущих сессий (воспроизведено спайком #104 `apps/gateway/perf/ws-spike.js`, latency 50 мс).
- **`transports: ['websocket','polling']` НЕ фолбэчится на polling при падении WS в современных браузерах** — порядок задаёт ПЕРВЫЙ транспорт, а фолбэк между попытками отсутствует (подтверждено socket.io docs «Client options» и discussion socketio/socket.io#3998): официальный паттерн — на `connect_error` транспортного характера ОДИН раз вернуть `['polling','websocket']` (реализовано в socket-client.ts, #104 раунд 2).
- **`useMessageScrollerVisibility` примитива MessageScroller видит только ПРЯМЫХ детей контента**: снапшот собирается по `content.children` c `data-message-id`, а ленты чата вкладывают строки в обёртки серий message-groups — список «видимых» всегда пуст (воспроизведено #104 раунд 2: квитанции просмотров не уходили); для viewport-механик по вложенным строкам — свой IntersectionObserver с root=скроллер (`use-viewport-read.ts`).
- **Реф-эффекты с deps `[id]` молча протухают при РЕМОНТЕ нативного элемента внутри того же компонента**: селект-режим композера размонтирует textarea, выход монтирует новую — эффект регистрации «вечного курсора» не перезапускался, registry держал отсоединённый узел, а `focus()` на detached-элементе НЕ бросает и НЕ работает (воспроизведено #104 раунд 2 «супер-курсор»; фикс — ref-колбэк вместо эффекта).

- **Prisma interactive-транзакция + ЛЮБОЕ чтение мимо tx-клиента = второе соединение пула**: чтение справочника (порт профилей) внутри `txRunner.run` шло через общий PrismaService — под пачкой параллельных отправок (repro chat-reliability: 10–20 одновременных send) транзакции занимают все соединения, вложенные чтения ждут свободного — таймаут tx 10 c и «Unable to start a transaction». Правило: всё, что читается внутри транзакции, читается ПО её клиенту (`findRefs(ids, tx)` в порту) или резолвится ДО её открытия (упоминания — текст известен заранее; воспроизведено раундом 3 чата 25.09).
- **Живой второй consumer группы `nodus:gateway` = тихая потеря событий чата** (воспроизведено k6-стрессом #117 26.09: ~20% сообщений «терялось», REST 201 + запись в стриме + XACK есть, но эмит не приходил НИ ОДНОМУ сокету): XREADGROUP раздаёт записи ЛЮБОМУ консьюмеру группы — забытый dev-gateway на хосте (`node --watch src/main.ts`, `REDIS_URL=redis://localhost:6379` — контур портов это допускает) забирает долю записей и ACK-ает их в никуда; pending=0, ошибок в логах нет, деградация невидима. Перед k6-прогонами/диагностикой потерь: `XINFO CONSUMERS nodus:chat:events nodus:gateway` — активен (idle < 10 c) должен быть ровно один `gateway-<pid>` контейнера; мёртвых чистим `XGROUP DELCONSUMER` (задел GC #117), живых-сирот ищем по XINFO+`Get-CimInstance Win32_Process` и убиваем деревом (taskkill /T /F — у `--watch` родителя ребёнок перезапустится). До фикса GC-задела детект сироты стоит в pre-flight любого нагрузочного прогона.
- **Не-ASCII символы в паролях из `.env` ломают URL-DSN, но не env-подключения** (воспроизведено пересборкой прода 26.09: контейнер api в рестарт-лупе P1000, при этом psql с PGPASSWORD работает): плейсхолдерный пароль с кириллицей («…замените-на-случайный-пароль») через `PGPASSWORD` аутентифицируется, а в собранном compose `DATABASE_URL` без percent-encoding — нет; старый контейнер жил, потому что env фиксируется при создании. Правило: секреты в `.env` — только ASCII/url-safe; после любой правки `.env` — `docker compose up -d <svc>` и проверка health.
- **INCLUDE-индекс PostgreSQL не моделируется Prisma — постоянный дрейф schema↔БД**: индекс `ON (conversation_id) INCLUDE (last_read_seq)` из миграции chat-core не выразим в schema.prisma, и каждый следующий `migrate dev` генерирует его DROP (можно незаметно прихватить в чужую миграцию — так и случилось в chat_thread_watch 25.09). Индексы, которых нет в схеме, держаться не могут: либо моделируемые индексы, либо осознанный DROP с комментарием в миграции (доступный путь покрыт PK; схема — истина).

## Десктоп (Tauri, apps/desktop)
- **Панель задач Windows берёт значок приложения из РЕСУРСОВ exe (bundle.icon), а не из рантайм-`set_icon`** — перекрас иконки окна кодом (и даже отложенный повтор после старта) не меняет то, что видно на таскбаре и ярлыке: они слушаются только картинки, вшитой в установщик; рантайм-перекрас меняет лишь иконку заголовка окна. Решение — единый статичный значок (плитка + белый знак), правки только перегенерацией `tauri icon` (воспроизведено живой приёмкой 09.10 #263: два раунда рантайм-перекраса не тронули таскбар).
- **Кэш иконок Explorer переживает замену exe: после смене иконки приложения ярлык и панель задач показывают СТАРУЮ, хотя exe уже несёт новую** (подтверждено: иконка установленного exe — новая, 93% непрозрачных пикселей; ярлык — старый). Гарантированного программного сброса нет — известная боль инсталляторов (Cendio bugzilla 7970: SHCNE_ASSOCCHANGED из NSIS не чинит закреплённый таскбар; MS Learn forums: `WM_SETICON`-манипуляции мимо). Рабочие сбросы: свойства ярлыка → сменить значок (вердикт владельца 09.10 «обновил в свойствах — всё изменилось»), `ie4uinit.exe -show`, перезапуск explorer с удалением iconcache*. Правило: смена иконки = редкое событие, сопровождать инструкцией (runbook desktop-deploy).
- **WiX-шаблон Tauri v2 УЖЕ создаёт ярлык рабочего стола** (`ApplicationDesktopShortcut` → компонент в `ShortcutsFeature`, просматривается в таблицах собранного MSI через COM `WindowsInstaller.Installer`) — свой WiX-фрагмент с `DirectoryRef Id="DesktopFolder"` (как в гайдах для v1) даёт ДУБЛЬ ярлыка; кастомный фрагмент нужен только для того, чего в шаблоне нет (подтверждено таблицами MSI 1.0.0/1.0.1, #263). UpgradeCode дефолтно выводится из `productName` (UUID v5, tauri-utils config.rs) — фиксировать значением, извлечённым из Property-таблицы собранного MSI, иначе переименование продукта = «второе приложение» у установленных машин.
- **tauri-plugin-updater: `platforms.*.url` парсится как АБСОЛЮТНЫЙ URL** (serde `Url` — относительный путь = ошибка парсинга манифеста), а target-ключ манифеста ищется по типу СВОЕЙ установки: `windows-x86_64-nsis` / `-msi`, затем fallback `windows-x86_64` (`get_urls`, 2.13.2) — манифест может нести оба канала без кросс-прыжков; `install()` делает `std::process::exit(0)`, `restart_after_install` по умолчанию `true` (NSIS `/R` сам возвращает приложение); http-эндпоинты отвергаются `validate_endpoints` без `dangerousInsecureTransportProtocol` (локальный http-цикл автообновления не проверить). Подтверждено исходниками плагина 2.13.2 (#263).
- **Свой `SW_SHOWNOACTIVATE` на окне Tauri ломает рендер попапа** — Windows рисует системную рамку с заголовком на непрозрачном чёрном фоне (вид «попап в попапе», живой вердикт 08.10 #254). Кражу фокуса подавляй только `WS_EX_NOACTIVATE` через `SetWindowLongPtrW(GWL_EXSTYLE)`; показ — штатный `win.show()`.
- **WebView2 при `win.hide()` НЕ меняет `document.hidden`** — `visibilitychange` не стреляет: квитанции просмотров чата и гейты «фона» обязаны переключаться по сигналу `shell-visibility` оболочки (desktop-bridge → flush квитанций), иначе хвост остаётся непрочитанным («зомби-бейдж» #254, воспроизведено и починено 08.10).

- Создание `WebviewWindow` в СИНХРОННОЙ tauri-команде дедлокит WebView2 — окно висит на `about:blank` и держит foreground Windows (пользователь не может активировать другие окна!): команды, создающие окна, — только `async fn` (docs.rs WebviewWindowBuilder «Known issues», tauri #13963/#13092; подтверждено живым репро 08.10 #254).
- Наличие каталога `src-tauri/permissions/` включает строгий AppManifest-режим: КАЖДАЯ команда приложения (включая локальный мини-UI) требует явной capability — «command not allowed. Command not found» даже для локальных страниц (tauri 7a2672f; репро #254).

## Фронтенд (React, Tailwind)
- Замер просмотрщика изображений: «картинка загрузилась» ≠ «картинка показана» — naturalWidth/complete/opacity могут быть идеальны при rendered-боксе, сжатом под потоковую миниатюру (контейнер `inline-flex` сжимается по содержимому, `max-w/max-h` НЕ растягивают; #221: natural=2400 при client=800×533). Вердикт приёмки — по `getBoundingClientRect()` изображения, не по natural-полям (подтверждено воспроизведением пробы #221, 06.10).
- Плитки ленты НЕ грузят оригинал изображения при отсутствии миниатюры (#221): `thumbnailUrl ?? url` в `<img>` ленты — мегабайты в пузыре и «висящая» картинка после отправки; оригинал грузит только лайтбокс по клику, лента живёт на серверном WebP-превью, фоновая готовность — событием `chat.attachment_preview_ready` (канон Zulip thumbnailing: спиннер до готовности воркера, docs/subsystems/thumbnailing.md; подтверждено исследованием #221).
- **Список поверхностей ПКМ-меню (`message-menu.tsx` onContextMenuCapture) — точка расширения:** новая вариация сообщения без слота из списка (`bubble-content`, `post-surface`, `message-tombstone`, `sticker-surface`, `media-message`) = контекстное меню ТИХО не открывается на ней (stopPropagation для «пустого места строки»); до #171 bare-медиа (своё фото без пузыря, #187) не имело слота в списке — меню было недоступно на нём вовсе. Добавляя новый data-slot поверхности сообщения — проверять список. (воспроизведением, #171)

- **Ховер-пилюля с отрицательным полем внутри truncate-контейнера режется клипом на КОРОТКОЙ стороне (#269):** кнопка-название с `-mx` + `rounded` + `hover:bg` внутри `overflow-hidden`-обёртки (усечение для многоточия) вылезает полем за клип-границу; когда соседний текст (подпись) длиннее названия, контейнер шире пилюли и её левое скругление срезается в прямую вертикаль, правое остаётся мягким — асимметрия зависит от ДЛИНЫ СОСЕДНЕГО текста, не кнопки. Канон: `-mx` раздвигающего клип живёт на ОБЁРТКЕ, усечение (`truncate w-fit max-w-full`) — на самой кнопке (conversation-bar.tsx; воспроизведено живой приёмкой владельца, механика — CSS overflow: клип по padding-краю контейнера).

- **Пиксельная идентичность двух линий возможна только в ОДНОМ механизме отрисовки (#155, 8 раундов):** CSS (box-shadow/border) и SVG-штрих каждый по-своему округляют координаты к физическим пикселям — на целых зумах совпадают (вводит в заблуждение), на дробных расходятся принципиально, это не баг, а свойство. Идеальный стык «пузырь+хвост» получился только когда ВСП (заливка И граница) стал одним SVG-путём на весь силуэт. Правило: требуется пиксель-в-пиксель — рисуй одним растеризатором; стык двух механизмов «подгонкой констант» не лечится. Полезные числа из блужданий, вошедшие в итог: глубина кольца [1,2]css (inset-тень рисуется под прозрачной рамкой 1px), вертикальная касательная на входе кромки, продление полосы по низу (заливка хвоста перекрывает полосу пузыря), device-снаппинг рёбер (round(rect×dpr)/dpr), полу-штрих SVG центрируется на контуре (внутрь = ширина/2). **Реинкарнация в #187 (раунд 14):** плавник медиа-части, нарисованный ОТДЕЛЬНЫМ svg рядом с CSS-фоном части, на 125/175/200% «разъезжался вертикальной линией» — нижняя часть переведена на Bubble+BubbleOutline (один путь); отдельный BubbleFin удалён.

- **absolute right-0/bottom-0 на блоке с собственным padding даёт 0px от КРАЯ (#187, раунды 6–8):** abs-pos отсчитывается от PADDING-бокса якоря (внутренний край рамки), а не от контентного — если несущая padding (px-2.5) сама является якорем, метка прилипает к внешнему краю; если якорь — вложенный контентный блок, метка уезжает ВНУТРЬ на двойное поле. Канон: якорь = элемент, растянутый на ширину ПОВЕРХНОСТИ (пузырь/часть/блок-карточки), инсеты от края задавать явно. Подтверждено CSS-спекой (CSS 2.1 §10.1: containing block = padding edge).

- **overflow-hidden НЕ клипает абсолютного потомка с внешним containing block (#187, валидатор):** клип-спан (overflow-hidden + border-radius) обязан быть `relative` — иначе absolute-щит селекта (inset-0) якорится к внешнему фрейму и красится КВАДРАТОМ поверх скруглённых углов картинки. Механизм: CSS-overflow не применяется к abs-pos, чей containing block вне клип-контейнера (CSS 2.1 §11.1.1). Общий вывод: абсолют-оверлей внутри клипа = явный `relative` на клипе.

- **Метка времени «уголком» без обрезки узких карточек — пара «призрак+булавка» (#187, раунды 7–11):** чистый absolute не участвует в shrink-to-fit (карточка из 1 символа ОБРЕЗАЕТ метку), флоат топится к верху line-box, а на своей строке (только флоат) линия нулевой высоты — метка проваливается без зазора; чистый inline садится сразу за текстом и слева на своей строке. Решение: невидимая КОПИЯ меты в потоке (резервирует точную ширину, без замеров — состав меты меняется сам) + видимая absolute от края с явными инсетами. Зазор текст→мета живёт на призраке (ml-14px): перенос «метки на свою строку» происходит автоматически, когда текст+зазор+призрак не влезают.

- **fit-content пузырь + процентные размеры детей = схлоп до загрузки** (#150, подтверждено research Telegram tdesktop/FB Messenger): `w-full`/`aspect-ratio` внутри `w-fit`-контейнера не дают вклада в intrinsic-ширину, незагруженный `<img>` = 0×0 → контент прыгает при доскролле (lazy). Лечится ЯВНЫМИ px из сохранённых габаритов (fit-в-бокс, «не апскейлим мелкое» — модель FB Messenger); ширина пузыря с вложениями задаётся блоком вложений, текст переносится (captionw = _maxw − padding, Telegram).

- Эндпоинт конфигурации, нужный реестру на буте (office-config #138), должен быть `@Public`: запрос до логина с Bearer-получением 401 кэширует «движок выключен» на staleTime, и все офисные вложения тихо едут в фолбэк до рефеча.
- **`dark:`-утилиты Tailwind в проекте НЕ применяются** (мертвый код): вариант объявлен на класс `.dark` (`@custom-variant dark (&:is(.dark *))` в globals.css), а тема переключается АТРИБУТОМ `data-theme='dark'` на `<html>` (index.html/app-shell) — селектор `.dark *` никогда не матчится. Проверка замером: под `[data-theme='dark']` computed-стиль элемента с `bg-muted dark:bg-accent/60` остаётся `--muted` (#96). Следствие: тона обеих тем — ТОЛЬКО токенами (`--chat-zone`, семантика в globals.css); попутно многие `dark:`-классы в shadcn-примитивах (switch, button, bubble) фактически не работают — чинить точечно при касании, не разом.

- **Ширина кастомного DialogContent: голый `max-w-*` НЕ перебивает дефолт с вариантом (`sm:max-w-sm` у dialog.tsx)** — tailwind-merge считает классы с разными вариантами разными группами конфликта; на десктопе панель остаётся 384px и широкий контент вылезает за её фон («фон не покрывает»); канон: `className="w-full sm:max-w-2xl"` (тот же вариант + w-full). Воспроизведено скриншотом (#69), фикс в четырёх диалогах корреспонденции/контрагентов.

- **`animationend` всплывает**: обработчик `onAnimationEnd` на контейнере ловит завершение CSS-анимаций всех потомков — фильтруй по `event.animationName`, иначе дочерняя короткая анимация (напр. draw-on 450мс) преждевременно «завершит» логику родителя (подтверждено воспроизведением: док-ребро слайдера исчезало до кадра, issue #4).
- **SMIL `<animateMotion>` не стреляет DOM `animationend`** — для «один пробег и убрать» таймаут/JS, не событие; перемонтирование через `key` перезапускает SMIL-анимацию надёжнее, чем смены атрибутов.
- **SMIL `<animateMotion>` с `begin > 0` и без `fill="freeze"` показывает элемент в (0,0)**: до старта движения и после окончания пробега анимируемый кружок возвращается в начало координат SVG — виден как «светящийся пиксель» в левом верхнем углу экрана. Лечение: `fill="freeze"` на animateMotion (остаётся в конце пути) + стартовый `opacity={0}` с `<animate attributeName="opacity">` на момент begin (подтверждено воспроизведением: пиксель в углу при каждой вспышке контура, issue #4; механика — модель времени SMIL: до begin и после активной длительности значение не применяется).
- **`transitionend` приходит на КАЖДОЕ свойство и всплывает**: цикл покадрового слежения за transition панели глохнет от `transitionend` посторонних коротких анимаций (затухание текста 200мс против движения панели 300мс) — запуск и остановку фильтруй по `event.propertyName` (у нас — только `'width'`; подтверждено воспроизведением: контур «отставал» от правой панели на последние ~100мс, issue #4).
- **transition на треке сетки с drag-ресайзом = фризы**; и даже БЕЗ transition `setState` на каждый pointermove/rAF-кадр гоняет ре-рендер всего дерева (сообщения, поля, панели) — на реальных машинах это видимые лаги. Канон ресайза (подтверждено react-resizable-panels issue #310, bvaughn + замерами issue #4): во время drag ширина выставляется ИМПЕРАТИВНО (`el.style.width` через ref в rAF-лупе), React-state и persist — один раз на pointerup; transitions — только для программных toggle, на время drag сняты флагом (`!dragging && 'transition-[width]'`); «панель выталкивает соседа» = две синхронные transition-[width] (растёт одна — на ту же величину суется соседняя, сумма постоянна); тяжёлые дети (обсуждение, поля, панели) — memo + стабильные колбэки. Итог замера: 0 лонгтасков, ~60 fps, ширина следует за мышью 1:1.
- **vite: добавление `export *` в barrel на живой dev-сессии залипает модульный граф** — свежая страница падает с `SyntaxError: does not provide an export named …` при корректных исходниках; лечится перезапуском dev-сервера (не правь код вслепую; подтверждено воспроизведением в issue #4, mocks/data/tasks.ts).
- **fr-колонка слева от ресайзимых ломает drag-ресайз таблицы**: в grid `… 1fr …` при изменении фиксированной колонки резиновая компенсирует дельту — ручка отрывается от курсора, колонка визуально «растёт не в ту сторону» (компенсация меняет её ЛЕВУЮ грань). Ресайзимая таблица — только с фиксированными px-треками (включая колонку названия), контейнер `w-max min-w-full` + `overflow-x-auto` (модель Битрикса: пустое место справа, переполнение — скролл; подтверждено воспроизведением: ручка «Стадии» инвертировала drag, issue #4).
- **Эталон ресайза колонок (AG Grid / Excel):** drag меняет только свою колонку, соседние сдвигаются не меняя ширины (переполнение — скролл); защиты — `minWidth` под осмысленный контент (контент не «спрятать») и `maxWidth` (не «растянуть навсегда»), сужение — с ellipsis; **dblclick на ручке = автоподбор по контенту**. Измерение контента для автоподбора — по ДЕТЯМ ячейки: `scrollWidth` самой ячейки не бывает меньше её `clientWidth` и возвращает текущую ширину трека (подтверждено: доки AG Grid column-sizing, воспроизведение в issue #4).
- **dnd-kit multi-container: «Maximum update depth» при ховере у границы колонок** — осцилляция onDragOver (переложил в B → раскладка сдвинулась → под указателем снова A → переложил обратно) плюс setState с НОВОЙ ссылкой массива при идентичном порядке топливают цикл измерение→setState (measureRect в layout-эффектах). Предохранители, не меняющие поведение: анти-осциллятор (кадр после межколоночного переноса игнорируем, сброс rAF-ом) и гейт `isSamePlacement` (идентичное размещение не создаёт состояния); трансформ sortable у активного элемента обязателен (иначе слот не едет за пересортировкой), но именно он же даёт обратную связь rect→проекция — держим оба предохранителя. Подтверждено воспроизведением: стресс «дрожание на границе колонок/слотов + серийные дропы» — 0 ошибок после предохранителей (issue #36).
- **dnd-kit: дроп в пустую колонку «не применяется» — ДВА механизма сразу** (вердикт владельца в #4, воспроизведено пробой debug-dnd: две пустые колонки подряд, дроп во вторую падал в первую). (1) **Активная карточка затеняет колонку в pointerWithin**: `useSortable` НЕ отключает droppable активного элемента (sortable.esm: `useDroppable({disabled: disabled.droppable})` без учёта isDragging), а её rect едет за указателем (sortable-трансформ); `pointerWithin` сортирует кандидатов по среднему расстоянию до УГЛОВ rect (core.esm) → мелкий rect карточки под курсором всегда ближе секции колонки → после живого переезда в первую пустышку следующая пустая колонка затенена навсегда. Лечение: активный id исключён из кандидатов в `makeKanbanCollision` (pointerWithin/rectIntersection/closestCenter). (2) **Гейт только по порядку id глотал setState**: переезд между пустыми колонками ставит задачу в конец плоского массива оба раза → порядок id совпадает → `isSameOrder` пропускал обновление, стадия в состоянии не менялась, PATCH уходил со старой колонкой (а у последней задачи массива глотался даже первый переезд в пустую колонку). Лечение: `isSamePlacement(a, b, axis)` сравнивает id И колонку по оси. Регрессионные тесты: `kanban-collision.test.ts`, `kanban-board.test.ts` (подтверждено: исходники @dnd-kit/core 6.3.1 / sortable 10 + проба — после фиксов дроп во вторую пустую колонку точен).
- **Фризы канбана на объёме = reflow, не рендер и не замеры:** межколоночный перенос физически переставляет DOM-узел карточки → reflow обеих колонок со всеми СМОНТИРОВАННЫМИ карточками (121 карточка: 19 longtasks / 1495 мс headless, первый 203 мс); внутри колонки sortable сдвигает соседей CSS-transform'ами (compositor) — 0 longtasks. memo-карточки и смена MeasuringStrategy НЕ помогают (замерено: 18/1544 в обоих пробах) — стоимость ∝ числу смонтированных узлов. Структурный фикс — виртуализация окна колонки (@tanstack/react-virtual): скрытые карточки не «доезжают» — рендер читает порядок из состояния на заказ, «момента схождения» нет; скролл с зажатой карточкой = ограниченные тики домонтажа overscan. Дизайн и критерии приёмки — issue #36 и навык nodus-ui-style (раздел DnD).

Канон: keyframes `slider-expand` с CSS-переменными FLIP (globals.css); WAAPI оставлен только для закрытия (элемент уже отрисован, работает везде). Любое paint/layout-свойство в keyframes (morph border-radius) декомпозитит ВСЮ анимацию на main thread — она фризится синхронным маунтом контента панели на первом открытии (подтверждено: web.dev «Why are some animations slow» — композитор выполняет только transform/opacity; замером — первое открытие 0 longtasks после удаления morph).

- **1px-линии SVG разной яркости («хвостики ярче шины» при зуме ≤ 100%)** — два механизма, оба не лечатся правками «0.5px/DPR» наугад: (1) самопересечения подпутей одного path (подходы отводов/засечек лежат на шине/оси) композитятся дважды, если прозрачность сворачивается в alpha кисти: Chromium фолдит opacity элемента/группы в кисть, КОГДА элемент без собственного композитного слоя — лечится CSS-opacity на отдельном svg + `will-change: opacity` (форс слоя: буфер рисуется полным alpha, opacity — на композите); `<g opacity>` и svg-opacity БЕЗ will-change не помогают (замерено: 130 в перекрытии против 82 на чистой линии → после will-change 82/82); (2) линия с центром на целой device-координате размазывается на две полупрозрачные полосы (тусклая), на дробной — хрустит одной (яркая); при зуме > 100% все координаты дробные и разница исчезает. Лечение — снап прямых координат к полупикселю устройства: `snapPx()` из `@nodus/ui/components/node-edge` (devicePixelRatio учитывает зум браузера); подтверждено пиксель-замером скриншотов (альфа-профили и 2D-патчи углов) в issue #4.

Канон: мышь открывает панель по `onClick` (слой монтируется ПОСЛЕ события — как у Trigger), клавиатура/программный focus — по `onFocus` с указательным гардом (`onPointerDown → ref=true; onFocus → if (!ref.current) open(); onClick → ref=false; open()`); автофокус контента отменять (`onOpenAutoFocus` prevent) — печатать можно сразу. **Зеркальный случай:** панель УЖЕ открыта, повторный клик по якорю — дисмисс по pointerdown-outside запланирован нативным событием и добивает ПОСЛЕ нашего onClick-переоткрытия (инверсия бэтчинга React: нативный апдейт флашится после дискретного); лечение — `onInteractOutside` на Content с `preventDefault`, когда цель внутри якоря (тот же приём, что Radix применяет для Trigger в PopoverContentNonModal). Подтверждено: исходники `DismissableLayer` (`usePointerDownOutside`/`useFocusOutside`) и `PopoverContentNonModal` (radix-ui/primitives) + issue radix-ui #3598 + MutationObserver/лог-замеры в наших пробах (issue #4).

- **Кликабельная карточка с интерактивными детьми — НЕ `<button>`** (урок thread-feed, аудит #45): `<button>` по спецификации HTML не может содержать interactive content — галерея/реакции внутри дают hydration-ошибку «button cannot be a descendant of button», а клик по вложенному контролу вызывает ОБА обработчика (лайтбокс И тред открывались вместе). ## Процесс и документация

- ADR нумеруются плотно, без дыр: перед созданием нового — проверь max существующего номера (`ls docs/adr/`), не присваивай «следующий с конца + запас».
- `gh api .../branches/main/protection`: поле `restrictions` обязательно (передавать `-F restrictions=null`), булевы значения — только через `-F` (через `-f` уходит строка и API отвечает 422 «not a boolean»).

- **Незакоммиченное рабочее дерево «ездит» за git switch/checkout**: неподконфликтные между ветками локальные правки сохраняются при переключении (git-scm git-checkout: «Uncommitted changes will otherwise be kept») — параллельная сессия, сменившая ветку, утаскивает чужую незакоммиченную фичу с собой. Правило: коммить на свою ветку НЕМЕДЛЕННО после правок (канон — локальный коммит до вердикта, push после; грязное дерево между правкой и коммитом — процессная ошибка), перед каждым коммитом сверяй `git branch --show-current`, параллельная сессия живая — только отдельный worktree (`git worktree add`). Воспроизведено 24.09.2026: дерево линии A (#87) уехало с feat/87 на fix-ветку хотфикса #88 и далее на main; повторено 03.10.2026 (#204): 20 минут правок без коммита — коммит лёг на чужую ветку и уехал в main чужим squash-PR #205.
- **Revert-ветка для чистки main плодить ТОЛЬКО от текущего main**: дифф PR GitHub считает от merge-base — ветка, ответвлённая ДО случайного сквоша, показывает в PR только свои коммиты (hotfix), а чужой WIP в main не убирает; squash применяет ровно то, что в диффе. Репро 30.09: #159 (ветка от fa935fe) не убрал WIP-стикеры из сквоша #158, потребовался честный `git revert <sha-WIP>` от origin/main (#160; механизм — docs.github.com «comparing branches», трёхточечный дифф).
