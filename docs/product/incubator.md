# Инкубатор идей — единый вход для «хотелок»

Место, где идеи владельца и руководства живут **до плана**: обсуждаем, критикуем, дружим между собой — и только устоявшееся уходит в roadmap. Это НЕ план и НЕ канон: агенты-исполнители задач этот файл не читают; из него не меняются roadmap и issues.

## Правила

- Любая идея/хотелка, прозвучавшая в разговоре с владельцем, → сначала **полноценное обсуждение и критика в том же разговоре** (за/против/риски/вопросы/альтернативы), затем итог — запись сюда **тем же днём**. Правки roadmap/issues «на горячую» — запрещены.
- Запись: суть (близко к словам владельца) → разбор агента (за / против / риски / открытые вопросы) → связи с другими идеями → статус.
- Статусы: **обсуждается** · **зреет** (не сейчас, вернёмся) · **в план** (→ ссылка на roadmap-кейс или issue) · **отклонено** (с причиной — чтобы не возвращаться к отвергнутому вслепую).
- Продвижение в план — только на **разборе инкубатора** с владельцем (обычно недельный цикл): пачкой, одним решением, одним обновлением roadmap.
- Правки этого файла — не «фиксация документации»: коммитятся свободно как chore, без issue, PR и вердикта владельца (черновик, не канон).
- Внешние входы (интервью, переписки, обсуждения с руководством) сначала — саммари в `docs/product/interviews/`; оттуда живые темы попадают сюда короткими записями со ссылкой.

**Суть:** при регистрации ИИ сам предлагает тему/номер/дату — из тела письма и из вложений (реквизиты подрядчика живут в приложенных файлах). Боль: письма ПассатПроекта сегодня несопоставимы с входящими.
**Разбор:** сильная экономия канцелярии; но до живой почты (#56) нечего автозаполнять. Паттерн «ИИ предложил → человек подтвердил» общий со всей ИИ-тематикой. Открытый вопрос: какие форматы вложений читать в первой версии (PDF? сканы — OCR или нет?).
**Связи:** семантический поиск (ниже); источник — интервью 23.09.
**Статус:** обсуждается.

### 2026-09-23 · Семантический поиск по письмам
**Суть:** искать по смыслу/ключевым словам, индексируя содержание писем, вместо ручного заполнения полей. Референс — опыт CSR Match Online.
**Разбор:** закрывает боль «невозможно найти письмо подрядчика»; одна векторная инфраструктура (VectorStore, I13) на поиск и на будущую базу знаний. В декабрьский скоуп не лезет — но архитектуру хранения тел писем продумать заранее. Вопрос: скоуп — только письма или сразу всё?
**Связи:** база знаний ИИ; автозаполнение.
**Статус:** обсуждается.

### 2026-09-23 · Граф цепочек писем (канвас)
**Суть:** визуализация переписки «наш ответ → ответ заказчика → письмо подрядчика» как канваса карточек со связями.
**Разбор:** прямое попадание в node-UI и EntityLink; отдельная экранная механика, немалая. Кандидат после запуска декабря. Ценность растёт при связи с накладными (судьба документа видна на том же графе).
**Связи:** учёт передачи документации.
**Статус:** обсуждается.

### 2026-09-23 · Учёт передачи документации (накладные)
**Суть:** видеть судьбу выданного документа (направили → согласовали → загрузили → выдали, накладная №) без перещёлкивания десятков накладных вручную. «Таблички ГИПов» → единый бизнес-процесс.
**Разбор:** самая «дорогая» боль из интервью; требует рабочей сессии с ГИПами (мини-спека по конвейеру process-discovery) до любых решений. Зависит от файлов/документов и корреспонденции.
**Связи:** граф писем; источник — интервью 23.09.
**Статус:** обсуждается (нужна сессия с ГИПами).

**Связи:** #38, #39 (уже в roadmap как V2).
**Статус:** обсуждается.

### 2026-09-23 · ИИ-база знаний с кураторами (позиция по шифрованию)
**Суть:** без сквозного шифрования — осознанно; локальный ИИ читает переписку/новости/документы и наполняет базу знаний; куратор темы подтверждает записи; подача анонимная («А и Б обсудили → резюме»), чтобы не отпугнуть сотрудников.
**Разбор:** флагман V3; требует накопленных данных (то есть успешного декабря) и векторной инфраструктуры. Позицию «данные принадлежат компании» зафиксировать в non-functional при проектировании безопасности. Кейс КМ/КМД показал: ценность = доступ ИИ ко всем данным в одной системе.
**Связи:** семантический поиск; калькулятор сроков (уже в roadmap V3).
**Статус:** обсуждается.
