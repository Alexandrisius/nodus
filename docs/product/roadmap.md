# Roadmap — мастер-план разработки Nodus

Единственная точка, где живёт стратегический план: куда движемся, из чего состоит путь и что уже пройдено. **Правило «нет issue вне roadmap»**: каждый issue — дочерний к бизнес-кейсу этой таблицы (или chore/bug-заготовка). Агент сверяется с этим документом при создании и нарезке issues.

Читать: при планировании, создании issues, вопросах «что дальше» и «зачем это».

## Как устроена работа с планом

- **Бизнес-кейс** — строка таблицы вехи + issue с лейблом `type:epic` (чеклист дочерних issues в описании). Создаётся только с одобрением владельца (это продуктовое решение).
- **Эпик-issue** — контейнер: ценность для бизнеса, критерии завершения кейса, чеклист дочерних issues со ссылками. Сам эпик кодом не закрывается — только дочерними issues.
- **Статусы (закрытый словарь):** `запланирован` / `в работе` / `готово` — других значений не вводим; уточнения — в скобках («запланирован (следующий, P0)»). Статусы обновляются тем же PR, который закрывает эпик (или меняет состав вехи) — устаревший roadmap = баг (I12).
- **Владелец** управляет roadmap (приоритеты, новые кейсы, вынос за рамки); **агент** нарезает эпики на issues и предлагает изменения плана комментарием в эпике.
- Детали продукта — `vision.md`; объём MVP — `docs/mvp/` (временно); этот файл — статусы и порядок, а не спецификации.

### Шаблон эпик-issue

```markdown
## Бизнес-кейс M<N>: <название>

**Ценность:** <зачем это бизнесу, одной-двумя фразами — из таблицы roadmap>
**Критерии завершения кейса:** <как поймём, что кейс закрыт целиком>

### Дочерние issues
- [ ] #N — <название>
- [ ] #N — <название>

Новые дочерние issues добавляются сюда при нарезке; закрытие эпика =
все дочерние готовы + статус кейса «готово» в roadmap.md тем же PR.
```

## Вехи

| Веха | Цель | Критерий завершения |
|---|---|---|
| **MVP** (8–10 недель) | «Жизнь после Битрикса» для пилотного отдела | Поток «письмо → поручение → закрытие» e2e; все кейсы MVP готовы; аудит безопасности/производительности пройден |
| **Пилот** | Один отдел работает в портале ежедневно | Метрики: регистрация письма с поручением ≤ 30 с; согласование переработки ≥ 50% быстрее; пиковый профиль k6 выдержан |
| **V2** | Вся компания + автоматизации | Миграция остальных отделов; автоматизации по подтверждённым процессам; AD/LDAP при требовании |
| **V3** | ИИ поверх накопленных данных (C10) | Self-hosted ИИ: суммаризация, ассистенты, модель сроков; ЭЦП при подтверждённом объёме (C4) |
| **Платформа** | Отраслевой контур | CDE-хранилище, BIM-элементы как адресуемые объекты, интеграции NormaCore/VectorSearch |
