# Roadmap — мастер-план разработки Nodus

Единственная точка, где живёт стратегический план: куда движемся, из чего состоит путь и что уже пройдено. **Правило «нет issue вне roadmap»**: каждый issue — дочерний к бизнес-кейсу этой таблицы (или chore/bug-заготовка). Агент сверяется с этим документом при создании и нарезке issues.

Читать: при планировании, создании issues, вопросах «что дальше» и «зачем».

## Как устроена работа с планом

- **Бизнес-кейс** — строка таблицы вехи + issue с лейблом `type:epic` (чеклист дочерних issues в описании). Создаётся только с одобрения владельца (это продуктовое решение).
- **Эпик-issue** — контейнер: ценность для бизнеса, критерии завершения кейса, чеклист дочерних issues со ссылками. Сам эпик кодом не закрывается — только дочерними issues.
- **Статусы (закрытый словарь):** `запланирован` / `в работе` / `готово` — других значений не вводим; уточнения — в скобках («запланирован (следующий, P0)»). Статусы обновляются тем же PR, который закрывает эпик (или меняет состав вехи) — устаревший roadmap = баг (I12).
- **Владелец** управляет roadmap (приоритеты, новые кейсы, вынос за рамки); **агент** нарезает эпики на issues и предлагает изменения плана комментарием в эпике. Новые идеи до плана живут в инкубаторе (`incubator.md`); план меняется только решением владельца на разборе инкубатора.
- Детали продукта — `vision.md`; сценарии — `core-flows.md`; объём MVP — `docs/mvp/` (живые рабочие документы + `archive/`); этот файл — статусы и порядок, а не спецификации.

## Дедлайн: замена Битрикс24 — 20.12.2026

До декабря весь план подчинён одному: компания переходит с Битрикса до окончания подписки **20.12.2026** (~12,5 недель от 23.09; в бюджете ~месяц параллельной работы двух систем). В Битриксе активны только мессенджер и задачи/проекты; файлов в облаке практически нет; после отключения Битрикс остаётся read-only-архивом. Планка качества: мессенджер Битрикса хороший — наш не хуже.

**Решения владельца (вердикты 23.09.2026):**

- До начала декабря всё живёт на стейджинге (ПК владельца, nodus.by); VPS не поднимаем и не платим. К запуску боевой контур остаётся на ПК владельца для 170 сотрудников (#474, эпик M14 #476; вердикт 21.10); VPS-коробка — позже (V2).
- **Бэкенд стартует только после карты процессов MVP** от владельца: процессы могут изменить UI (кнопки, шаги) и контракты. Карта чертится только для MVP-скоупа, не подробная. **Исключение (вердикт 23.09): чат-ядро** — стартует до карты (границы в #58: без «в задачу», автоканалов проектов, чатов задач/писем; вложения после #57).
- Пока чертится карта: полировка UI на моках как контракты бэкенда (ADR-0001: zod-схема → мок → экран) и фронтовая механика (#48); detail = полнота состояний, не количество экранов; экраны, которые карта может перекроить, не вылизываем.
- Чат-мелочи декабря — скоуп в #41 (оценки и резка — там же; невлезшее — «после запуска»).
