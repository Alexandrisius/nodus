# Ключевые потоки

Сценарии, которые демонстрируем на защите концепта и которые обязаны проходить e2e-тестами. Поток А — центральный сценарий продукта.

Читать: перед проектированием любого из затронутых модулей и перед написанием e2e-тестов.

## Поток А. Входящее письмо → резолюция → поручения (главный; ADR-0027)

1. Письмо приходит на общий ящик → забирается по IMAP → появляется во вкладке «Новые» (видит только канцелярия; отправитель, тема, дата, вложения на месте; исходный .eml хранится). Канцелярия: «Зарегистрировать» (корреспондент из CRM, подписант, их № и дата, тема, способ поступления, проект — необязательно, адресат — один руководитель, «приложенные письма», «конфиденциально») → номер серии «Вх» без пропусков; или «Закрыть без регистрации» с причиной; спам удаляется без хранения. Цель — ≤ 30 секунд на регистрацию.
2. Адресат пишет резолюцию: «На исполнение» (текст, конкретный ГИП, один срок) — письмо становится долгом ГИПа «Расписать поручения»; «Расписать сразу» — поручения на конкретных людей; «Для ознакомления» — получатели жмут «Ознакомлен», после последнего письмо закрывается само.
3. ГИП создаёт из карточки письма поручения — полноценные задачи (исполнитель, соисполнители, наблюдатели, срок, проект и узел письма по умолчанию) — или отмечает «Поручения не требуются» с причиной. Исполнители работают в задачах с трекингом времени; итоги поручений падают блоками в чат письма, часы суммируются в письмо.
4. Когда все поручения выполнены — статус «Ждёт закрытия»: закрывает только расписавший — «Ответ направлен» или «Отработано без ответа» с причиной. «Ответить» на входящем создаёт исходящее со связью «ответ на»; исходящее: черновик → (согласование) → подпись (ЭЦП в приложении Nodus или «на бумаге, скан приложен») → регистрация с номером в конце → отправка с общего ящика. Пересылка писем запрещена — вместо неё ссылка, разворачивающаяся в чате карточкой; обсуждение письма — внутренний чат.

## Поток Б. Сообщение → задача

В любом чате сообщение → «В задачу» → карточка с предзаполненным описанием и ссылкой на переписку → задача появляется мгновенно (оптимистично), участники чата видят системное сообщение со ссылкой на задачу.

## Поток В. Согласование переработки (тип «Переработка», ADR-0024/0025)

Сотрудник создаёт заявку формой типа (дата не в прошлом по часовому поясу компании, часы, проект, причина) → решающий по должности «зам директора по персоналу» разрешает или отклоняет с причиной (итог «отклонена») → заявитель указывает факт (дата и часы) → руководитель заявителя по оргструктуре подтверждает факт; одобрение может опоздать. Всё настраивается маршрутом типа в «Процессах», без кода; реестр типа — по подразделениям, людям, проектам, портфелям.

## Поток Г. Мгновенный чат

Сообщение доставлено онлайн-адресату < 200 мс; индикатор «печатает», двойная галка прочтения, офлайн-отправка с догрузкой (очередь на клиенте), синхронизация «прочитано» между вкладками/устройствами.

## Поток Д. Канал проекта (треды-новости)

Каждый проект АВТОМАТИЧЕСКИ получает канал в мессенджере (вердикт владельца 2026-09-10). Каждое сообщение канала — новость-тред: лента канала показывает корневые посты со счётчиком ответов и участниками; «провалиться внутрь» — обычный чат (корневой пост + ответы). Уведомления канала получают ТОЛЬКО участники конкретного треда и наблюдатели проекта — канал не спамит всю команду (анти-спам-политика; подписка на тред — по первому ответу). Правая колонка обсуждения карточки проекта рендерит тот же канал (единый механизм, без второй реализации). Список бесед мессенджера — единый по активности, без секций (вердикт владельца, раунд 2); обсуждения задач собраны в отдельный подраздел топбара «Чаты задач» (открытие задачи — карточкой поверх, стек ADR-0009).
