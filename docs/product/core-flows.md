# Ключевые потоки

Сценарии, которые демонстрируем на защите концепта и которые обязаны проходить e2e-тестами. Поток А — центральный сценарий продукта.

Читать: перед проектированием любого из затронутых модулей и перед написанием e2e-тестов.

## Поток А. Входящее письмо → поручение (главный)

1. Письмо приходит на общий ящик → забирается по IMAP → появляется во «Входящих» с пустым рег. номером (отправитель, тема, дата, вложения уже на месте); очередь секретаря — пресет-фильтр «К регистрации» (отдельной папки «Незарегистрированные» нет — модель v2, вердикт 22.09.2026).
2. Секретарь: «Зарегистрировать» → карточка регистрации: тип Вх/Исх (из папки, сменяем), контрагент из справочника (создание «на лету»), проект, адресат (дефолт — ГИП проекта), срок, № и дата документа корреспондента, вид документа (дефолт «Письмо») → система присваивает рег. номер; письмо становится документом и попадает в Журнал корреспонденции. (Цель: ≤ 30 секунд на регистрацию.)
3. Письмо уходит адресату. Адресат выпускает резолюцию → 1..N поручений (исполнитель, срок, что сделать); каждое поручение = задача со ссылкой на письмо (цепочка Письмо → Резолюция → Поручение → Задача). Резолюция без поручения допустима («для сведения»).
4. Ответственный получает пуш + центр уведомлений, трекает время по задаче, закрывает. Статус документа: в работе → исполнено (все поручения закрыты) → в дело; просроченные — производный фильтр журнала. Пересылка писем запрещена — вместо неё ссылка (portal://), разворачивающаяся в чате карточкой-превью; обсуждение письма — внутренний чат (наружу не уходит).

## Поток Б. Сообщение → задача

В любом чате сообщение → «В задачу» → карточка с предзаполненным описанием и ссылкой на переписку → задача появляется мгновенно (оптимистично), участники чата видят системное сообщение со ссылкой на задачу.

## Поток В. Согласование переработки

Сотрудник создаёт заявку (дата, часы, проект, причина) → пуш руководителю отдела → «Согласовать»/«Отклонить» с комментарием → директор → кадры; заявитель видит прогресс по шагам, эскалация при простое шага > 2 рабочих дней. Процесс описан декларативно (JSON), без хардкода шагов в коде.

## Поток Г. Мгновенный чат

Сообщение доставлено онлайн-адресату < 200 мс; индикатор «печатает», двойная галка прочтения, офлайн-отправка с догрузкой (очередь на клиенте), синхронизация «прочитано» между вкладками/устройствами.

## Поток Д. Канал проекта (треды-новости)

Каждый проект АВТОМАТИЧЕСКИ получает канал в мессенджере (вердикт владельца 2026-09-10). Каждое сообщение канала — новость-тред: лента канала показывает корневые посты со счётчиком ответов и участниками; «провалиться внутрь» — обычный чат (корневой пост + ответы). Уведомления канала получают ТОЛЬКО участники конкретного треда и наблюдатели проекта — канал не спамит всю команду (анти-спам-политика; подписка на тред — по первому ответу). Правая колонка обсуждения карточки проекта рендерит тот же канал (единый механизм, без второй реализации). Список бесед мессенджера — единый по активности, без секций (вердикт владельца, раунд 2); обсуждения задач собраны в отдельный подраздел топбара «Чаты задач» (открытие задачи — карточкой поверх, стек ADR-0009).
