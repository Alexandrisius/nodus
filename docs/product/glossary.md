# Глоссарий

Доменные и технические термины проекта. Интерфейсная терминология — только русская деловая (см. `ux-principles.md`); таблица UI-строк — `packages/contracts/i18n/ru.ts`.

## Доменные термины

- **Поручение** — обычная задача (тип «Поручение» или любой рабочий тип), созданная из карточки письма исполнителем письма (ГИПом) или руководством при «Расписать сразу»; `source = letter`, проект письма по умолчанию (узел дерева — по выбору в форме); итог поручения падает блоком в чат письма, часы суммируются в письмо (ADR-0027).
- **Резолюция** — распоряжение адресата письма (руководителя): текст + один срок + ветка — «На исполнение» (исполнитель письма — конкретный ГИП, письмо становится его долгом «Расписать поручения»), «Расписать сразу» (поручения на конкретных людей) или «Для ознакомления» (получатели жмут «Ознакомлен»); у письма с поручениями кнопки «Ознакомлен» нет (ADR-0027).
- **Канал проекта** — чат, автоматически создаваемый для проекта; сообщения канала — новости-треды (поток Д, core-flows.md).
- **Тред (обсуждение)** — ветка ответов на сообщение канала (ровно один уровень: корень + ответы); UI-термин — «Обсуждение», уведомления — только участникам треда и наблюдателям.
- **Чат задачи** — беседа мессенджера, привязанная к задаче (`conversation.type=task`), — тот же движок, что у обычных чатов (канон владельца #252: двух чатов нет); состав = участники задачи; собраны во вкладке мессенджера «Чаты задач и писем», открытие задачи — карточкой в стеке (ADR-0009).
- **CDE** (Common Data Environment) — единая среда данных проектной документации (цель V3).
- **СМДО / АИС МВ** — государственная межведомственная система электронного документооборота РБ; подключение только через сертифицированные ВСЭД (перечень НЦЭУ).
- **ВСЭД** — ведомственная система электронного документооборота.
- **ГИП** — главный инженер проекта.
- **СЭД** — система электронного документооборота (у нас заменяет «Е-дело»).
- **Тип процесса (ProcessType; вкладка «Процессы» раздела «Автоматизация»)** — глобальный справочник шаблонов процессов двух категорий: тип задачи и тип письма (ADR-0024); тип несёт маршрут, форму создания, состав карточки, доступ, нумерацию (письма). Типы задач — системные «Стандартный» (с утверждением постановщиком) и «Быстрый» (без утверждения), пользовательские — в разделе «Автоматизация» (#378); тип определяет маршрут и значок/цвет в интерфейсе (ADR-0020/0021).
- **Маршрут (Workflow)** — статусы задачи и кнопки переходов между ними; статусы мапятся на скрытые системные состояния (I15); кнопки несут показ (главная / видна / в меню «Ещё»), условия «кто видит», гейты и пост-действия (ADR-0020). Правится в редакторе на холсте и публикуется версиями (конфликт версий — 409, ADR-0021).
- **Этап** — системная группа статуса: Ожидание / В работе / Пауза / Утверждение / Итог; уведомления, просрочка и порядок колонок канбана слушают этап (I14–I15). **Утверждение — промежуточный этап, не завершение**: работа сдана и ждёт приёмки, утверждающий может вернуть её в работу. Задача завершена только на этапе «Итог»; на утверждении она не просрочена (ADR-0020, дополнение 2).
- **Утверждающий / решающий** — кто вправе нажать кнопку шага: роль в задаче или письме, должность, руководитель автора или исполнителя, конкретные сотрудники, поле «Сотрудник», роль в проекте (ADR-0025). Решающий видит сущность, пока ход за ним, после решения становится наблюдателем без звука; утверждение пропускается, если утверждающий сам сдал работу.
- **Итог** — смысл закрытой задачи или письма: «выполнена», «отменена» или «отклонена» (отказ решающего, отличим от отзыва автором); задаётся статусом этапа «Итог» (ADR-0020, ADR-0025).
- **Кнопка (переход)** — действие смены статуса в карточке задачи («Взять в работу», «Завершить», «Утвердить»…); «из любого» — кнопка, доступная из всех статусов, кроме пары «Итог → Итог».
- **Панель процесса** — нижний бар действий карточки задачи: слева главная кнопка, затем видимые, «Ещё ⋯»; порядок задаёт маршрут (сервер).
- **Схема маршрутов (WorkflowScheme)** — соответствие «тип задачи → маршрут»; системная — для задач без проекта, проект выбирает свою (ADR-0020).
- **Автоматизация** — раздел настройки процессов: вкладки «Процессы» (типы задач и писем, маршруты, формы, состав карточки), «Поля» (кастомные поля), «Типы проектов» (уровни дерева, роли, схема проекта), «Права доступа».
- **Гейт DoR / DoD задачи** — условие перехода: DoR — «можно взять в работу» (заполнены поля), DoD — «можно завершить» (закрыт чек-лист, нет открытых подзадач, есть часы/результат). Не путать с DoD процесса разработки (`docs/process/definition-of-done.md`).

- **Мои действия** — вид канбана задач по умолчанию: только задачи, где от меня ждут кнопку-действие или мою отметку в сборе; пусто = от меня ничего не нужно (ADR-0026). Термин «ждёт меня» запрещён.
- **Кнопка «действие» / «служебная»** — флаг перехода: «действие» попадает в «Мои действия», «служебная» (пауза, отмена) — нет (ADR-0024).
- **Кнопку жмут несколько** — настройка статуса: одну кнопку («Сдать отчёт», «Ознакомлен», «Подписать») жмут несколько людей со счётчиком «N из M», каждый заполняет своё; после кворума — автопереход или кнопка ответственному (ADR-0025). Отдельного термина-существительного нет.
- **Тип письма** — тип процесса категории «письмо» (входящее / исходящее): маршрут, поля регистрации, серия номеров (ADR-0027).
- **Ждёт закрытия** — статус письма, когда все поручения выполнены: закрывает только расписавший — «Ответ направлен» или «Отработано без ответа» с причиной.
- **Приложенные письма** — системное поле письма: № + организация + дата вложенных писем-«матрёшек»; по нему ищется письмо.
- **Контрагент** — внешняя организация в справочнике CRM (заказчик, подрядчик, поставщик, госорган): краткое и полное название, УНП (уникален, если указан), адрес, e-mail, телефон. Письмо и проект ссылаются на контрагента по id, а не текстом (I14); удаления нет — только архив (ADR-0033, #460).
- **Контактное лицо** — сотрудник контрагента (ФИО, должность, телефон, e-mail) в его карточке; подписант письма — контактное лицо (#55).
- **Корреспондент** — контрагент, от которого пришло письмо или которому оно адресовано; поле письма — ссылка на справочник CRM.
- **Проект** — договор (на этап или весь объект) со своим шифром; «тема» — проект без шифра («Тендер», «Внедрение IT») (ADR-0030).
- **Портфель** — один заказчик одного большого объекта с десятками договоров-проектов.
- **Узел** — папка дерева проекта настраиваемого уровня (стадия, очередь, здание по генплану, раздел…) без своих полей, ответственного и срока; часы и сроки собираются с задач-листьев. **Уровень** — вид узла из каталога.
- **Комплект** — задача типа «Комплект» (лист дерева); изм. N — задача типа «Изменение» под комплектом.
- **Пульс** — вид проекта: комплекты и их изм. N по дереву со статусами, процентом маршрута и колонками-полями — замена таблиц ГИПов.
- **Схема проекта** — холст у типа проекта: заглушки будущих задач и стрелки «после статуса задачи A → создать задачу B с окном дозаполнения». **Заглушка** — не задача и не черновик, а шаблон будущей задачи.
- **Мастер создания проекта** — пошаговое окно: основа → структура → контрольный штамп (вставка таблицы) → роли → схема.

## Технические термины

- **Outbox / Event log** — таблица доменных событий, гарантирующая доставку событий подписчикам (I9).
- **Оптимистичная мутация** — применение изменения в UI до ответа сервера с откатом при ошибке (I4).
- **ADR** — Architecture Decision Record, документ-фиксация архитектурного решения (`docs/adr/`).
- **Идемпотентность** — повторный запрос с тем же `Idempotency-Key` возвращает первый результат, не создавая дублей.
- **Transactional outbox** — запись события в `events` в той же транзакции БД, что и изменение сущности.
- **MSW** (Mock Service Worker) — библиотека моков HTTP-запросов; основа frontend-first разработки (ADR-0001).
- **Feature flag** — флаг включения модуля без пересборки (I10).
- **EntityLink** — универсальная связь между любыми сущностями портала; основа графа знаний.
- **Revision** — версия diff-аемого текстового контента (описание задачи, тело письма, текст сообщения).
- **DoD (процесса)** — Definition of Done, чеклист готовности issue разработки (`docs/process/definition-of-done.md`); гейты DoR/DoD задач продукта — в доменных терминах.

- **Окно перехода** — диалог, открывающийся по кнопке маршрута: итог/отчёт, причина, файлы итога (в том числе выбранные из чата задачи), сообщения чата как отчёт, дозаполнение полей и трудозатрат. Пока обязательное (по гейтам кнопки) не заполнено, главная кнопка окна неактивна; настраивается в редакторе маршрута (#380).
- **Итог работы (результат задачи)** — отчёт исполнителя в окне перехода и в карточке: текст + сообщения/файлы чата; хранится ревизиями (`TaskResult`), текущая — последняя. Не путать с **итогом** закрытой задачи («выполнена/отменена/отклонена»).
- **Блок перехода** — компактная запись в ленте чата задачи о переходе: кнопка, «из → в», причина/комментарий, строка «Итог обновлён · N файлов»; автор — нажавший (#380).
