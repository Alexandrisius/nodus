# Глоссарий

Доменные и технические термины проекта. Интерфейсная терминология — только русская деловая (см. `ux-principles.md`); таблица UI-строк — `packages/contracts/i18n/ru.ts`.

## Доменные термины

- **Поручение** — задача, созданная из письма/резолюции; живёт в модуле задач, связана с письмом.
- **Резолюция** — текстовое распоряжение руководителя на письме; порождает поручение.
- **Канал проекта** — чат, автоматически создаваемый для проекта; сообщения канала — новости-треды (поток Д, core-flows.md).
- **Тред (обсуждение)** — ветка ответов на сообщение канала (ровно один уровень: корень + ответы); UI-термин — «Обсуждение», уведомления — только участникам треда и наблюдателям.
- **Чат задачи** — беседа мессенджера, привязанная к задаче (`conversation.type=task`), — тот же движок, что у обычных чатов (канон владельца #252: двух чатов нет); состав = участники задачи; собраны во вкладке мессенджера «Чаты задач и писем», открытие задачи — карточкой в стеке (ADR-0009).
- **CDE** (Common Data Environment) — единая среда данных проектной документации (цель V3).
- **СМДО / АИС МВ** — государственная межведомственная система электронного документооборота РБ; подключение только через сертифицированные ВСЭД (перечень НЦЭУ).
- **ВСЭД** — ведомственная система электронного документооборота.
- **ГИП** — главный инженер проекта.
- **СЭД** — система электронного документооборота (у нас заменяет «Е-дело»).
- **Тип задачи (TaskType)** — глобальный справочник видов работ (ступень 1 — один системный «Задача»; ступень 2 — Разработка/Задание/Изменение/Проверка/Обычная); тип определяет маршрут (ADR-0020).
- **Маршрут (Workflow)** — стадии задачи и переходы между ними; стадии мапятся на скрытые системные состояния (I15); переходы несут условия (кто видит кнопку), гейты и пост-действия (ADR-0020).
- **Схема маршрутов (WorkflowScheme)** — соответствие «тип задачи → маршрут»; системная — для задач без проекта, проект выбирает свою (ADR-0020).
- **Гейт DoR / DoD задачи** — условие перехода: DoR — «можно взять в работу» (заполнены поля), DoD — «можно завершить» (закрыт чек-лист, нет открытых подзадач, есть часы/результат). Не путать с DoD процесса разработки (`docs/process/definition-of-done.md`).
- **Структурная задача (узел)** — раздел/комплект дерева проекта: задача структурного типа с ответственным, чатом и сроком; часы детей суммируются в неё; в «Мой план» исполнителей не попадает (ступень 3).

## Технические термины

- **Outbox / Event log** — таблица доменных событий, гарантирующая доставку событий подписчикам (I9).
- **Оптимистичная мутация** — применение изменения в UI до ответа сервера с откатом при ошибке (I4).
- **ADR** — Architecture Decision Record, документ-фиксация архитектурного решения (`docs/adr/`).
- **Идемпотентность** — повторный запрос с тем же `Idempotency-Key` возвращает первый результат, не создавая дублей.
- **Transactional outbox** — запись события в `events` в той же транзакции БД, что и изменение сущности.
- **MSW** (Mock Service Worker) — библиотека моков HTTP-запросов; основа frontend-first разработки (ADR-0001).
- **Feature flag** — флаг включения модуля без пересборки (I10).
- **EntityLink** — универсальная связь между любыми сущностями портала; основа графа знаний.
- **Revision** — версия diff-аемого текстового контента (описание задачи, тело письма, текст сообщения).
- **DoD (процесса)** — Definition of Done, чеклист готовности issue разработки (`docs/process/definition-of-done.md`); гейты DoR/DoD задач продукта — в доменных терминах.
