## Новые боли и требования (сверх плана)

### 1. Письмо и поручение — одна карточка; «один родитель» — ГИП

Суть: «У нас письмо и поручение — это одно и то же» (00:08:51); «у каждого письма должен быть один «родитель» — тот, кто отвечает. И по-хорошему это ГИП. Дальше ГИП, прочитав письмо, должен направить на исполнение кого-то — либо присоединить, либо направить» (01:35:06). Расписывать «на всех подряд» — «коллективная безответственность» (00:03:59). Цепочка: письмо → ГИП → Кокин пишет текст / помечает изменение → возвращается к ГИПу → ГИП формирует ответное письмо — «тогда это уже результат у ГИПа» (00:05:15). Помощник ГИПа — всегда в копии. Резолюция на нескольких: **один ответственный, один срок на всех** (00:59:16–00:59:30); исполнители — главспецы и ГИПы (00:58:58). Автоматически направлять ГИПу проекта без руководителя — «нет, тогда будет хаос: они меняются» (01:36:33), но роли ГИП/помощник в карточке объекта с подсказкой резолюции — «однозначно... Путятов очень часто путается сам в показаниях» (01:36:56).

Значит для Nodus: карточка письма **и есть** поручение — исполнители письма назначаются резолюцией (ГИП★ + соисполнители с частями, помощник — наблюдатель), отдельная задача «Поручение» — только когда ГИП делегирует вниз (подзадача с временем). Это модель «исполнитель собирает части» из раунда 6, применённая к письму. Подсказка ГИПа/помощника — из ролей проекта (ступень 3 модуля проектов), решение — за руководителем.

### 2. Кнопка «мне похуй» и ознакомление без резолюции

Суть: «Отметить ознакомление» в Е-деле есть у любого письма — «ознакомился — и письмо пропало, никакой реакции нет»; у письма с поручением такой кнопки быть не должно (00:03:12). Для информационных писем — отдельная кнопка «для ознакомления» со списком людей, «никакой резолюции не накладывается»; где показывать сотрудникам — «в корреспонденции, не в задачу» (01:00:16–01:00:50). ~90–95 % писем получают поручение, «почти все» (00:00:54).

Значит для Nodus: кнопки — по типу и статусу (уже канон); «Для ознакомления» — решения участников «каждый, Ознакомлен» **на карточке письма**, без отдельных задач; у получателя — строка в перечне корреспонденции и «мой ход» на доске; у письма с поручением кнопки «Ознакомлен» нет.

### 3. Контроль «К» и «отработанное = расписанное»

Суть: для троих «отработанное письмо — расписанное» (00:11:02): после резолюции оно уходит из их списка; важные помечают контролем «К» — отдельное окно «письма, контролируемые мной», «Снять с контроля» — «максимально законченный вариант» (01:01:52). В Е-деле у письма нет статусов вообще — узнать, сделано ли, можно только открыв и прочитав отчёты (01:04:28); «самая большая проблема, которая меня бесит» (01:04:58); чтобы проверить — «записная книжка с номерами» и поиск (00:31:21).

Значит для Nodus: флаг «Контроль» на письме + пресет «На контроле у меня» (резолюировавший — решающий на закрытии); статусы письма видны в реестре; обратные уведомления о сдаче частей.

### 4. Представление писем: перечень, не доска

Суть: на канбане «если мы будем все письма видеть здесь, которые не закрыты, — будет простыня»; удобно — перечень как в Директуме: выполнен/не выполнен, «единичка» о новом ответе (01:21:44–01:23:01).

Значит для Nodus: у типов писем место работы — **реестр**, не доска: настройка типа «работать из реестра» (30 писем в день у Путятова на доске — именно простыня); счётчик «мой ход» — на иконке «Корреспонденция». Поправка к решению 21.10 «на доске всё»: для писем — нет.

### 5. Связи «ёлочкой», матрёшки, OCR

Суть: в Е-деле связи — плоский список у каждого письма, «чтобы понять, как вся цепочка происходила, мне нужно щёлкать каждое письмо» (00:34:43); нужно дерево ответов «ответвлениями», без вложений в дереве («разрастёт офигеть огромное дерево», 00:36:00). Матрёшки — сканы пачкой (00:20:46); разбор «с чего всё начиналось» — «можно просто умереть» (00:25:06); ассистент с топ-3 вариантами (идея владельца, 00:25:44). Регламент оформления писем был в договоре с Беларуськалием; по Нежину 500 писем «для экспертизы» за два месяца не найти по зданию; люди дублируют письма на диски (00:26:03).

Значит для Nodus: связь «ответ на» — дерево в карточке; OCR сканов → номера вложенных писем в поле «приложенные письма» (ИИ предлагает — человек подтверждает); поля этап/здание у проектов-этапов; письма проекта — в модуле «Проекты» без скачивания.
