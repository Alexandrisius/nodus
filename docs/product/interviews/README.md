# Саммари интервью и обсуждений

Отфильтрованные агентом выжимки разговоров с руководством и сотрудниками (аудио, встречи, переписки), значимые для продукта. Хранится **только очищенное саммри в терминах продукта**; оригиналы (аудио, сырые транскрипты, скриншоты переписок) в репозитории не хранятся.

## Зачем

Мысли руководства — источник требований, который легко теряется. Здесь они зафиксированы самодостаточно: файл читается без оригинала и написан в терминах канона — глоссарий, core-flows, roadmap-кейсы, issues.

## Правила

- Один разговор = один файл: `ГГГГ-ММ-ДД-<кто-или-тема>.md` (ASCII, kebab-case).
- Шапка: дата, участники, источник и способ расшифровки, что из оригинала отброшено как нерелевантное.
- Тело по темам: суть → «значит для Nodus» (терминами канона, со ссылками). В конце — «Подтверждения канона» (что совпало с уже зафиксированным, чтобы не переизобретать), «Открытые вопросы» и таблица «тема → куда в плане».
- Цитаты — короткие, «близко к расшифровке»; имена из аудио — с пометкой, что могут быть искажены.
- Судьба тем: когда тема превращается в roadmap-кейс или issue, у неё в таблице появляется ссылка `→ #N`. Файлы не удаляются.
- Новые темы не вносятся в roadmap до решения владельца — они ждут в таблице со статусом «не внесено» и живые из них уходят записями в инкубатор (`../incubator.md`) для обсуждения.

## Когда читать

Перед сессиями планирования, нарезкой issues и работой по модулям корреспонденции, проектов, мессенджера и ИИ-контура (V3). Методология проведения интервью — `../process-discovery.md`.
