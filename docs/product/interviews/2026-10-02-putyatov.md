## Боли и требования

### 1. Контроль исполнения писем — боль №1, с механикой решения

Суть: письмо расписано на исполнителя → «ознакомился и забыл» → через три месяца заказчик: «я письмо направлял, что с ним?» — поиск по номеру, никто не сделал. Прозрачного цикла нет: исполнитель в Е-деле проставляет в табличке «вести отчёт» статус («временный/окончательный/не окончательный»), но контролёр это видит только если сам зайдёт через поиск по номеру письма.

Требование дословно: поручение **с открытой датой «стучит»** исполнителю («у тебя письмо, оно не выполнено») и контролёру — до тех пор, пока не поставлен отчёт; первое напоминание — через неделю, не через месяц. В карточке письма должен быть виден срок реакции («до 02.10 ответить») и событие исполнения («30.09 направлены ответы») со связкой на исходящее.

Значит для Nodus: ядро #55 — контроль исполнения как первоклассная механика: (а) статус письма/порождения «исполнено» виден постановщику без поиска (подтверждено позже интервью Вашурова — «инструмента контроля нет»); (б) напоминания о незакрытых поручениях — периодические (мехника повторов #177/#189 уже существует — перенести на поручения); (в) счётчик незавершённых поручений у исполнителя («двоечка»).

### 2. Резолюции: «ознакомиться» vs «исполнить»; 80% писем требуют реакции

Суть: поручение ставится почти на любое письмо (90–95%), включая «ознакомиться» на информационные (ТУ, исходные данные — «учли и всё»); ~80% писем требуют реальной реакции: ответ, изменение документации, передача по накладной. Кейс: «дверь не по месту» — подрядчик прорубил проём не там и требует оплату — резолюция «написать ответ» требует знания контекста, которого нет в письме.

Значит для Nodus: #55 — резолюция без поручения допустима (канон), но здесь уточнение: «ознакомиться» — тоже поручение-задача с лёгким закрытием (acknowledge); развилка «чекбокс к ознакомлению/к исполнению» — по факту писем «к ознакомлению» мало, дефолт — исполнение.

### 3. Связки писем вх↔исх: кто и как ставит сегодня

Суть: в Е-деле у письма «документы по исполнению»: жёлтое входящее, синее исходящее; связки ставят помощники ГИПов при загрузке исходящего (через СМДО — в шаблоне автоматически: «ответ на такое-то, исполнители такие-то»); видимость исходящего-ответа у входящего — только если ты в исполнителях. Путятов периодически пишет замечание «поставьте связки в письмах» — связки забывают.

Значит для Nodus: #55 — связь «ответ на» ставится системой при регистрации исходящего из карточки письма (не человеком отдельно); участники переписки по письму видят исходящие без ручного добавления в исполнители.

### 4. Исходящие, мокрая подпись и СМДО

Суть: Вика регистрирует исходящие и сканирует мокрую подпись; СМДО-письма подписываются ЭЦП и уходят через ВСЭД; СМДО отложен (Валерия: «редко пользуемся, пусть остаётся как есть»); доля СМДО-заказчиков — уточнить у Вики. Почтовый поллер: раз в час достаточно, «а то и реже».

Значит для Nodus: подтверждение C4 (СМДО — труба через ВСЭД, не наша) и вводной к #56 (IMAP-интервал 1 час); сканирование мокрых исходящих — вне MVP.

### 5. Уведомления и «красный шум» задач

Суть: 1–3 красные просроченные — смотрит; 30+ — «не видно, какие две новые действительно важные». Подтверждён показанный владельцем макет приоритетов (urgent пробивает всё мьюты, отчёт «кто не ознакомился», счётчик только для urgent/high, точка для остального, наблюдателей — спрятать вниз раскрывашкой).

Значит для Nodus: подтверждение закрытых #189/#177; сигнал к #37 — просрочка-шум лечится приоритетами и сводкой, не тотальной краснотой (тот же вывод из интервью Левчук/Кураленя/Вашуров).

### 6. Инфраструктура/деньги (контекст)

Топовый сервер ~50 тыс. $ (год назад), диски сейчас ~20 тыс. $ — фон для решений M14 (self-hosted на существующем железе, экономия — мотив продукта).

## Подтверждения канона

- **Контроль исполнения писем = боль №1** (C7, #55) — первоисточник декабрьского фокуса.
- **Чат-обсуждение письма** (А.4: слева письмо, справа чат) — одобрено в разговоре («наверное, да»).
- **Связи вх↔исх** через карточку (EntityLink, #55).
- **Резолюция → поручение-задача**; «ознакомиться» — частный случай поручения.
- **СМДО отложен** (C4); IMAP-поллер раз в час (#56).
- **Приоритеты уведомлений + повторы + «пробивает mute»** — реализовано (#189, #177); «наблюдателей — не рубить, спрятать вниз» — учтено в фильтрах-вкладках #189.
