# ADR-0032. Временное исключение из I11: облачный контур смыслового поиска

- **Статус:** Принят (согласовано владельцем 24.10.2026)
- **Дата:** 2026-10-25
- **Контекст:** ответ владельца 40 («поиск по смыслу нужен обязательно, после нового года; сначала облачный ИИ, позже локальный»), вердикт 24.10 (облачные эмбеддинг-модель, реранкер и LLM на первом этапе), эпик #272 (M18), master-plan §7, #427. Отклонение от I11 (self-hosted, zero cloud) — поэтому ADR и согласование владельца.

## Контекст

Локальный контур (Qwen 27B ~36 ГБ + реранкер и эмбеддинг ~12 ГБ, итого ~48 ГБ видеопамяти) сейчас дорог. Сценарий: «найди письмо, связанное с тем-то» — ИИ делает 5–10 запросов к векторному индексу, читает вложения и выдаёт ссылки.

## Решение

1. На первом этапе #272 эмбеддинги, реранкинг и ответы LLM — через облачный API за точками расширения `EmbeddingProvider` / `SearchProvider` (I13); векторный индекс — у нас (pgvector).
2. **Конфиденциальное в облако не уходит:** письма, задачи и чаты с флагом «конфиденциально» и всё из секретных проектов не индексируются облачным провайдером.
3. Исключение **отключаемо настройкой** (выключено — поиск только полнотекстовый) и **временное**: переход на локальные модели при появлении железа — смена реализации провайдеров без смены контрактов.
4. Отправляемые данные и провайдер фиксируются в README модуля поиска; журнал вызовов (без содержимого) — для аудита.

## Альтернативы

| Альтернатива | Почему отклонена | Когда пересмотреть |
|---|---|---|
| Сразу локальные модели | ~48 ГБ видеопамяти — дорого сейчас | Покупка сервера с GPU |
| Без смыслового поиска | Владелец: нужен обязательно | — |

## Последствия

**Проще:** смысловой поиск появляется без закупки железа. **Сложнее:** контроль того, что уходит наружу (фильтр конфиденциального — блокер ревью безопасности); зависимость от внешнего сервиса в рантайме (деградация до полнотекстового поиска).
