# ADR-0033. CRM: контрагенты и контактные лица — минимальный бэкенд

- **Статус:** Принят
- **Дата:** 2026-10-25
- **Контекст:** вердикт владельца 23.09 (дом контрагентов — раздел «CRM», #83), 23.10 (минимальный бэкенд в декабре — иначе «корреспондент» станет текстом и убьёт аналитику, I14), #427.

## Контекст

Контрагент нужен как корреспондент письма (входящего и исходящего), подписант — как контактное лицо, заказчик — у проекта. Сейчас реестр контрагентов живёт только на моках (`features/crm`, `shared/counterparties`). По правилу 23.09 master-данные с двумя и более потребителями — отдельный модуль, не внутри корреспонденции.

## Решение

1. **Модуль `crm`** (фичефлаг): `counterparties` (краткое и полное название, УНП — уникален, если указан; адрес; e-mail; телефон; кастомные поля) и `contact_persons` (контрагент, ФИО, должность, e-mail, телефон).
2. **API:** список с поиском (название, УНП) и курсором; карточка; создание (в том числе «на лету» из регистрации письма с подсказкой похожих по названию и УНП); правка; контакты. Удаление — архивация.
3. **Потребители** ссылаются по id (plain UUID, I3): корреспондент и подписант письма, заказчик проекта; счётчики писем и проектов в реестре — проекции по событиям.
4. **Не входит:** слияние дублей (позже — событие резолвинга поверх, без переписывания истории), договоры и тендеры (будущие вкладки CRM), сделки и воронки (не моделируются).

## Альтернативы

| Альтернатива | Почему отклонена | Когда пересмотреть |
|---|---|---|
| Корреспондент — текст | Убивает аналитику и автозаполнение (I14) | — |
| Контрагенты внутри корреспонденции | Потребителей больше одного (проекты) — правило 23.09 | — |

## Последствия

**Проще:** корреспонденты и заказчики едины; аналитика «по корреспонденту», «по заказчику». **Сложнее:** дубли при быстром создании — подсказка похожих обязательна.

## Обоснование (research)

- Запись инкубатора 23.09 «Контрагенты: вкладка корреспонденции, свой раздел или CRM?»; #83.

## Дополнение (#460, 2026-10-25): реализация

Минимальный бэкенд собран модулем `apps/api/src/modules/crm/` (флаг `crm`),
веб переведён на живой API. Уточнения, принятые при реализации:

1. **Поиск похожих — `pg_trgm`** (contrib, trusted с PG13): `word_similarity`
   ловит опечатки, кавычки и порядок слов («Галургея» → «АО «Галургия»»),
   чего не даёт `ILIKE`. Расширение ставит миграция (`CREATE EXTENSION IF NOT
   EXISTS pg_trgm`), GIN-индексы `gin_trgm_ops` — по краткому и полному
   названию. Порог сходства — константа 0,45, подбирается тестами подсказки.
   На масштабе компании запрос — последовательный проход (миллисекунды); при
   импорте Е-дела (#451) — переход на оператор `%>` с
   `pg_trgm.word_similarity_threshold` (тогда работает GIN).
2. **УНП** нормализуется общей грамматикой контракта (`unpInputSchema`:
   «УНП 100 123 456» → `100123456`) и объявлен обычным `UNIQUE` по
   nullable-колонке — NULL-ы в PostgreSQL различны, значит «уникален, если
   указан». Архив **держит** УНП: повторная запись с тем же номером получает
   `409 CRM_UNP_TAKEN` с `details {counterpartyId, shortName, archived}` —
   UI ведёт к «Вернуть из архива», а не создаёт дубль. Частичный индекс
   (`WHERE unp IS NOT NULL AND archived_at IS NULL`) отклонён: Prisma не
   объявляет partial-индексы → дрейф схемы.
3. **Права:** чтение справочника — всем (строки в `rbac-inventory.test.ts`
   с причиной), создание (в т.ч. «на лету») — `crm.create`, ведение — `crm.manage`.
   По умолчанию оба у администратора; «Канцелярия» получит их в #55,
   остальным — галочка в матрице #379. Права доезжают до прода миграцией
   (`INSERT … ON CONFLICT DO NOTHING`), не только сидом (#398).
4. **Read-порт до потребителя:** `COUNTERPARTY_READER` (`refs`, `activeRef`)
   заведён сразу — у него два параллельных потребителя (#55, #52); иначе
   каждый спроектировал бы порт в чужом модуле. Порт работает и при
   выключенном флаге (I10). Методы контактов добавит #55, адреса — #464.
5. **Проекция счётчиков** `counterparty_usages` (PK `(source_kind, source_id)`)
   — сейчас, обработчики — в #55/#52: событий писем и проектов ещё нет, а
   «нули в мэппере» пришлось бы переделывать двум модулям параллельно.
6. **События** `crm.counterparty_archived` / `crm.counterparty_restored`
   добавлены к зарезервированным — явная семантика для будущих подписчиков
   (как `workflow.type_archived`, `project.archived`).
7. **Realtime не нужен:** gateway отбрасывает события без беседы; свежесть
   реестра — staleTime и инвалидации мутаций.
