# ADR-0022. Холст схем: @xyflow/react как единый движок редакторов схем

- **Статус:** Предложен (#378)
- **Дата:** 2026-10-19 (редакция 2 — 2026-10-20, вердикты владельца по живому холсту)
- **Контекст:** #377/#378, north-star §5 («один холст на все схемы»). Номер ADR уточняется в момент PR.

## Контекст

Эпику #377 нужен визуальный холст: редактор маршрутов типа задачи (#378), «Схема маршрута» в карточке задачи, позже — схема развития проекта (#38) и вкладки «Согласования». Требования: перетаскивание узлов, зум/панорама, ортогональные рёбра с подписями, порты соединения, клавиатурная доступность, обе темы. В проекте уже есть собственные SVG-графы-витрины (`task-list-graph.tsx`, `project-flow.tsx`) — они рисуют связи, но не дают интерактивного редактирования.

## Решение

**`@xyflow/react` v12** (стабильная ветка; ветка 13 — `next`, не берём) — зависимость `@nodus/web`, единый движок в `apps/web/src/shared/flow/`:

- подключается **`@xyflow/react/dist/base.css`** (только структура: слои, трансформаты), не `style.css` — внешний вид наш, тема через CSS-переменные `--xy-*` → токены Nodus (`flow-theme.css`, обе темы, `--ui-scale`);
- `nodeTypes`/`edgeTypes` объявлены на уровне модуля (стабильные ссылки — иначе React пересоздаёт узлы);
- над движком — наши чистые слои с unit-тестами: `route-layout.ts` (свободная слоевая авторасстановка без колонок этапов), `route-resolve.ts` (разрешение раскладки: сохранённое — закон, недостающее — авто), `flow-handles.ts` (12 точек подключения), `route-loops.ts` (глубины U-обходов), `route-labels.ts` (места подписей), `edge-geometry.ts` (ортогональные пути по реальным концам), `route-graph.ts` (узлы и рёбра — одинаково для редактора и «Схемы маршрута»);
- визуальный канон — раздел «Холст схем» навыка `nodus-ui-style` и `references/flow-canvas.md` (правило зеркала): один язык для маршрутов задач и будущей схемы проектов.

### Модель холста (редакция 2, 20.10.2026)

1. **Раскладка — общая, в документе маршрута на сервере** (`workflows.layout`): позиции статусов, точки подключения стрелок, доля подписи на стрелке, глубина U-обхода, место метки «Любой статус». Нет записи элемента — авторасстановка. Редактор и «Схема маршрута» в карточке видят одно и то же.
2. **«Что видишь — то и стоит».** Первая правка фиксирует видимую картинку целиком; дальше двигается только то, что двигает пользователь (перетаскивание статуса не пересчитывает чужие позиции, точки и стрелки). Сдвинутые обходы не слипаются с соседними, подпись сдвинутой стрелки (или подпись, на которую положили статус) уходит на ближайшее свободное место своей стрелки. Авторасстановка — только явной кнопкой «Упорядочить».
3. **Расстановка — оформление, не маршрут** (ADR-0021 п. 9): сохраняется сразу без новой версии; рабочая копия и публикация — только структура.
4. **Связи:** 12 точек подключения (по три на сторону), режим `Loose`, переподключение концов; занятые точки — кружки, видимые всегда (стрелка упирается в кружок); наконечники — свои SVG-маркеры в единицах холста с заливкой токеном (встроенные маркеры не понимают `var()` в `fill` и растут с толщиной линии).
5. **Подпись кнопки — на своей стрелке** в доле длины, перетаскивается вдоль; ставится без наезда на узлы и другие подписи; слой подписей — над всеми линиями.
6. **«Из любого статуса»** — переключатель в панели статуса + метка-пилюля «Любой статус» со стрелкой в статус (модель Jira/Трекера; в данных — `fromStageId = null`).
7. **Окно редактора — сплит как мессенджер:** бар h-14 с линией, правая панель — полновысотная колонка, выезжает и сужает холст; вписывание один раз (граф не дёргается при выезде панели); масштаб и отмена — слева внизу, атрибуция — справа внизу.

**Атрибуция React Flow остаётся видимой, но приглушённой.** Политика авторов: библиотека MIT, «атрибуция видна — подписка не нужна; убрали — подпишитесь» (reactflow.dev/remove-attribution, proOptions). Убрать атрибуцию — бизнес-решение владельца (Pro-подписка), не техническое.

## Альтернативы

| Альтернатива | Почему отклонена | Когда пересмотреть |
|---|---|---|
| Свой SVG-движок (развить `task-list-graph`) | Драг с extent-ограничениями, зум/панорама, хендлы, автофокус, a11y — месяцы работы против одной зависимости; свои графы-витрины остаются для списков | Если политикой I11 потребуется нулевая зависимость |
| Rete.js | Ориентирован на пин-редакторы потоков данных; тяжелее и чужероднее для статусов-колонок | — |
| JointJS | Продвинутые фичи — коммерческая лицензия | — |
| dagre / ELK | Не движок, а автоукладка; своя слоевая укладка маршрута — ~100 строк, предсказуема и нужна только по «Упорядочить» (ручная расстановка — закон) | Схемы проектов #38 или маршруты > 40 статусов |
| Пересчитывать раскладку на каждую правку (без фиксации) | Перетаскивание одного статуса двигало граф и перестраивало чужие стрелки — выровнять схему было невозможно (вердикт владельца 20.10) | — |
| Расстановка — часть публикуемой версии | Перестановка «для красоты» требовала бы новой версии и черновика (вердикт владельца 20.10) | Если появится аудит/откат оформления схем |

## Последствия

**Проще:** зрелый движок (используют Stripe, LinkedIn и др.), доступность и жесты из коробки, один холст на все будущие схемы; расстановка общая и стабильная — схема выглядит одинаково у всех и не «плывёт» от правок. **Сложнее:** +1 зависимость в бандле (~40–50 КБ gzip) только там, где холст нужен (лениво); канон обязателен — иначе каждый новый редактор напишет свой «xyflow по-своему»; атрибуция — видимая строка в углу холста (решение владельца, если захочет убрать).

## Обоснование (research)

- React Flow: MIT-навсегда, политика атрибуции «visible — no subscription; hidden — please subscribe» (reactflow.dev/pro, /remove-attribution, ProOptions).
- Документация v12: `base.css` для кастомных тем, `nodeExtent`, `nodesFocusable/edgesFocusable`, `ariaLabelConfig` для локализации ARIA-строк (reactflow.dev/api-reference/react-flow).
- Опыт индустрии: node-based UI на React Flow — стандарт (Stripe docs, Render, Jira-подобные визуальные редакторы).
- Jira workflow editor и Яндекс Трекер: ручная расстановка статусов сохраняется со схемой и общая для всех; «из любого статуса» — переключатель статуса + метка «Any status»; подписи переходов на стрелках; точки подключения по сторонам статуса.
- React Flow, маркеры рёбер: `MarkerType` красит наконечник атрибутами SVG и масштабирует по толщине линии (`markerUnits`); свои `<marker>` по id — штатный путь (`markerEnd: '<id>'`, reactflow.dev/examples/edges/markers).
