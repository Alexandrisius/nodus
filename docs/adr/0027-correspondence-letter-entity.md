# ADR-0027. Корреспонденция: письмо — сущность на движке «Процессы»

- **Статус:** Принят
- **Дата:** 2026-10-25
- **Контекст:** вердикты владельца 23–25.10 (master-plan §7, ответы 1–45), интервью 22.10 (Шайдерова) и 02.10 (Путятов), `docs/mvp/process-model-plan-2026-10-25.md` §4.4, #427. Отменяет модель v2 моков (22.09: «Входящие/Отправленные/Журнал», «в дело», резолюция → 1..N задач через Commission) и задел `Letter/Resolution/Commission` в `data-model.md`.

## Контекст

Боль №1: 30 входящих и 30 исходящих в день, «60 % писем не отвечено» из-за невидимости, «ознакомился — письмо пропало», связи «ответ на» ставят руками и забывают, вложенные письма-матрёшки (до 5–6 уровней) Вика вписывает в примечание. Е-дело остаётся архивом на декабрь–январь; Nodus заменяет его поэтапно.

## Решение

1. **Модуль `correspondence`** (фичефлаг, I10). Письмо (`letters`) — сущность на движке «Процессы» (ADR-0024: категория `letter`, `direction`), своя карточка. На канбан задач не попадает: место работы — реестры раздела «Корреспонденция».
2. **Таблицы:** `letters` (тип, маршрут, стадия, направление, рег. номер и дата, корреспондент — контрагент CRM, подписант — контакт, их № и дата, тема, способ поступления/отправки — словарь, проект, адресат, исполнитель письма, расписавший, срок ответа, конфиденциальность, кастомные поля, исходные заголовки почты); `letter_attachments` (исходные файлы, распакованные — с родителем и путём, главный документ «Тело»); `letter_relations` (`reply_to | nested_in`); `letter_attached_refs` («приложенные письма»: №, организация, дата — системная повторяющаяся группа, ищется); `letter_assignments` (проекция поручений из событий задач: статус, часы); `letter_action_holders` (ADR-0026); `number_series` + `number_counters` (серия, год, последнее значение — без щелей: `UPDATE … RETURNING` в транзакции регистрации, сброс по году); `mail_sources` (ящики, курсор UIDVALIDITY/UID).
3. **Вкладки:** «Новые» (сырой ящик; только право `correspondence.register`), «Входящие», «Исходящие». Термины «Журнал» и «Почта» в корреспонденции не используются («Почта» — будущий модуль личных ящиков).
4. **Приём** (IMAP общего ящика, только чтение, опрос раз в 10 минут — настраиваемо): исходный `.eml` хранится; разбор (кодировки, вложения, inline, winmail.dat/TNEF); дедуп по Message-ID + UID; карточка в «Новые»; подсказка связи «ответ на» по `In-Reply-To`/`References` и теме «Исх. №». Спам удаляется без хранения; «Закрыть без регистрации» — с причиной (паттерн 1С:ДО). Бумажное письмо — ручное создание с тем же окном регистрации.
5. **Сеемый маршрут входящего:** «Новое» → (регистрация: номер серии «Вх») «На резолюции» → «На исполнение» (ГИП + срок) → «Расписывается» (долг ГИПа: «≥1 поручение или причина „не требуются“»; «Вернуть руководителю») → «В работе» → автопереход «Ждёт закрытия», когда все поручения в итоге → «Закрыто: ответ направлен» / «Отработано без ответа» (причина). Ветки «Расписать сразу» (руководство создаёт поручения само) и «Для ознакомления» (сбор «каждый жмёт „Ознакомлен“» → закрывается само; у письма с поручениями кнопки «Ознакомлен» нет). **Закрывает только расписавший**; подписанный зарегистрированный «ответ на» подсвечивает «можно закрывать», но не закрывает. «Стучалок», контроля «К» и «в дело» нет. Маршрут — данные: тип письма настраивается в «Процессах».
6. **Поручения — обычные задачи** модуля задач (`source = letter`, `source_id = letterId`), создаются из карточки письма формой типа «Поручение» (проект письма по умолчанию, узел дерева — по выбору в форме; срок — предупреждение, если позже срока резолюции). «Расписать сразу» — событие `correspondence.assignments_requested` с заранее сгенерированными id; модуль задач создаёт задачи идемпотентно (I3). Письмо держит проекцию статусов и часов (сумма — «работы, порождённые перепиской», I14); итог поручения — блок в чате письма.
7. **Исходящее:** «Черновик» → «На согласовании» (необязательный статус типа; сбор) → «На подписи» (сбор «любой 1» из подписантов: ЭЦП (ADR-0031) или «подписано на бумаге, скан приложен») → «На регистрации» (номер «Исх» в самом конце) → «Готово к отправке» → «Отправлено» (с общего ящика SMTP или «иначе»: заказным, нарочным — поле). «Ответить» на входящем — связь «ответ на», корреспондент, тема «На № … от …». Номер исходящего не встраивается в подписанный ЭЦП файл: он в карточке, теме и сопроводительном тексте. Исходящий Message-ID хранится для связывания ответов.
8. **Конфиденциальность:** флаг письма закрывает письмо, его чат, файлы (contributor доступа к файлам) и созданные поручения (`confidential = true`) для всех, кроме участников; право `correspondence.view_confidential` — в каталоге, по умолчанию ни у кого. Обычные зарегистрированные письма видят все сотрудники.
9. **Безопасность:** HTML-тела писем показываются только в песочнице (sandbox-iframe + санитизация, внешние картинки по умолчанию не грузятся); вложения — через подписанные ссылки files.
10. **Чат письма** — единый движок мессенджера (беседа `type = letter`, мост «чат письма», как чат задачи); участники синхронизируются с участниками письма; не-участник открытого письма может «Присоединиться к обсуждению».
11. **Права:** `correspondence.register` (роль «Канцелярия»), `correspondence.resolve` (список адресатов сверху; не жёсткий запрет), `correspondence.view_confidential`.

## Альтернативы

| Альтернатива | Почему отклонена | Когда пересмотреть |
|---|---|---|
| Письмо = поручение (одна карточка) | Перекрыто вердиктом 23.10: поручение — большая работа с часами, живёт на канбане задач | — |
| Резолюция → Commission → задачи (старый #55) | Лишняя сущность; «один родитель — ГИП» и гибкий маршрут закрывают сценарий | — |
| Канбан писем как основной вид | «Будет простыня» (Шайдерова 01:21:44) | Опциональный вид — после НГ |
| СМДО-труба | 10–15 % потока, «надо просто отключить» (ответ 42) | — |
| Автозакрытие подписанным ответом | Закрывает расписавший (ответ 17) | — |

## Последствия

**Проще:** статусы писем видны всем; поручения и часы связаны с письмом и проектом; реестры, поля, права и маршрут — общие с задачами. **Сложнее:** разбор реальной почты (кодировки, TNEF, HTML) и песочница; проекции поручений по событиям; нумерация без щелей под конкурентной регистрацией (тест).

## Обоснование (research)

- Инструкция по делопроизводству РБ: регистрационно-контрольная карточка, номер и дата документа корреспондента; 1С:ДО — «закрыть без регистрации».
- Directum: перечень писем со статусами и индикатором нового ответа (референс Шайдеровой 01:22:52).
- imapflow / mailparser (imapflow.com/docs); TNEF от Outlook RTF.

## Дополнение (#56, 28.10.2026) — приём почты: вердикты владельца

- **O1. Уведомление на каждое принятое письмо** вместо «не уведомление, а счётчик» (§4.6 плана трека): вердикт В4 28.10 — «по каждому новому письму Вике было уведомление… не хуже аутлука»; приоритет обычный.
- **O2. Таблица `letter_relations` и авто-связи «ответ на»** принесены из #461: вердикт В1 — «связи нужно собирать автоматически как-то… все клиенты почтовые как-то ж склеивают письма легко». Авто — по цепочке In-Reply-To/References (JWZ/RFC 5256), нечёткая подсказка по теме «Исх-ГГГГ/N» / «на № N от ДД.ММ.ГГГГ» с подтверждением галочкой при регистрации; ёлочка и ручное управление связями — по-прежнему #461.
- **O3. Мгновенность приёма — IMAP IDLE** вместо «опрос раз в 10 минут» (п.4 исходного решения): вердикт В4 — «я не хочу чтобы мы опрашивали сервер, а хочу чтобы все письма приходили мгновенно». Фолбэк-опрос остаётся страховкой; механизм подсистемы — ADR-0035.

## Дополнение (#55, 26.10.2026) — письмо на движке «Процессы»

- **Регистрация — переход маршрута, а не отдельный эндпоинт**: окно с разделом `registration` (`letter-registration.schemas.ts`), пост-действие `assign_number` выдаёт номер серии в транзакции перехода (без пропусков). Повторная регистрация — 409 `LETTER_ALREADY_REGISTERED` с выданным номером.
- **Нумерация — свойство типа** (`ProcessType.numbering { seriesId, prefix, reset: 'year' }`), серии «Вх»/«Исх»; правка серии — #504, каталог типов писем системный (UI — только просмотр, 409 на публикацию).
- **Категория `letter` в движке**: `WORKFLOW_SECTIONS_BY_CATEGORY`, `WORKFLOW_ROLES_BY_CATEGORY`, `WORKFLOW_VALIDATORS_BY_CATEGORY`, `WORKFLOW_POST_FUNCTIONS_BY_CATEGORY`; у письма в #55 гейтов нет, окно — «Регистрация» и «Причина / комментарий».
- **Тело письма — недоверенный HTML**: DOMPurify + iframe `sandbox` с CSP; внешние изображения блокируются до явного разрешения (Р9).
- **Чат письма — обычная беседа** `type='letter'` с `letter_transition`-сообщениями; участники — адресат и присоединившиеся, наружу не уходит (Р10).
- **Вкладки «Новые / Входящие / Исходящие»**: `box=new` — только держателю `correspondence.register` (иначе 403); «Права доступа» — общая матрица раздела.
- **Вне пакета**: приём почты (#56), исходящие с отправкой (#464), резолюции/поручения и конфиденциальность (#461/#463).

## Реализация (#55, бэкенд)

- **Схема:** `letters` (номер и его состав — CHECK полноты, UNIQUE серия×год×порядок, индексы «Новые»/реестров/корреспондента/адресата, GIN `custom_fields`), `letter_attachments` (роли `main|body|attachment|source`, частичные unique «один main и один body»), `letter_participants` (PK письмо×сотрудник), частичный unique беседы `conversations(letter_id) WHERE type='letter'`, `counterparty_usages.contact_id`.
- **Модуль `correspondence`:** чтения (keyset-курсоры «Новые» по `received_at`, реестры по `registered_at`; серверный поиск по теме/номеру/их номеру/корреспонденту), карточка, ручное создание multipart (файлы потоком через временные файлы, атомарно с письмом, компенсация хранилища), правка реквизитов с историей, спам, присоединение. Видимость и права — одна функция (`letter-access.ts`): незарегистрированное — только `correspondence.register`, невидимое — 404, `box=new` без права — 403.
- **Адаптер письма:** роли `registrar | addressee | participant | author` (автор — только у исходящих), факты нейтральные (гейтов в #55 нет), `applyStage` пишет `system_state`, номер и события `letter_stage_changed` / `letter_registered` / `letter_closed_unregistered`.
- **Повторная регистрация** — 409 `LETTER_ALREADY_REGISTERED` с выданным номером: движок видит запрет перехода, сервис перечитывает письмо и объясняет причину; страховка — адаптер.
- **Чат:** беседа `type='letter'` (find-or-create по `letter_id`), состав — адресат (owner) + участники, регистратор не входит (В2); мост через порт `LETTER_CHAT_READER`; блок `letter_transition` — по `letter_stage_changed` с причиной (цвет чипа — из каталога стадий, в событии его нет).
- **Файлы:** порт `FILE_OBJECT_READER` (метаданные), `FILE_ACCESS_CONTRIBUTORS` заменён реестром `FileAccessRegistry` (маркер `fileAccessContext`), `LetterFileAccess` — видимость по письму, `canEdit:false`; офисные вложения письма ставятся в очередь PDF-производных обработчиком `correspondence.letter_received`.
- **CRM:** обработчики `letter_registered|updated|deleted` ведут `counterparty_usages` (корреспондент + подписант); удаление контакта-подписанта — 409 `CRM_CONTACT_IN_USE`.
