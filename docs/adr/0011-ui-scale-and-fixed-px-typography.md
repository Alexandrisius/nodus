# ADR-0011. Масштаб интерфейса — root font (`--ui-scale`); типографика — фиксированная px-лестница

- Статус: accepted (2026-09-21, вердикт владельца «всё норм, финализируй» по итогам issue #60, раунды 1–4)
- Дополняет: механику масштаба UI (инварианты не затрагивает); канон типографики — `tokens.md` навыка nodus-ui-style

## Контекст

Жалоба владельца и тестировщиков (issue #60): UI и кнопки мельче Битрикс24 на 24" мониторах; при браузерном зуме 125% «намного лучше». Замер владельца: основные кнопки Битрикс ≈ 40px против наших 32px. После первого раунда (всё масштабируется корневым шрифтом, контент 17.5px) последовал обратный вердикт: «шрифт везде слишком огромный», «два шрифта, второй огромный» (моно-метки), правая панель с чатами не вмещает список. Требовался механизм, в котором плотность интерфейса и читаемость текста регулируются независимо и калибруются по внешнему эталону (Битрикс24, живые замеры через in-app browser 21.09.2026: меню 240px/15px/400, ряд 38px, канбан 14px, титул задачи 21px/600).

## Решение

1. **Масштаб контролов и отступов** — CSS-переменная `--ui-scale` (дефолт **1.25**, шаги дискретные 0.9/1.0/1.125/1.25) на корневом шрифте: `html { font-size: calc(100% * var(--ui-scale)) }`. Все rem-утилиты Tailwind (spacing, высоты контролов, радиусы, container-пороги) масштабируются одним рычагом; JS-геометрия (рейка, панели, тред, таблицы, Гант, схема, FLIP) — через `uiPx()` (`apps/web/src/shared/ui/ui-scale.ts`, масштаб читается из computed font-size корня с фолбэком на переменную). Дефолт 1.25: базовая кнопка `h-8` = 40px = кнопки Битрикс на 100% зума.
2. **Типографика фиксирована в px и НЕ зависит от `--ui-scale`** (density ≠ type, как в Material/Fluent): лестница 11/12/13/14/15/16/18/20/24/28px в `@theme` (globals.css), включая переопределение кор-токенов Tailwind (`text-xs/sm/base/…`). Body 15px, метки полей и заголовки таблиц/секций 13px, плотный контент 14px, навигация 15px, титул карточки 18px. Одна гарнитура (Onest) на весь интерфейс; JetBrains Mono — ТОЛЬКО данные (номера, коды, время, счётчики, оси, ключ-чипы), 11–12px, tabular-nums; заголовки — `NodeLabel` sans 13px semibold UPPERCASE; статус-чипы sans 12px.
3. **Сетка контролов единая**: высоты 40px (`h-8`) дефолт / 35px (`h-7`) плотные / 30px (`h-6`) xs; квадратные икон-кнопки 40/35/30; CTA задач одной высоты со вторичными (важность — заливкой, не размером); ряды левой рейки 40px, ширина рейки 240px (замеры Битрикс); нижние бары карточек — одна горизонталь, поле композера и отправка 40px.
4. **Кастомные text-* токены зарегистрированы в группе font-size tailwind-merge** (`packages/ui/src/lib/utils.ts`, `extendTailwindMerge`): без этого merge классифицирует неизвестный `text-*` как ЦВЕТ и глушит кегль следующим тоном (баг раунда 2, регрессионный тест `cn-tokens.test.ts`, механика — `docs/gotchas.md`).

## Обоснование

- **Почему НЕ CSS `zoom`**: getBoundingClientRect учитывает zoom, а offsetHeight/clientHeight/scroll* — нет (ломает императивные drag и FLIP-замеры); порталы Radix, смонтированные в body, позиционируются мимо; hairline-линии получают subpixel-мыло; zoom не анимируется и конфликтует с браузерным зумом (research: Display Scale Strategy, документированный класс багов порталов).
- **Почему НЕ отдельные `--display-scale`-токены поверх rem**: rem-системе Tailwind достаточно одного root font-size; второй рычаг удвоил бы поверхность рассинхрона CSS↔JS без выигрыша (research тот же).
- **Почему типографика НЕ масштабируется вместе с интерфейсом**: при линейном rem-масштабе body достиг 17.5px — вердикт «огромный везде»; enterprise-канон (Atlassian/Carbon/Fluent, обзоры плотных B2B-порталов, research Exa 20.09.2026) держит плотную лестницу 11–14px независимо от density; доступность размера текста закрывает браузерный зум (WCAG 1.4.4 проверен эквивалентом 960×540).
- **Калибровка по живому эталону**: ambient-замеры Битрикс24 из сессии владельца (in-app browser) дали точные px целевых элементов — навигация 15px/400, ряд 38px, меню 240px, титул 21px/600; наша лестница и сетка сведены к ним с осознанными отступлениями (ряд 40px = наша сетка контролов; +2px невидимы).
- **Дискретные шаги масштаба**: непрерывные значения дают артефакты округления пикселей на hairline-геометрии (research).

## Последствия

- Персональная настройка «Масштаб интерфейса» (0.9/1.0/1.125/1.25, каскад user → system, запись `--ui-scale` на html из ui-prefs-store + схема contracts) — follow-up issue: снимает конфликт «34" владельца против 24" тестировщиков».
- Любой НОВЫЙ text-* токен добавлять и в `@theme`, и в группу font-size tailwind-merge (иначе кегль молча глушится тоном).
- «Размер масштабируется, внешний вид фиксирован»: hairline 1px, порты r=3/r=7, stroke, скроллбар 3px НЕ масштабируются.
- Зеркала канона в том же коммите: `tokens.md`/SKILL.md навыка nodus-ui-style, `ux-principles.md`, gotchas (rem в @container против media queries; tailwind-merge и кастомные text-*).
