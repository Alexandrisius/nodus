# ADR-0013. Файловое хранилище фазы 1: S3-движок SILO, multipart через api, сервисная учётка, подписанные ссылки отдачи

- **Статус:** Принят
- **Дата:** 2026-09-28
- **Контекст:** issue #57 (M9 фаза 1, эпик #51), первый потребитель — вложения чата (M6/Ф6)

## Контекст

Всем модулям с документами нужны файлы: вложения сообщений чата (первый
потребитель), дальше — письма (M5), стикеры и аватарки. MinIO-контейнер стоит
в compose с самого начала (ADR-0002), таблица `message_attachments` жила в БД
без реализации. Драфт бэкенд-плана (трек 4, решение Q5) выбирал «presigned PUT
после контекстной проверки прав»: браузер льёт напрямую в MinIO, api не
проводит байты через себя.

Топология прода изменила расклад: единственный вход — Cloudflare Tunnel
(nodus.by). У Cloudflare жёсткий лимит тела проксированного запроса —
**100 МБ на Free/Pro-тарифах** (Business 200 МБ, Enterprise 500 МБ; лимит
не отключается). Значит «200 МБ мимо api» через туннель недостижимо в любом
варианте — байты проходят Cloudflare и в presigned, и в multipart-схеме.
Presigned PUT дополнительно требует: публичный маршрут браузер→MinIO (новый
hostname + правки Cloudflare-панели владельца), CORS на MinIO, конфиг
подписания под внешний endpoint и трёхшаговый клиент (presign→PUT→confirm)
вместо уже построенного UI (FormData POST с XHR-прогрессом, #87/A1).

## Решение

1. **Движок — SILO** ([silo.pigsty.io](https://silo.pigsty.io/), образ `pgsty/silo`,
   запинен точным тегом RELEASE.…): поддерживаемый форк MinIO от Pigsty. Upstream
   мёртв — community-версия заморожена (май 2025 вырезана консоль, октябрь 2025
   последний официальный образ — наш прежний `minio/minio:RELEASE.2025-09-07`
   навсегда без патчей, включая фикс CVE-2025-62506; апрель 2026 репозиторий
   заархивирован). SILO — тот же код/S3-API/`MINIO_*`-env/макет данных (том
   `nodus_miniodata` совместим, миграция не нужна), релизы раз в 1–2 месяца,
   публичные CVE-фиксы. Отличия в эксплуатации: клиент в образе — `mcli`
   (mc-совместимый; `mc`-алиас тоже есть), `user add` — упсерт секрета (команды
   `user reset` нет), нативная проба `silo healthcheck ready`. Стратегия
   обновлений: watch релизов, тег — осознанно, не `latest`. Имена
   контейнеров/volume/алиаса `nodus-minio` и `MINIO_*`/`STORAGE_*`-env не менялись.
2. **Транспорт загрузки — multipart-стрим через api** (`@fastify/multipart`,
   стрим без буферизации → `putObject` в SILO): один канал входа, никакого
   CORS, клиентский контракт уже готов. Отклонение от Q5 осознанное:
   обоснование (а) лимит Cloudflare делает выгоду presigned нулевой в текущей
   топологии, (б) zero внешних зависимостей, (в) на 170 сотрудников двойной
   хоп по внутренней docker-сети неощутим.
3. **Presigned PUT остаётся фазой 2** (переезд на VPS в декабре убирает
   Cloudflare из пути): порт `FileStorage` и структура ключей менять не
   потребуется — добавятся эндпоинты presign/confirm в модуль files.
4. **Отдача — HMAC-подписанные URL нашего api** (`GET /files/:id/content?exp&sig`):
   `<img>`/«скачать»/новая вкладка не умеют Authorization-заголовок; подпись
   HMAC-SHA256(`id:exp`) секретом `STORAGE_URL_SECRET`, TTL 24 ч — виза на
   просмотр, права проверены при выдаче (лента сообщений требует членства).
   Same-origin через nginx-прокси `/api` — без CORS. ETag (версии неизменяемы)
   даёт 304; Content-Disposition: inline для изображений, attachment для
   остального.
5. **Изоляция (I3/I13, по канону ADR-0012)**: интерфейс `FileStorage`
   (save-стрим/remove) + токен `FILE_STORAGE` — в `core/ports`; модуль files
   (`@Global`, как CryptoModule) реализует порт MinIO-драйвером и владеет
   таблицами `file_objects`/`file_versions`; chat знает только интерфейс.
   `message_attachments.file_id` — plain UUID без FK (правило data-model).
6. **Безопасность с первого дня**: бакет приватный; **сервисная учётка api**
   (права только на объекты, создаёт одноразовый `minio-init` из compose) —
   root-креды api не получает; `scan_status: pending|clean|infected` —
   infected не отдаётся (410 FILE_QUARANTINED) уже сейчас, сканер ClamAV и
   карантинный префикс ключей — фаза 2 (M14), pending в фазе 1 отдаётся
   (иначе файлы нельзя посмотреть без сканера); лимиты: потолок хранилища
   200 МБ (busboy+сверка байт), чат — 100 МБ/файл и ≤20 неотправленных
   (вердикт владельца 24.09, серверная сверка); аудит на загрузку/отмену;
   идемпотентность POST (Idempotency-Key, ADR-0005).
7. **Сверка размера**: клиент заявляет `size` (File.size точен), драйвер
   считает фактически прожитые байты — расхождение = FILE_SIZE_MISMATCH,
   объект удаляется (обрыв/подмена не хранятся).
8. **Уборка**: объект пишется раньше строки БД (строка не ссылается в пустоту;
   объект-сирота при сбое БД редок, убирается фазой 2); брошенные загрузки
   (неотправленные >48 ч) снимаются лениво при следующей загрузке того же
   владельца — без новых воркеров.

## Альтернативы

- **Presigned PUT из Q5** — см. Контекст; возвращается фазой 2 на VPS.
- **Presigned GET для отдачи** — требует того же публичного маршрута к MinIO;
   подписанные URL своего api проще и дают scan-гейт/Content-Disposition
   централизованно.
- **Blob через api-client (fetch → objectURL)** — память на галереях, ломает
   «открыть в новой вкладке»/«скачать», нативное кэширование.

## Последствия

- Все байты вложений проходят api — мониторим размер запросов; nginx уже
  настроен (`client_max_body_size 200m`, таймауты 300 с — дефолт nginx 1 МБ
  срезал бы загрузки).
- Файлы >100 МБ через nodus.by не пройдут (Cloudflare, не наш код): лимит
  чата 100 МБ стоит на границе; снимается VPS-переездом или Business-тарифом.
- Отзыв доступа в пределах TTL подписи (24 ч) невозможен — принято для
  внутреннего портала; кэш браузера 1 ч private.
- Inline отдаётся только whitelist растровых mime (валидация #57: SVG с
  клиентским mime в «новой вкладке» = stored XSS на origin портала);
  прочее — attachment + nosniff.
- Идемпотентность POST вложений не сверяет тело (multipart в
  интерсепторе ещё не разобран): повтор с тем же Idempotency-Key и другим
  файлом получает реплей первого ответа, а не CONFLICT — клиенты генерируют
  ключ на каждую попытку, расширение ADR-0005 при появлении ретраев загрузок.
- Новые env: `STORAGE_*` (endpoint/учётка/бакет/секрет подписи) — обязательны,
  fail-fast при старте.
