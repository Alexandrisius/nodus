# ADR-0009. Стек карточек сущностей: единая геометрия, наслоение, стек в URL

- **Статус:** Принят
- **Дата:** 2026-09-10
- **Контекст:** вердикт владельца по итогам UI-чекпоинта issue #4 (2026-09-10)

## Контекст

Карточки сущностей (задача, проект, письмо, сотрудник) открывались вложенными
маршрутами (`/projects/:id/task/:taskId`) с уровневой геометрией: уровень 2 был
уже и ниже уровня 1. Проблемы, зафиксированные владельцем:

- при открытии карточки из карточки «дёргается весь UI» — размеры различаются;
- цепочки навигации (сотрудник → его задача → её проект) не выражаемы
  статической вложенностью роутов — комбинаторный взрыв маршрутов;
- карточки не-задач открывались с микролагом: слайдер-страницы были lazy-чанками
  (первый клик платил загрузку и компиляцию графа модулей).

Референс владельца — слайдеры Битрикс24: карточки наслаиваются одна на одну,
закрытие верхней возвращает к предыдущей; в новых версиях Битрикс отказался от
визуального смещения слоёв — нижние просто не видны, и это нормально.

## Решение

1. **Закон единой геометрии:** все карточки сущностей — один размер и позиция
   (`SliderPanel`, inset-2 внутри хоста: парящий лист от самого верха,
   скругление всех углов 18px, пакет мягкости 12.09.2026). Правый край хоста =
   левый край служебной полосы (полоса — ЗА пределами мягкой рамы, план
   14.09.2026 R4): карточка полосу не накрывает и при её раскрытии
   (кнопка-шевроны внизу полосы, вердикт 14.09.2026: без авто-раскрытия)
   (40 ⇄ 192px) сужается синхронно с рамой (`transition-[right]` 200ms на
   хосте; FLIP-dst = 8 / 8 / innerWidth − stripW − 16 / innerHeight − 16).
   Уровней и смещений нет.
2. **Стек вместо вложенных роутов:** открытие карточки — push в стек,
   закрытие — pop; нижние карточки остаются смонтированными под верхней
   (состояние, скролл, вкладки сохраняются). Глубина и цепочки произвольные
   (employee → task → project → letter…).
3. **Источник истины — URL:** стек сериализован в search-параметр
   `?cards=task:<id>,project:<id>` (deep-link, восстановление после F5;
   «назад» браузера снимает верхнюю карточку — открытие push, закрытие replace).
   Разделные search-параметры (папка писем, вид задач) при открытии сохраняются
   (апдейтеры через `search: (prev) => …`, `to: '.'`).
4. **Хост `CardStackHost`** в AppShell читает стек и рендерит панели в порядке
   стека (DOM-порядок = z-порядок). Реестр видов карточек — в нём же.
5. **Все карточки — eager-импорты** (не lazy-чанки): карточка — центральный
   экран продукта, открывается из любого раздела; загрузка кода платится один
   раз на старте (где есть loading-состояние), открытие мгновенное у всех
   сущностей — как у карточки задач (gotchas: «первое открытие lazy-роута»).
6. Маршруты `/tasks/:id`, `/letters/:id`, `/projects/:id`, `/employees/:id` и
   вложенные комбинации удалены; точки открытия используют `useOpenCard()`.

## Альтернативы

| Альтернатива | Почему отклонена | Когда пересмотреть |
| --- | --- | --- |
| Вложенные роуты (прежняя модель §10.2) | Комбинаторный взрыв (N сущностей × глубина), уровневая геометрия ломала единый размер, lazy-чанки лагали | — |
| Стек в Zustand без URL | Теряется при F5, нет deep-link на открытую карточку, «назад» браузера не работает — против духа I2 | Если search-параметр станет узким местом (очень длинные стеки) |
| Смещённые слои (старый Битрикс: каждая следующая карточка ниже/уже) | Владелец: современный Битрикс от этого ушёл; единый размер проще и спокойнее | Если владелец попросит видимость глубины стека |
| Lazy-чанки карточек с префетчем по ховеру | Ховер-префетч не покрывает первый клик с клавиатуры/палитры/deep-link; eager дешевле (~десятки КБ в основном бандле) | При росте бандла > бюджета NFR — пересмотреть сплит |

## Последствия

- **Проще:** один механизм открытия сущностей для всего продукта; любые цепочки
  без новых роутов; закрытие возвращает контекст (состояние нижних карточек
  живо); мгновенное открытие всех карточек; палитра Ctrl+K открывает карточку
  поверх текущего раздела, не уводя со страницы.
- **Сложнее:** основной бандл web несёт код всех карточек (следить за бюджетом);
  смена раздела через главное меню сбрасывает стек (search не наследуется при
  прямой навигации — задокументированное поведение, как у модалок).
- Риск «стек разрастается неудобно» снимается приёмкой владельца на
  UI-чекпоинте; глубина в демо-концепте — 2–3 уровня.

## Дополнение (2026-09-11): два режима открытия — «Навигация» и «Поверх»

Вердикт владельца по итогам ревизии раунда 4 (issue #4): левая панель ветки
задачи (навигатор, референс ClickUp) конфликтовала со стеком — каждый клик по
связанной задаче наращивал стопку карточек (10 переходов = 10 Escape).

**Решение:** режим открытия определяет ИСТОЧНИК клика, а не вычисление
«связанности» (предсказуемо для пользователя):

- **«Навигация» (замена верхней карточки, `useReplaceTopCard`):** клики по
  строкам левой панели (вкладки «Подзадачи»/«Связи») и по полям «Подзадачи»/
  «Связи» тела карточки. Подмена последнего CardRef в `?cards=` с
  `replace: true` (без записи истории) + ключ записи хоста БЕЗ id
  (`index:kind`) — панель не перемонтируется: рамка, панель ветки и её
  состояние живут, меняется содержимое. Стек не растёт — один Escape
  закрывает всю сессию; «←» в навигаторе — шаг назад по переходам.
- **«Поверх» (push, `useOpenCard`):** все внешние переходы — ссылка на задачу
  из чата, палитра Ctrl+K, карточки других модулей, поля-люди/проекты.

Карта навигатора стабильна: дерево — от корня СТАРТОВОЙ задачи карточки
(rootId неизменен за жизнь карточки), переезжает только подсветка текущей.
Связь в чужое дерево не пересаживает карту — у такой задачи своя панель.

## Обоснование (research)

- Референс владельца — слайдеры Битрикс24 (наслоение без видимых нижних слоёв).
- TanStack Router: search-параметры как состояние UI — документированный паттерн
  (`to: '.'` + `search: (prev) => …`, наследование root validateSearch) —
  проверено по докам Context7 (/tanstack/router) и типам router-core 1.170.
- Производительность eager-импортов центральных экранов — gotchas «Первое
  открытие lazy-роута = фриз хореографии» (замеры 429→48 мс, issue #4).
