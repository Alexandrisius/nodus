# ADR-0018: Превью ссылок — linkpeek + многослойный SSRF-контроль

## Статус

Принято (ночной прогон #212, 05.10.2026).

## Контекст

Сообщения чата несут голые URL; все мессенджеры разворачивают ссылку в карточку
(Open Graph). Превью требует внешнего фетча недоверенного HTML — канонический
вектор SSRF (RFC1918, cloud-metadata 169.254.169.254, DNS-rebinding,
редирект публичный→приватный). Спека #212: BullMQ-конвейер, кэш по
нормализованному URL, TTL 24ч/отрицательный 1ч, lazy-прогрев.

## Решение

**linkpeek** (зависимость `linkpeek`, MIT) + собственные гварды:

- linkpeek из коробки: схема http/https, блок приватных/зарезервированных
  диапазонов (`allowPrivateIPs=false`, `PRIVATE_NETWORK_BLOCKED`), ручные
  редиректы с ревалидацией КАЖДОГО хопа, стрим с `maxBytes` (30 КБ — голова
  HTML достаточна для meta), `timeout` 8 с, свой User-Agent, TTL-политика на
  нашей стороне. Известное ограничение (документировано): финальный DNS
  резолв делает платформенный fetch — TOCTOU между проверкой и коннектом.
- Наши слои поверх (unit-тесты): порт только 80/443/не указан (linkpeek
  порт-фильтра не имеет); self-domain short-circuit (свой домен/localhost —
  карточка-заглушка без фетча); лимиты длин полей; per-user Redis-счётчик
  фетчей (~30/час); отказ = заглушка-карточка из домена (I11, главный режим
  отказа). Ограничение TOCTOU принято: продукт self-hosted в закрытом
  контуре, внешний фетч инициируют только аутентифицированные участники
  бесед, счётчик ограничивает масштаб; усиление (прокси-egress) — за
  пределами MVP.
- Альтернатива `fetch + htmlparser2` (свой парсер + ручные все гварды)
  отклонена: дублирует зрелую поверхность linkpeek (meta/JSON-LD/twitter
  fallback, redirect-ревалидация) — больше своего SSRF-кода = больше риск.

## Последствия

- Новая зависимость — фиксируется здесь (правило «зависимости без ADR
  запрещены»); карточка и og:image/favicon скачиваются в SILO через
  файловый конвейер #139 (sharp-дериват ≤640px webp) — без хотлинков.
- Конвейер: слушатель `chat.message_sent/edited` (I9) → BullMQ
  `chat-link-preview` (jobId = нормализованный URL — дедуп) → кэш
  `link_previews` → WS `chat.link_preview_ready` (комната беседы).
