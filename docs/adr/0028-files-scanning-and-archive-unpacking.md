# ADR-0028. Файлы: точка расширения антивирусной проверки и автораспаковка архивов

- **Статус:** Принят
- **Дата:** 2026-10-25
- **Контекст:** требование владельца 23.10 («все устали скачивать вложения, чтобы просмотреть»), уточнение 24.10 (распаковка только у зарегистрированных писем), ответ 8 («проверкой вирусов занимается корпоративный антивирус»), ответ 25.10 (на сервере компании Kaspersky, второй антивирус под сомнением), #427. Развивает ADR-0013.

## Контекст

Входящие письма часто приходят архивом (zip/rar/7z). Распаковка на сервере — это разбор недоверенного содержимого: архивные бомбы, выход за каталог (zip slip), шифрованные архивы, русские имена в кодировке cp866. Отдельный вопрос — антивирус: ClamAV требует 3–4 ГБ оперативной памяти и обновлений баз из интернета; Kaspersky на хосте не видит объекты внутри S3-хранилища SILO (внутренний формат), но проверяет файлы при скачивании и открытии на рабочих местах и временные файлы на диске сервера.

## Решение

1. **Точка расширения `FILE_SCANNER`** (I13, первый потребитель — письма): интерфейс «проверить поток файла → `clean | infected | error`», статусы `scan_status` у `FileObject` (поле есть с #57). Провайдер по умолчанию — `none`: файл помечается «не проверялся» и доступен (слои защиты — антивирус почтового сервера и корпоративный Kaspersky на рабочих местах). Адаптер ClamAV (clamd INSTREAM по внутренней сети, отдельный профиль compose) включается по решению компании (draft в M14). Заражённый файл (если провайдер включён) — 410 `FILE_QUARANTINED`, уведомление администратору.
2. **Автораспаковка — только у зарегистрированных писем** (в «Новых» архив не трогаем): BullMQ-задание в изолированном воркере (отдельный процесс, временный каталог, таймаут, ограничение параллельности). Сначала оглавление (`7zz l -slt`), проверка пределов и шифрования, затем извлечение. Бинарь 7-Zip (`7zz`) — zip, rar, 7z, имена cp866 (`-mcp=866` для zip без флага UTF-8).
3. **Пределы** (настройка администратора): глубина вложенных архивов ≤ 3, ≤ 100 файлов, ≤ 200 МБ распакованного на архив, коэффициент сжатия ≤ 100:1. Нарушение — метка «не распакован: причина», архив доступен целиком. Запароленные — метка «защищён паролем». Запрещены абсолютные пути, `..`, NUL, имена устройств Windows, символьные и жёсткие ссылки.
4. **Результат:** каждый файл — `FileObject` через `FILE_STORAGE` + строка `letter_attachments` с родителем-архивом и путём внутри; в карточке письма распакованное показывается деревом под архивом; исходный архив скачивается. Если провайдер проверки включён — распакованное показывается только после `clean`.
5. **Совместимость с Kaspersky:** при включении ClamAV исключить из проверки Kaspersky каталог баз ClamAV и тома Nodus (иначе ложные срабатывания и блокировки временных файлов).

## Альтернативы

| Альтернатива | Почему отклонена | Когда пересмотреть |
|---|---|---|
| ClamAV обязателен с декабря | 3–4 ГБ ОЗУ, обновления из интернета, владелец против второго антивируса | Решение компании / требование безопасности |
| Распаковка в «Новых» | Больше поверхность атаки и мусора до решения о регистрации (вердикт 24.10) | — |
| Только yauzl (zip) | Нет rar/7z, которые реально приходят | — |
| Показ архива «как папки» во вьювере без распаковки | Каждый просмотр — повторный разбор; нет проверки и поиска | После НГ (M9) |

## Последствия

**Проще:** сотрудники видят содержимое архива сразу в карточке письма. **Сложнее:** новая системная зависимость (7-Zip в образе воркера — обновлять вместе с базовым образом); тесты на бомбы, zip slip, пароль, cp866. Без включённого провайдера проверки полагаемся на почтовый сервер и рабочие места — осознанный риск владельца.
