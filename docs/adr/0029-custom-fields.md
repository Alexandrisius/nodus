# ADR-0029. Кастомные поля: реестр определений, JSONB-значения, участие в процессах

- **Статус:** Принят
- **Дата:** 2026-10-25
- **Контекст:** вердикты владельца 23.10 (ответы 29, 33, 62, 63, 66: «как в ClickUp, не как в Битриксе — поля должны участвовать в процессах, фильтрах, реестрах, отчётах»), запись инкубатора 24.09, #427. Актуализирует задел `FieldDefinition` в `data-model.md` и модуль `custom-fields` из `modules.md`.

## Контекст

Без полей не собрать ни письма (корреспондент, подписант, их №/дата), ни заявки (дата, часы, проект), ни комплекты («№ накладной», «дата передачи»). В Битриксе пользовательские поля только отображаются — владелец назвал это «полной чушью».

## Решение

1. **Модуль `custom-fields`** (ядро): реестр определений по областям `task | letter | project | counterparty`; область `node` зарезервирована (узел — папка без полей, вердикт 24.10). Вкладка раздела «Автоматизация» (в интерфейсе — «Атрибуты», см. дополнение #431); тип процесса выбирает поля из реестра или создаёт на месте (ADR-0024).
2. **Типы полей:** текст, длинный текст, число (точность), деньги (сумма + валюта из справочника), дата, дата-время, продолжительность (минуты, «ч:мм»), флаг, словарь (один / несколько — по id элементов `dictionaries`, I15), сотрудник (один / несколько), проект, контрагент, ссылка/путь (URL или путь `\\сервер\…`: в десктопе — «Открыть в проводнике», в вебе — «Скопировать путь»). Тип «файл» — V2 (файлы задач живут в чате).
3. **Хранение:** значения — JSONB `custom_fields` сущности, ключ — id определения (переименование поля безопасно). Валидация на границе API — zod, собранная из определений. Индекс GIN `jsonb_path_ops`; для полей с флагом «индексировать для отчётов» — функциональные индексы / генерируемые типизированные колонки. Удаление — архивация; смена типа — только совместимая.
4. **Участие в процессах:** формы создания и карточки (ADR-0024); раздел «Дозаполнить поля» окна перехода и гейт `fields_required` (ссылки на системные и кастомные поля); фильтры списков, реестры, выгрузка; источник решающих «поле „Сотрудник“» (ADR-0025); значения по умолчанию, включая снимок на момент создания («подразделение автора» — для аналитики по подразделениям при переводах сотрудников).
5. **События:** `custom_field.definition_changed`; изменение значения — в событии изменения сущности (`task.updated` и аналоги) с кодом поля и старым/новым значением.

## Альтернативы

| Альтернатива | Почему отклонена | Когда пересмотреть |
|---|---|---|
| EAV (строка на значение) | Каждое поле — соединение; значения текстом | — |
| Колонка на поле (миграция на каждое поле) | Новое поле = релиз; противоречит I15 | Горячие поля продвигаются генерируемыми колонками |
| Поля «для отображения» (Битрикс) | Не участвуют в процессах — владелец против | — |

## Последствия

**Проще:** новое поле — данные, без релиза; поля сразу работают в формах, окнах, фильтрах и реестрах. **Сложнее:** динамическая валидация и рендер; сортировки по полям без индекса медленнее (флаг «индексировать для отчётов»); BI-представления по типам — позже.

## Обоснование (research)

- AWS Database Blog «PostgreSQL as a JSON database: advanced patterns» (2025): выражения и частичные индексы для частых ключей.
- «JSONB without regret» (2025): GIN — для вхождения, B-tree — для сортировок и диапазонов, продвижение горячих полей.
- ClickUp custom fields; Яндекс Трекер — типы «продолжительность» и «деньги» (06.2026).

**Замена архива скрытием (вердикт владельца 25.10.2026).** `archivedAt` у определения убран: вместо него `hidden`. Скрытый атрибут живёт для процессов, автоматики и отчётов, но не виден никому в карточках, фильтрах и окнах переходов. Удаление — физическое (`DELETE …/:id`, 204), значения стираются: запрещено, пока атрибут стоит в окне или условии «Заполнены поля» опубликованного маршрута (409 `CUSTOM_FIELD_IN_USE` со списком процессов). Причина: владелец не приемлет «архив вместо удаления» — тестовый мусор должен исчезать. Лимит 100 и уникальность имени считаются по ВСЕМ атрибутам области, поэтому уникальность — выраженный индекс `(scope, lower(btrim(name)))`, а не partial.

**Термин.** В интерфейсе — «Атрибуты» (вкладка «Автоматизации», блок карточки, группа фильтра, подгруппа редактора маршрута). В коде и контрактах остаётся `custom field` / `customFields`: ключи API и таблиц не переименовываются.

**Где живёт валидация.** Одна точка на сервере — порт `CUSTOM_FIELD_REGISTRY` (`definitions`, `prepareCreate`, `prepareUpdate`, `refs`). Модули-владельцы сущностей не читают `field_definitions` и не проверяют значения сами (I3/I7). Грамматика типов — общая в `packages/contracts/src/custom-fields/custom-field-values.ts` (исключение «общая грамматика» из `patterns.md`).

**События и ключи.** `custom_field.definition_changed {definitionId, scope, change: created|updated|deleted|reordered, fields?}` — каталожное (gateway рассылает всем); `task.updated` несёт `customFieldChanges[{fieldId, from, to}]` и ключи `cf.<id>` в `fields`. Ключ `cf.<uuid>` — общий для окна перехода и гейта `fields_required`; неизвестный (удалённый) ключ переход не блокирует, публикация даёт ошибку `custom_field_unknown`, а скрытый в окне — предупреждение `custom_field_hidden` (в условии скрытый допустим).
