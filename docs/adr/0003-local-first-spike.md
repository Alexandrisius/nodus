# ADR-0003. Local-first: свой sync-движок не строим; готовые движки проверяются спайком

- **Статус:** Принят (перенесено из концепт-ТЗ, Приложение А, ADR-001)
- **Дата:** 2026-09-02
- **Контекст:** целевой UX уровня Linear («мгновенно») при ограничении C3 (LAN ~1 мс) и требованиях аудита

## Контекст

Хотим UX уровня Linear. Классический local-first (клиент — хозяин данных, свой движок синхронизации) требует месяцев на движок, тащит конфликты/офлайн/миграции кэша и противоречит C3 (LAN и так даёт ~1 мс) и требованиям аудита. Рынок дозрел: Zero («навороченный кэш» поверх Postgres, self-host Docker), Electric SQL (read-path синхронизация, записи идут через наш API — авторизация и бизнес-логика остаются в NestJS).

## Решение

MVP строится на оптимистичном UI + WebSocket + LAN (I4) — это ~90% ощущения Linear без движка. Собственный sync-движок не разрабатывается никогда. После пилота (отдельный этап, до старта V2 — не параллельно с пилотом, C1) проводится time-boxed спайк (1–2 недели) готового движка (Electric в приоритете, Zero как альтернатива) на модулях «чат» и «список задач».

**Decision gate (критерии принятия движка в V2):** открытие чата с историей < 100 мс из кэша; 1000 офлайн-мутаций → реконнект без рассинхрона; миграция схемы не ломает клиентов с кэшем; read-path защищён auth-проксёй (права на уровне строк); k6: 300 WS-соединений, p95 в норме НФТ. Спайк провален → остаёмся на TanStack Query optimistic, потеря ограничена 2 неделями.

**Границы.** Сервер всегда авторитетен; движок — только ускоритель чтения/кэш. Модули `correspondence` и `workflows` (юридическая значимость, аудит) — всегда server-authoritative с оптимистичным UI, без sync-движка.

## Альтернативы

| Альтернатива | Почему отклонена | Когда пересмотреть |
|---|---|---|
| Свой sync-движок | Месяцы работы; конфликты/офлайн/миграции кэша; сервер должен видеть данные (аудит, поиск) | Никогда |
| Принять готовый движок без спайка | Непроверенные риски: миграции схемы, права на уровне строк, поведение под нагрузкой | После спайка — по decision gate |

## Последствия

**Проще:** MVP без движка — быстрее; потеря при провале спайка ограничена 2 неделями. **Сложнее:** дисциплина «сервер авторитетен» должна выдержаться при подключении движка; read-path auth-прокси — нетривиальная часть спайка.
