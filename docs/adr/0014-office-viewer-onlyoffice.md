# ADR-0014. Движок просмотра офисных вложений — ONLYOFFICE Docs CE (JS API + JWT)

- **Статус:** Принят (реализация #138, M9 фаза 2)
- **Дата:** 2026-09-28
- **Связанные:** ADR-0002 (dev/демо-хост), ADR-0013 (файловое хранилище SILO), ADR-0012 (read-порты)

## Контекст

Пилотная команда должна смотреть вложения чата, не скачивая (боль владельца:
«иначе качают всё и мусорят в папках»). Референс — Битрикс24.Докс (ядро
Р7-Офис = форк ONLYOFFICE): клик открывает редактор в режиме чтения, сессии
тарифицируются только на правку. Excel нужен как живая сетка (не PDF-копия),
Word — постранично, PowerPoint — слайдами; правка и ко-эдитинг — по праву
контекста. I11 (self-hosted, zero cloud) исключает облачные редакторы.

## Решение

**ONLYOFFICE Docs CE 9.4** (`onlyoffice/documentserver:9.4.0.1`) отдельным
контейнером-компаньоном под compose-профилем `office` (как SILO — не линкуемся
со сборкой; стек живёт и без него). Интеграция — **JS API + JWT** (не WOPI):
богаче возможностей, типовой путь (Nextcloud/Битрикс/Directum), смена вендора
(Р7) = замена контейнера.

- **Сессия документа собирается целиком на сервере**: `GET /files/:id/office-session`
  проверяет право контекста (порт `FILE_ACCESS_CONTRIBUTORS` — реализация chat
  по членству в беседе, паттерн ADR-0012), строит `document` + `editorConfig`,
  подписывает HS256 общим секретом `OFFICE_JWT_SECRET`. Клиент передаёт секции
  в `DocsAPI.DocEditor` дословно — подпись гарантирует целостность. Право =
  владение файлом ИЛИ контекст потребителя; чужим — 404 (не раскрываем).
- **Callback сохранений**: `POST /files/:id/office-callback` (@Public, вход —
  Bearer JWT документ-сервера с payload-обёрткой). Статусы 2/6 скачивают
  собранный файл (origin переписывается на внутренний адрес DS — DS строит
  ссылки от браузерного Host) и создают новую `FileVersion` (+указатель
  `file_objects`, событие `file.version_created` в outbox, аудит) одной
  транзакцией. Идемпотентность — по `document key` + `lastsave` (колонки
  `file_versions.source_key/source_lastsave`): повторная доставка и
  «forcesave → закрытие» не плодят версии; сессия правки живёт под ключом,
  породившим текущую версию. Документ-ключ = `fileId.v{version}` (алфавит DS —
  `0-9-.a-zA-Z_=`).
- **Роутинг вложений по типам** — единая точка решений `contracts/files/
  office-formats.ts` + web-реестр `shared/files/viewer-registry.ts`: офисные
  форматы → ONLYOFFICE view; PDF → pdf.js (без сессии, `pdfjs-dist`, воркер
  как vite-ассет, ленивые страницы); видео/аудио/изображения → нативные
  элементы; прочее (архивы, DWG) и файлы > 50 МБ → карточка скачивания.
  Fallback при недоступности движка — карточка скачивания без ошибок UI.
- **Прокси браузер→DS**: DS опубликован только в compose-сети; браузер ходит
  через origin портала по КОРНЕВЫМ путям DS (`/web-apps`, `/sdkjs`, `/cache`,
  `/doc/`-вебсокет, …) — nginx `web.conf` (regexp-location) в проде,
  vite-прокси в dev/песочнице. Субпаст не используем: DS строит абсолютные
  пути и 302-редиректы от корня + версионный префикс `/<версия>-<хэш>/`.
  Host форвардится с портом (`$http_host`): от него DS строит ссылки на
  собранные файлы.
- **Внутренние вызовы api↔DS** — по адресам compose-сети (env
  `OFFICE_API_INTERNAL_URL` / `OFFICE_INTERNAL_URL`; в песочнице —
  `host.docker.internal`). `ALLOW_PRIVATE_IP_ADDRESS=true` — SSRF-фильтр DS
  по умолчанию режет приватные адреса. Правка включается отдельным флагом
  `OFFICE_EDIT_ENABLED` (пилот: сначала просмотр).

## Альтернативы

- **Collabora (LOL)** — легче по RAM, но слабее фидельность OOXML (пилотная
  команда живёт в Excel/Word) и беднее JS API.
- **Р7-Офис** — та же кодовая база, платная поддержка в РФ; API идентичен,
  замена контейнера при необходимости, код не меняется.
- **WOPI** — стандарт, но меньше контроля над UI/режимами и лишний
  lifecycle-контур; JS API даёт то же самое короче.
- **Gotenberg-конвертер в PDF** — уже в стеке, но Excel-сетка и правка
  теряются (боль владельца именно про сетку); остаётся как конвейер
  производных (#139) для фолбэков.

## Последствия

- +1 контейнер (~2–4 ГБ RAM; профиль `office`, прод поднимается осознанно);
  тома `nodus_office*` для кэша/логов/шрифтов.
- Версии файлов: `file_objects.version` + `file_versions.source_*`
  (миграции 20260928202032/20260928202804); подписанные ссылки версионные
  (`:v`-суффикс в ресурсе HMAC).
- Тайминг первого старта DS — до 5 минут (шрифты); healthcheck
  `/healthcheck == true`.
- Ограничения DS: потолок скачивания 100 МБ (наш гейт 50 МБ раньше),
  сохранение legacy `.doc` может откатиться в `.docx` (документировано DS).
