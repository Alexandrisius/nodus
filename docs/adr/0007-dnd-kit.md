# ADR-0007: drag-and-drop — @dnd-kit/core

- **Статус:** принято
- **Дата:** 2026-09-09
- **Контекст:** канбану задач (и будущим переносимым сущностям) нужен drag-and-drop: перенос карточки между колонками-стадиями с оптимистичным обновлением (I4), отменой по Esc и клавиатурной доступностью. Писать свой движок pointer-events — значит вручную воспроизводить a11y (screen readers, keyboard-координаты), collision detection и touch-сенсоры: сотни строк на каждую сущность.

- **Решение:** `@dnd-kit/core` (линия 6.x) как движок DnD во фронте. Паттерн канбана — «множество контейнеров» без sortable: карточка = `useDraggable`, колонка = `useDroppable`, перенос — на `onDragEnd` по id колонки, призрак — `DragOverlay`; PointerSensor с `activationConstraint.distance` (клик без движения остаётся кликом — открытие слайдера), KeyboardSensor и TouchSensor из коробки. Collision detection — `closestCorners` (рекомендация доков для мульти-контейнерных раскладок).

- **Отклонённые альтернативы:**
  - `@dnd-kit/react` (новое поколение API): чище семантика (автоматический откат оптимизма), но заметно моложе; паттерн без sortable одинаково прост на обоих — взяли зрелую линию; миграция возможна точечно.
  - `hello-pangea/dnd`: отличный a11y, но заточен под списки/колонки фиксированной структуры, хуже под произвольные drop-зоны и overlay-стилизацию под наш канон.
  - `react-dnd`: низкоуровневый, больше бойлерплейта на тот же результат.
  - Свои pointer-events: приемлемо для ручек ресайза (одна механика), но не для DnD-матрицы a11y/touch/collision.

- **Последствия:** +зависимость в `@nodus/web` (tree-shakeable, без runtime-внешних сервисов — I11 не нарушает). Порядок внутри колонки (поле `order`) — не в скоупе первой итерации: перенос меняет стадию, порядок внутри колонки серверный; сортировка внутри колонки — следующей фазой вместе с контрактом `order`. Визуализация drag — только в грамматике «Инструмента» (плоско, без теней-«приподниманий»: overlay = карточка с `border-input` и свечением активного узла).
