# Карта модулей

Принцип-антитезис Битриксу: никаких модулей «на всякий случай». Модуль появляется только под реальный процесс. Каждый не-ядровой модуль отключаем feature-флагом (I10).

Читать: перед созданием нового модуля и при уточнении границ существующих.

## Ядро (всегда включено)

| Модуль | Ответственность |
|---|---|
| `auth` | Логин, JWT/refresh, сессии, (опц.) TOTP 2FA; интерфейс AuthProvider для Keycloak/LDAP в V2 |
| `directory` | Пользователи, отделы (дерево оргструктуры), роли, должности; карточка сотрудника. Роли — сущности с составом (сотрудники и подразделения); права ролей — точечная выдача и отзыв, каталог прав с привязкой к разделам; права сотрудника считает порт `ROLE_MEMBERSHIP_READER` (#379, ADR-0034) |
| `notifications` | Единый центр уведомлений + диспетчер каналов: in-app, Web Push, email-дайджест; настройки пользователя (mute, DND-расписание, «только @упоминания») |
| `files` | Загрузка/версии/права, превью-конвейер (PDF-рендер для просмотра), ViewerRegistry — реестр просмотрщиков (точка расширения под DWG/BIM) |
| `search` | Глобальный поиск по задачам, письмам, сообщениям, файлам; развитие — гибридный движок FTS + pgvector + RRF + реранк (эпик #272/M18: точки расширения SearchProvider/EmbeddingProvider по I13, первый потребитель — модуль `kb`) |
| `audit` | Неизменяемый журнал: кто/когда/что/с какого клиента; просмотр в админке; вкладка «История» в карточках сущностей; версии контента (Revision): правки сообщений, описаний задач, тел писем |
| `custom-fields` | Реестр **атрибутов** (ADR-0029, #431): определения по областям `task / letter / project / counterparty` (`node` — зарезервирована), 16 типов (текст, длинный текст, число, деньги, дата, дата-время, продолжительность, флаг, список, несколько значений, сотрудник, сотрудники, **подразделение**, проект, контрагент, ссылка/путь), настройки типа (точность, валюта, справочник), значение по умолчанию (в т.ч. снимок «подразделение автора»), скрытие, порядок; значения — JSONB-колонка сущности по id определения. Порт `CUSTOM_FIELD_REGISTRY` — единственная точка динамической валидации значений и умолчаний для владельцев сущностей (I7); грамматика типов общая в контрактах. Обязательность при создании — у формы типа (#432), не у определения. Событие `custom_field.definition_changed`; ключ `cf.<id>` в окнах и гейтах. Атрибуты участвуют в карточках, окнах переходов, гейтах, фильтрах, реестрах и источниках решающих |
| `workflows` | «Процессы» — единый движок маршрутов (ADR-0024/0025): типы процессов с категорией `task / letter`, маршруты (стадии, переходы, правила, окна), редактор и публикация версиями, каталог «засев один раз», конфигурация типа (форма создания, состав карточки, доступ, нумерация, пульс), «кнопку жмут несколько», источники решающих, общий журнал переходов `transition_records`, создание следующей задачи по шаблону. Сущности подключаются адаптерами (задачи, письма); строки сущностей — у модулей-владельцев. Веб — раздел «Автоматизация» |
| `links` | Универсальные связи между любыми сущностями (EntityLink): «связано с», «порождено из», «блокирует», «относится к»; единый блок «Связи» в карточках; основа графа знаний портала |
| `dictionaries` | Справочники/классификаторы, создаваемые в UI без кода (иерархические, с правами на редактирование): «Типы зданий», «Виды работ» и т.д.; элементы адресуются по ID; используются атрибутами-списками и системными выпадающими списками (I15). Запись (#431, Р10): список с вариантами, переименование, добавление/переименование/**удаление** варианта и порядок — правом `dictionary.manage`, с событиями `dictionary.*`; системные справочники (`document-kind`, `currency`) защищены от правки вариантов |
| `admin` | Управление пользователями, ролями, feature flags, просмотр аудита, редактор кастомных полей и справочников, системные настройки |

## Модули MVP

| Модуль | Ответственность |
|---|---|
| `projects` | Проекты (ADR-0030): проект = договор (шифр необязателен — «темы»), тип проекта, портфели (один заказчик — большой объект), видимость «открытый / секретный», участие (производное + приглашённые), роли проекта (подсказки и источник решающих), дерево узлов-папок настраиваемых уровней (без полей, ответственного, срока; агрегаты с листьев-задач), мастер создания по контрольному штампу, пульс, схема проекта (заглушки + генерация задач по статусу), канал проекта |
| `tasks` | Задачи — самостоятельные, проект необязателен: сущность «задача» на движке «Процессы» (адаптер категории `task`, ADR-0024), ответственный/соисполнители/наблюдатели, приоритет, срок, чек-листы, подзадачи, связи, вложения (через чат), трекинг времени (таймер + ручной ввод), итог, узел дерева проекта (`node_id`), канбан «Мои действия» с проекцией ожидающих действий (ADR-0026), реестры типов задач |
| `chat` | Личные чаты, группы, каналы проектов (автосоздание при создании проекта), ответы, реакции, закрепы, @упоминания, черновики, статусы доставлено/прочитано, typing, presence, «сообщение → задача» |
| `correspondence` | Письма (ADR-0027): сущность «письмо» на движке «Процессы» (адаптер категории `letter`), вкладки «Новые / Входящие / Исходящие», приём из общего ящика (IMAP, исходный .eml, дедуп), регистрация с сериями номеров без пропусков, связи «ответ на» / «вложено в», «приложенные письма», резолюция (исполнение ГИПом, «расписать сразу», ознакомление), поручения = задачи (проекция статусов и часов), «Ждёт закрытия», исходящие (согласование, подпись, регистрация, отправка SMTP), конфиденциальность, чат письма, автораспаковка архивов |
| `crm` | Дом фич взаимодействия с клиентами (вердикт владельца 23–24.09.2026, #83; ADR-0033): реестр контрагентов + контактные лица (#460, флаг `crm`; потребители — корреспонденция и проекты по id через read-порт `COUNTERPARTY_READER`), договоры и тендеры — будущие вкладки (V2); лиды/сделки/воронки НЕ моделируются; бэкенд — `apps/api/src/modules/crm/` |
| `esign` | ЭЦП (ADR-0031): подпись файлов через клиентскую программу НЦЭУ NTClientSoftware — только мост десктоп-оболочки; хранение отсоединённой подписи и данных сертификата; потребитель — исходящие письма |
| `resources` | Ресурсный календарь (M16): переговорные и автомобиль — справочник ресурсов, брони, конфликты, сетка день/неделя |
| `automation` (веб-раздел) | «Автоматизация» — единый дом настройки процессов (north-star §5): один пункт левой рейки, вкладки сверху «Процессы» (типы задач и писем), «Атрибуты», «Типы проектов», «Права доступа». Веб-фича `apps/web/src/features/automation/` — композиция API модулей `workflows`, `custom-fields`, `projects`, `directory`; общий холст — `shared/flow` (ADR-0022) |

## Будущие модули (вне MVP, архитектура готова)

Календарь и ресурсное планирование; опросы; база знаний проекта `kb` (эпик #272: документы-датасеты с дифф-импортом Excel и страницы-чанки, иерархический каталог, вход из проекта; первый жилец — каталог строительных ресурсов КСР); CDE (проектная документация, DWG/BIM-просмотр за ViewerRegistry); модуль «Почта» (личные ящики сотрудников, создание задач из письма — после НГ). Направления V3+: ИИ-ассистенты (клиенты API + подписчики событий, MCP-сервер; навигация по графу `links`); ИИ-суммаризация обсуждений и голосовых заметок; ИИ-классификация знаний в чатах (ночной фоновый агент, применение с подтверждением человеком); база знаний по модели «обратный RAG» с кураторами тем; конфигуратор типов сущностей и иерархий; регрессионная модель сроков на данных I14; портфельная карта проектов.

## Правила для новых модулей

- Новый модуль = папка `apps/api/src/modules/<name>/` + зеркальный `apps/web/src/features/<name>/` + `README.md` в каждой (назначение, контракты, события, лимиты).
- Имя модуля — единственное число в префиксе событий (`task.*`, `workflow.*`, `correspondence.*`).
- Модуль не импортирует другие модули (I3, I6): только события и `@nodus/contracts`.
- Не-ядровой модуль с первого коммита — за feature flag (I10).
