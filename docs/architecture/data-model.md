# Модель данных (верхнеуровневая)

Фиксирует состав и связи сущностей; детальная схема — в Prisma (`prisma/`). Новые **доменные** сущности — через ADR; вспомогательные таблицы (join, настройки) добавляются по мере реализации без ADR.

Читать: перед проектированием миграций и новых сущностей.

## Сущности

- **User** (id, email, ФИО, должность, отдел→Department, роль, настройки уведомлений, аватар; presence-статус — НЕ в БД: эфемерный, TTL-ключи Redis, живёт в WS-gateway)
- **Department** (дерево: parent_id)
- **Project** (код, название, стадия, руководитель, даты, chat_channel_id, статус) — **ProjectMember** (project_id, user_id, роль в проекте)
- **ProjectGroup** (название, parent_id?) — портфели/программы: дерево группировки проектов (по заказчикам, типам объектов, годам)
- **WorkPackage** (project_id, название, порядок, ответственный-ГИП) — этап/пакет работ для группировки задач; НЕ задача: без чата, исполнителя и трудозатрат
- **Task** (номер, проект?, родитель?, пакет→WorkPackage?, название, описание, **системное состояние: backlog|active|paused|done|closed** (скрытое, системное, I15-граница), **stage_id→WorkflowStage**, приоритет, дедлайн, постановщик, ответственный, соисполнители[], наблюдатели[], source: manual|chat_message|letter, связь→Message/Letter?, теги)
- **WorkflowScheme** (код, название, **kind: project|personal** (ADR-0008: одна механика, два масштаба), owner→User? (владелец личной схемы), правило применения: фильтр по типу задачи/полям/проекту, приоритет правила) — **TaskType** (scheme_id, название) — **WorkflowStage** (scheme_id, task_type?, название, **цвет** (палитра тонов темы), порядок, → системное состояние, права переходов, автоматические действия при входе/выходе — V2); стадия = колонка канбана; переходы пишут событие `task.stage_changed`. Личная схема «Мой план» — экземпляр-копия дефолтного шаблона per user; проект выбирает схему при создании (отклонение = форк)
- **TaskPersonalPlacement** (task_id × user_id → stage_id личной схемы пользователя, порядок в колонке) — размещение задачи на личной доске «Мой план» (ADR-0008); встроенное автоперемещение: смена системного состояния → переезд в первую личную колонку этого состояния; событие `task.personal_stage_changed`
- **ChecklistItem**, **TimeEntry** (task_id, user_id, минуты, дата, способ: timer|manual, комментарий)
- **TaskResult** (task_id, текст результата, закреплённые сообщения: message_id[], автор, created_at) — результат задачи; в V3 дополняется ИИ-выжимкой обсуждения
- **Conversation** (тип: direct|group|project_channel|task|letter; project_id?/task_id?/letter_id? — привязки к сущностям других модулей plain UUID (I3); title, description, visibility, матрица прав JSONB; **last_seq** — счётчик порядка сообщений: seq выделяется инкрементом last_seq В транзакции отправки (лок строки сериализует вставки беседы → порядок seq == порядок коммита; глобальный bigserial это ломает — конкурентные коммиты вне порядка seq рвут курсорную выдачу); last_message_at — ось курсора списка бесед; для direct — нормализованная пара user_min<=user_max с частичным уникальным индексом (равенство = «Заметки» с собой)) — **ConversationMember** (роль owner|admin|member, **last_read_seq** — watermark прочитанности (GREATEST, не откатывается), last_read_at — для readAt и «правка → повторный unread», mute, pinned, snoozed (гасится своей отправкой), hidden) — **ConversationDraft** (user_id×conversation_id, text≤4000, revision — серверный монотонный LWW между устройствами)
- **Message** (conversation_id, **seq** — per-conversation монотонный (см. Conversation.last_seq): порядок, курсор пагинации, якорь прочитанности; автор, текст, **client_message_id — значение Idempotency-Key, unique(author_id, client_message_id)** — crash-окно идемпотентности закрывает БД (ADR-0005); reply_to_id? + **reply_snapshot** — замороженный снапшот цитаты (authorId, text≤160, quoteText≤160, attachmentKind; правка оригинала не меняет, удаление помечает deleted), **thread_root_id?** (тред — ровно один уровень), fwd_* — атрибуция пересылки (оригинальный автор/координаты), edited_at, deleted_at + **obliterated** — «бесследное» удаление: строка и seq остаются (непрерывность курсоров, ссылки тредов/цитат, аудит), из выдач исключается; у надгробия text='' и пустые вложения/реакции в DTO, строки-оригиналы сохраняются) — **MessageReaction** (PK message×user×emoji — toggle), **ConversationPin** (одно закрепление на сообщение, лента закрепов — pinned_at DESC), **MessageAttachment** (file_id → FileObject после #57, одноразовая привязка: загруженные строки ждут владельца с message_id NULL), **ThreadParticipant** (thread_root_id, user_id, источник подписки: автор|ответил|наблюдатель) — уведомления о треде только участникам
- **Letter** (тип: incoming|outgoing; рег. номер, дата рег., от/кому, тема, тело, message_id оригинала письма, статус, проект?, срок исполнения?) — **LetterAttachment**, **Resolution** (letter_id, текст резолюции, автор, → task_id созданного поручения)
- **WorkflowDefinition** (код, название, JSON-схема шагов) — **WorkflowInstance** (объект-связка, текущий шаг, история действий, статус, дедлайны шагов)
- **FileObject** (бакет-ключ, имя, mime, размер, владелец, контекст: task|letter|project|message + id) — **FileVersion** (версия, ключ, автор, preview_key?)
- **Notification** (получатель, тип, payload-ссылка на сущность, каналы, прочитано) — **NotificationPreference**
- **EventLog** (id, тип события, actor, aggregate_type/id, payload JSONB, created_at) — append-only, инвариант I9
- **AuditLog** (actor, действие, сущность, детали, ip/user-agent) — append-only
- **Revision** (entity_type, entity_id, поле, old_value, new_value, author, created_at) — версии diff-аемого контента: описание задачи, тело письма, текст сообщения. Поле-уровневая история остальных изменений покрыта EventLog (I9)
- **FeatureFlag** (ключ, включён, scope)
- **Session** (user_id, refresh-token hash, устройство/user-agent, ip, expires_at, revoked_at) — ротация и отзыв сессий
- **PushSubscription** (user_id, endpoint, ключи p256dh/auth, user-agent)
- **FieldDefinition** (код, название, тип: text|number|date|money|bool|enum|multienum|user_ref|entity_ref|file, `dictionary_id` для enum/multienum, конфиг валидации, обязательность, сущность-область: task|project|letter|user|workflow, группа/порядок, права чтение/запись, активен) — реестр кастомных полей; значения в JSONB-колонке `custom_fields` каждой сущности (GIN-индекс); **элементы списков хранятся по ID элемента справочника** (I15); поля «индексировать для отчётов» материализуются в типизированные генерируемые колонки
- **Dictionary** (код, название, иерархический?, права редактирования) — **DictionaryItem** (dictionary_id, parent_id?, название, код?, порядок, активен/архивен) — архивация вместо удаления (I15)
- **EntityLink** (from: тип+id, to: тип+id, тип связи: related|derived_from|blocks|belongs_to, автор, created_at) — универсальные связи поверх явных FK; основа графа знаний портала

## Правила схемы

- Суррогатные UUID PK; `created_at/updated_at` везде; FK с onDelete явно — **но только внутри одного модуля**: между таблицами разных модулей — plain UUID без FK-констрейнта (изоляция модулей, I3; связь живёт на уровне приложения и событий).
- Мягкое удаление только там, где есть бизнес-смысл (сообщения, файлы).
- Индексы под запросы списков и FTS — с первой миграции.
- Классификаторы сущностей (тип объекта, тип проекта, вид работ) — обязательные кастомные поля (I14); перечень утверждается владельцем.
- Таблица `messages` партиционируется по месяцам **по триггеру** — при достижении десятков миллионов строк (контроль перед пилотом при росте объёма). До того — обычная таблица; курсор пагинации по `seq` и временные фильтры закладываются с первой миграции, чтобы будущий переезд на партиции не менял контракты.
- Миграции задним числом не изменяются — только новые миграции.
