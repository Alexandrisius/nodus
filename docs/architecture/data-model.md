# Модель данных (верхнеуровневая)

Фиксирует состав и связи сущностей; детальная схема — в Prisma (`prisma/`). Новые **доменные** сущности — через ADR; вспомогательные таблицы (join, настройки) добавляются по мере реализации без ADR.

Читать: перед проектированием миграций и новых сущностей.

Уникальность имени — выраженный индекс `(scope, lower(btrim(name)))` в миграции (Prisma выражений не декларирует, прецедент ADR-0033).
- **Dictionary** (#54; код kebab-case — стабильный ключ потребителей, название, иерархический, системный — создан миграцией и нужен коду) — **DictionaryItem** (dictionary_id, parent_id? — только у иерархических, название, код? — уникален в справочнике, порядок, активен/архивен) — архивация вместо удаления (I15), FK Restrict; ссылающиеся модули хранят UUID элемента без FK (I3). Системные справочники и их стартовые элементы — данными миграции (`INSERT … ON CONFLICT DO NOTHING`: правки администратора не перетираются). **Запись (с #431, Р10):** список создаётся с вариантами (код `list-<8hex>` генерирует сервер), вариант переименовывается, **удаляется физически** (вердикт владельца 25.10.2026 — у вариантов атрибутов нет архива: значения с ним читаются пустыми) и упорядочивается; системный справочник защищён (`DICTIONARY_SYSTEM_LOCKED`), имя варианта уникально среди активных под advisory-локом справочника. Системный `currency` («Валюты»: BYN, RUB, USD, EUR, CNY) — миграцией. Полный админ-контур — M12
- **(задел)** **EntityLink** (from: тип+id, to: тип+id, тип связи: related|derived_from|blocks|belongs_to, автор, created_at) — универсальные связи поверх явных FK; основа графа знаний портала

## Правила схемы

- Суррогатные UUID PK; `created_at/updated_at` везде; FK с onDelete явно — **но только внутри одного модуля**: между таблицами разных модулей — plain UUID без FK-констрейнта (изоляция модулей, I3; связь живёт на уровне приложения и событий).
- Мягкое удаление только там, где есть бизнес-смысл (сообщения, файлы).
- Индексы под запросы списков и FTS — с первой миграции. **Каждая FK-колонка — с индексом** (PostgreSQL не индексирует FK сам: без индекса каждая Restrict/SetNull/Cascade-проверка при удалении родителя и каждый джойн — seq scan; аудит #317).
- Классификаторы сущностей (тип объекта, тип проекта, вид работ) — обязательные кастомные поля (I14); перечень утверждается владельцем.
- Таблица `messages` партиционируется по месяцам **по триггеру** — при достижении десятков миллионов строк (контроль перед пилотом при росте объёма). До того — обычная таблица; курсор пагинации по `seq` и временные фильтры закладываются с первой миграции, чтобы будущий переезд на партиции не менял контракты.
- Миграции задним числом не изменяются — только новые миграции.
