# Структура монорепозитория

Целевая структура — фиксируется заранее, чтобы рост до сотен тысяч строк не требовал перекладки файлов. Новые папки создаются только по этой схеме; отклонение — через ADR.

Читать: перед созданием любого нового пакета, модуля или папки верхнего уровня.

## Дерево

```
nodus/
├── AGENTS.md                  # правила для ИИ-агентов (карта проекта)
├── README.md                  # для людей
├── docker-compose.yml         # все сервисы — с префиксом nodus_ (Gotchas в AGENTS.md)
├── .env.example               # шаблон окружения; секреты не коммитятся
├── apps/
│   ├── web/                   # React SPA
│   │   └── src/
│   │       ├── app/           # роутер, провайдеры, layout-оболочка (меню, топбар)
│   │       ├── features/      # по одной папке на модуль — зеркало backend-модулей
│   │       │   └── <module>/
│   │       │       ├── api/        # хуки TanStack Query, мутации (optimistic)
│   │       │       ├── components/ # UI-компоненты фичи
│   │       │       ├── pages/      # страницы
│   │       │       ├── model/      # локальное состояние, селекторы
│   │       │       └── README.md   # назначение, контракты, события, лимиты
│   │       ├── shared/        # переиспользуемое: lib, hooks, ui-kit re-export
│   │       └── ws/            # WebSocket-клиент, синхронизация, офлайн-очередь
│   ├── api/                   # NestJS backend (Fastify)
│   │   ├── prisma/            # schema.prisma, миграции (задним числом не меняются), seed dev-БД
│   │   └── src/
│   │       ├── core/          # event bus, audit, guards RBAC, ошибки, логирование,
│   │       │                  # пагинация, идемпотентность, feature flags, database (Prisma),
│   │       │                  # redis-клиент (канон путей core — patterns.md)
│   │       ├── health/        # liveness/readiness (terminus): /api/v1/health/*
│   │       ├── modules/
│   │       │   └── <module>/  # controller / service / repo / dto / events / README.md
│   │       └── infra/         # minio, mail (IMAP/SMTP) клиенты — появятся с модулями
│   ├── gateway/               # WebSocket gateway (Socket.IO): auth, presence, fanout
│   └── desktop/               # Tauri-оболочка — создаётся в фазе «Десктоп» (после пилота)
├── packages/
│   ├── contracts/             # ЕДИНСТВЕННАЯ точка обмена между фронтом, бэком и модулями:
│   │                          # DTO, zod-схемы, типы доменных событий, константы прав, i18n
│   ├── ui/                    # дизайн-система: компоненты shadcn/ui, токены, темы
│   └── config/                # общие tsconfig, eslint, tailwind presets
├── tests/
│   ├── e2e/                   # Playwright — только критичные пути
│   └── load/                  # k6-сценарии нагрузочного тестирования
├── .agents/
│   └── skills/                # проектные навыки (коммитятся, едут с репо): react, nestjs, миграции...
├── infra/                     # конфиги инфраструктуры: caddy, cloudflared, prometheus, grafana
├── docs/
│   ├── product/               # видение, глоссарий, UX-принципы, ключевые потоки
│   ├── architecture/          # инварианты, стек, эта структура, модули, API, данные, НФТ
│   ├── process/               # как мы работаем: workflow через GitHub Issues, DoD
│   ├── adr/                   # архитектурные решения (NNNN-title.md)
│   ├── modules/               # расширенные описания модулей (по мере появления)
│   ├── runbooks/              # эксплуатация: бэкапы, обновление, восстановление
│   └── mvp/                   # ВРЕМЕННАЯ рабочая зона MVP (ТЗ, айдентика) — архивируется после MVP
└── .github/
    ├── ISSUE_TEMPLATE/        # шаблоны задач (фича, баг)
    ├── PULL_REQUEST_TEMPLATE.md
    └── workflows/             # CI: lint → typecheck → test → build
```

## Правила файлов (инварианты I5, I6)

- Один файл = одна ответственность. Цель ≤ 200 строк, ориентир ≤ 300; линтер: предупреждение > 300, ошибка > 500; 300–500 — только с комментарием-обоснованием.
- Один компонент / класс / сущность на файл. Имя файла = имя сущности (kebab-case).
- Запрещены импорты `apps/api/src/modules/X/*` из модуля `Y` — только события и `@nodus/contracts`. Контроль: `eslint-plugin-boundaries` + CI.
- Barrel `index.ts` допускается только на границе модуля (публичный контракт), не внутри.
- Генерируемое (Prisma client, OpenAPI) в репозиторий не коммитится.
- Любая новая папка модуля содержит `README.md`: назначение, контракты, события, лимиты.
- Внутренние пакеты — `@nodus/*`, приватные, зависимости через `workspace:*`.
- Никакой папки `mvp/` для кода: код с первого коммита живёт в финальной структуре (ADR-0001).

## Где что искать

| Что | Где |
|---|---|
| Новый бэкенд-модуль | `apps/api/src/modules/<name>/` + зеркальный `apps/web/src/features/<name>/` |
| Общие типы/DTO/схемы/события | `packages/contracts/` (никогда не дублировать в apps) |
| Общие UI-компоненты | `packages/ui/` (никогда не дублировать в features) |
| e2e-тест | `tests/e2e/` |
| Миграция БД | `apps/api/prisma/migrations/` (новая миграция, никогда не правка старой) |
| Конфиг инфраструктуры | `infra/` |
| Эксплуатационная процедура | `docs/runbooks/` |
