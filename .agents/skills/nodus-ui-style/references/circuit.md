# Контур Nodus — связи, вспышки, хореография

Код: `apps/web/src/app/shell/circuit-geometry.ts` (измерение/пути), `circuit-frame.tsx` (рендер + пульс). Контур — фирменная навигационная связь: шина рейки → стык → ось шапки до правого края вьюпорта.

## Геометрия — измерение живого DOM (никаких констант позиций)

Контур достраивается сам при добавлении модулей/вкладок — измеряет элементы по data-атрибутам:

| Атрибут | Где | Что даёт |
|---|---|---|
| `data-topbar` | шапка | ось = bottom шапки; правый край оси = засечка ПОСЛЕДНЕГО подмодуля (дуга в неё, без хвостов и зазоров); в мессенджере — правый край мягкой рамы (`data-soft-frame`): там ось одновременно верхняя граница окна чата; на Главной (подмодулей нет) — ось до ЛЕВОГО края мягкой области с терминальной точкой на нём; засечки вкладок — локти со скруглённым входом в ось (голая вертикаль читалась «прямоугольным углом» рядом со скруглением вспышки) — вердикты 14.09.2026 вечером |
| `data-module-port` (+`data-active`) | пункты рейки | порты модулей (PORT_X=42, Ø7px — вердикт 15.09.2026: 9px «толстоваты») |
| `data-tab-port` (+`data-active`) | вкладки топбара | точки вкладок |
| `data-left-node` | шов схлопнутого меню | якорь; точку 5px рисует оверлей контура (svg-круг, не DOM рейки — overflow-hidden срезал бы половину) |

- **Артерия — одна ломаная** с круглыми сопряжениями (не подпути — иначе прямые углы на стыках): низ шины → стык (БЕЗ точки) → ось до правого края.
- **Равномерность hairline 1px:** прозрачность контура — CSS-opacity на ОТДЕЛЬНОМ svg + `will-change: opacity` (форс композитного слоя): без слоя Chromium сворачивает opacity в alpha кисти, и самопересечения подпутей (подходы отводов к шине, засечек к оси) удваивают яркость — «хвостики ярче шины» при зуме ≤ 100% (`<g opacity>` и svg-opacity без will-change НЕ помогают). Прямые координаты — через `snapPx()` (полупиксель устройства, devicePixelRatio учитывает зум): линия на целой координате размазывается на две полуполосы и выглядит тусклее дробной (механизмы и замер — `docs/gotchas.md`).
- **Шина** одним блоком: конец = точка отхода последнего отвода (порт − 10, без хвоста); отводы — локти к портам.
- **Засечки вкладок** — локти ВВЕРХ к точкам вкладок (Y точки — `tabY`: центр топбара + половина строки подписи + 6px, `TAB_DOT_DY=18`), по одной у пункта; на оси точек нет.
- **Стык и лого — без точек всегда.** Порты рисует NodeEdge (`ports='end'` — точка только в целевом порту).
- Панели двигаются — контур пересчитывается **покадрово (rAF-loop)**, фильтр `propertyName === 'width'` (см. ловушку ниже).

## Вспышка (nav-пульс)

- **Ровно одна**, всегда ОТ ПОРТА МОДУЛЯ по шине и оси К ТОЧКЕ АКТИВНОЙ ВКЛАДКИ — клик по модулю и по вкладке дают одну траекторию.
- **Только на смену фокуса**: фокус = `moduleTo | tabLabel` (не координаты!) — resize, сворачивание панелей вспышки не вызывают (sig по tabLabel, не по tabX).
- Скорость 400 px/s; длительность = длина/400; затухание подсветки тоже ∝ длине (fadeMs = draw + пульс + 0.9 с).
- **Главная — вспышка до ТЕРМИНАЛЬНОЙ точки на левом краю мягкой области** (вердикт владельца 15.09.2026, заменил «без вспышки»: путь порт → стык → ось → точка мягкой карточки, dot на конце; ПРЕРЫВАЕТСЯ новой сменой фокуса — не летит в никуда при быстром переключении туда и обратно); точки у логотипа нет. Модуль без вкладок — обрубок за стык без точки.
- В схлопнутом меню — пульс от точки бокового шва по оси к вкладке; портов внутри схлопнутого меню нет.

## Связей для движущегося контента НЕТ (закон, вердикт владельца 15.09.2026)

- **Контур — ТОЛЬКО для ПОСТОЯННОЙ структуры**: рейка, вкладки, рамка, порты панелей. Движущийся контент (посты ленты, строки, карточки) связями и вспышками НЕ соединяется — скролл/подгрузка/ресайз делают живой замер хрупким (цепочка rAF-циклов, MutationObserver, settle-таймеров), а честного места порту нет: **бары — запретная зона для связей** (связь не пересекает чужие компоненты).
- Семантику связи передаёт СОДЕРЖИМОЕ, а не линия: «к какому посту тред» показывает корневой пост внутри окна треда (сверху, за штриховой линией — как в Slack).

## Слайдер: shared-element раскрытие из источника

Источник клика (строка списка, карточка канбана/ленты) пробрасывается rect'ом через `useShellStore.lastSource` → `SliderPanel sourceRect` (фиксируется на маунте карточки стека и сбрасывается — прямые ссылки и палитра без источника). Само открытие — ВСЕГДА через `useOpenCard()` (стек карточек, ADR-0009): карточки НЕ маршруты; стек живёт в search `?cards=тип:id,…`, хост — `CardStackHost` в AppShell; все карточки одной геометрии (inset-2 — прямоугольник мягкой рамы, уровней/смещений нет), наслаиваются произвольными цепочками (employee → task → project…), закрытие верхней (`useCloseCard`, replace) возвращает к смонтированной нижней с целым состоянием.

**Хореография (утверждена):** FLIP через CSS @keyframes `slider-expand` (globals.css): переменные `--flip-tx/ty/sx/sy` считаются из детерминированной геометрии панели (единая: inset-2 — прямоугольник мягкой рамы, ADR-0009, уровневых вариантов нет) и rect источника, `animation-fill-mode: both` — инверсия видна с первого кадра, рост 430 мс с овершутом. Keyframes — СТРОГО transform/opacity (композитор): morph border-radius и любые paint/layout-свойства в keyframes запрещены — декомпозитят всю анимацию на main thread, и первое открытие фризится на маунте контента (механизм в gotchas). Тяжёлый контент панели (children) монтируется ПОСЛЕ первого отрисованного кадра — double rAF в `SliderPanel`: маунт дерева карточки не задерживает старт раскрытия; шапка-хром — сразу, контент/шапка проявляются `content-fade` (задержка 160 мс). **Затемняющего задника НЕТ** (канон владельца, референс — слайдер Битрикс24): фон страницы цвета не меняет никогда; модальность дают тень `slider-shadow` (токен `--slider-shadow` двух тем) и прозрачный click-catcher (клик мимо = закрытие). Код ВСЕХ карточек сущностей — eager-импорт в хосте стека (не lazy-чанки): карточка — центральный экран, открывается из любого раздела; ленивый чанк давал ~430 мс тишины до первого кадра на первом открытии (вердикт владельца 2026-09-10: мгновенно, как карточки задач). Без источника — `slider-pop`. Закрытие — ДВЕ ФАЗЫ (баг-вердикты владельца 15.09.2026): контент и хром гаснут за 100 мс (`transition-opacity`, константа CONTENT_FADE_MS), затем пустая оболочка схлопывается `el.animate` (WAAPI) в rect источника за 200 мс и unmount: мгновенное скрытие контента одним кадром читалось «вспышкой на весь экран», схлопывание с живым текстом — «отпечатком» текста поверх страницы; `fill: 'both'` — ОБЯЗАТЕЛЕН: без него между концом анимации и unmount элемент на 1–2 кадра возвращается в натуральный полноэкранный стиль = «призрак» окна после закрытия (gotchas). Transition и WAAPI из layout-effect для РАСКРЫТИЯ запрещены: на свежем элементе в части окружений не стартуют с первого кадра. Никаких линий поверх контента.

**Структура vs контент (вердикт владельца):** зональные фоны карточки (тёмная зона чата `bg-background`, бордюры полос) — СТРУКТУРА: рендерятся вне content-fade, видны с первого кадра роста. content-fade получают только текст/контролы зон. Если фон зоны появляется вместе с контентом, в середине раскрытия читается «смена цвета фона» — приёмка это отклоняет. Карточки с зональными фонами передают в SliderPanel `fadeContent={false}` и расставляют fade по контентным блокам сами (скелетон зеркалит ту же зональную структуру).

## Фулскрин-карточка мессенджера: контур в режиме карточки

План `docs/mvp/messenger-fullscreen-plan.md`, вердикт владельца 15.09.2026: клик по беседе служебной полосы открывает ПОЛНОЭКРАННУЮ карточку мессенджера (`messenger:<id>`, стек ADR-0009): то же тело, что страница `/chat` (`MessengerBody` — список бесед + рабочая область + панель беседы; вкладки Чаты/Чаты задач/Настройка — в хроме карточки), inset-2 периметра = мягкая область на весь экран; полоса под карточкой НАКРЫТА ею (inset-2 периметра — дубль списка невидим и недоступен; шелл её НЕ скрывает: карточки стека под верхней иначе ехали бы на 40px во время раскрытия — баг-вердикт владельца 15.09.2026; скрытие полосы — только на модуле мессенджер `/chat*`, `useRailHidden`).

- Код: `circuit-geometry.ts` (`measureCardCircuit`, `CIRCUIT_REMEASURE`), `circuit-frame.tsx` (z-[60] в режиме карточки, settle-таймаут). Хедер карточки — `data-card-topbar` (хром `SliderPanel` c `cardTopbar`), его вкладки — те же `data-tab-port`/`data-active`, что вкладки топбара шелла (`MessengerTabs`).
- **Шина — урезанная, реф владельца «свёрнутая левая рейка»:** узел-точка на ЛЕВОЙ границе мягкой области карточки на оси вкладок (fill — тон карточки), ось до ПРАВОГО края карточки (`axisFull`: в мессенджере она же верхняя граница окна чата), засечки вверх к точкам вкладок карточки; шины рейки под карточкой нет (виртуальный активный модуль опирает вспышки на ось, приём схлопнутой рейки).
- **Z-лестница:** контур карточки рисуется ПОВЕРХ слайдера (z-[60] > z-50), но под оверлей-порталами (z-70+); шина шелла (z-30) под карточкой невидима и не считается.
- **Первый замер — после оседания FLIP-раскрытия** (CARD_SETTLE_MS 480 мс): `slider-expand` трансформирует всю карточку вместе с хедером — rect'ы переходные; контур гаснет на раскрытие и появляется одним кадром на осевшей геометрии (settling-флаг глушит и покадровые transition-замеры).
- **Вкладки карточки — локальное состояние** (не маршрут): `MessengerTabs` после коммита `data-active` шлёт `window`-событие `CIRCUIT_REMEASURE` → перемер + вспышка на смену фокуса (сигнатура `moduleTo|tabLabel` — та же).
- **СОН контура под карточкой (issue #63):** ЛЮБАЯ верхняя карточка (не только мессенджер) накрывает мягкую раму целиком (inset-2 = её прямоугольник) — контур шелла невидим, и во время width-перехода полосы НЕ меряется покадрово: под нефулскрин-карточкой контур СПИТ (один замер на вход, `geo=null` после CARD_SETTLE_MS, слушателей нет — иначе rAF-цикл forced-layout + SVG-ре-рендер гонялся вхолостую). Пробуждение — `cardClosing` в shell-store (SliderPanel.requestClose): перемер ДО схлопывания верхней, схлопывающаяся карточка открывает шелл с готовым контуром; вспышка на пробуждении НЕ стреляет (фокус не менялся). Закрытие фулскрин-мессенджера: cardMode→shell переключается СРАЗУ по cardClosing (не ждём pop из `?cards=`) — `cardModeLive`. deps эффекта — режимы (cardModeLive/covered), НЕ searchStr: подмена вершины replaceTop не перезапускает режим и не гасит контур на 480мс.
- Закрытие карточки (X/Esc) — стек pop'ом: контур возвращается в режим шелла (пробуждение по `cardClosing` — мгновенно, до схлопывания).

## Ловушки анимаций (детали — `docs/gotchas.md`, фронтенд)

1. **SMIL `<animateMotion>` без `fill="freeze"` и opacity-гейта** — элемент возвращается в (0,0): «светящийся пиксель» в левом верхнем углу. Обязательно: `fill="freeze"` + `<animate attributeName="opacity">` на begin.
2. **`transitionend` приходит на каждое свойство и всплывает** — цикл слежения фильтровать по `event.propertyName` (у нас `'width'`), иначе глохнет от посторонних анимаций.
3. **`animationend` всплывает** — фильтровать по `event.animationName` (дочерний draw-on завершит логику родителя раньше времени).
4. SMIL не стреляет DOM-событиями — «один пробег и убрать» таймаутом/перемонтированием через `key`.

## Панели каркаса (утверждённые правила)

- **Правая служебная полоса (план 14.09.2026, R4):** ЗА ПРЕДЕЛАМИ мягкой рамы, в правом периметре (`mr-2` — щель 8px до края вьюпорта), на тоне периметра и БЕЗ вертикальных границ; ширина 40px ⇄ 192 дизайн-px (240px при масштабе 1.25 — замер Битрикс24, #60; `EDGE_W_*`) по КНОПКЕ-шевронам внизу полосы (как сворачивание левой рейки; вердикт владельца 14.09.2026: без авто-раскрытия по наведению, выбор персистится) — РЕФЛОУ (`transition-[width]` 200ms ease-out): мягкая рама (flex-сосед `flex-1`) и карточки сущностей сужаются влево синхронно (сузившуюся ширину карточка отдаёт ЧАТОМ — канон «чат — буфер сужений», SKILL.md), на страницах без карточек контур перемеряется покадрово слушателем transition width, под карточкой — спит (см. раздел карточки); БЕЗ заголовка и видимого скроллбара (`data-no-scrollbar`); ЭКСПРЕСС-МЕССЕНДЖЕР (вердикт владельца 15.09.2026): ВСЕ беседы КРОМЕ чатов задач (`sortByActivity` — закреплённые сверху, далее по активности, та же сортировка что в мессенджере), аватары 28px (size-7), в раскрытом состоянии имя 13px () (тултип ТОЛЬКО когда имя обрезано), непрочитанные — маленький цифровой бейдж справа внизу аватарки в ОБЕИХ состояниях (ни чипов, ни точек, ни глифов типа); «Заметки» — сид-диалог с собой (мок `cid(11)`, профиль не дублируется в списке — модель Битрикс24); список начинается под осью (y ≥ 64).
- **Скроллбар контента** — собственный ползунок В ПРАВОЙ ЩЕЛИ ПЕРИМЕТРА, правее служебной полосы (`edge-scrollbar`): трек на всю высоту экрана, хотя управляет скроллером страницы внутри мягкой рамы; шелл усыновляет главный вертикальный скроллер (самый большой по площади прокручиваемый элемент #content; узкие панели и колонки канбана — не «страница»), нативный вертикальный скроллбар скрыт `data-edge-scroll` (горизонтальный широких таблиц в webkit сохранён), ползунок 4px в тон `--scrollbar`, drag и клик по треку пишут scrollTop (вердикт владельца ночью 14.09.2026).
- **Аватар профиля** — В ТОПБАРЕ справа от колокола (`ProfileMenu`, вердикт владельца 15.09.2026: из полосы убран — полоса стала экспресс-мессенджером); меню — `align="end"`, портал z-[70]. Авто-раскрытия полосы НЕТ: раскрытие только кнопкой-шевронами внизу полосы (вердикт владельца 14.09.2026), наведения ничего не раскрывают.
- **Кнопки сворачивания панелей** — только шевроны 16px, без текста и разделительных линий.
- **Меню:** плашка ховера — ПРАВЕЕ графа портов (развёрнутая рейка: `mr-3 ml-[52px]`; схлёпнутая: `mx-3`, графа внутри нет), плашка тёплая почти-белая (`sidebar-accent`, пакет мягкости 12.09.2026 — структура ≠ ховер); бейдж `pr-2.5`; схлопнутое — точка 5px на ЛЕВОМ КРАЕ мягкой области (якорь `data-left-node` на `-right-[8.5px]`: рейка без границы и в один тон с периметром, связь опирается на границу мягкой зоны; точку рисует оверлей контура svg-кругом — DOM-точка внутри рейки резалась её overflow-hidden), порты не рендерятся.
- **Топбар** без «Создать»; вкладки модулей — ФИКСИРОВАННЫЕ из единого реестра `app/shell/nav-registry.ts` (`NAV_MODULES[].tabs`; top-bar читает `navModuleForPath`; новая вкладка — в реестр, контур достроит сам; верхние вкладки кастомизации НЕ подлежат — вердикт владельца 15.09.2026).
