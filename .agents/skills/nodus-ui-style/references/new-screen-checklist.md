## Шаги — НОВЫЙ МОДУЛ (все точки касания, аудит #45)

Экран существующего модуля — по шагам ниже. НОВЫЙ модуль целиком = экран(ы) + эта регистрация (пропуск любой точки = модуль наполовину мёртв):

1. `packages/contracts/src/<domain>/` — zod-схемы DTO + экспорт из `index.ts`; строки — блоком в `i18n/ru.ts` → `pnpm --filter @nodus/contracts build`.
2. `apps/web/src/features/<name>/` — вертикальный срез (`api/` + `api/mocks/`, `components/`, `pages/`, `lib/`, `README.md`).
3. `app/shell/nav-registry.ts` — запись модуля (иконка, маршрут, вкладки, badge) — рейка/персональный порядок/лендинг подхватывают автоматически.
4. `app/router.tsx` — lazy-импорт страницы + `createRoute` + `addChildren`.
5. `app/shell/card-stack.ts` + `card-stack-host.tsx` — вид карточки сущности (`CardKind` + Entry).
6. `app/mocks-handlers.ts` — +хендлеры фичи (тела мутаций — safeParse схемами contracts).
7. Демо-данные — `shared/mocks/data/<domain>.ts` (по канону существующих).
8. Реестр полей, используемый >1 фичей — в `shared/views/` (канон локации: кросс-модульные — shared, свои — `features/<name>/lib/`).
9. Доска-канбан (если есть) — конфиг `shared/ui/board/use-kanban-board.ts`, НЕ копия контейнера.
10. Дальше — шаги «Экран модуля» ниже (компоненты, проверки, кадры, вердикт).

## Шаги — экран модуля

1. **Чтение:** этот навык (SKILL.md + нужные references) → легаси экрана в `apps/web/src/features/<name>/` (компоненты, api-хуки, моки, README) → навыки `react-best-practices`, `shadcn` (rules, не только индекс).
2. **Дизайн-решение:** какие фирменные механики применить (цепочка, граф, таблица, слайдер-док) — сдержанно: изюминка на сущности, не по всему экрану.
3. **Реестр полей** — по `references/views-customization.md`; ЛОКАЦИЯ (аудит #45): реестр только своей фичи — `features/<name>/lib/<module>-fields.tsx`, кросс-модульный (>1 потребителя) — `shared/views/<module>-*fields.tsx`; колонки — только данные контракта (нет поля в данных → сначала расширить мок/контракт обратно-совместимо, отметить в отчёте).
4. **i18n:** новые строки → `packages/contracts/src/i18n/ru.ts` → `pnpm --filter @nodus/contracts build`; мёртвые строки — удалить там же.
5. **Компоненты с нуля** под канон (визуал с нуля, НЕ рестайл легаси-файлов); один файл = одна ответственность, ≤ 300 строк (I5).
6. **Проверки:** `pnpm --filter @nodus/web typecheck`, `pnpm lint`, `pnpm --filter @nodus/web test` — зелёные.
7. **Прогон и кадры:** рестарт dev (kill по порту 5173 — vite на Windows протухает), debug-скрипт `tests/e2e/debug-flash.mjs` (Playwright) → скриншоты в `tests/e2e/shots/` (общий кадр + зумы деталей, обе темы!) → **скрипт удалить после прогона** (иначе упадёт lint: no-undef document).
8. **Отчёт владельцу** простым языком + кадры → **СТОП, ждать вердикт** (UI-чекпоинт). Правки по фидбеку — тем же циклом.
9. **Коммит:** conventional `feat(web): … (#4)` / `fix(web): … (#4)`; README фичи — в том же коммите (I12); опыт — комментарием в issue #4; новые ловушки — в `docs/gotchas.md`.
10. **Раскатка на nodus.by:** `docker compose build web && docker compose up -d web` → curl 200 на https://nodus.by/ (образ собирается из рабочей ветки; чужие проекты хоста не трогать).

## Верификационные приёмы (отработано)

- Визуальные баги линий/яркости/толщин — верифицировать 2D-патчами альфы (скриншот → canvas: сетка device-пикселей вокруг узла, excess над фоном) на DPR 1 / 1.25 / 1.5: один профиль или глаз пропускают удвоения в перекрытиях и размазывание на целых координатах (механизмы — `docs/gotchas.md`, фронтенд). Фикс визуального бага не рапортуется без патчей «до/после» на этих DPR.

- Геометрия контура/графа — читать `d` из SVG-path и координаты портов в живом DOM (не «на глаз» по скриншоту).
- Скорость пульса: `dur` из `animateMotion` × 400 == длина пути.
- Пресеты: читать `localStorage['nodus-views-v1' / 'nodus-shell-v1']` после действий и после reload.
- Ресайз: drag ручки → width в пресете + позиция ручки следует за курсором (Δx == Δwidth).
- Сворачивание веток: счёт строк DOM до/после.
- MSW авто-аутентифицирует (логин не мешает); в collapsed-меню навигация — через `a[href="/tasks"]`.

## Типовые решения (не переизобретать)

- Шапка страницы модуля: `h1` + справа моно-сводка + `ViewSettings`.
- Статусы — `NodeChip` по системному состоянию; приоритет — тон `priorityTone` из реестра полей.
- Открытие сущности: `openCard({ kind, id }, rect элемента)` из `use-card-stack.ts` (стек карточек, ADR-0009 — НЕ navigate на маршрут слайдера: маршрутов карточек нет); карточка — `SliderPanel` + shared-element раскрытие (FLIP из rect источника); доменная цепочка — `DomainChain` в шапке карточки.
- Новый модуль/вкладка навигации = +1 запись в ЕДИНОМ реестре `app/shell/nav-registry.ts` (рейка и топбар читают оттуда; для МОДУЛЯ персональный порядок/скрытие и стартовая переадресация «/» подхватываются автоматически, вкладки топбара фиксированные — концепт #4).
- Анатомия карточек (раунд 2): полоса цепочки/якоря → контентная зона со скроллом и `@container` (поля-реестр EntityFields перестраиваются 1→2 колонки) → замоноличенный нижний бар h-16; у задачи, проекта и письма — правая колонка обсуждения (тёмный фон = структура; у письма — общий механизм `ConversationPane`, беседа type 'letter'); у сотрудника — контент max-w-4xl; карточка письма — ЕДИНЫЙ шаблон сущности (модель v2, #69: почтовая шапка корреспондент/кому/копии/дата/чипы → тело max-w-3xl → вложения → реквизиты EntityFields → [у документа] резолюции с поручениями-задачами; нижний бар — «Зарегистрировать» | «Резолюция» + «В дело»).
- Мессенджер: единый список бесед по активности БЕЗ секций (маркер типа на аватаре); подразделы «Чаты»/«Чаты задач» — в топбаре; посты канала — `max-w-2xl`, счётчик ответов скрыт при нуле.
- Обсуждение сущности: Message/Bubble + `ChatComposer` (отправка встроена островком, вердикт 24.09); «О сущности» — правая колонка с секциями на `NodeLabel`.
- **Выдвижная поверхность (панель, окно, дровер) на экране — обёртка смонтирована ПОСТОЯННО в покое (`w-0`/translate), открытие = flip состояния существующего элемента, контент — лениво** (закон: рывок ровно один раз у свежего элемента — баг-вердикты 15.09.2026, gotchas); обязательная верификация: ПЕРВОЕ открытие после Ctrl+R — замер ширины покадрово (плавный ход, не мгновенная целевая).
