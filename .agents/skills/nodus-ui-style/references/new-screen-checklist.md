# Рецепт нового экрана модуля + DoD

Порядок экранов — roadmap issue #4: Главная ✓ → Задачи ✓ → Письма → Проекты → Мессенджер → Сотрудники. Каждый экран — вертикальный срез и UI-чекпоинт владельца.

## Шаги

1. **Чтение:** этот навык (SKILL.md + нужные references) → легаси экрана в `apps/web/src/features/<name>/` (компоненты, api-хуки, моки, README) → навыки `react-best-practices`, `shadcn` (rules, не только индекс).
2. **Дизайн-решение:** какие фирменные механики применить (цепочка, граф, таблица, слайдер-док) — сдержанно: изюминка на сущности, не по всему экрану.
3. **Реестр полей** — `lib/<module>-fields.tsx` (список/карточка) по `references/views-customization.md`; колонки — только данные контракта (нет поля в данных → сначала расширить мок/контракт обратно-совместимо, отметить в отчёте).
4. **i18n:** новые строки → `packages/contracts/src/i18n/ru.ts` → `pnpm --filter @nodus/contracts build`; мёртвые строки — удалить там же.
5. **Компоненты с нуля** под канон (визуал с нуля, НЕ рестайл легаси-файлов); один файл = одна ответственность, ≤ 300 строк (I5).
6. **Проверки:** `pnpm --filter @nodus/web typecheck`, `pnpm lint`, `pnpm --filter @nodus/web test` — зелёные.
7. **Прогон и кадры:** рестарт dev (kill по порту 5173 — vite на Windows протухает), debug-скрипт `tests/e2e/debug-flash.mjs` (Playwright) → скриншоты в `tests/e2e/shots/` (общий кадр + зумы деталей, обе темы!) → **скрипт удалить после прогона** (иначе упадёт lint: no-undef document).
8. **Отчёт владельцу** простым языком + кадры → **СТОП, ждать вердикт** (UI-чекпоинт). Правки по фидбеку — тем же циклом.
9. **Коммит:** conventional `feat(web): … (#4)` / `fix(web): … (#4)`; README фичи — в том же коммите (I12); опыт — комментарием в issue #4; новые ловушки — в `docs/gotchas.md`.
10. **Раскатка на nodus.by:** `docker compose build web && docker compose up -d web` → curl 200 на https://nodus.by/ (образ собирается из рабочей ветки; чужие проекты хоста не трогать).

## Верификационные приёмы (отработано)

- Визуальные баги линий/яркости/толщин — верифицировать 2D-патчами альфы (скриншот → canvas: сетка device-пикселей вокруг узла, excess над фоном) на DPR 1 / 1.25 / 1.5: один профиль или глаз пропускают удвоения в перекрытиях и размазывание на целых координатах (механизмы — `docs/gotchas.md`, фронтенд). Фикс визуального бага не рапортуется без патчей «до/после» на этих DPR.

- Геометрия контура/графа — читать `d` из SVG-path и координаты портов в живом DOM (не «на глаз» по скриншоту).
- Скорость пульса: `dur` из `animateMotion` × 400 == длина пути.
- Пресеты: читать `localStorage['nodus-views-v1' / 'nodus-shell-v1']` после действий и после reload.
- Ресайз: drag ручки → width в пресете + позиция ручки следует за курсором (Δx == Δwidth).
- Сворачивание веток: счёт строк DOM до/после.
- MSW авто-аутентифицирует (логин не мешает); в collapsed-меню навигация — через `a[href="/tasks"]`.

## Типовые решения (не переизобретать)

- Шапка страницы модуля: `h1` + справа моно-сводка + `ViewSettings`.
- Статусы — `NodeChip` по системному состоянию; приоритет — тон `priorityTone` из реестра полей.
- Открытие сущности: `openCard({ kind, id }, rect элемента)` из `use-card-stack.ts` (стек карточек, ADR-0009 — НЕ navigate на маршрут слайдера: маршрутов карточек нет); карточка — `SliderPanel` + shared-element раскрытие (FLIP из rect источника); доменная цепочка — `DomainChain` в шапке карточки.
- Обсуждение сущности: Message/Bubble + `SendHexButton`; «О сущности» — правая колонка с секциями на `NodeLabel`.
