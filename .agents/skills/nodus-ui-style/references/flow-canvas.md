# Холст схем (ADR-0022, #378 ред. 2)

Единый движок схем — `apps/web/src/shared/flow/` (редактор маршрутов,
«Схема маршрута» задачи, будущие схемы проектов #38). Референсы — Jira
workflow editor и Яндекс Трекер: свободный канвас, никаких колонок-контейнеров.
Всё ниже — вердикты владельца 19–20.10.2026; старый канон («нижняя
магистраль», «позиции в черновике браузера», «зум в тулбаре», «инспектор
поверх холста») ОТМЕНЁН.

## Слои кода (чистые функции + unit-тесты)

| Модуль | Что делает |
|---|---|
| `route-layout.ts` | авторасстановка: слои слева направо по длиннейшему пути от начального (циклы рвёт DFS, «из любого» — от старта); узел 208×52, коридор 132, ритм 64, поля 48 |
| `route-resolve.ts` | разрешение раскладки: СОХРАНЁННОЕ — закон, недостающее — авто; позиции, метки «Любой статус», точки стрелок, разнос, пути, места подписей; `frozenLayout` — видимая картинка целиком |
| `flow-handles.ts` | 12 точек подключения (по три на сторону `t1..l3`), выбор стороны/слота |
| `route-loops.ts` | U-обходы (вход и выход с одной стороны): глубины вложенных без слипания |
| `route-labels.ts` | путь стрелки как его рисует холст; место подписи на СВОЕЙ стрелке без наезда на узлы и другие подписи |
| `edge-geometry.ts` | ортогональный путь по реальным концам, скругление r=10, точка по доле длины, проекция курсора; `edgeBend` — свободный участок стрелки (#395) |
| `snap-guides.ts` | направляющие выравнивания узлов: притяжение краёв/центров к соседям |
| `route-graph.ts` | узлы и рёбра React Flow из разрешённой раскладки (одинаково для редактора и «Схемы») |

## Раскладка — общая, хранится на сервере

- `document.layout` (`workflows.layout`): позиции статусов, точки подключения
  стрелок, доля подписи `labelT`, глубина обхода `offset`, ручной сдвиг
  участка `shift` (#395), место метки «Любой статус» `anchor`. Одна на всех — редактор и «Схема маршрута» видят
  одно и то же.
- **«Что видишь — то и стоит»:** первая правка фиксирует ВСЮ видимую картинку
  (`freezeLayout`); дальше двигается только то, что двигает пользователь —
  перетаскивание статуса не трогает чужие статусы, точки и стрелки.
  Сдвинутые обходы не слипаются с соседними (`settleLoops`), подпись
  сдвинутой стрелки — или подпись, на которую положили статус, — уходит на
  ближайшее свободное место своей стрелки (`settleLabels`). Авторасстановка —
  ТОЛЬКО кнопкой «Упорядочить».
- **Расстановка — оформление, не маршрут:** сохраняется сама
  (`use-layout-autosave`, 600 мс тишины → `PUT .../layout`, без новой версии),
  черновиком маршрута не считается, «Опубликовать» не включает. Места новых
  статусов/кнопок (`new:*`) уходят с их публикацией; места стоящих
  публикация берёт из сохранённой раскладки (перед публикацией клиент
  досылает своё). Чужая сохранённая расстановка приходит в открытый
  редактор, свои неотправленные места остаются.

## Рёбра, точки, подписи

- 12 точек на статусе, `ConnectionMode.Loose`, концы выделенной стрелки
  перетаскиваются на другие точки (у «из любого» — только цель).
- Точки — кружки r=3.5 ПО ЦЕНТРУ границы: ЗАНЯТЫЕ видны всегда и залиты
  `--edge-solid` (стрелка упирается в кружок, зазора нет); свободные в правке
  приглушены ТОНОМ ОБВОДКИ, не прозрачностью (сквозь полупрозрачный кружок
  просвечивала цветная полоса статуса — «мыло», 21.10), ярче на
  наведении/выделении/протягивании, в просмотре скрыты. Левые точки — с
  ободком цвета карточки поверх цветной полосы.
- Выделенная стрелка: кружки-концы React Flow (`edgeupdater`) невидимы (только
  хит-зона с курсором grab) — конец отмечают ТОЧКИ УЗЛОВ (`flow-port-selected`:
  заливка `--primary` + мягкое свечение, размер прежний — наконечник не
  перекрыт). Второй кружок касался точки узла и прятал стрелку (21.10).
- Свободный участок выделенной стрелки (#395) тянется поперёк за ЛЮБОЕ место
  участка — невидимая полоса 14px с курсором ↔/↕, отдельной ручки НЕТ
  (вердикт 21.10); «ступенька»/обход «за спиной» — `shift`, U-обход —
  `offset`; магнит к краям/центрам узлов (6px экрана), двойной клик — авто.
  У прямой и «уголка» участка нет — их разводят переносом конца.
- Перетаскивание узла: направляющие выравнивания (края и центры соседей,
  порог 6px экрана) — волосяной пунктир 1px в ЭКРАННЫХ координатах с
  округлением к центру пикселя (в координатах холста на дробном зуме линия
  размывалась и выглядела жирной — 21.10).
- Наконечник — свой SVG-маркер (`flow-markers.tsx`): `markerUnits=
  userSpaceOnUse` (один размер у тонкой, главной и выделенной линии),
  заливка CSS-классом токеном `--edge-solid` / `--primary`. Встроенный
  ArrowClosed запрещён: `fill`-атрибут не понимает `var()` (пустой
  наконечник), размер растёт с толщиной линии.
- Линия по показу кнопки: главная — 1.75px, кнопка — 1px, «Ещё» — пунктир;
  выделенная — `--primary` 2px.
- Подпись — чип НА СВОЕЙ стрелке в доле `labelT`, тянется вдоль неё (проекция
  курсора); главная — залитый, кнопка — карточка с рамкой, «Ещё» — пунктир.
  Фон чипа непрозрачный. Слой подписей — над ВСЕМИ линиями, под узлами:
  выделенное ребро НЕ поднимать z-index'ом (оно перечёркивало чипы — баг
  20.10), а ставить последним в массиве рёбер.
- Метка «Любой статус» — пунктирная пилюля со стрелкой в статус (переключатель
  «Можно перейти из любого статуса» в панели статуса); клик — панель её
  кнопки. По умолчанию — строго НАД статусом по центру (стрелка — прямая
  вертикаль; смещённая влево давала петлю, 21.10), следует за статусом, пока
  её не перетащили.
- Старт «Создание задачи» — пунктирная пилюля на линии центра начального
  статуса (стрелка прямая); клик — панель «Окно создания» (#432). Выделенный
  старт — сплошное кольцо `border-ring ring-1 ring-ring/30` и тон
  `foreground`, БЕЗ свечения (вердикт владельца 26.10: свечение — только у
  текущего статуса задачи); ховер меняет рамку ТОЛЬКО у невыделенного
  (класс наведения перебивал кольцо, выделение «пропадало» под курсором —
  баг-вердикт 26.10).

## Окно редактора — сплит как мессенджер

- Слева колонка типов (w-80, border-r, шапка h-14 с border-b), справа колонка
  холста: верхний бар h-14 с линией border-b (продолжает линию шапки типов),
  ниже холст.
- Правая панель — ПОЛНОВЫСОТНАЯ колонка-сиблинг (канон панели беседы
  мессенджера): шапка h-14 продолжает линию бара, `border-l`, выезжает
  справа налево шириной (384px, `useFrameReady`) и СУЖАЕТ холст.
- Вписывание — ОДИН раз после измерения узлов (и при смене схемы, `fitKey`):
  смена размера холста вид не трогает — граф стоит, край обрезает.
- Масштаб, «вписать», отмена/повтор (классические стрелки ↶ ↷, обводкой) —
  слева внизу; атрибуция React Flow — справа внизу с отступом; фон —
  точечная сетка токеном.

## Правая панель — одна анатомия у всех элементов

- Шапка — вид элемента («Статус», «Кнопка перехода») или раздел + «назад»;
  название — первое поле (не дублируется в шапке).
- Поля элемента → строки «Название ›» со сводкой (раздел или связанный
  элемент) → удаление внизу. Примитивы `panel-kit.tsx`: `PanelField`,
  `SwitchRow`, `SectionLink`, `Segmented`, `PanelDanger`.
- Статус: «Кнопки из статуса ›» (порядок, добавление, «Как увидят в
  карточке» с выбором «Смотреть как»). Кнопка: «Кто видит ›», «Условия
  перехода ›», «Особые правила ›».
- Окно создания (#432): список полей строками «подпись / сводка ›» с ручкой
  перетаскивания (сводка — «Дата · обязательно», «Скрыто: Высокий»), клик —
  раздел поля «Поле окна» (`field` выделения; туда же ведёт клик по проблеме
  публикации); «+ Поле» и «Посмотреть окно» — тихие `PanelAction`; блоки
  внизу окна — `SwitchRow`. Предпросмотр — НАСТОЯЩЕЕ окно создания по центру
  экрана с черновой формой (`TaskCreateWindow preview`), копий окна в
  панели нет (вердикт 26.10).
- «Настройки типа» — та же панель: в корне поля типа, дальше «Доступ ›»,
  «Блоки карточки ›», «Названия ролей ›» со сводками (вердикт 26.10: «дикая
  колбаса вниз» запрещена).
- Нативных `<select>` нет; горизонтальной прокрутки нет (`min-w-0`,
  `break-words`).
