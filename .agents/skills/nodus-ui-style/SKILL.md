# Nodus UI — канон темы «Инструмент»

Тёмный (и светлый) «инструмент» по референсу `docs/mvp/ref/node-based UI/1.png`. **Визуальный слой пишется с нуля под этот канон; слой данных наследуется** (query-хуки, моки, роутер, слайдер-стек). Эталон реализации — `apps/web/src/features/home` и `features/tasks`.

## Жёсткие правила (нарушение = баг)

1. **Только токены** (`--background`, `--edge`, `--port`, семантика…): хардкод hex/rgb в компонентах запрещён. Темы — две: `dark` (дефолт, токены в `:root`) и `light` (`[data-theme='light']`, пересборка не инверсия). Тумблер темы — в топбаре; persist `nodus-shell-v1`.
2. **Легаси-утилиты запрещены** в новом коде (grep-контроль DoD): `paper-`, `crayon`, `sketch`, `texture-`, `bg-rust`, `text-ochre`, `text-cream`, `bg-sage`, `bg-steel`, `bg-tealink`, `border-pencil`, `bg-cream`, rose-цвета.
3. **Плоско:** без текстур, теней, градиентов, translate-«приподниманий». Свечение `drop-shadow(var(--glow))` — только активному узлу/связи.
4. **Типографика:** контент — Onest; метки/ключи/даты/счётчики — JetBrains Mono UPPERCASE 10–12px, tracking 0.14–0.16em (`NodeLabel`).
5. **i18n:** все UI-строки из `packages/contracts/i18n/ru.ts` (I15). Новые строки → туда же → `pnpm --filter @nodus/contracts build` до typecheck. Мёртвые строки удаляются в том же коммите.
6. **Связи — по нашей грамматике:** ортогональные рёбра 1px с локтями (скругление 6–8px) и портами r=3; порты по центру линий вычисляются из геометрии, не «на глаз». Никаких точек/узлов декоративных внутри панелей; свечение и вспышки — только на смену фокуса.
7. **Аватары — графитовые** (`PersonAvatar`, детерминированный тон от имени), в обеих темах.

## Кратко-канон (детали — в references)

- **Контур Nodus** — измерение живого DOM по data-атрибутам (`data-topbar`, `data-module-port`, `data-tab-port`, `data-left-node`); артерия — одна ломаная; вспышка одна, от порта модуля к точке вкладки, скорость 400 px/s (draw 1200 px/s), фокус = `moduleTo|tabLabel`; Главная — без вспышки.
- **Таблица** — модель AG Grid/Битрикс: px-треки (никакого fr!), `w-max min-w-full`, `overflow-x-auto`; ресайз ручкой (min под контент, max 640, следует за курсором 1:1), dblclick — автоподбор (мерить детей ячеек, не ячейку); колонки и поля карточек настраиваются шестерёнкой (`shared/views`, пресет `nodus-views-v1`).
- **Карточка-слайдер:** shared-element раскрытие из rect источника (`lastSource` → `SliderPanel sourceRect`): CSS @keyframes `slider-expand` строго на transform (композитор; paint/layout-свойства в keyframes запрещены — декомпозит, gotchas), контент монтируется после первого кадра (double rAF); закрытие — WAAPI-схлопывание в источник; без источника — scale-fade. Затемняющего задника НЕТ: тень `slider-shadow` + прозрачный click-catcher. Esc закрывает верхний слайдер стека, НО не когда открыт Radix-поповер/меню внутри (меню съедает Esc: фильтр `event.defaultPrevented` + `[data-radix-popper-content-wrapper]` в `SliderPanel`). Зональные фоны (тёмная зона чата) — структура с первого кадра (`fadeContent=false` + fade по контентным блокам). Шапка: кнопка навигатора ветки слева + доменная цепочка (`DomainChain` без свечения; само-узел — только «ТИП · №», БЕЗ повтора названия) + чип источника + кнопка «О задаче»; хлебных крошек НЕТ — ГЛАВНОЕ НАЗВАНИЕ живёт в хроме слайдера рядом с X (`SliderPanel title`, на видном месте; в теле карточки не дублируется — тело начинается с описания; вердикт владельца). Левая колонка (`@container`): название → описание → поля (`task-fields.tsx`: РЕЕСТР дескрипторов — любое количество полей, видимость настраивается кнопкой «+ Поле» с чекбоксами (persist localStorage), кастомные поля после MVP = те же дескрипторы из справочника (I13/I15); строки иконка+метка/значение без рамок; СТАДИЯ — поле-чип с компактным списком строго ПОД ПРОЕКТОМ (модель Битрикса), НАБЛЮДАТЕЛИ — системное поле под СОИСПОЛНИТЕЛЯМИ; личная колонка «Моего плана» в карточке НЕ показывается и из неё не меняется — только DnD на доске; сетка 1→2 колонки по container query (2 только без обрезки значений, @min-[880px]), блок до max-w-4xl, на узкой зоне значение переносится под метку; ЗНАЧЕНИЯ НЕ СОКРАЩАЮТСЯ — имена сотрудников и названия задач всегда целиком (перенос), truncate только для сверхдлинных названий типа проектов, с title-тултипом (вердикт владельца)) → подзадачи/чек-лист. Внизу левой панели — ЗАМОНОЛИЧЕННЫЙ бар действий (вне скролла, модель Битрикса, `task-stage-controls.tsx` TaskActionBar): «⟲ вернуть» ghost / «вперёд →» solid / «✓ Завершить задачу» outline-success (свободная задача без workflow: прыжок в первую done-стадию схемы — НЕ в последнюю по порядку, после «Завершена» может идти «Отложена»; workflow применён → кнопки = переходы схемы, после MVP #38). Справа — постоянная колонка обсуждения с перетаскиваемой запоминаемой границей (дефолт 680px): граница — `border-r` левой зоны (структурная линия; горизонтальные бордеры упираются ровно в неё, висячих сепараторов внутри зон нет — секции разделяются отступами), ручка ресайза — невидимый оверлей w-3 поверх границы (НЕ трек сетки); нижние бары обеих зон — ОДНОЙ высоты h-16 (бар действий = композер чата: их верхние линии — одна горизонталь через границу, замер y==y, вердикт владельца); drag ИМПЕРАТИВНЫЙ (el.style.width в rAF, React не рендерит карточку, коммит state + localStorage на pointerup; transition на ширине чата снят во время drag — флаг `dragging`, gotchas); «О задаче» — **вталкивающая колонка справа**, пушит НЕ левую панель: чат СУЖАЕТСЯ на ширину панели (синхронные `transition-[width]` 0↔360 / chatW↔chatW−360, сумма постоянна — левая зона стоит, вердикт владельца); навигатор ветки (подзадачи любой вложенности, быстрое создание, переход без закрытия панели) — **вталкивающая колонка слева** (auto-трек + `transition-[width]` 0↔300px на самой колонке: контент и разделитель чата сдвигаются плавно, НЕ оверлей; тоггл — иконка `Waypoints`).
- **Канбан «Мой план» — личная ось стадий (ADR-0008):** колонки = стадии личной схемы пользователя (не глобальной!); шапка — цветной чип стадии (`lib/stage-tone.ts`: палитра neutral/info/success/warning/danger на токенах темы) + счётчик + «+» быстрого создания задачи в колонку (инлайн-инпут в топе колонки) + меню «⋯» (переименовать inline / цвет / удалить — единственную нельзя, задачи переезжают в первую колонку того же состояния); создание стадии — КОМПАКТНАЯ инлайн-форма в конце ряда («точка цвета + название», Enter/Esc — референс ClickUp «Add group»; никаких больших панелей настроек). Привязка колонки к системному состоянию живёт в МОДЕЛИ (контракты/моки готовы к workflow-схемам), в UI до MVP не спрашивается (вердикт владельца: автоматизация — после MVP, через редактор схем). DnD по личной оси (`personalAxis` в kanban-board.ts), персист `personalStageId`.
- **Законы чата (вердикт владельца, раунд 3):** где чат — там ПРАВАЯ панель с файлами/ссылками беседы (`shared/chat/chat-side-panel.tsx`) по канону панели «О задаче»: тоггл — кнопка СПРАВА ВВЕРХУ в шапке КАРТОЧКИ/страницы (таб-бар проекта, полоса сотрудника, шапка беседы мессенджера — `ChatPanelToggle`); ШАПКИ У САМОГО ЧАТА НЕТ (никаких «чёрных областей» с названием канала/именем собеседника — вердикт); панель — ВНУТРИ колонки чата справа (одна анимируемая ширина — левая зона не дёргается; лента ≥ 360px при открытой панели, колонка ≥ 660 — тогда выталкивает левую зону); действия над сообщением — КОНТЕКСТНОЕ МЕНЮ ТОЛЬКО по правому клику (`shared/chat/message-menu.tsx` на Radix ContextMenu: меню у курсора, кламп в viewport примитивом; реестр-заготовка под бэкенд; «Редактировать»/«Удалить» — только свои; кнопок «⋯» на сообщении НЕТ); пустые состояния — канонический `Empty` (пунктирных рамок нет; drop-зона канбана — исключение, affordance переноса); перегородка чата в карточках тянется мышью С ПАМЯТЬЮ (`shared/ui/use-chat-width.ts` — единая память на все карточки, дефолт 680px, drag императивный — gotchas).
- **Карточки проекта/сотрудника — анатомия карточки задачи (раунд 3):** левая зона = ВКЛАДКИ на всю высоту (проект: Задачи/Гант/Отчёт/Схема/О проекте — три витрины будущих модулей; сотрудник: Профиль/Задачи/Проекты — журналы ПОЛНОЦЕННЫЕ на shared-реестрах, «модули не отличаются»), горизонтальных зон «поля над списком» НЕТ; правая колонка — чат всегда (канал проекта / личный диалог find-or-create).
- **Хореография:** вспышки/рисовка — только события смены фокуса/открытия; SMIL — с `fill="freeze"` + opacity-гейтом; `transitionend`/`animationend` — с фильтром по имени.
