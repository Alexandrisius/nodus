# Nodus UI — канон темы «Инструмент»

Тёмный (и светлый) «инструмент» по референсу `docs/mvp/ref/node-based UI/1.png`. **Визуальный слой пишется с нуля под этот канон; слой данных наследуется** (query-хуки, моки, роутер, слайдер-стек). Эталон реализации — `apps/web/src/features/home` и `features/tasks`.

## Жёсткие правила (нарушение = баг)

1. **Только токены** (`--background`, `--edge`, `--port`, семантика…): хардкод hex/rgb в компонентах запрещён. Темы — две: `dark` (дефолт, токены в `:root`) и `light` (`[data-theme='light']`, пересборка не инверсия). Тумблер темы — в топбаре; persist `nodus-shell-v1`.
2. **Легаси-утилиты запрещены** в новом коде (grep-контроль DoD): `paper-`, `crayon`, `sketch`, `texture-`, `bg-rust`, `text-ochre`, `text-cream`, `bg-sage`, `bg-steel`, `bg-tealink`, `border-pencil`, `bg-cream`, rose-цвета.
3. **Плоско:** без текстур, теней, градиентов, translate-«приподниманий». Свечение `drop-shadow(var(--glow))` — только активному узлу/связи. **Мягкость (пакет 12.09.2026, вердикт владельца): лестница радиусов — контролы 8–10px, поверхности (node-panel, поповеры, меню, селекты) 14px, рамы 18px; мягкая рама = топбар + рабочая зона ОДНОЙ панелью (bg-card, отступы 8px); левая рейка — БЕЗ вертикальной границы и В ОДИН ТОН с периметром (`--sidebar` = `--background`, воздушность по рефу «Задачи_Светлая тема», план R1): структуру рейки несут плашки `sidebar-accent`, узел схлопнутой рейки сидит на левом крае мягкой области; списковые колонки ВНУТРИ рамы — ступень `bg-muted` (не `bg-sidebar`: шелл-токен в раме давал чёрный список против светлой зоны); служебная полоса (профиль + коллеги) — ЗА ПРЕДЕЛАМИ мягкой рамы, в правом периметре (щель 8px справа от полосы): 40px на тоне периметра БЕЗ вертикальных границ; профиль верхом — size-7 с тонким ободком `ring-1 ring-primary/60`, точно над аватарками коллег (центр аватарки y=36 = центр топбара); раскрытие — КНОПКОЙ-шевронами внизу полосы (как у левой рейки; вердикт владельца 14.09.2026: без авто-раскрытия по наведению — пользователь сам выбирает: список всегда или только аватарки; выбор персистится в `nodus-shell-v1`): РЕФЛОУ 40 ⇄ 192px (240 − 20%, `transition-[width]` 200ms): мягкая рама и карточки сущностей синхронно сужаются влево (хост карточки `transition-[right]`, FLIP-dst считается от ширины полосы); в раскрытой полосе профиль подписан «Мой профиль» (кросс-фейд max-width/opacity, как строки рейки); список — «Заметки» (сообщения себе, закладка вместо своей аватарки — профиль не дублируется в коллегах, модель Битрикс24; диалог с собой = «Заметки» и в мессенджере: глиф и заголовок, find-or-create + инвалидация списка бесед до перехода) и коллеги ПО АКТИВНОСТИ диалогов (lastMessage контракта; серверная сортировка — с реальным API); ось — связь модуль→подмодули: заканчивается ПОСЛЕДНИМ подмодулем, аккуратной дугой поворачивая в его засечку (НИЧЕГО не торчит, зазора нет — вердикт 14.09.2026 вечером: длинного бордюра на всю ширину нет, воздушность); в мессенджере ось идёт до правого края рамы — там она одновременно верхняя граница окна чата; у модуля без подмодулей (Главная) связь доводится до ЛЕВОГО КРАЯ мягкой области и заканчивается на нём терминальной точкой; засечки вкладок — локти со скруглённым входом в ось (как локти вспышки; голая вертикаль читалась «прямоугольным углом»); ось не пересекает зону аватарок (полоса вне рамы); скроллбар страниц — собственный ползунок В ПРАВОЙ ЩЕЛИ ПЕРИМЕТРА (правее служебной полосы): трек на всю высоту экрана, управляет скроллером страницы внутри рамы (`edge-scrollbar`: усыновление главного скроллера, нативный вертикальный скрыт `data-edge-scroll`, горизонтальный широких таблиц сохранён; вердикт владельца ночью 14.09.2026); лестница z: контент 0–40 · слайдеры 50 · оверлей-порталы и тосты z-[70]; на Главной (без вкладок) полосу топбара занимает приветствие `HomeGreeting` (лента выше); структура — ступенями тона И формы, не линиями; контур мягкой рамы на периметре — мягкая тень `frame-shadow` (реф «реф_белая тема_1.png»: в светлой теме панель читается тенью, не линией, вердикт 14.09.2026); мессенджер — лестница без зоопарка: список бесед и весь хром = тон панели (`card`), лента каналов/личных/тредов = ОДИН токен углубления `chat-zone` в обеих темах, пузыри = `node-panel` поверх углубления (вердикт 14.09.2026: «фон каналов один, чатов другой, зоопарк»);**
4. **Типографика:** контент — Onest; метки/ключи/даты/счётчики — JetBrains Mono UPPERCASE 10–12px, tracking 0.14–0.16em (`NodeLabel`).
5. **i18n:** все UI-строки из `packages/contracts/i18n/ru.ts` (I15). Новые строки → туда же → `pnpm --filter @nodus/contracts build` до typecheck. Мёртвые строки удаляются в том же коммите.
6. **Связи — по нашей грамматике:** ортогональные рёбра 1px с локтями (скругление 6–8px) и портами r=3; порты по центру линий вычисляются из геометрии, не «на глаз». Никаких точек/узлов декоративных внутри панелей; свечение и вспышки — только на смену фокуса.
7. **Аватары — графитовые** (`PersonAvatar`, детерминированный тон от имени), в обеих темах.
8. **Цвет = смысл, ярусами:** нейтральный холст → ЕДИНСТВЕННЫЙ брендовый акцент (navy `#16233A`: светлая тема — primary/фокус/порт/контур; тёмная — хром монохромный по вердикту) → функциональные статусы (семантика, никогда декор) → выразительность (glow/пульсы) → categorical-палитра `--chart-1..6` (Okabe-Ito, colorblind-safe) ТОЛЬКО графики и маркеры идентичности (`ProjectIdentityIcon`, `identityTone`, `chartRowTone`). Раскраска хрома запрещена.

## Кратко-канон (детали — в references)

- **Контур Nodus** — измерение живого DOM по data-атрибутам (`data-topbar`, `data-module-port`, `data-tab-port`, `data-left-node`); артерия — одна ломаная; вспышка одна, от порта модуля к точке вкладки, скорость 400 px/s (draw 1200 px/s), фокус = `moduleTo|tabLabel`; Главная — без вспышки.
- **Таблица** — модель AG Grid/Битрикс: px-треки (никакого fr!), `w-max min-w-full`, `overflow-x-auto`; ресайз ручкой (min под контент, max 640, следует за курсором 1:1), dblclick — автоподбор (мерить детей ячеек, не ячейку); колонки и поля карточек настраиваются шестерёнкой (`shared/views`, пресет `nodus-views-v1`).
- **Карточка-слайдер:** shared-element раскрытие из rect источника (`lastSource` → `SliderPanel sourceRect`): CSS @keyframes `slider-expand` строго на transform (композитор; paint/layout-свойства в keyframes запрещены — декомпозит, gotchas), контент монтируется после первого кадра (double rAF); закрытие — WAAPI-схлопывание в источник; без источника — scale-fade. Виды сущностей стека: задача, проект, письмо, сотрудник + **беседа** (`chat:<id>`, вердикт 14.09.2026: чат поверх карточки задачи из служебной полосы; верхняя чат-карточка подменяется новым собеседником; рабочая область — общий `ChatWorkspace` страницы и карточки). Тень карточки `slider-shadow` — НАПРАВЛЕННАЯ (влево-вниз): без разлива вправо на служебную полосу (вердикт 14.09.2026: «пятна» справа от карточки). **Парящий лист (пакет мягкости 12.09.2026): inset-2 — тот же прямоугольник, что мягкая рама (от самого верха), скругление ВСЕХ углов 18px**. Затемняющего задника НЕТ: тень `slider-shadow` + прозрачный click-catcher. Esc закрывает верхний слайдер стека, НО не когда открыт Radix-поповер/меню внутри (меню съедает Esc: фильтр `event.defaultPrevented` + `[data-radix-popper-content-wrapper]` в `SliderPanel`). Зональные фоны (тёмная зона чата) — структура с первого кадра (`fadeContent=false` + fade по контентным блокам). Шапка: кнопка навигатора ветки слева + доменная цепочка (`DomainChain` без свечения; само-узел — только «ТИП · №», БЕЗ повтора названия) + чип источника + кнопка «О задаче»; хлебных крошек НЕТ — ГЛАВНОЕ НАЗВАНИЕ живёт в хроме слайдера рядом с X (`SliderPanel title`, на видном месте; в теле карточки не дублируется — тело начинается с описания; вердикт владельца). Левая колонка (`@container`): название → описание → поля (`task-fields.tsx`: РЕЕСТР дескрипторов — любое количество полей, видимость настраивается кнопкой «+ Поле» с чекбоксами (persist localStorage), кастомные поля после MVP = те же дескрипторы из справочника (I13/I15); строки иконка+метка/значение без рамок; СТАДИЯ — поле-чип с компактным списком строго ПОД ПРОЕКТОМ (модель Битрикса), НАБЛЮДАТЕЛИ — системное поле под СОИСПОЛНИТЕЛЯМИ; личная колонка «Моего плана» в карточке НЕ показывается и из неё не меняется — только DnD на доске; сетка 1→2 колонки по container query (2 только без обрезки значений, @min-[880px]), блок до max-w-4xl, на узкой зоне значение переносится под метку; ЗНАЧЕНИЯ НЕ СОКРАЩАЮТСЯ — имена сотрудников и названия задач всегда целиком (перенос), truncate только для сверхдлинных названий типа проектов, с title-тултипом (вердикт владельца)) → подзадачи/чек-лист. Внизу левой панели — ЗАМОНОЛИЧЕННЫЙ бар действий (вне скролла, модель Битрикса, `task-stage-controls.tsx` TaskActionBar): «⟲ вернуть» ghost / «вперёд →» solid / «✓ Завершить задачу» outline-success (свободная задача без workflow: прыжок в первую done-стадию схемы — НЕ в последнюю по порядку, после «Завершена» может идти «Отложена»; workflow применён → кнопки = переходы схемы, после MVP #38). Справа — постоянная колонка обсуждения с перетаскиваемой запоминаемой границей (дефолт 680px): граница — `border-r` левой зоны (структурная линия; горизонтальные бордеры упираются ровно в неё, висячих сепараторов внутри зон нет — секции разделяются отступами), ручка ресайза — невидимый оверлей w-3 поверх границы (НЕ трек сетки); нижние бары обеих зон — ОДНОЙ высоты h-16 (бар действий = композер чата: их верхние линии — одна горизонталь через границу, замер y==y, вердикт владельца); drag ИМПЕРАТИВНЫЙ (el.style.width в rAF, React не рендерит карточку, коммит state + localStorage на pointerup; transition на ширине чата снят во время drag — флаг `dragging`, gotchas); «О задаче» — **вталкивающая колонка справа**, пушит НЕ левую панель: чат СУЖАЕТСЯ на ширину панели (синхронные `transition-[width]` 0↔360 / chatW↔chatW−360, сумма постоянна — левая зона стоит, вердикт владельца); навигатор ветки (подзадачи любой вложенности, быстрое создание, переход без закрытия панели) — **вталкивающая колонка слева** (auto-трек + `transition-[width]` 0↔300px на самой колонке: контент и разделитель чата сдвигаются плавно, НЕ оверлей; тоггл — иконка `Waypoints`).
- **Канбан «Мой план» — личная ось стадий (ADR-0008):** колонки = стадии личной схемы пользователя (не глобальной!); шапка — цветной чип стадии (`lib/stage-tone.ts`: палитра neutral/info/success/warning/danger на токенах темы) + счётчик + «+» быстрого создания задачи в колонку (инлайн-инпут в топе колонки) + меню «⋯» (переименовать inline / цвет / удалить — единственную нельзя, задачи переезжают в первую колонку того же состояния); создание стадии — КОМПАКТНАЯ инлайн-форма в конце ряда («точка цвета + название», Enter/Esc — референс ClickUp «Add group»; никаких больших панелей настроек); тело колонки — читаемая пастель тона (`bg-*-soft/40`, вердикт владельца). Привязка колонки к системному состоянию живёт в МОДЕЛИ (контракты/моки готовы к workflow-схемам), в UI до MVP не спрашивается (вердикт владельца: автоматизация — после MVP, через редактор схем). DnD по личной оси (`personalAxis` в kanban-board.ts), персист `personalStageId`.
- **Законы чата (вердикт владельца, раунд 3):** где чат — там ПРАВАЯ панель с файлами/ссылками беседы (`shared/chat/chat-side-panel.tsx`) по канону панели «О задаче»: тоггл — кнопка СПРАВА ВВЕРХУ в шапке КАРТОЧКИ/страницы (таб-бар проекта, полоса сотрудника, шапка беседы мессенджера — `ChatPanelToggle`); ШАПКИ У САМОГО ЧАТА НЕТ (никаких «чёрных областей» с названием канала/именем собеседника — вердикт); панель — ВНУТРИ колонки чата справа (одна анимируемая ширина — левая зона не дёргается; лента ≥ 360px при открытой панели — минимум `MIN_FEED_WITH_PANEL` для панели беседы; при открытом ОКНЕ ТРЕДА минимум ленты 320 (`MIN_FEED_W`, #42), при панели и окне одновременно пол ленты 320; колонка ≥ 660 — тогда выталкивает левую зону); действия над сообщением — КОНТЕКСТНОЕ МЕНЮ ТОЛЬКО по правому клику (`shared/chat/message-menu.tsx` на Radix ContextMenu: меню у курсора, кламп в viewport примитивом; реестр-заготовка под бэкенд; «Редактировать»/«Удалить» — только свои; кнопок «⋯» на сообщении НЕТ); пустые состояния — канонический `Empty` (пунктирных рамок нет; drop-зона канбана — исключение, affordance переноса); перегородка чата в карточках тянется мышью С ПАМЯТЬЮ (`shared/ui/use-chat-width.ts` — единая память на все карточки, дефолт 680px, drag императивный — gotchas); ленты сообщений — СЕРИЯМИ одного автора (`shared/chat/message-groups.ts`, разрыв только по смене автора/дня): имя — чужое и только первое в серии (в личных имён нет), аватар один — у ПОСЛЕДНЕГО (колонка аватара зарезервирована всегда, пузыри серии на одной вертикали), ритм 2px внутри серии / 12px между, дата-чип при смене дня; пузыри чата БЕЗ рамки (вариант `card` Bubble-примитива: контур ступенью тона, рефы Битрикс24); время ВНУТРИ пузыря справа внизу + галочки sent/read у своих (`readAt` контракта; левая галочка поверх, правая прячется за ней); реакции и вложения — ВНУТРЬ пузыря (расширяют высоту; нижняя строка = реакции слева + время справа); хвостик у последнего пузыря серии — ОДНА заливка SVG (`shared/chat/bubble-tail.tsx`): силуэт сам несёт вогнутую кромку и закруглённый носик к низу аватарки; АНТИПРИМЕР: CSS-бордюр пузыря + SVG-обводка хвоста — разный антиалиасинг двух движков рисования = «полутонкие линии», расдвоенные кончики и швы на стыке (разбор вердиктов 14.09.2026); композер автофокусится при входе в чат (autoFocus, ремоунт по conversationId); вложения — грамматика Битрикс24 (`shared/chat/attachments.tsx`): схема `messageAttachment` с `kind`/`url`/`thumbnailUrl`/`width`/`height` (задел под загрузку в MinIO и лайтбокс), порядок в пузыре и посте СВЕРХУ: галерея изображений (`attachment-gallery.tsx`: 1 — крупное, 2–3 — ряд равновысотных плиток, 4+ — ряды по 3; бокс резервируется по width/height — лента без сдвига; `onOpen` — точка будущего лайтбокса) → чипы файлов (`attachment-file.tsx` на примитиве `Attachment`: иконка по mime, имя, размер, скачивание) → текст → нижняя строка; карточка поста канала: автор сверху, вложения выше текста, реакции+время строкой, ответы — тонированной полосой «N ответов» + «Обсудить».
