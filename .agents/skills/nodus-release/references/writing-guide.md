# Как писать «Что нового» для сотрудников

Читатель — инженер-проектировщик, сметчик, секретарь, руководитель. Он не
знает, что такое PR, API или WebSocket, и ему всё равно, КАК сделано. Ему
важно: **что теперь можно делать / что стало удобнее / что больше не
мешает**. Один пункт читается за 5 секунд.

## 1. Отбор: что идёт в окно

| Попадает | Не попадает (только GitHub Release) |
|---|---|
| Новая кнопка, экран, действие, жест мыши | Зависимости, CI, тесты, линтеры, доки агентов |
| Изменение поведения, которое человек заметит | Рефакторинг «отрисовка не менялась» |
| Исправленный баг, который кто-то мог встретить | Внутренние проверки прав без видимого эффекта |
| Заметное ускорение (доска быстрее, меньше ожидания) | Ускорение, измеримое только в DevTools |
| Изменение приватности/доступа, которое касается людей (уволенный теряет доступ, чужие задачи скрыты) | Защита от атаки, которую обычный пользователь не совершает (подделка запросов, чужие id) |

Сомнение «заметит ли?» — смотри в PR раздел «Как проверить (приёмка)»: если
там шаги в интерфейсе — заметит. «Отрисовка не менялась» / «API не менялся»
в теле PR — почти всегда техника.

Фиксы багов, которые появились и исчезли ВНУТРИ одного выпуска (ни разу не
были на проде), — не пишем: пользователь их не видел.

## 2. Склейка и разбивка

- Несколько коммитов про одно (фикс + дофикс, фича + полировка) → **один
  пункт**.
- Один PR с двумя независимыми видимыми изменениями → **два пункта** (пример:
  #354 дал «чужие подзадачи скрыты» в Задачах и «личная беседа видна после
  первого сообщения» в Мессенджере).
- Безопасность + видимое поведение → пишем видимое поведение, безопасность —
  как польза одной фразой («приписать коллеге чужие слова нельзя»).

## 3. Модуль

`module` — где человек ВСТРЕТИТ изменение, а не где лежит код.

| Код / скоуп коммита | module |
|---|---|
| tasks, канбан, карточка задачи, учёт времени | `tasks` |
| chat, каналы, треды, стикеры, обсуждения | `chat` (обсуждение задачи — тоже `chat`, если про сообщения) |
| correspondence, письма, регистрация | `letters` |
| crm, контрагенты | `crm` |
| projects | `projects` |
| directory, сотрудники, структура, увольнение | `employees` |
| home, уведомления в ленте Главной, дни рождения | `home` |
| auth/вход, шапка, тема, поиск Ctrl+K, колокольчик, приложение для Windows, скорость всего портала | `general` |

Новый модуль в рейке → его id из `apps/web/src/app/shell/nav-registry.ts`
(тест-страж принимает только id реестра + `general`).

## 4. Тип

- `new` — **Новое**: раньше этого не было совсем (кнопка, экран, жест).
- `improved` — **Улучшено**: было, стало удобнее/быстрее/понятнее/безопаснее.
- `fixed` — **Исправлено**: было сломано или работало не так, как ожидали.

Порядок в файле внутри типа сохраняется — ставь важное первым. Модули и
типы сортирует панель сама.

## 5. Стиль

- **Заголовок** (≤ 90 символов) — что изменилось, глаголом или
  существительным, без точки: «Канбан прокручивается подводом мыши к краю».
- **Текст** (1–2 фразы, ≤ 320) — как этим пользоваться и что это даёт.
  Обращение на «вы». Конкретные названия из интерфейса в «ёлочках»
  («Мой план», «Подзадачи / Связи»).
- Фикс — описываем НОРМАЛЬНОЕ поведение, которое вернулось, а не баг:
  «снова появляются двойные галочки», не «исправлена ошибка подписки на
  комнату».
- Термины — только деловые русские из интерфейса (`docs/product/glossary.md`):
  задача, поручение, письмо, беседа, канал. Запрещено (ловит тест): номера
  `#123`, API, PR, WS, Redis, endpoint, бэкенд/фронтенд, токен, кэш,
  миграция, коммит, рефакторинг, деплой.
- Не обещай того, чего нет («мгновенно», «никогда») и не хвали себя
  («значительно улучшен», «оптимизирован»): факт + польза.
- `summary` — одна фраза о главном в обновлении, для тех, кто дальше не
  прочитает.

## 6. Примеры

| Плохо (пересказ коммита) | Хорошо (польза) |
|---|---|
| «Ширина навигатора ветки тянется с памятью, минимум центра» | «Панель подзадач в карточке задачи можно расширить» — «Потяните мышью границу панели «Подзадачи / Связи» — длинные названия больше не обрезаются. Ширина запоминается для всех карточек задач.» |
| «Запрос на колонку и точечная WS-инвалидация» | «Доска быстрее обновляется, когда коллеги меняют задачи» |
| «Стоп-лист access-токенов в Redis» | «Уволенный сотрудник сразу теряет доступ к порталу» — «…за несколько секунд, а не через 15 минут.» |
| «Email без учёта регистра — нормализация и CHECK в БД» | «Вход не зависит от заглавных букв в почте» |
| «Каждый хост ленты подписан на комнату беседы» | «Галочки «прочитано» в обсуждении задачи» — «…снова появляются двойные галочки, когда собеседник прочитал сообщение.» |

Эталон целиком — `apps/web/src/features/whats-new/releases/0.1.0.json`.
