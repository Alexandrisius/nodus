# Фаза 4 — атаки субагентами: ядро против воспроизведённых болей

Атака — не «покритикуй модель», а воспроизведение конкретной боли сценарием и
прогон её через ядро. Только так вердикт проверяем: сценарий можно перечитать
и переиграть. Свободная критика («мне не нравится иерархия») — мусор.

## Атакующие

2–5 субагентов `general-purpose` на раунд, по кластерам реестра. Каждому —
**персона**: роль из процесса (практик-скептик, аудитор стандартов, вредный
пользователь, человек из смежного отдела, «новичок без контекста») + характер.
Персоны НЕ повторяются между атакующими одного раунда — одна модель у всех
и так, разные роли — единственное настоящее разнообразие.

Вход атакующему (самодостаточный промпт): снапшот `core.md` + `boundaries.md`
+ его кластеры болей с источниками + этот протокол + формат вердикта.
HOLD-OUT кейсы досье подаются как обычные сценарии, без пометки.

## Протокол атаки на один сценарий

1. **Воспроизведи боль** конкретным эпизодом: кто, что, когда, что предшествовало
   (структура критического инцидента). Сценарий из источника, не из головы.
2. **Прогони через ядро**: какие правила отвечают на сценарий, что молчит,
   где ядро отвечает противоречиво (два правила дают разное).
3. **Негация (KAOS)**: пройди по утверждениям ядра — какое из них этот
   сценарий нарушает? Сломом считается конкретное нарушение, не «дух модели».
4. **Проверь границы**: если лечится только расширением скоупа — это OUT
   (вопрос заказчику), а не FAIL.
5. **Вердикт**:
   - `PASS` — ядро отвечает сценарий целиком;
   - `FAIL` — какое правило сломано + минимальный вариант фикса + помогает ли
     фикс другим кейсам (тест абстракции);
   - `OUT` — сценарий вне границ + формулировка вопроса границы для заказчика.

## Анти-консенсус (ловушки мультиагентных дебатов)

Исследования мультиагентных дебатов дали три ловушки — протокол их гасит:

- **Ложный консенсус**: дебаты уверенно сходятся к неправильному. Гасится
  правилом: вердикт без воспроизводимого сценария не принимается.
- **Коррелированные слепые зоны**: агенты одной модели ошибаются одинаково.
  Гасится разными персонами и разными формулировками жатвы.
- **Сговорчивость**: модель после RLHF легко соглашается. В промпт атакующему
  явно: «твоя работа — ломать; к каждому "ядро справится" поищи контрпример;
  фраза "в целом модель хорошая" запрещена».

Расхождения атакующих НЕ усредняются и не «голосуются»: кузнец разбирает
каждый FAIL отдельно. Спорное между PASS и FAIL — воспроизведи сценарий сам
по шагам, а не выбирай чьё-то мнение.

## Обработка кузнецом

1. FAIL с воспроизводимым сценарием → фикс: тест абстракции (правило для
   класса, ≥2 независимых кейса из разных источников) + трассировка (откуда
   правило). Оба не прошли — фикс отклонён, сценарий в open-questions.
2. Каждый фикшенный сценарий остаётся в сьюте `attack-log.md` со своим
   вердиктом по раундам — это регрессионный сьют ядра.
3. Отклонённые предложения — одной строкой в attack-log (что, почему нет),
   чтобы следующие раунды не приносили то же.
4. **Регрессия после фиксов**: перезапуск атакующих по изменённым кластерам;
   все прошлые FAIL обязаны стать PASS; выборочная проверка, что старые PASS
   не сломались (особенно кейсы, ради которых правило появилось).

## Раунды и стоп

Обычно 1–3 раунда на заморозку. Раунд = атака по всем живым кластерам +
обработка + регрессия. Стоп-правило — сатурация: раунд без новых FAIL и OUT
(косметика «можно уточнить формулировку» не считается). Больше 3 раундов —
только с разрешения заказчика: дальше обычно не новые сломы, а дрейф модели
под вкусы атакующих — то самое переобучение, против которого всё затевалось.
