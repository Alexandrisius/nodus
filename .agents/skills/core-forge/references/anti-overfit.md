# Защита от переобучения — четыре предохранителя

Ядро переобучено, если оно идеально отвечает кейсы, по которым строилось, и
валится на первый новый. Эти четыре механизма включены на всех фазах.

## 1. Трассировка: правило без источника не существует

Каждое правило `core.md` несёт источник: дословная цитата из досье или URL
из pain-registry. Колонка «откуда» — обязательная. Правило, которое «и так
очевидно» — кандидат №1 в галлюцинации: либо найди источник, либо это
гипотеза — и она идёт в open-questions заказчику, а не в ядро.

## 2. Тест абстракции: правило для класса, не для кейса

Каждый фикс (и каждое новое правило) формулируется как правило для КЛАССА
ситуаций и обязан помогать минимум двум независимым кейсам из разных
источников (два эпизода одного собеседника — не независимы).

- Полезен одному кейсу → переобучение: отклонить или понизить до вопроса.
- Формулируется только через частный случай («а если сметчик Анна...») →
  обобщи, пока правило не отлипнет от кейса; не отлипает — не правило.

## 3. HOLD-OUT: кейсы, которые ядро не имеет права видеть

Каждый 3–4-й кейс досье помечен HOLD-OUT. Кузнец не читает их при
построении ядра и при фиксах — только атакующие получают их как сценарии
(без пометки, что они тестовые). HOLD-OUT, на котором ядро молчит — обычный
FAIL. Это train/test split: расширять ядро «под прохождение теста», зная его
заранее, запрещено — поэтому доступ и закрыт.

## 4. Сатурация: стоп-правило вместо «пока не надоест»

Цикл «улучшай и атакуй» бесконечен и сам по себе расползается: каждый раунд
генерирует «ещё немного улучшений». Стоп: раунд без новых FAIL и OUT —
модель насыщена, заморозка. По grounded theory это теоретическая сатурация:
новые данные не дают новых свойств категорий. «Мы слышим одно и то же» —
насытились данные (плохой знак, узкая жатва); «новые данные ложатся в
существующие правила» — насытилась теория (правильный стоп).

## Побочные механизмы

- **Leave-one-out sanity** (в регрессии): при крупном фиксе проверь, не
  сломал ли он кейсы, ради которых старое правило появилось.
- **Лог отклонённого**: всё отклонённое — строкой в attack-log. Без него
  каждый раунд заново приносит отклонённое, и оно просачивается в ядро
  через усталость.
- **Смена автора сценария ≠ смена модели**: субагенты одной модели делят
  слепые зоны. Разнообразие дают персоны и формулировки жатвы, а не
  количество агентов.
