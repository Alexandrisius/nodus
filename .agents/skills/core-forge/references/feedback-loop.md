# Фаза 5 — заморозка, вопросы заказчику и цикл после фидбека

## Заморозка

Условия: сатурация атак (раунд без новых FAIL/OUT) + регрессия зелёная +
ядро отвечает все must-answer своей версии границ. Тогда:

1. Зафиксируй `core.md` (версия vN, один абзац «что ядро собой представляет»
   без истории изменений — история в boundaries и attack-log).
2. Перегенерируй `open-questions.md` для заказчика: нерешённые OUT-вопросы
   границ, спорные фиксы, гипотезы без источника, осознанные упрощения.
   Каждый вопрос — простой язык, по существу выбора: что выбираем и чем
   рискуем. Без методологического жаргона.
3. Отдай заказчику: ядро + вопросы. Его протыкивание и есть приёмка.

## Классификация фидбека (каждый пункт — в свою корзину)

| Тип | Признак | Действие |
|---|---|---|
| Сдвиг границы IN | было out-of-scope, стало нужно | `boundaries.md` vN+1, новая компетентностная гипотеза-вопрос, точечная жатва + атака по этому кластеру |
| Новый кейс в скоупе | новая боль внутри существующих границ | кейс в сьют attack-log, атака кластера, фикс по общим правилам |
| Конфликт правил | два правила дают разный ответ на один сценарий | оба варианта — в open-questions, выбор за заказчиком; без его слова ядро не трогать |
| Сужение (OUT) | правило больше не нужно / мешает | удалить правило, регрессия сьюта: не сломалось ли то, что на него опиралось |
| Подтверждение | «ок, так и задумано» | отметить в attack-log, ничего не менять |

## Точечный ре-прогон

Фидбек обрабатывается диффом, а не полным перезапуском конвейера: только
затронутые кластеры + регрессия сьюта. Полная жатва заново — только если
сдвиг границ крупный (появилась целая новая область), и это решение
заказчика, не агента. Ядро, пересобираемое с нуля после каждого комментария,
— не ядро, а чемодан без ручки.

## MVP ядра — тот же цикл

Замороженное ядро, воплощённое в продукте, начинает собирать боевые боли.
Замечания пользователей ядра = новый кластер pain-registry («эксплуатация»),
дальше по общей схеме: классификация → точечный прогон → сатурация →
заморозка vN+1. Конвейер не кончается — у него просто растут версии.

## Правило версии

Каждая заморозка = новая версия: `boundaries.md` сдвиг + `core.md` абзац
сути + attack-log раунд. Никаких «тихих» правок ядра между версиями —
изменение без раунда атаки и регрессии запрещено.
