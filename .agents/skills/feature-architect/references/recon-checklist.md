# Чеклист разведки (Ф1): что читать, где искать, что подтверждать

Разведка отвечает на два вопроса: **что уже есть в коде** (переиспользовать, не
изобретать) и **что уже решено людьми** (не переспрашивать отвеченное). Оба — до
каких-либо вопросов владельцу и до черновика.

## Что читать (минимум, по типу задачи)

| Тип задачи | Обязательно |
|---|---|
| Любая | тело issue целиком; эпик; строка плана трека (`docs/mvp/process-model-plan*.md`); AGENTS.md (уже в контексте) |
| Затрагивает модуль | README модуля; `docs/architecture/modules.md` (раздел модуля) |
| Новые сущности/поля | `data-model.md`; последняя миграция в `prisma/migrations/` (метка для новой) |
| API/DTO/события | `api-conventions.md`; `packages/contracts/` — реально существующие схемы области |
| Поток пользователя | `core-flows.md`; `ux-principles.md` |
| Права | каталог прав в `apps/api/…/auth`; матрица/README `directory` |
| Экраны | навык `nodus-ui-style` (рецепт экрана); похожие экраны в `features/` |
| Область с ADR | ADR из `docs/adr/` по теме (список — `docs/adr/README.md`) |
| Непонятная ошибка/поведение хоста | `docs/gotchas/` области |

## Где искать уже данные ответы (порядок)

1. `docs/mvp/process-model-plan*.md` §1–5 — решения и целевая модель трека.
2. Тело и комментарии эпика; комментарии соседних issues трека.
3. `docs/product/incubator.md` — обсуждённые и отложенные идеи.
4. `docs/product/interviews/` (+`full/`) — слова руководства: как процесс живёт на деле.
5. `docs/mvp/plans/` — черновики планов соседних задач (не в git, чистятся при закрытии).
6. Продуктовые указания владельца вне репо — память агента (`owner-product-decisions`).
7. `docs/product/glossary.md`, `north-star.md` — термины и цели.

Ответ найден → в план с цитатой и источником; не найден → вопрос/допущение по
классификатору (business-questions.md).

## Чужие системы: вопрос по границам, а не «по жизненному циклу»

- Библиотека (Context7/Exa): (а) жизненный цикл; (б) формы значений, пересекающих наши
  границы хранения/сравнения — тип (массив/строка), нормализация (скобки/регистр/
  кодировка), ширина чисел, формат дат — с правилом нормализации на границе
  («голый ID везде»); (в) сигнатуры критичных вызовов (что вернёт на пустом/ложном:
  `false | number[]`). Есть реальный образец (файл, ответ сервера) — проба на нём
  сильнее доков. Артефакт: таблица «значение → форма → нормализация».
- Инфраструктура (сети, порты, маршрутизация, поведение окружения): аксиома проверяется
  пробой ДО плана (2–5 минут на поднятом стеке) — шаг фазы 0 с командой, ожиданием и
  результатом; непроверенное — посылка с обязательным fallback.
- Внешний сервис (почта, конвертеры и т.п.): одна контрольная авторизация до старта
  живой работы; именованные переменные тестового контура; правила вежливости
  (2 отказа → стоп, пауза 15–30 минут — защита от банов).

## Карта точек интеграции (заполнить по коду)

Для каждой строки — подтверждение `file:line`, а не «предполагаю, есть»:

- **Сущности**: таблицы/модели Prisma, которых касается фича; их индексы/unique.
- **События**: каталог области (`*-events.ts`), кто подписан (`events/*.handler.ts`) —
  новое событие или payload-изменение обязано знать своих слушателей.
- **Контракты**: схемы в `packages/contracts/src/<область>/`; кто ещё импортирует.
- **Права**: существующие коды прав области; мёртвые/дубли (кандидаты на чистку).
- **Порты** (ADR-0012): существующие порты модуля; куда ложится новый.
- **Очереди BullMQ**: есть ли тяжёлая работа, которую нельзя делать в HTTP.
- **Фичефлаг**: флаг модуля, поведение при выключенном (I10).
- **WS-gateway**: какие комнаты/события рассылаются, нужна ли маршрутизация новых.
- **Файлы/S3**: если фича несёт вложения — `FILE_ACCESS_*`, подписанные ссылки.
- **i18n**: словарь области (`ru-<область>.ts`), терминология глоссария.
- **MSW-мир**: существующие моки области — что расширять, что сносить.

## Фан-аут: одна поверхность — один целевой субагент

- Пачка параллельных запусков, по одной поверхности Ф0 на каждый; запрос конкретный:
  «как сегодня создаётся письмо: сервис → repo → событие → история, file:line» — не
  «изучи модуль correspondence» (широкий запрос возвращает пересказ, конкретный — факты).
- Чистый поиск («найди все места, где X», карта модуля) — субагент `Explore` (дёшево);
  многошаговая проверка цепочки — `general-purpose`. Промпту — точный возврат:
  список `file:line` + одна строка на место.
- Сам: конкретная схема, конкретный обработчик — Read напрямую.
- Фронт закрыт, когда по каждой поверхности Ф0 есть факты; «не нашёл» принимается
  только с перечисленными запросами и вариантами терминов. Не жалей запусков —
  разведка дешевле дыры в плане.

## Выход фазы

Таблица «Что уже есть»: | Что | Состояние (file:line) | Переиспользуем/расширяем/новое |.
Отдельно: расхождения спеки и кода («issue говорит X, код показывает Y» — продуктовые
решаются владельцем в Ф2, технические решает архитектор); мёртвый код и мелкие
дефекты по пути — в находки F# (мелочь правим в скоупе, остальное — issue-заготовка).

Гейт: в таблице нет строк без источника; факты покрывают все поверхности Ф0;
расхождения выписаны; карта интеграций заполнена по затронутым точкам (не по всем
одиннадцати — только релевантные).
