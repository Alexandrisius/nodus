# Nodus dev-сборки и живые проверки — единый канон

Проблема, которую закрывает навык: каждая сессия изобретала свою песочницу —
случайные порты, смесь моков и живых БД, самодельные пользователи. Итог —
каша, потерянные часы и инцидент 01.10 (песочница молча села на прод-БД).
Здесь зафиксирован ЕДИНСТВЕННЫЙ способ проверять код живьём (#178).

## Закон трёх контуров — никаких четвёртых

| Контур | Порты | Чей | Для чего |
|---|---|---|---|
| dev владельца | `:5173` (vite dev, моки по `VITE_API_MOCK`, chat живой) | **владельца** | его приёмка «на живую»; НЕ трогать, НЕ перезапускать, НЕ плодить второй dev-сервер — фикс в дереве виден ему по F5 |
| прод | `:3000/:3001/:3002` + `nodus.by` (docker compose) | владельца | только смок после деплоя; пробы ЗАПРЕЩЕНЫ |
| песочница агента | `:3011` api / `:3012` gateway / `:4173` web-preview | агента | ВСЕ живые пробы и приёмка на ветке |

Свой сервер/порт/мок-хост = баг. Нет подходящего контура под задачу → STOP & ASK владельцу, а не поднимать своё.

## Что чем проверять (лестница — вниз, если можно)

1. **Unit (Vitest)** — всё, что проверяется без браузера и сервера: чистые функции, редьюсеры, компонентная разметка. Это 95% проверок.
2. **Интеграционные (CI)** — контракты API, идемпотентность, outbox; гоняются в CI сами.
3. **Живая проба (песочница live-stack)** — только поведение, которое существует лишь живьём: WebSocket-догон, скролл, два пользователя, тайминги, миграции на живой БД.
4. **Приёмка владельцем** — на `:5173` или `:4173` (решает владелец); до вердикта НЕ коммитим.

Правило: подумал «надо бы проверить в браузере» → сначала спроси себя, нельзя ли unit-ом. Живая проба — осознанное решение, не рефлекс.

## Песочница live-stack — одна команда

```bash
pnpm live-stack up      # сборка из рабочего дерева + АВТО-изоляция:
                        #   DATABASE_URL -> nodus_night, REDIS_URL -> db1
                        #   + бутстрап: создать БД -> миграции -> night-пользователи
pnpm live-stack status  # api :3011 / gateway :3012 / web :4173, pid-файл .live-stack/
pnpm live-stack down    # снять (свои процессы гасить после приёмки)
pnpm live-stack bootstrap  # только бутстрап БД (up делает это сам)
```

- Подъём/снятие — ТОЛЬКО через эти команды (PID-файл ловит сирот прошлых сессий; чужой процесс на порту = громкая ошибка, а не молчаливый EADDRINUSE).
- **Изоляция автоматична и принудительна**: без явного env процесс уходит в `nodus_night` (та же nodus_postgres) + Redis db1; запуск против прода — только `SANDBOX_ON_PROD=1` (не надо). Почему: два api на одной БД/редисе воруют outbox-события и fanout стрима друг у друга.
- После правок кода — `down` + `up`: vite preview держит СТАРУЮ сборку, пока жив процесс.
- Тестовые пользователи: `night-a@nodus.local` / `night-b@nodus.local`, пароль `Night-Probe-100!` (секрет одноразовой песочницы, не прод). Двухпользовательские сценарии = эти двое.
- Полный сброс данных песочницы: `docker exec nodus_postgres psql -U nodus -c 'DROP DATABASE nodus_night'` → `pnpm live-stack up` пересоздаст.

## Правила живых проб

- **Бюджет: 1–2 пробы на фикс** (вердикт владельца 01.10): гипотеза → одна проба → гейты → владельцу. Непонятное — вопрос, а не серия прогонов.
- Проба владеет своими данными: сущности создаёт с маркером («Проба …») и чистит за собой; упавшая проба оставляет полусозданное — добить/удалить перед следующим прогоном.
- Скрипты проб — в `.live-stack/` (gitignored), каркас и паттерны — `references/probes.md` (REST-логин Bearer, SPA-навигация, Idempotency-Key, ожидания вместо sleep).
- Замеры UI в дизайн-px = фактические ÷ 1.25 (ui-scale); пиксельные сканы скриншотов — dpr=3, инсент 6px от краевого ореола.
- Владельцу — живой взгляд (или видео), НЕ свои скриншоты вместо приёмки.
