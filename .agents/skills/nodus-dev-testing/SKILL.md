# Nodus dev-сборки и живые проверки — единый канон

Проблема, которую закрывает навык: каждая сессия изобретала свою песочницу —
случайные порты, смесь моков и живых БД, самодельные пользователи. Итог —
каша, потерянные часы и инцидент 01.10 (песочница молча села на прод-БД).
Здесь зафиксирован ЕДИНСТВЕННЫЙ способ проверять код живьём (#178).

## Закон трёх контуров — никаких четвёртых

| Контур | Порты | Чей | Для чего |
|---|---|---|---|
| dev владельца | `:5173` (vite dev, моки по `VITE_API_MOCK`, chat живой) | **владельца** | его приёмка «на живую»; НЕ трогать, НЕ перезапускать, НЕ плодить второй dev-сервер — фикс в дереве виден ему по F5; **может быть выключен — перед отсылкой владельца проверить порт (правило ниже)** |
| прод | `:3000/:3001/:3002` + `nodus.by` (docker compose) | владельца | только смок после деплоя; пробы ЗАПРЕЩЕНЫ |
| песочница агента | `:3011` api / `:3012` gateway / `:4173` web (`--dev` — vite dev, по умолчанию — preview; `--dev --mock <домены\|all>` — MSW для UI-чекпоинта до бэкенда: `all` — вход любыми данными, список доменов — живой вход учётками песочницы) | агента | ВСЕ живые пробы и приёмка на ветке |

Свой сервер/порт/мок-хост = баг. Нет подходящего контура под задачу → STOP & ASK владельцу, а не поднимать своё.

**Песочница non-mock** — исключение `--dev --mock` для UI-чекпоинта до бэкенда (ADR-0001): моки живут только в vite dev (`vite build` всегда non-mock, #171); пробы поведения и e2e — без моков.

## :5173 — чужой контур, проверяй перед отсылкой

Dev владельца **может быть выключен** — типовая ситуация, а не инцидент (вердикт владельца 24.10.2026: «агенты считают :5173 всегда запущенным — это не так»). Правило: **никогда не пиши владельцу «смотри на :5173», не проверив порт**. Проверка — `pnpm live-stack status` (строка `dev-owner :5173`) или `curl -sm2 -o NUL -w '%{http_code}' http://127.0.0.1:5173` (`000` = вниз; *nix — `/dev/null`).

- Порт ВНИЗ → :5173 в ответе не давать как рабочий. Живая копия для приёмки — песочница `:4173`: поднять `pnpm live-stack up --dev` (если ещё не) и ДЕРЖАТЬ up до вердикта владельца — в этот момент она контур приёмки, не «моя проба».
- Владелец хочет именно свой dev → его контур, его и поднимать: предложить ему `pnpm dev`; самому молча не стартовать (чужой процесс = чужой контур).

## Что чем проверять (лестница — вниз, если можно)

1. **Unit (Vitest)** — всё, что проверяется без браузера и сервера: чистые функции, редьюсеры, компонентная разметка. Это 95% проверок.
2. **Интеграционные (CI)** — контракты API, идемпотентность, outbox; гоняются в CI сами.
3. **Живая проба (песочница live-stack)** — только поведение, которое существует лишь живьём: WebSocket-догон, скролл, два пользователя, тайминги, миграции на живой БД.
4. **Приёмка владельцем** — на `:5173` (если поднят — проверить!) или `:4173` песочницы; коммитим на локальную ветку до вердикта, push — после (workflow п.3/п.7).

Правило: подумал «надо бы проверить в браузере» → сначала спроси себя, нельзя ли unit-ом. Живая проба — осознанное решение, не рефлекс.

## Песочница live-stack — одна команда

```bash
pnpm live-stack up --dev  # цикл правок/приёмки: vite dev на :4173 (правка фронта — за секунды, без down/up)
pnpm live-stack up --dev --mock all  # ИСКЛЮЧЕНИЕ: MSW в песочнице — UI-чекпоинт ДО бэкенда (#431, ADR-0001)
                          # вход любыми данными; пробы поведения и e2e — только без моков
pnpm live-stack up --dev --mock roles  # покомпонентный режим #48: живой вход учётками песочницы,
                          # на моках только перечисленные домены — когда чекпоинту нужны права разных сотрудников (#379)
pnpm live-stack up        # = --preview: собранная копия — финальная проверка перед вердиктом владельцу
                          # оба: АВТО-изоляция DATABASE_URL -> nodus_night, REDIS_URL -> db1
                          #   + бутстрап: создать БД -> миграции -> сид (роли, флаги, пользователи CI) -> night-пользователи
pnpm live-stack status  # api :3011 / gateway :3012 / web :4173, pid-файл .live-stack/
pnpm live-stack down    # снять (свои процессы гасить после приёмки)
pnpm live-stack bootstrap  # только бутстрап БД (up делает это сам)
```

- Подъём/снятие — ТОЛЬКО через эти команды (PID-файл ловит сирот прошлых сессий; чужой процесс на порту = громкая ошибка, а не молчаливый EADDRINUSE).
- **Изоляция автоматична и принудительна**: без явного env процесс уходит в `nodus_night` (та же nodus_postgres) + Redis db1; запуск против прода — только `SANDBOX_ON_PROD=1` (не надо). Почему: два api на одной БД/редисе воруют outbox-события и fanout стрима друг у друга.
- **Цикл правок — dev-режим, финальный показ — preview** (#247): в `--dev` правка фронта видна по F5/HMR; правки api/gateway (dist) и preview-режим — `down` + `up` (preview держит СТАРУЮ сборку, пока жив процесс). Preview-прогон — один раз перед вердиктом владельца.
- **Тестовые пользователи — один источник для всех сред: `tests/e2e/e2e-users.json`** (#247): CI-пользователи e2e (`admin@nodus.by`, `a.klimovich@passatproekt.by` — сид с паролями оттуда) + алиасы проб `night-a@nodus.local` / `night-b@nodus.local`. Любой `*-live` спек CI идёт против песочницы без правок: `E2E_LIVE_API=1 NODUS_BASE_URL=http://127.0.0.1:4173 pnpm --filter @nodus/e2e test specs/<spec>`. Пароли — секреты одноразовых стендов, не прод.
- Полный сброс данных песочницы: `docker exec nodus_postgres psql -U nodus -c 'DROP DATABASE nodus_night'` → `pnpm live-stack up` пересоздаст.

## Правила живых проб

- **Гасить — только свои процессы по PID** (инцидент 19.10, #326): массовое `taskkill /IM node.exe` / `pkill node` убивает песочницу, dev :5173 владельца и чужие сессии. Песочница — только `pnpm live-stack down`. `pnpm build` в дереве работающей песочницы перезаписывает отдаваемый ею `dist` (preview) — ревью-сборки — в отдельном worktree (`git worktree add`) или точечно во временный каталог (`pnpm --filter @nodus/web exec vite build --outDir <tmp>`), не корневым `pnpm build`.
- **Бюджет: 1–2 пробы на фикс** (вердикт владельца 01.10): гипотеза → одна проба → гейты → владельцу. Непонятное — вопрос, а не серия прогонов.
- Проба владеет своими данными: сущности создаёт с маркером («Проба …») и чистит за собой; упавшая проба оставляет полусозданное — добить/удалить перед следующим прогоном.
- Скрипты проб — в `.live-stack/` (gitignored), каркас и паттерны — `references/probes.md` (REST-логин Bearer, SPA-навигация, Idempotency-Key, ожидания вместо sleep).
- Замеры UI в дизайн-px = фактические ÷ 1.25 (ui-scale); пиксельные сканы скриншотов — dpr=3, инсент 6px от краевого ореола.
- Владельцу — живой взгляд (или видео), НЕ свои скриншоты вместо приёмки.
